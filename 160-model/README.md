# 160-model 主流模型档案

按模型家族归档**已发布模型**的架构规格、技术路线与部署账。与 `80-model-architectures` 的分工是：那个域讲**机制本身**（attention 变体、MoE 路由、归一化的数学），本域讲**某一家在某几代上怎么选、为什么这么选、代价是多少**。

## 本域覆盖什么

| 主题 | 内容 | 状态 |
|---|---|---|
| [glm](glm/) | 智谱 GLM 家族：技术路线（130B → 5.3）+ GLM-5 代骨架 + 部署账 | 已完成 |
| [deepseek](deepseek/) | DeepSeek 家族：技术路线（MLA → CED + CSA2）+ V4.1-Flash 实例分析 | 已完成 |
| [kimi](kimi/) | Kimi 家族：技术路线（MuonClip → KDA + AttnRes）+ K3 实例分析 | 已完成 |

三个主题恰好构成**同一问题的三种答案**——长上下文的 KV 太贵，怎么办：

| | 解法 | 代表机制 | 每 token 全局 KV |
|---|---|---|---|
| **DeepSeek** | **压缩**那份 $O(L)$ 的缓存 | CSA/HCA → CSA2 跨层复用 → FP4 | **890 B**（V4.1-Flash） |
| **GLM** | 在缓存里**挑位置** | DSA（top-k = 2048）→ IndexShare | 576 维 latent（1M 约 94 GB） |
| **Kimi** | **换掉**缓存 | KDA（69 层线性注意力）+ 24 层 Gated MLA | 24 层 × MLA latent（1M 约 29 GB） |

建议按「路线 → 实例」的顺序读，并把三家的**同一小节**并排看：技术路线三篇的 §1 第三步都在回答「注意力怎么变便宜」，但给出的机制完全不同。

## 与其他域的关系

- **上游**：`80-model-architectures`（Transformer / attention-variants / moe / normalization / positional-encoding）——机制正文都在那里，本域只回链。
- **下游**：`120-inference`（KV 容量、调度、解码策略）、`130-model-optimization`（W4A8 / KV cache 量化）、`100-parallelism`（EP 与其他并行轴的组合）。
- **横切**：本域**不复述**机制推导。凡「这个机制是什么」的内容，位置在 80 / 120 / 130 域；本域只放「这一家怎么用它、用它换来什么数」。

## 写作约定

1. **规格值必须带口径。** 同一个模型的总参在不同来源下可能是 744B 或 753B、1.0174T 或 1.0465T，层数可能是 78 / 79 / 80，KV 可能是 800 B 或 960 B——差异来自「含不含 embedding」「MTP 算不算一层」「indexer K 用什么精度」。本域的每篇文档都必须写明用的是哪个口径；**对不上时把区间算出来并断言它夹住官方值**，而不是替官方选一个。
2. **官方倍数 ≠ 推导值。** 厂商公布的「FLOPs 降 2.9×」「KV 小 4.4×」一律标为**引用值**并附官方给的归一化口径；本仓库自己只推导**结构性结论**（如「indexer 侧降 4×」），两者不得混用。
3. **代码形态（CONTRIBUTING §2 判定表第二种）**：编号程序是 `.py`，在**默认 `python3` + `numpy`** 下可跑，三类断言（A 算法正确性 / B 代价模型 / C 边界与反例）**全部在程序内部**，失败以非零码退出。因此本域**不需要 `verify.py`**。
   - 程序产出**一律是推导值**：不加载权重、不 import 推理框架、不测硬件。
   - 构造者本机没有 GPU，也不会有——这不是缺陷，而是本域知识对象（**架构规格与解析账**）的性质决定的：744B / 2.78T 模型的 FLOPs 与 KV 字节是算出来的，不是测出来的。
4. **§5 章节形态：判据表。** 按 CONTRIBUTING §4 的三种合法形态择一，本域用**判据表**，理由：
   - 「实测数据」形态要求**能真跑目标系统**——本域的知识对象是 744B 级模型与国产芯片集群，本机无 GPU，跑不了，因此该形态**不适用**；
   - 「整节省略」形态只适用于交付物是 `.cu` 而本机无 CUDA 工具链的情形，本域交付物是 `.py`，**不适用**；
   - 判据表要求「每行是可机械判定的条件 → 结论」且表要闭合。本域的账恰好都是这种形式（例如「规格有 `kv_lora_dim` 而无 `kv_heads` ⇒ 是 MLA，KV 维度 = `kv_lora_dim` + RoPE 维且不乘 2」），所以选它。
5. **不写预测。** 本域记录的是**已发布模型**的已公布规格。官方没说的事（如 GLM-5.3-Flash 用的是哪一种线性注意力、K3 的 MLA latent 与 head dim、Block AttnRes 的块数）一律记为 `UNRESOLVED`；推导必须用到的缺失参数一律标注为**示例假设**。
6. **经验结论与架构结论分开。** 「scaling 效率提升 2.5×」「榜单反超 X」这类是**经验结果**，架构账算不出来，一律标为引用值并附测量条件；本仓库只推导参数量、FLOPs、KV 字节、通信量这类可复算的量。
