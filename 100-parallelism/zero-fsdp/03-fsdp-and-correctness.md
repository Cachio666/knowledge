# FSDP 的策略与分片后的正确性：A 类很弱，如实写

> **ZeRO-3 的工程形态之一就是 FSDP**（PyTorch 的 `FullyShardedDataParallel`）。
> 它把**参数 / 梯度 / 优化器状态全分片**，**按需 all-gather、用完即丢**。
> ★★ 本文讲两件事：**它有哪几种策略**（`sharding_strategy` 的取值，★ 只引列表、不解释语义），
> 以及 ★★★ **分片之后的「正确性」到底是什么** —— **答案是「搬运正确」**，
> 这也正是**本主题的 A 类【很弱】的原因**（本文**如实写，不硬凑**）。

## 0. 背景与动机

`01` 给了三个 ZeRO 阶段的账，`02` 给了通信量。**FSDP 是 `P_os+g+p`（ZeRO-3）的实现形态**：
它把全部状态**分片**，于是**每张卡在任一时刻只持有参数的一个分片** ——
用到时 `all-gather` 起来、**用完即丢**。

★★★ **本文的主线是一条【否定性】的**：**FSDP 的正确性本质就是「搬运正确」** ——
**它不改变任何浮点运算的求值顺序**（切的是「哪一块在谁手里」，不是「怎么算」）。
⇒ **「全分片 == 不分片」这条判据【恒真】**（`§4.1`）⇒ **本主题的 A 类很弱**。

★ **本文不写框架 API 的通用语义**（`torch.distributed` / `DDP` / `ProcessGroup` 的用法）——
★★ **全库当前在这上面没有正文** ⇒ 把禁区指向 `70-frameworks` 是**假让渡**
（见 `§1.1` 的边界）。

| 取值 | 一句话（★ 文档自己的描述，本文**不扩写**） |

## 3. 实现与演进

### 3.1 FSDP 是 `P_os+g+p` 的实现形态

★ **`FULL_SHARD` 的账** = `16Ψ/N`（三项全切）—— 与 `01` 的 `P_os+g+p` 那一档**对拍**。
★ **`SHARD_GRAD_OP`** ≈ `P_os+g`（**参数不分片**）→ 每设备 `2Ψ + 2Ψ/N + 12Ψ/N`。
★ **`NO_SHARD`** 等价 DDP → 一项都不切 → `16Ψ`。

### 3.2 ★★★ 三种策略的每设备字节账（本机实测）

**本机实测（`code/` 的 `B.1`：真的建状态、量 `nbytes`，`Ψ = 65536`、`N = 4`）**：

| 策略 | 每设备字节 | ÷ Ψ | 与闭式 |
|---|---|---|---|
| **`FULL_SHARD`** | `262144 B` | **`4.0000Ψ`** | **精确一致** ✓ |
| **`SHARD_GRAD_OP`** | `360448 B` | **`5.5000Ψ`** | **精确一致** ✓ |
| **`NO_SHARD`** | `1048576 B` | **`16.0000Ψ`** | **精确一致** ✓ |

★★ `FULL_SHARD` 的 `4.0000Ψ` 正是 `16Ψ/4` —— ★ 与 `01` 的「三项全切」那一档**对拍**。

★★★ **一条口径提醒（本机实测，`B.2`）**：`SHARD_GRAD_OP` 在 `N = 4` 的 **`5.5000Ψ`**
与 `ZeRO-1`（`P_os`）在 `N = 8` 的 **`5.5000Ψ`** **数值相同** —— ★★ **但那是因为 `N` 不同**：
- `SHARD_GRAD_OP`（`N = 4`）：`2 + 2/4 + 12/4 = 5.5Ψ`；
- `ZeRO-1`/`P_os`（`N = 8`）：`2 + 2 + 12/8 = 5.5Ψ`。

⇒ ★★★ **报这个数时必须带 `N`**，否则两个来自不同配置的 `5.5` 会被当成同一个东西。

### 3.3 ★★★ 分片边界的配对（`A.1`）到底钉的是什么

★★ 本主题的 A 类只能钉在**一个很窄的地方**：**「第 `k` 片的边界落在正确的全局下标」**。
**本机实测（`code/` 的 `A.1`，`Ψ = 65536`、`N = 4`、`L = 16384`）**：

| 片 `k` | 首元素应 == | 末元素应 == | 长度 |
|---|---|---|---|
| `0` | `params[0]` ✓ | `params[16383]` ✓ | `16384` |
| `1` | `params[16384]` ✓ | `params[32767]` ✓ | `16384` |
| `2` | `params[32768]` ✓ | `params[49151]` ✓ | `16384` |
| `3` | `params[49152]` ✓ | `params[65535]` ✓ | `16384` |

★★★ **它【弱】在哪**：一个**正确实现当然满足**它。★ **它【不恒真】在哪**：
把分片换成**跨步映射**（`params[k::N]`）⇒ 第 `k` 片的**首元素**变成 `params[k]`（**不是** `params[k*L]`）
⇒ ★★ 配对**失败**（`A.1g` 守卫把它跑了一遍）—— **这就是它存在的意义**。
★★ **覆盖边界**（必须写明）：本程序 A 类守的是「**分片做对了没有**」（边界落在哪个下标），
**不守**「算子本身对不对」（那由 `numpy` 保证）⇒ **不得声称 A 类验证了更多东西**。

### 3.4 ★★★ 「拼回」（all-gather）为什么不可能有内容判据

★★★ **关键事实**：`gather`（把 `N` 片按顺序拼回）是**纯搬运** ——
**它连一次浮点运算都不改** ⇒ 「拼回 == 原始」**恒真**（本机实测 `D.4`：`max|diff| = 0.000e+00`）。
⇒ ★★ **A 类在 FSDP 上【没有】「改变了求值顺序」的落点**（与 TP 的行并行、DP 的累加不同）。
★★★ **唯一的出路是 C 类**：证明「**搬运做错会真的失败**」——
只拼一半 `4.188065`、忘了 all-gather `4.300922`、拼错顺序 `5.883126`（三条都**不报错**）。
★ **这就是本文反复说「A 类很弱、主力在 B/C」的原因** —— ★★★ **不得为了「三类缺一不可」
而编一条恒真的 A 类**（那正是 `P12`；本库 `D.4` 把那个 `0` 明写成**报告**、**不是判据**）。

## 4. 踩坑与失败模式

### 4.1 ★★★ 把「全分片 == 不分片」当 A 类判据

- **现象**：分片再拼回与原始参数**逐位相同**（`max|diff| = 0.000e+00`），看起来「完美通过」；
- **成因**：★ **分片再拼回是纯搬运** —— 它**连一次浮点运算都不改** ⇒ **恒真**（`D.4` 量它）；
- **规避**：★★★ **本程序不把那个 `0` 写成判据** —— `D.4` 是一条**恒真性自检（报告）**，
  它**与 `C.1`/`C.2`/`C.3` 的内容级差【并列】**。**没有那三个数，`D.4` 的信息量为零。**
  ★ A 类因此钉在**分片边界的配对**（`A.1`）上。

### 4.2 ★★★ 「只 all-gather 了【一部分】就用」

- **现象**：张量的形状、类型全对，程序**一次异常都不抛**；
- **成因**：`N` 个分片里**只拼回了一部分**（其余位置仍是 `0`）⇒ **一半的参数是错的**；
- **本机实测**（`code/` 的 `C.1`）：`N = 4` 只拼回 **2** 片 ⇒ `max|diff| = 4.188065`
  （≫ 内容级阈 `1e-3`）；
- **规避**：★★★ **唯一的信号是「与原始参数的差」** —— `gather` 是纯搬运，没有运行时检查会发现它。

### 4.3 ★★★ 「忘了 all-gather」与「拼错顺序」

- **现象**：同样**不报错**；前者一片都不拼、后者把分片**倒过来**拼；
- **本机实测**（`C.2`/`C.3`）：忘了 all-gather ⇒ `max|diff| = 4.300922`
  （★ **≥ `C.1` 的 `4.188065`** —— 漏得越多、差越大）；拼错顺序 ⇒ `max|diff| = 5.883126`；
- **规避**：★★ **三条错法都是「搬运做错」** ⇒ 这正是 `A.1`（边界配对）与 `C` 类存在的理由。

### 4.4 ★★ 「分片」（显存）与「分片检查点」（落盘）

- **现象**：把两者当同一件事，于是以为「分片保存 = 显存分片」；
- **成因**：★★ **同名不同指** —— 前者在**显存**里（`ZeRO`/`FSDP`），后者在**磁盘**上；
- **规避**：★★★ **落盘一律回链 `90-training/checkpointing/02,03`**（本文不写落盘）。

## 6. 小结与延伸

**一句话**：**FSDP 把参数 / 梯度 / 优化器状态全分片、按需 all-gather、用完即丢**
（`FULL_SHARD` 是默认策略）；★★★ **而它的「正确性」本质就是「搬运正确」** ——
**分片再拼回逐位相同** ⇒ **A 类很弱**，主力在 **B 类**（三种策略的字节账）。

**三条可独立复用的结论**：

1. ★★★ **「全分片 == 不分片」恒真**（纯搬运）⇒ **不是 A 类**；A 类钉在**分片边界的配对**上，
   **内容判据在 C 类**（只拼一半 `4.188065` / 忘了 all-gather `4.300922` / 拼错顺序 `5.883126`）；
