# 三个 ZeRO 阶段各切什么、省多少：分片不是除法

> **ZeRO 把训练状态分成三项** —— **参数、梯度、优化器状态**。**每一项都可以单独切**，
> 而**「切了一项」只省那一项**：没切的项**留在每张卡上**。
> ★★★ **所以「每卡占用」不是 `16Ψ/N`** —— 这就是本文的主线：**分片不是除法**。
> · `P_os`（只切优化器状态）在 `N` 很大时**仍趋近 `4Ψ`**（参数 `2Ψ` + 梯度 `2Ψ` 没切）；
> · `P_os+g`（再切梯度）趋近 **`2Ψ`**（只剩参数没切）；
> · **只有 `P_os+g+p`（三项全切）** 才到 `16Ψ/N`。

## 0. 背景与动机

`data-parallel` 那一支讲的是**数据并行**：每张卡放**完整**的模型、梯度与优化器状态，
只把梯度平均一下。★ 那笔账的结论是：**单卡显存装不下** —— 优化器状态本身就很大。

**ZeRO** 的观察是：**训练状态里的大部分，在任何时刻都只有一部分是「当下要用」的**
（这一点在 `03` 里用 FSDP 的 `FULL_SHARD` 时序讲得更具体）。
于是把这些状态**摊到 `N` 张卡上**（每张存 `1/N`），需要时再**集合**起来。

★ **本文要回答的只有一件事**：**每一项状态切或不切，每张卡还剩几个字节**。
★★★ 而这件事有一个**非常容易被算错的地方**：**把「分片」当成「除法」**。

> ★★★ **一句话的反例**：`P_os` 在 `N = 512` 时，每卡仍需 **`4.0234Ψ`** ——
> **不是 `16Ψ/512 = 0.03125Ψ`**。因为 `P_os` **只切优化器状态**，参数与梯度**没切**。

★ **本文不重推 `16Ψ` 的分解** —— `2Ψ + 2Ψ + KΨ = 16Ψ` 的正文在
`90-training/checkpointing/01-state-and-bytes.md:97-107`（§1.3 与 `:229-230` 的判据表）。
**本文只写「分片后」的账**（见 `§1.1` 的口径声明）。

## 1. 原理

### 1.1 ★★ 口径：`16Ψ` 是【单卡】的账，本文只写「分片后」

| 项 | 每参数字节 | 依据 |
|---|---|---|
| **参数**（fp16） | `2` | `90-training/checkpointing/01` 的 [C] 口径 |
| **梯度**（fp16） | `2` | 同上 |
| **优化器状态** | **`K = 12`** | 同上（★ 它的**取值与内部构成** —— `fp32 主权重 + m + v` —— **见 90 域**，本文不重推） |
| **合计（单卡）** | **`16`** | `2 + 2 + 12 = 16` |

★★ **三项的取值与构成（含 `K` 的内部拆解 `4 + 4 + 4`）一律回链 90 域**
（`90-training/checkpointing/01-state-and-bytes.md:97-107`）—— ★★ **本文不重推那个分解**。

★★★ **两条口径纪律**：
1. **`16Ψ` 是【单卡】的账**（`90-training/checkpointing/01-state-and-bytes.md` 的正文）——
   本文**只写「分片后」**，**不重推那个分解**（那是 90 域的正文，见 `§3.2`）。
2. **`Ψ` 是【参数个数】**（不是张量个数、不是字节数）——
   `90-training/checkpointing/01:109-113` 逐字：`denotes model size (number of parameters)`。
   ★ 本机实测用 `Ψ = 1024`（A 类）与 `Ψ = 4096`（B 类）**个元素**。

### 1.2 ★★★ 三个 ZeRO 阶段各切什么

| 阶段 | 切优化器状态？ | 切梯度？ | 切参数？ | `N → ∞` 时每卡趋近 |
|---|---|---|---|---|
| **ZeRO-0**（baseline DP） | ✗ | ✗ | ✗ | `16Ψ` |
| **`P_os`**（ZeRO-1） | ✓ | ✗ | ✗ | **`4Ψ`**（参数 `2` + 梯度 `2`） |
| **`P_os+g`**（ZeRO-2） | ✓ | ✓ | ✗ | **`2Ψ`**（只剩参数） |
| **`P_os+g+p`**（ZeRO-3） | ✓ | ✓ | ✓ | `0`（`16Ψ/N`） |

★★ **命名**：`P_os` = **O**ptimizer **S**tate partitioning；`P_g` = **g**radient partitioning
（论文把它与 `P_os` 合称 `P_os+g`）；`P_p` = **p**arameter partitioning。
★★★ **`stage` 在这里一律写全称「ZeRO 阶段」** —— 本库的 `stage` 有**四个**含义
（TVM 的计算阶段、cutlass 的流水级数、**流水线并行的 stage**、**ZeRO 阶段**），
见域 README 的「同名不同指」一节。

### 1.3 ★★ 为什么下界是 `4Ψ` / `2Ψ`（「收益饱和」）

`P_os` 每卡 = 参数 `2Ψ` + 梯度 `2Ψ` + 优化器状态 `12Ψ/N` = **`4Ψ + 12Ψ/N`**。
⇒ `N` 越大，**`12Ψ/N` 那一项越小**，但 `4Ψ` **不动** ⇒ **收益饱和在下界 `4Ψ`**。
★ 同理 `P_os+g` = `2Ψ + 2Ψ/N + 12Ψ/N` ⇒ 下界 **`2Ψ`**（只剩参数那一项没切）。

★★★ **本机实测（`code/01_three_stages.py` 的 `B.1`/`B.2`，`Ψ = 4096`）**：

| `N` | `P_os` 的每卡字节 ÷ Ψ | `P_os+g` 的每卡字节 ÷ Ψ |
|---|---|---|
| `1`（退化对照） | `16.0000` | `16.0000` |
| `2` | `10.0000` | `9.0000` |
| `8` | `5.5000` | `3.7500` |
| `64` | `4.1875` | `2.2188` |
| `512` | `4.0234` | `2.0273` |
| **`4096`** | **`4.0029`** | **`2.0034`** |

★ **最后一行离下界已经很近**：`N` 从 `4096` **翻了一倍**到 `8192`，`P_os` 只从 `4.0029Ψ`
降到 `4.0015Ψ` —— **只省 `0.0366%`**（`B.5`，★ 后一个数由**闭式外推**得到、标为推导值）。
★★★ **这就是「收益消失」**：`N` 大到某值后，**再翻倍也几乎不省**。
（★ 计划 §3 给的同档值是 `4.0000`；**本机实测是 `4.0029`** —— 见 `§4.4` 的口径说明。）

### 1.4 ★★ 四个状态的字节账逐项展开（`N = 8`、`Ψ = 1024` 元素）

| 状态 | 参数 | 梯度 | 优化器状态 | 每卡合计 | ÷ Ψ |
|---|---|---|---|---|---|
| `ZeRO-0` | `2Ψ` | `2Ψ` | `12Ψ` | `16Ψ = 16384 B` | `16.0000` |
| `P_os` | `2Ψ` | `2Ψ` | `12Ψ/8` | `5.5Ψ = 5632 B` | `5.5000` |
| `P_os+g` | `2Ψ` | `2Ψ/8` | `12Ψ/8` | `3.75Ψ = 3840 B` | `3.7500` |
| `P_os+g+p` | `2Ψ/8` | `2Ψ/8` | `12Ψ/8` | `2Ψ = 2048 B` | `2.0000` |

★★★ **一眼看出的两件事**：
1. **`ZeRO-0` 那一列全是「不切」** ⇒ 它就是 `16Ψ`（与 `N` **无关**）；
2. **从 `P_os` 到 `P_os+g+p`，「切」的列在变多** —— **每多切一项，分子就多一个 `/N`**，
   但**还没切的那几项原样留在每张卡上** ⇒ ★★ **这就是「分片不是除法」的算术**。

★★ **一个常见的误算**：把 `P_os` 写成 `16Ψ/8 = 2Ψ`（**错**）——
它**只切了优化器状态那一项**，参数与梯度**还在**。★ 本机实测 `P_os` 是 `5.5Ψ`
⇒ **与「除法」差了 `2.75` 倍**。

## 2. 执行映射

### 2.1 本机怎么算这件事

`code/01_three_stages.py` **真的建出 numpy 数组、真的切、真的量 `nbytes`** ——
**不是**把 `16*Psi/N` 算一遍。

| 角色 | 是什么 | 依据 |
|---|---|---|
| **被测** | `sharded_state_bytes(Psi, N, shard_param, shard_grad, shard_opt)` —— 建状态、量字节 | `specs.py` 的 `[C]`/`[E]` 常量 |
| **参照** | `closed_form_bytes(...)` —— **只用常量与算术的独立闭式** | 同上 |

★★★ **参照实现不调用被测实现的任何函数**（域 README 的硬要求）：
`D.8` 用 **AST 调用表**给出**源码级线索**（★ **不是证明**）——
`closed_form_bytes()` 里调用的函数是**空集**，**没有** `sharded_state_bytes` / `np`。
★ **降级措辞**：这只说明「两段代码不互相调用」，**不证明**判据有物理信息量 ——
后者由 `A.1g`/`B.3g`/`C.1g` 的**行为**兜底。

### 2.2 ★★★ A 类的落点：为什么不能写成 `assert per_card == 16*Psi/N`

★★★ **那句断言是【乘法自证】**：右边就是把左边再算一遍 ⇒ **恒真**（`P12`）。
⇒ 本程序**一个这样的断言都没有**，改成：

> ★★★ **真的建出四种分片状态、量 `nbytes`**，断言
> **「每卡字节 ÷ (16Ψ/N) 只有【三项全切】那一档才 `== 1`」** ——
> 它钉住的是**「名字 ↔ 切了哪几项」是否对上**，且 `A.1g` 的守卫证明**改错配置它真的会失败**。

**本机实测（`A.1`，`Ψ = 1024`、`N = 8`、参照口径 `16Ψ/N = 2048` 字节）**：

| 状态 | 每卡字节 | ÷ (16Ψ/N) |
|---|---|---|
| `ZeRO-0` | `16384 B` | `8.0000` |
| `P_os` | `5632 B` | `2.7500` |
| `P_os+g` | `3840 B` | `1.8750` |
| **`P_os+g+p`** | **`2048 B`** | **`1.0000`** |

★ 四档的字节除以 `Ψ = 1024` 正是 `16.0000 / 5.5000 / 3.7500 / 2.0000` ——
**与 `§1.2` 的公式逐项吻合**（`P_os` 那一格 `5.5Ψ` 与本库**计划 §D3** 记的
`ZeRO-1 N=8 → 5.500000Ψ` **同值**；★★ **90 域【没有】这个数** —— 它把「ZeRO 三阶段」
让渡给了本域，`90-training/checkpointing/01-state-and-bytes.md` 里**既无 `ZeRO-1` 也无 `5.5`**）。

### 2.3 一条必须写明的限定语

> ★★ 本机**无 GPU、无多卡、无 NCCL、无真实网络**；本程序里的「分片」是 **numpy 切片**，
> **没有一次真实通信**。★ 强制限定语：**「不是 NCCL，也不是真机」**。
> ★★ 本程序的数字是**本机实测值**：`python3 3.13.5` / `numpy 2.4.4`（macOS arm64）。

## 3. 实现与演进

### 3.1 三个阶段的工程含义

| 阶段 | 换来什么 | 付什么 |
|---|---|---|
| `P_os` | 优化器状态**摊到 `N` 张卡** ⇒ 省的是**最大的一项**（`12Ψ`） | **通信量不变**（`02` 讲）；参数与梯度**仍留完整一份** |

★★★ **一句话**：**`P_os`/`P_os+g` 是「几乎免费」的那两步**（不增通信），
**`P_os+g+p` 才是那个要付通信代价的阶段** —— 这条分野在 `02` 里是核心。

## 4. 踩坑与失败模式

### 4.1 ★★★ 「分片 = 除法」

- **现象**：按 `16Ψ/N` 估每卡占用 ⇒ 在 `N` 大时**严重低估**；
- **成因**：**每个 ZeRO 阶段只切它声明的那几项** —— `P_os` 不切参数与梯度；
- **本机实测**（`code/` 的 `B.1`）：`P_os` 在 `N = 4096` 时仍是 **`4.0029Ψ`**（下界 `4Ψ`），
  而 `16Ψ/4096 = 0.0039Ψ` —— **差了三个数量级**；
- **本机实测**（`code/` 的 `C.1`）：把这个错法**具名**成 `naive_division_bytes()`（= `16Ψ/N`），
  断言它与真值（`sharded_state_bytes()` 真的建状态）之差 **`> 1.0`**（`N=4096` 给 **`3.9990`**）
  ⇒ ★★ **这个错法【不报错】**，只是一个**算术合法、语义错**的估计；
- **规避**：★★★ **把「切了哪几项」写全**（本文 `§1.2` 的表），**再乘各自的 `1/N`**。

### 4.2 ★★ 「参数也切」时把 `P_os` 的下界算错

- **现象**：以为 `P_os` 的下界是 `2Ψ` 或 `0`；
- **本机实测**（`code/` 的 `B.3g` 守卫）：把 `P_os` 改成**参数也切** ⇒ 下界从 `4.0000Ψ`
  **掉到 `2.0000Ψ`** ⇒ ★★ 换掉「参数切不切」**真的改变了被判量**，`B.3` **能失败** ✓；
- **规避**：下界 = **没切的那些项之和**（`P_os`：参数 `2Ψ` + 梯度 `2Ψ`）。

### 4.3 ★★ 在不能暴露差异的取值上验证判据

- **现象**：拿 `N = 1` 或 `N = 2` 当 B 类的档 ⇒ 看不到「饱和」；
- **成因**：`P_os` 在 `N = 1` 时是 `16Ψ`（与不分片同值）、`N = 2` 时是 `10Ψ` ——
  **离下界 `4Ψ` 还很远**，**看不到「收益消失」这件事**；
- **规避**：★ **B 类的档必须跨到「已经很接近下界」的地方**（本文到 `N = 4096`，`4.0029Ψ`），
  并用 `B.5` 显式量「再翻倍的边际收益」（`0.0366%`）。

### 4.4 ★★ 一个口径数字：计划记 `4.0000`，实测 `4.0029`

- **现象**：`P_os` 在 `N = 4096` 的每卡字节 ÷ Ψ，计划 §3 记 **`4.0000`**；
- **本机实测**：**`4.0029`**（`= 4 + 12/4096`，即 `2 + 2 + 12/4096`）；
- **成因**：★ `4.0000` 是**把下界 `4Ψ` 当成了 `N = 4096` 的实际值** ——
  而 `N = 4096` 时 `12Ψ/N = 0.00293Ψ` **还没小到可以忽略**（要到 `N ≈ 10^5` 才到 `4.0000` 四位）；
- **规避**：★★ **凡报 Ψ 倍数，一律按公式直算**（`2 + 2 + 12/N`），**不四舍五入到下界**
  （这正是 90 域 `D3` 那条「不从舍入值反算」纪律的同族）。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 说「每卡占用 = `16Ψ/N`」 | ★★★ **不成立**：`P_os` 的下界是 **`4Ψ`**、`P_os+g` 是 **`2Ψ`**（`A.1`/`B.3`/`B.4`） |
| 四项分片状态的「每卡字节 ÷ (16Ψ/N)」 | ★★★ **只有【三项全切】才 `== 1`**：`8.0000 / 2.7500 / 1.8750 / 1.0000`（`A.1`，`Ψ=1024, N=8`） |
| 把「全切」那一档漏切参数 | ★★ 归一化值变 **`1.8750 ≠ 1`** ⇒ `A.1` **失败**（`A.1g` 守卫） |
| `P_os` 的每卡字节 ÷ Ψ vs `N` | ★★ 六档 `16.0000 / 10.0000 / 5.5000 / 4.1875 / 4.0234 / 4.0029`，**严格单调下降**（`B.1`） |
| `P_os+g` 的每卡字节 ÷ Ψ vs `N` | ★★ 六档 `16.0000 / 9.0000 / 3.7500 / 2.2188 / 2.0273 / 2.0034`（`B.2`） |
| 报「`P_os` 的下界」 | ★★★ **`4Ψ`**（参数 `2Ψ` + 梯度 `2Ψ`）—— **不是 `0`**（`B.3`） |
| 报「`P_os+g` 的下界」 | ★★★ **`2Ψ`**（只剩参数没切）（`B.4`） |
| 把 `P_os` 改成「参数也切」 | ★★ 下界掉到 **`2Ψ`** ⇒ `B.3` **失败**（`B.3g` 守卫） |
| 报「`N` 大到某值后收益」 | ★★ 从 `N=4096` 翻倍到 `8192` 只省 **`0.0366%`** ⇒ **收益已饱和**（`B.5`） |
| 按「分片就是除法」估 `P_os`（**错法** `16Ψ/N`） | ★★★ **不报错、结果错**：与真值差 **`3.9990`**（`N=4096`：`0.0039Ψ` vs `4.0029Ψ`）⇒ 判据**成立**（`C.1`）；换回对法 ⇒ 差归零 ⇒ `C.1` 失败（`C.1g` 守卫） |
| 引用 `N = 4096` 时 `P_os` 的 Ψ 倍数 | ★★ 写 **`4.0029Ψ`**（**不是 `4.0000`** —— 见 `§4.4`） |
| 报「`Ψ` 是什么」 | ★★ **参数个数**（不是张量个数、不是字节数）；`16Ψ` 是**单卡**口径 |
| 报「`K` 是什么」 | ★★ **优化器状态的内存乘子**（`= 12`）；★ **不是通信量**（那是 `02` 的事） |

## 6. 小结与延伸

**一句话**：**ZeRO 把训练状态分成参数 / 梯度 / 优化器状态三项，每个阶段只切其中几项**
⇒ ★★★ **「切了一项」只省那一项 ⇒「每卡占用」不是 `16Ψ/N`**（**分片不是除法**）。

**三条可独立复用的结论**：

1. ★★★ **下界 = 没切的那些项之和**：`P_os` 是 `4Ψ`、`P_os+g` 是 `2Ψ`，
   —— **不是 `0`**；只有 `P_os+g+p` 才到 `16Ψ/N`（`A.1`/`B.3`/`B.4`）；
2. ★★ **收益饱和**：`N` 从 `4096` 翻倍只省 `0.0366%`（`B.5`）——
   ★ 所以「把 `N` 加到很大」不是省显存的免费手段；
3. ★★ **A 类不能写成 `assert per_card == 16*Psi/N`**（乘法自证）——
   要**真的建状态、量 `nbytes`**，断言「**只有全切才归一化到 1**」（`A.1`）。

**延伸**：

- ★★★ **通信量**（`P_os`/`P_g` **不增**、`P_os+g` = baseline、只有 `P_os+g+p` = `1.5x`）
  → [02-communication](02-communication.md)；
- ★★ **FSDP 的策略与分片后的正确性**（★ 本主题的 A 类很弱，如实写）
  → [03-fsdp-and-correctness](03-fsdp-and-correctness.md)；
- **本域不写、只回链的正文**：
  · ★★★ **`16Ψ` 的组成与字节分解**（`2Ψ+2Ψ+KΨ=16Ψ`）→
    `90-training/checkpointing/01-state-and-bytes.md:97-107`；
  · **`4x`/`8x` 与 `P_os`/`P_os+g` 的对应关系** →
    `90-training/checkpointing/02-sharded-save-and-load.md:156`；
  · **优化器状态的更新式** → `90-training/optimizers/01,02`；**混合精度的类型选择** →
    `90-training/mixed-precision/01-type-selection.md`；
  · **分片检查点的落盘与恢复** → `90-training/checkpointing/02,03`
    （★ 本域只写「**分片**（放进显存）」，不写「**落盘**」）；
