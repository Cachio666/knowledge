# EP 与别的轴：EP 组的划分，以及 EP 的约束（只写取到过的那一条）

> **EP 从不单独存在。** 一台设备同时属于**两个**组：**EP 组**（**同一批 token**、各持不同专家）
> 与 **DP 组**（**同一批专家**、各持不同数据分片）。★ 这两组**共用同一批设备** ——
> 于是「**怎么划**」不再是自由度，而是**正确性**。
> ★★★ **划错的后果**：一次 EP 通信会把**不同数据分片**的 token 送进**同一组专家** ——
> **不报错、结果错**。
> ★★★ **而「`EP` 的约束」本库只写【取到过】的那一条**（`EP` 与 `DP` 的关系）；
> **另一条在任何载体上都没取到** ⇒ **本文不写它**（§1.3）。

## 0. 背景与动机

`01` 讲了专家怎么分、`02` 讲了负载的账。**本文回答的是「它和别的轴怎么共存」**：

- **EP × TP**：专家内部还能不能再切一刀？（§1.1）
- **EP 组的划分**：EP 组与 DP 组共用设备时，「谁和谁一组」是**算术**还是**自由选择**？（§1.2）
- **`EP` 的约束**：有没有一条规则说 `EP` 能取多大？（§1.3 —— ★ 答案是「**只有一条取到过**」）
- **`EP > E`**：设备比专家还多时会发生什么？（§1.4）

★★ **一条贯穿全文的纪律**：本域讲的是**切分的代数** ——
**不是 NCCL，也不是真机**；本机**无 GPU、无多卡、无真实网络**。

## 1. 原理

### 1.1 ★★★ EP × TP：专家内部再切一刀

**切法**：EP 把**专家**分到设备上；**TP 把每个专家的权重矩阵再切一刀**。
★ 本文**只用到 TP 的「行切」**（把 `W1` 的 `D_in` 维切成 `TP` 份、各自算完再**求和**）——
★★★ **理由不是「它更方便」，而是「它【改变了求值顺序】」**：

| `tp` | 行切+求和做了什么 | 本机实测 `max|diff|`（对单卡） |
|---|---|---|
| `1` | **什么都没做**（切 1 份） | **`0.000e+00`** |
| `2` | 求和拆成 `Σ_{p=1,2}` | **`4.441e-16`** |
| `4` | 求和拆成 `Σ_{p=1..4}` | **`4.441e-16`** |

★★★ **这张表就是本域那条纪律的实例**：域 README 说
「**A 类判据只在『切分改变了求值顺序』的地方才有信息量**」——
⇒ ★★ 本文把 `tp = 1` 与 `tp > 1` **写在【同一条判据】里**：
**前者必须恰为 `0.000e+00`（纯搬运）、后者必须严格大于 0**。
★★★ **少了后半条，前半条就是【恒真】的伪断言**（`01` 的 `D.4` 量过同一件事）。

> ★★★ **TP 本身的切法与配对约束不在本文** —— 列切 `D_out` / 行切 `D_in` 的配对、
> `2+2` 次 all-reduce 的逐字出处，正文在 `100-parallelism/tensor-parallel/01`、`02`、`03`
> 与 `10-foundations/performance-models/02-amdahl-and-scaling.md:417`
> （★ **不是 `:223`** —— 那一行是**纯 TP 段**）。★ **本文一行都不重写它们**。

★★ **EP 度对这一档**没有影响**（本机实测 `A.2`：`EP ∈ {2, 4}` 下三档 TP 的差值序列
**逐项相同**）—— ★★ 理由：**EP 在本程序里只改「哪些项被加起来」（纯搬运），
不改任何一项的浮点值** ⇒ 它不影响「几 ulp」这个档位。★★ 它影响的是**别的**东西
（搬运条目数、负载分布）—— 那在 `01`/`02`。

### 1.2 ★★★ EP 组的划分：**连续** vs **跨步**

**布局口径**（本库）：**EP 为内层** ⇒ `r = dp_rank * EP + ep_rank`，`world = EP * DP`。于是：

| 组 | 成员 | 它们共享什么 |
|---|---|---|
| **EP 组** | `{g*EP + j : j ∈ [0, EP)}` —— **连续的一段** | 同 `dp_rank` ⇒ **同一批 token** |
| **DP 组** | `{e + k*EP : k ∈ [0, DP)}` —— **跨步的一批** | 同 `ep_rank` ⇒ **同一批专家** |

★★★ **关键不变式**：**一个 EP 组内的设备必须持有【同一个】数据分片** ——
因为它们处理的是**同一批 token**、只是**专家不同**（这正是 EP 的定义）。

**本机实测**（`C.1`，`EP = DP = 2`，逐个组打印）：

| 划分 | 组 | 数据分片 | 组内跨分片数 |
|---|---|---|---|
| **连续**（正确） | `[0,1]` / `[2,3]` | `[0,0]` / `[1,1]` | **0 / 0** |
| **跨步**（错法：`r % EP == e`） | `[0,2]` / `[1,3]` | `[0,1]` / `[0,1]` | **1 / 1** |

★★★ **后果**：错法下**一次 EP 通信会把 2 个不同数据分片的 token 送进同一组专家** ——
★ **形状、类型、索引全都合法** ⇒ **不报错、结果错**。

### 1.4 ★★ `EP > E` 时会发生什么（★ **本库设计的一个情景**）

★★★ **先把性质说清**：§1.3 说了那条规则**没取到** ⇒
**本节的 `EP > E` 不是「违反规则的例子」，而是「本库的记账模型会多出什么」**。

**机制**：`EP > E` 时**一台设备摊不到一个完整专家** ⇒ 专家必须**跨设备切开**
（专家内部再切 `ceil(EP/E)` 份）⇒ 每份 token 拷贝要**复制到那几台设备**上。

**本机实测**（`B.1`，`T·top_k = 64` 条、载荷单位 `d_model` = 8）：

| `EP` | `ceil(EP/E)`（`E = 8`） | 投递条目 | 载荷（元素） |
|---|---|---|---|
| `2` / `4` / `8`（`≤ E`） | **1** | 64 | 512 |
| `16`（`> E`） | **2** | **128** | **1024** |
| `32`（`> E`） | **4** | **256** | **2048** |

★★★ **条目数与载荷都按因子涨** —— 这就是「专家的内部切分」的代价。
★ 两档取 `16` 与 `32` 是**故意的**：它们**整除** `E = 8`（因子 `2` / `4` 看得见）；
★★ 不整除时 `ceil` 与 `//` 的差别是 `01` 的 `A.1`，**本节不重算它**。

## 4. 踩坑与失败模式

### 4.1 ★★★ 把 EP 组划成「跨步」的

- **现象**：**不报错**；形状、类型、索引全都合法；
- **成因**：把 EP 组当成「同余类 `r % EP == e`」而不是「**连续的一段**」
  （★ 直觉上两者都「把设备分成 `EP` 组」，**但组内设备的 `dp_rank` 不同**）；
- **本机实测**（`C.1`）：`EP = DP = 2` 时，连续划分的跨分片数是 **0/0**，
  跨步划分是 **1/1** ⇒ ★★ **一次 EP 通信混进 2 个数据分片**；
- **规避**：★★★ **把「组划分」当成算术来钉**（`device_rank` / `data_shard` 必须**同源**）。

### 4.2 ★★★ 把 EP 的行切当成「不做也没关系」

- **现象**：`tp > 1` 时结果**看起来对**（差只有 `4.441e-16`）；
- **成因**：★ 行切+求和**只改求和顺序** ⇒ 误差在**几 ulp** 档；
  ★★ 但**如果压根不做**（只留一片）⇒ 差跳到 **`1.925698` / `2.090017`**；
- **规避**：★★★ **A 类的两个条件必须写在同一条判据里** ——
  只有「`tp > 1` 时差**严格大于 0**」这一半能抓住「没做行切」；
  ★ 「差 `< 1e-9`」这一半能抓住「少加了几片」。

### 4.3 ★★ 用「expert 数」去限制「EP 度」

- **现象**：写出「因为一台设备至少要有一个专家，所以 `EP` 不能超过专家数」；
- **★★★ 问题**：这条规则本库**没有在任何载体上取到**（§1.3）——
  ★ 它可能是**某些实现**的工程约定，但**本文不给它出处** ⇒ ★ **不得当规范写**；
- **规避**：★★ 要写「`EP > E` 会怎样」，就照 §1.4 那样**明写它是本库设计的情景**。

### 4.4 ★★ 把「EP 与 DP 的约束」升格成规范

- **现象**：把 Megatron 文档里那句写成「**EP 必须是 DP 的子组**」这条**规范**；
- **★★★ 问题**：那是 **[B] 级**（**某实现的官方文档，不是规范**），
  而且原文的主语是 **`Prior MoE frameworks`**（**先前的**框架）；
- **规避**：★★ **引用时三样都要带上**：**级别 [B]** + **抓取日**（活文档）+ **主语**
  （讲的是**先前的**框架）。

## 6. 小结与延伸

**一句话**：**EP 与别的轴共存时，「怎么划组」不是自由度而是正确性** ——
★★★ **一个 EP 组里的设备必须持有同一个数据分片**；
★★★ **而「`EP` 的约束」本库只有一条是取到过的**（`EP` 与 `DP` 的关系）。

**三条可独立复用的结论**：

1. ★★★ **A 类判据要选在「切分改变了求值顺序」的地方** ——
   `tp = 1` 恰为 `0.000e+00`（纯搬运、恒真）**而** `tp > 1` 是 `4.441e-16`；
   ★★ **两个条件写进同一条判据**，否则它是伪断言；
2. ★★★ **EP 组是【连续的一段】、DP 组是【跨步的一批】** ——
   划反了 ⇒ 一次 EP 通信混进 `DP` 个数据分片（**不报错、结果错**）；
3. ★★ **`EP > E` 时专家要被内部切开**，条目与载荷按 `ceil(EP/E)` 涨
   （`16→2×`、`32→4×`）；★ **这是本库设计的情景，不是任何规范**。
