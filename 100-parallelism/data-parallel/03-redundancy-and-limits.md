# 数据并行的冗余账与它的上限（加卡不能解决显存问题）

> **DP 是最省事的一刀：它只切数据、不动模型 —— ⇒ 每张卡都持有一份【完整】的训练状态。**
> ★★ 于是 `N` 张卡用 **`N × 16Ψ`** 的总显存，存了**同一份 `16Ψ`** 的状态：
> **冗余度 `(N−1)/N`**（本机 `N=8` → **`0.875000`**，`N → ∞` 时**趋于 1**）。
> ★★★ 推论：**「每卡要放多少」只由 `Ψ` 决定，与 `N` 无关** ⇒
> **加卡买不到显存**（它买到的是吞吐与更大的全局 batch）—— 这正是 `zero-fsdp` 存在的理由。

## 0. 背景与动机

### 一个具体的对照场景

一个 `Ψ = 65536` 个参数的玩具模型，**每张卡**的训练状态按 `16Ψ` 算 ⇒ **`1048576 B`**。
`N` 张卡的实际总占用：

```
N=1   单份 524288 B（参数，fp64）× 1  =   524288 B      冗余度 0.000000
N=8        ...                     × 8  =  4194304 B      冗余度 0.875000
N=16       ...                     × 16 =  8388608 B      冗余度 0.937500
```

★ 注意**单份那一列完全不动**：`N` 从 `1` 涨到 `16`，**每卡的字节一个都没变**
（本机实测：五种 `N` 下单份**逐位都是 `524288 B`**）。
⇒ **多出来的卡没有换来「每卡少放一点」，只换来了「同一份东西多存了几遍」。**

### ★★★ 本文的落点：冗余是**账**，不是**抱怨**

「DP 有冗余」这句话本身没有信息量。本文要把它变成**可判定的量**：

1. **冗余度** `= (总量 − 单份) / 总量 = (N−1)/N` —— ★ **这个量全库没有既有定义**，
   它是本主题**自立的定义**（`specs.UNSOURCED`：`data_parallel_redundancy_ratio_definition`）；
2. **每卡状态的字节数**（`16Ψ`）**与 `N` 无关** —— 它只由 `Ψ` 决定；
3. **`N` 份副本的参数必须【逐位相同】** —— 这是 DP 的**隐含假设**，
   ★★ 而 [B] PyTorch 2.14 把它写成了**逐位**（逐字 `bitwise identical in all processes`），
   不是「近似相同」⇒ 本文的判据因此用 **`sha256` 摘要相等**，**不用容差比较**。

★★★ **本文的头号坑是「模拟器同时是被测对象」（本库 `P12`）**：
若程序里就是 `assert total == N * 16 * Psi`，那是在**断言它自己写的那行乘法**。
⇒ 本文的落法是：**真的建出 `N` 份状态**，量它们的 **`nbytes`**、算它们的 **摘要**
—— 判据钉在「**副本一致性**」上，而**不是**钉在乘法上。
★ 并且**每一条都要能失败**：`A.3` 与 `C.1` 把「一份漂掉」的后果真的跑出来。

## 1. 原理

### 1.1 ★ 每卡的状态是 `16Ψ`（本文只消费，不重推）

[C] ZeRO 的 §5.1 把每卡的训练状态列成三项，逐字依据是：

> `In total, this results in 2` … `bytes of memory requirement`
> （中间夹着公式 `2Ψ+2Ψ+KΨ=16Ψ`，★ 含标记 ⇒ 切头取尾）

以及 `K` 的定义（只限**优化器状态**）与它的条件：

> `i.e., the additional memory required to store them is K`
> `based on mixed-precision training with Adam optimizer.`

**本机实测**（`code/03_redundancy.py` 的 `A.2`，按四个 dtype **真的建出来**再量）：

| 项 | dtype | 本机 `nbytes` | 与 `Ψ` 的关系 |
|---|---|---|---|
| `param` | fp16 | `131072 B` | `2Ψ` |
| `grad` | fp16 | `131072 B` | `2Ψ` |
| 优化器三项（主权重 / `m` / `v`） | fp32 | `786432 B` | `12Ψ`（`4 + 4 + 4`） |
| **合计** | —— | **`1048576 B`** | **`16.0000Ψ`** |

★★★ **`K = 12` 是 ZeRO 的举例口径** —— 它的成立条件是
`based on mixed-precision training with Adam optimizer.`。
⇒ **凡引用 `16Ψ` / `12Ψ`，必须带上这句限定语**（这是「订正不扩散」在本主题的可执行落法：
配套程序的 `D.5c` 会去**读本文件**，检查这个字符串**逐字在**）。
★★ **这一段不是本文的知识点**：`16Ψ` 的**组成与字节分解**的正文在
`90-training/checkpointing/01-state-and-bytes.md`（§1.3 + 判据表 +
`code/01_state_bytes.py:310` 的 `A.3`）⇒ 本文**只消费**这个系数。

### 1.2 ★★ 判据 ②：每卡的字节数**只由 `Ψ` 决定**

把上表里的 `Ψ` 翻倍（每层的输出维 ×2）：

| | `Ψ = 65536` | `Ψ = 131072` | 比值 |
|---|---|---|---|
| 每卡状态 | **`1048576 B`** | **`2097152 B`** | **`2.0`** |

⇒ **`每卡 = 16Ψ 个字节`**（`16` 这个倍数**已经含了**各 dtype 的字节数）
⇒ **它与 `N` 无关**（§1.3 的实测：五种 `N` 下单份逐位相同）。

★★★ **这就是「加卡不能解决显存问题」的全部内容**：
要在 `N` 张卡上装下一个 `2Ψ` 的模型，**每张卡**都得有 `2 × 1048576 B` ——
**`N` 不出现**。
★ 而它的反面（**分片之后**怎么变：`P_os` 在 `N = 512` 时每卡仍要 `4.0234Ψ`）**不在本文**
⇒ 回链 `100-parallelism/zero-fsdp/01-three-stages.md`。

### 1.3 ★★ 判据 ③：`N` 份副本的参数必须**逐位相同**

DP 的隐含假设是：**所有副本持有完全相同的参数**。
[B] PyTorch 2.14 在 `all_reduce` 的说明里把它写成了**逐位**：

> `bitwise identical in all processes`

**本机实测**（`A.1`，`N ∈ {1, 2, 4, 8, 16}`）：

| 量 | 实测 |
|---|---|
| 单份（参数，fp64，`Ψ = 65536`） | **`524288 B`**（`= Ψ × 8`，★ 与「不碰数组的算术参照」逐位一致） |
| 总计（`N = 8`） | **`4194304 B`** |
| 总计 / 单份 | **`1.000000 → 16.000000`**（逐个 `N` **恰好等于 `N`**） |
| 不同 `sha256` 摘要的个数 | **`1`**（全部副本**逐位相同**） |

★★★ **这个判据能失败 —— 这是它存在的全部意义**（本库 `P12` 的解药）：

| 坏法 | 后果 | 本机实测 |
|---|---|---|
| **一个 rank 的参数漂掉**（第 `3` 份换成另一组种子） | 与 `rank 0` 不同的 rank == **`[3]`** | ★★ **而两份的字节数完全相同** ⇒ 「量字节数」的检查**完全放不过**它 |
| **每一份都独立初始化**（忘掉广播） | **`16/16`** 个 rank 互不相同 | 每份都是**合法的**随机初始化 ⇒ **没有人会报错** |

⇒ ★★ **副本一致性不是自动成立的**：它是 DP 的一条**前置条件**
（初始化时必须**广播**，或从**同一个检查点**加载）。

### 1.4 ★★ 判据 ④：冗余度 `(N−1)/N`

**定义**（本主题自立，`E` 级）：`冗余度 = (总量 − 单份) / 总量`。

**本机实测**（`B.1`，把 `N` 份**真的建出来**再量）：

| `N` | 总计 | 单份 | **冗余度** |
|---|---|---|---|
| `1` | `524288 B` | `524288 B` | **`0.000000`** |
| `2` | `1048576 B` | `524288 B` | **`0.500000`** |
| `4` | `2097152 B` | `524288 B` | **`0.750000`** |
| `8` | `4194304 B` | `524288 B` | **`0.875000`** |
| `16` | `8388608 B` | `524288 B` | **`0.937500`** |

⇒ ★★ **`N → ∞` 时冗余度趋于 `1`**：**几乎全部显存都在存重复的东西**。
★ 且这条曲线是**单调增且上凸**的：`N` 从 `8` 到 `16`（**翻倍**），冗余度只从
`0.875000` 到 `0.937500`（**涨 `7.14%`**）—— 收益**递减**。

★ **这就是 `zero-fsdp` 存在的理由**：既然冗余度会饱和到 `1`，
那么「**把那份重复的东西切开**」就是唯一剩下的方向 ——
而它的**代价**（`P_os`/`P_os+g` 的通信量、`P_os+g+p` 的 `1.5x`）**不在本文**
⇒ 回链 `100-parallelism/zero-fsdp/02-communication.md`。

## 2. 执行映射

### 2.1 每卡的显存在 DP 下由什么决定

| 组成 | 它在哪一步产生 | 与 `N` 的关系 |
|---|---|---|
| 参数（fp16）、优化器状态（fp32 的三项） | 训练**前**就要全部就位 | **无关**（每卡各一份完整副本） |
| 梯度（fp16） | 反向产生 ⇒ 规约（`02`）后**每卡仍各一份** | **无关**（★ 见 `01` 的 `B.2`：`2Ψ` 与 `N` 无关） |
| **激活**（按 batch 分） | 前向产生 | ★ **与 `N` 有关**：每卡只放 `1/N` 的 batch ⇒ 这一项**确实被切了** |

★★ **注意最后一行**：DP **确实切掉了激活**（数据在卡之间分开了）。
⇒ 「加卡不能解决显存问题」这句话**必须指名作用域**：
它说的是**模型状态**（参数 / 梯度 / 优化器状态）那一块**没有**被切，
**不是**「加卡一点显存都不省」（激活是省的）。
★ 本文的判据（`A.2`/`B.2`/`C.3`）量的**全部是模型状态**这一块。

### 2.2 初始化：副本一致性是怎么来的

| 步骤 | 做什么 | 依据 / 后果 |
|---|---|---|
| 1 | `rank 0` 初始化参数（或从同一个检查点加载） | —— |
| 2 | **广播**给其余 rank | ★★ 少了这一步：`N` 份各自独立 ⇒ **`N/N` 个 rank 互不相同**（本机 `16/16`），而**没有任何一处会报错** |
| 3 | 训练开始 | ★ 此后每一步都靠**规约**保持一致性（正文在 `01`/`02`） |

★★ **术语**：这一步的「分片」在本文里**一律指显存分片**；
**落盘**的那个「分片」（`sharded checkpoint`）是**另一件事**
（正文在 `90-training/checkpointing/02-sharded-save-and-load.md`）——
两者**同名不同指**（域 README 的消歧表）。

### 2.3 规模上限由谁定

「**用 DP 装大模型**」这条路的上限是：**单卡要放得下全部模型状态**（`16Ψ`）。
⇒ 加卡**不改变**这个上限（每卡字节只由 `Ψ` 决定，§1.2），
它改变的是**吞吐**与**全局 batch**（`01` 的 `B.2`：全局 batch `N × B`）。

★★ 而「**怎么把上限降下来**」（分片 / 重算 / 混合精度）**不在本文**：
分片的正文在 `100-parallelism/zero-fsdp/01-three-stages.md`，
重算的正文在 `90-training/autograd-and-backward/02-gradient-checkpointing.md`，
精度的正文在 `90-training/mixed-precision/01-type-selection.md`。

## 3. 实现与演进

| 阶段 | 做法 | 它换来了什么、付了什么账 |
|---|---|---|
| **单卡** | 什么都不切 | 上限 = 单卡显存；★ 无法再大 |
| **DP** | 切数据（每卡一份完整模型状态 + `1/N` 的 batch） | ★ 换到**吞吐**与**更大的全局 batch**；★★ **没换到模型状态的显存**（冗余度 `(N−1)/N` 趋 `1`） |
| **梯度累积** | 在**一张卡**上把 `k` 个 micro-batch 攒起来 | ★ 换到更大的**有效 batch**（正文在 `90-training/autograd-and-backward/03-gradient-lifecycle.md`）；**也没换到模型状态的显存** |
| **ZeRO / FSDP** | 把模型状态**按 `N` 切开** | ★★ **这才换到显存**；★ 代价是**通信量**（`P_os+g+p` 是 `3Ψ` = `1.5x`）与**「什么时刻谁手里有哪一块」的复杂度** —— **正文全部在 `100-parallelism/zero-fsdp/`**，本文只回链 |

★ 这条演进线只有一句话：**「切数据」与「切状态」是两刀**。
DP 只做了前一刀 ⇒ 它的显存上限**卡在单卡**上；
`zero-fsdp` 做的正是**后一刀**。

## 4. 踩坑与失败模式

**① ★★★ 用「加卡」解决模型状态的 OOM。**
- **现象**：显存不够就加卡，加了还是 OOM（甚至更糟：全局 batch 变了，`lr` 也得跟着改）。
- **成因**：DP 只切**数据**（激活），**模型状态（`16Ψ`）每卡一份完整副本**
  ⇒ 每卡字节**只由 `Ψ` 决定**（本机 `Ψ` 翻倍 ⇒ 每卡 `1048576 → 2097152 B`，**与 `N` 无关**）。
- **规避**：把「显存不够」按**作用域**拆开问：**是激活**（加卡 / 累积 / 重算有用）
  还是**模型状态**（只有**分片**有用，正文在 `zero-fsdp/01`）。

**② ★★ 只比字节数就认为副本一致。**
- **现象**：检查里写 `state_bytes(a) == state_bytes(b)`，**永远通过**。
- **成因**：漂移的那一份**大小完全相同**（本机实测：`A.3`/`C.1` 里漂移份与基准份
  各 `524288 B`）⇒ 字节数**不含任何关于内容的信息**。
- **规避**：判据必须钉在**内容**上（本文用 `sha256` 摘要相等），
  ★★ 依据是 [B] PyTorch 2.14 用的词是 **`bitwise`（逐位）**，不是「近似相同」。

**③ ★★ 忘了广播（每份独立初始化）。**
- **现象**：训练能跑，但各副本从**第 0 步**就不一样；loss 曲线诡异。
- **成因**：DP 的隐含假设是「初始参数**相同**」，而它**不是自动成立**的
  （本机：`16/16` 个 rank 互不相同）。
- **规避**：把「广播（或从同一检查点加载）」写成初始化流程的**必需步骤**，
  并让「副本摘要全同」成为一条**在训练开始前就断言**的判据。

**④ ★ 把「冗余」当成可以忽略的常数。**
- **现象**：按「加卡就能装下 `N` 倍的模型」做容量规划。
- **成因**：冗余度是 `(N−1)/N`（**不是常数**）：`N=2` 时 `0.500000`、
  `N=16` 时 `0.937500` ⇒ 它**趋于 1**，而**每卡那一项始终不动**。
- **规避**：容量规划用**每卡**的量（`16Ψ`），不要用**总量 ÷ N** ——
  后者恰好把冗余当成了「被除掉了」（而它没有被除）。

**⑤ ★ 把「每卡显存不随 `N` 下降」当成一条算术断言。**
- **现象**：写 `assert per_card == 16 * Psi`，看起来很稳。
- **成因**：那是**程序自己写的那行乘法**（`P12`：模拟器同时是被测对象）。
- **规避**：判据钉在**真的建出来的数组的 `nbytes`** 与**副本一致性**上；
  ★★ 而「加卡不能解决显存问题」这一条本身，按计划 §1.3.3 的裁定，
  在本文**只作陈述 + 回链**，**不另给判据**（它的定量正文在 `zero-fsdp/01`）。

## 5. 判据表

> ★ 本表是**闭合的**：每一行都是「**可机械判定的条件 → 结论**」，读完能照着做判断。
> 全部数值为**本机实测值**（`code/03_redundancy.py` 的 `make run`，
> `python3 3.13.5` + `numpy 2.4.4`、macOS arm64、**无 GPU/无多卡/无 NCCL**）。
> ★★ **口径**：`Ψ = 65536`（`8` 层 × `(64, 128)`）；参数用 **fp64**（`Ψ × 8` 字节）；
> 「每卡完整状态」按 `16Ψ` 的四项 dtype **真的建出来**再量；
> 副本一致性用 **`sha256` 摘要相等**（不是容差比较）。

| 可机械判定的条件 | 结论 |
|---|---|
| `N` 份副本的**参数**是否逐位相同 | **是**：不同摘要数 == **`1`**（`N ∈ {1,2,4,8,16}` 全部）★ 依据是 [B] PyTorch 2.14 的逐字 `bitwise identical in all processes` |
| 单份（`Ψ = 65536`、fp64）有多少字节 | **`524288 B`**（`= Ψ × 8`，★ 与「不碰数组的算术参照」逐位一致） |
| 总量与单份的关系 | **恰好 `N` 倍**（本机 `1.000000 → 16.000000`，逐个 `N`） |
| 每卡**完整状态**有多少字节 | **`1048576 B` = `16.0000Ψ`**（`param` `2Ψ` + `grad` `2Ψ` + 优化器三项 `12Ψ`）★ 组成与分解的正文在 `90-training/checkpointing/01-state-and-bytes.md` |
| `K = 12` 的成立条件 | ★★ **`based on mixed-precision training with Adam optimizer.`** ⇒ 凡说 `16Ψ` / `12Ψ` 必须带「那是 **ZeRO 的举例口径**」这句 |
| **每卡**字节随 `N` 变吗 | **不变**（五种 `N` 下单份**逐位相同**）⇒ 加卡**不减少**每卡占用 |
| **每卡**字节随 `Ψ` 变吗 | **线性变**（`Ψ` 翻倍 ⇒ 每卡 `1048576 → 2097152 B`，**恰好 `2.0` 倍**） |
| **冗余度** `(N−1)/N` | `N = 1/2/4/8/16` ⇒ **`0.0 / 0.5 / 0.75 / 0.875 / 0.9375`**（逐个钉住）★ 定义是本主题自立的（`UNSOURCED`：`data_parallel_redundancy_ratio_definition`） |
| **一个 rank 漂掉**会怎样 | 与 `rank 0` 不同的 rank == **`[3]`**（本机：把第 `3` 份换成另一组种子）；★★ **而两份的字节数完全相同** |
| **全部独立初始化**会怎样 | **`16/16`** 个 rank 互不相同 ⇒ **副本一致性是 DP 的前置条件，不是自动成立的** |
| 「加卡能让单卡装下更大的模型」吗 | **不能**：每卡字节只由 `Ψ` 决定（`N` 不出现）→ ★ **分片后的账回链 `zero-fsdp/01`** |
| ★ 作用域：DP 切掉了什么 | **切掉了激活**（每卡 `1/N` 的 batch）；**没有切**模型状态（参数 / 梯度 / 优化器状态）⇒ 说「加卡不省显存」时必须指名这个作用域 |
| 冗余度随 `N` 的走向 | **单调增、上凸、趋于 `1`**（`N` 翻倍 `8→16` 时只涨 `7.14%`）⇒ 收益递减，**「切开它」是唯一剩下的方向**（→ `zero-fsdp`） |

> ★ 阈值与口径（`code/03_redundancy.py` 的 `preflight()` 逐位钉住）：
> `SEED = 20260943`、`SEED_DRIFT = 20260944`、`LAYERS = 8`、`LAYER_IN = 64`、
> `LAYER_OUT = 128`、`REPLICA_COUNTS = (1,2,4,8,16)`、`DRIFT_RANK = 3`、

> `REDUNDANCY_EXPECT = (0.0, 0.5, 0.75, 0.875, 0.9375)`、`TOL_SCALE_UP = 2.0`。

## 6. 小结与延伸

**一句话**：DP 的冗余是**可算的** —— 每卡 `16Ψ`（**与 `N` 无关**）、
总量 `N × 16Ψ`、冗余度 `(N−1)/N`（**趋于 `1`**）。
⇒ **加卡买到的是吞吐与更大的 batch，不是显存**；
★ 而它写进代码里的隐含假设是「**`N` 份副本逐位相同**」——
这条假设**能失败**（漂移 / 忘广播），且**字节数抓不到它**（必须比内容）。

- **平均的语义（除数在哪一边、`loss` 的口径）** ⇒ `100-parallelism/data-parallel/01-gradient-averaging.md`。
- **梯度分桶（桶的划分必须完备且不重叠）** ⇒ `100-parallelism/data-parallel/02-gradient-synchronization.md`。
- ★★ **`16Ψ` 的组成与字节分解** ⇒ `90-training/checkpointing/01-state-and-bytes.md`
  （**正文在彼**；本文只消费那个系数，并把它按四项 dtype **真的建出来量了一遍**）。
- ★★★ **按 `N` 分片之后怎么变**（`P_os`/`P_os+g`/`P_os+g+p` 的三阶段账、
