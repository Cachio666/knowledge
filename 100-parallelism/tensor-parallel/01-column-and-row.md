# 张量并行的列并行与行并行（以及它们的配对约束）

> **TP 的一刀切在**权重矩阵**上，切在哪一维决定了「谁要通信」：**
> **列并行**（切输出维）每卡算出一段**输出**、**免通信**；**行并行**（切输入维）每卡算出一份
> **局部部分和**、需要**一次 all-reduce**。
> ★★★ **而它们必须【配对】**：一个列并行后面跟一个行并行，中间的通信才是 `0` 次。
> **理由不是「正确性」，是【代价】** —— 四格（第一层切法 × 第二层切法）的**结果全对**，
> 差别只在块内通信次数（本机实测：配对 `1` 次、其余三种 `2` 次）。
> ★★ 而**列并行必须在前面**的根因，原文给的是一条**非线性**的理由：
> `since GeLU is a nonlinear function, GeLU(X₁A₁+X₂A₂) ≠ GeLU(X₁A₁)+GeLU(X₂A₂)`
> ⇒ 行并行先做会在**非线性之前**多一个同步点。

## 0. 背景与动机

### 一个具体的对照场景

一层 `Linear` 就是 `Y = XW`。单卡时，`X` 是 `(b, s, d_in)`、`W` 是 `(d_in, d_out)`。
显存或算力不够了，最自然的一刀是**把 `W` 切开**——但**切哪一维**？

```
切 W 的输出维（axis=1）：每卡拿 W 的一段列 ⇒ 各算出一段【输出】Y_i
                          X 被完整复制到每张卡      ⇒ Y = [Y_1, …, Y_t] 拼起来
切 W 的输入维（axis=0）：每卡拿 W 的一段行 ⇒ 各算出一份【部分和】P_i
                          同时 X 也要按输入维切   ⇒ Y = Σ_i P_i（要 all-reduce）
```

两种切法的**代数结果一样**，但**代价与误差档位完全不同**：前者是**纯搬运**（每个输出元素
仍由一次同样的点积算出），后者**改变了求和顺序**（`t` 次部分和再相加）。本机实测
（`code/01_column_row.py`，`x=(2,8,64)`、`W=(64,32)`、`TP=4`）：

| 切法 | `max|切分 − 单卡|` | 它改变了求值顺序吗 |
|---|---|---|
| **列并行**（切 `D_out`） | **`0.000e+00`** | **没有**（纯搬运） |
| **行并行**（切 `D_in`） | **`8.882e-16`** | **有**（求和顺序变了） |

★★ **同一份数据、同一个 TP 度，只换了一个轴，误差档位就从 `0` 变成了机器精度档** ——
「切在哪个轴」在本域是一条**比精度更基本**的选择。

## 1. 原理

### 1.1 ★ 两种切法的代数

设 `X ∈ ℝ^{b×s×d_in}`（沿最后一维切）、`W ∈ ℝ^{d_in×d_out}`，把 `t` 记为 TP 度。

**列并行**：`W = [W_1, …, W_t]`（沿 `axis=1` 分成 `t` 段，每段 `d_out/t` 列）。
每张卡 `i` 算 `Y_i = X W_i`，然后**拼**回来：

```
Y = [Y_1, …, Y_t] = X·[W_1, …, W_t] = XW          ← 恒等，不需要任何求和
```

★ 每张卡用的 `X` 是**完整**的 ⇒ **不需要通信就能开始算**；而 `Y_i` 是**输出的一段**，
**拼**（all-gather）之后就是完整输出。★★ 关键在于：**每个输出元素 `Y[.,.,j]` 仍由一次
同样的点积算出**（点积在 `d_in` 上，`d_in` 没被切）⇒ 这是**纯搬运**。

**行并行**：`W` 沿 `axis=0` 切成 `t` 段（每段 `d_in/t` 行），`X` **必须同步地**沿最后一维切成 `t` 段：

```
Y = Σ_{i=1}^{t} X_i W_i         X_i ∈ ℝ^{b×s×d_in/t}, W_i ∈ ℝ^{d_in/t×d_out}
```

★ 每张卡算出一份**局部部分和** `P_i = X_i W_i`（形状**就是**输出形状）⇒ 必须 **all-reduce**。
★★ 这里的点积被**拆成了 `t` 段** ⇒ **求和顺序变了** ⇒ 与单卡的差是机器精度档（不是 `0`）。

### 1.2 ★★ 判据 ①：MLP 的「列 + 行」== 单卡

一层 MLP 是两个 GEMM 夹一个非线性：`Y = φ(X W₁) W₂`（`W₁: d_in×d_ff`、`W₂: d_ff×d_out`）。
Megatron-LM 的标准切法是**第一层列并行、第二层行并行**：

```
第一层列并行： W₁ = [A_1, …, A_t]     每卡算 φ(X A_i)  —— 激活的一段，非线性【本地】做
第二层行并行： W₂ = [B_1; …; B_t]     每卡算 φ(XA_i)·B_i —— 部分和
出口：         Y = Σ_i φ(XA_i)·B_i    —— 一次 all-reduce
```

**本机实测**（`A.1`，`b=2`、`s=8`、`d_in=64`、`d_ff=128`、`d_out=32`、`t=4`）：
`max|列+行 − 单卡| = 8.882e-16`（`y` 的量级 `2.036`）—— 落在机器精度档。

★★ **这条差【不是 `0`】**：被测路径是 `t` 次矩阵乘 + `t−1` 次加法（第二层的部分和），
参照是**一次**矩阵乘 ⇒ 它是一条**有信息量**的判据（与列并行那条恒真的判据不同，见 §1.5）。

★★ **覆盖边界必须写明**：本条判据守的是「**这一刀切对了没有**」（切在输出维、
第二层与它配对切在输入维、索引有没有错位），**不守**「算子本身对不对」
（那由 `numpy` 保证）⇒ **不得声称它验证了更多东西**。

### 1.3 ★★★ 判据 ②：非线性的**不可交换性** —— 「列并行必须在前面」的算术证据

Megatron-LM（arXiv:1909.08053，**不确认同行评审**）§3 的 MLP 段给了**两条**理由句，逐字：

> `Since GeLU is a nonlinear function,` 〔公式：`GeLU(X₁A₁+X₂A₂) ≠ GeLU(X₁A₁)+GeLU(X₂A₂)`〕
> `and this approach will require a synchronization point before the GeLU function.`

> `Another option is to split` 〔公式：`A`〕 `along its columns …`
> `This is advantageous as it removes a synchronization point.`

★★★ **原文写的是 `removes a synchronization point` —— 这就是「列并行为什么非得在前面」的机制理由，
而且它是原文的，不是本库编的从句。** 把两句话读成一句：

```
非线性在【后面】（列并行先做）：每卡先做非线性、再规约 ⇒ 中间【不需要】同步点
非线性在【前面】（行并行先做）：部分和必须【先规约】才能上非线性
                                （因为 φ(Σ) ≠ Σφ）⇒ 非线性之前多一个同步点
```

★★ 本机把它变成一张**四格的表**（`A.2`，`t=4`）——**每一格都与独立参照 `φ(XW)` 比**
（`XW` 是单卡的**一次**点积）：

| 函数在规约的哪一侧 | `φ = 3u`（**线性**） | `φ = relu`（**非线性**） |
|---|---|---|
| **之后**（= **列并行先做**） | `2.665e-15` ✓ | `8.882e-16` ✓ |
| **之前**（= **行并行先做**） | `2.665e-15` ✓ | **`1.286880`** ✗ |

★ 表里的数是 `max|φ(这一格) − φ(单卡)|`；★★ 两格**互差**：线性 `8.882e-16`、非线性 `1.286880`。

⇒ ★★★ **四格把结论钉死了**：**线性时两种位置都对**（都在机器精度档内），
**非线性时只有「函数在规约之后」那一支对** ⇒
**不可交换性来自【非线性本身】，不是来自切分**。

★★ **一处口径声明（必须写出来）**：本程序用的非线性是**确定的 `relu(x) = max(x,0)`**，
**不是 GeLU** —— 机制只要求「非线性」，不要求具体形状。那是**本库的替身**，
**不是「GeLU 在本机上的实测」** ⇒ 不得据它声称任何关于 GeLU 的结论。

★★★ **一处必须记下来的现场（本库的纪律：把自己犯过的错留住）**：
`A.2` 的**第一版**写的是「`relu(Σ)` 与 `Σrelu` 互比」+「线性对照 = 两个**恒等**写法互比」——
★★ **那个线性对照是【自证的】**：`sum(partials_w)` 与 `sum([p for p in partials_w])`
是**同一个表达式**，差**恒为 `0.0`** ⇒ 它**只重述了恒等号**（`P12` 家族）。
⇒ 现行版本的两处修正：① **每一格都与独立参照比**，不互比；
② 线性对照换成 `φ = 3u`（**一个非平凡的线性映射**），此时两格互差 `8.882e-16`
（**不是 `0`**）⇒ 它**有内容**了。
★ 且 `A.2` 的**性质**必须写明：它是**机制的可执行说明**（被测的那段逻辑**就在它自己那几行里**），
**不是**对某个被测实现的判据 —— 按计划 §1.3.3 的自查问句，它在第二问上的答案是「**是**」。
★★ **两个变异都记下来**（都要实测过）：**能杀死它的**是把「行并行先做」那一格
**改成与参照同构**（把错法改对）✓；**杀不死它的**是把那一格里的 `relu` 换成 `3u`
（只换一边）—— 因为两边**仍然不等**。⇒ ★ 这条判据测的是「**两边是否同构**」，
不是「哪一边用了哪个函数」。

### 1.4 ★★ 判据 ③：配对约束 —— 它是【代价】约束，不是正确性约束

把「第一层怎么切」×「第二层怎么切」四格全跑一遍（`A.3`，本机实测）：

| 第一层 | 第二层 | 块内通信**总**次数 | 非线性**之前**的通信 | `max|结果 − 单卡|` |
|---|---|---|---|---|
| **列** | **行** | **`1`** | **`0`** | `8.882e-16` |
| 行 | 行 | `2` | `1` | `1.332e-15` |
| 列 | 列 | `2` | `0` | `0.000e+00` |
| 行 | 列 | `2` | `1` | `8.882e-16` |

★★★ **四格的【结果全对】**（都在机器精度档）⇒
**「列并行后面必须跟一个行并行」是一条【代价】约束，不是正确性约束** ——
配错不会算错，只是**多一次通信**（而且「行并行先做」的那两格还要在**非线性之前**多一个同步点）。

★★ **两件事要分开**（上表把它们分开了）：
「块内一共几次通信」与「有没有同步点在非线性**之前**」是**两个不同的量**：
`列 + 列` 的总次数也是 `2`，但它那次通信在**非线性之后**（一次 all-gather 把各段激活拼回全量）。

★ **两个计数都是【代码结构】的计数，不是实测的通信次数** ——
「通信发生了几次」在单进程模拟里**测不出来**（那是**写进代码的假设**）；
它的**次数依据**是 [C] 的外部事实（下节）与 [C] 的 `removes a synchronization point`。

### 1.5 ★★★ 一条**【形状依赖】**的判据：「列并行 == 单卡」（**在某些形状下恒真**）

「切分后的结果 == 单卡的结果」是本域最自然的一条 A 类判据。★ 它在**列并行**处、**在下面这组形状下**为 `0.0`：

**本机实测**（`D.10`，`x=(2,8,64)`、`W=(64,32)`、`t=4`）：

```
列并行 max|diff| = 0.000e+00      ← **本组形状下**为 0（★ 但这是**形状依赖**的，见下）
行并行 max|diff| = 8.882e-16      ← 有信息量：求和顺序真的变了
```

★★★ **为什么「恒真」是个问题**：那条判据**只重述了切分的定义** ——
「把输出列分开算」这句话本身**就等于**「结果不变」。把它当 A 类，等于**什么也没检查**。

★★ **另一个必须说清的细节**：`0.0` 是**形状依赖**的。同一份权重、同一个 `t`，
把 `(b, s)` 从 `(2, 8)` 换成 `(3, 4)`，`GEMM` 的 `M` 维变了 ⇒ BLAS 可能换分块/向量化路径
⇒ 差变成 `1.4e-14`（`02_heads_vocab.py` 的 `D.10` 在 vocab 维的列切上量到了这一档，
五种形状里**两种非零、三种恰好为 `0`**）。
⇒ ★★★ **纪律**：「列切 == 单卡」**不是一条恒真的判据，而是一条【形状依赖】的判据** ——
它在某些形状下恒真（无信息量），在另一些形状下给出与「切分对不对」**无关**的
BLAS 路径噪声（差**不保证非零**）⇒ **两种情形都不能当 A 类**。
（本库的 `probes/probe_100a.py` 与 `probe_100h.py` 在**它们自己那组形状**上量到的是
`0.000e+00` —— 两者都对，它们共同支持的是「**在该组形状下**的观测」。）

⇒ ★ 本文的 A 类因此落在**改变了求值顺序**的地方：`A.1`（列 + 行的组合）、`A.4`（行并行）、
`A.2`（非线性不可交换）、`A.3`（四格的通信次数表）。

### 1.6 ★ 每层几次 all-reduce —— 与 [C] 的逐字对拍

[C] `1909.08053` §3 末段逐字（`B.2` 引的就是它）：

> `two all-reduces in the forward path and two in the backward path`

[C] 的 Figure 4 caption 把同一件事写成：

> `There are 4 total communication operations in the forward and backward pass of a single model parallel transformer layer.`

★★★ **两条独立路径给出同一个数**：左边是**代码结构**（一个 transformer 层 = `2` 个块
〔attention + MLP〕× 每块 `1` 次），右边是 **[C] 的逐字**。
⇒ **前向 `2` 次** ✓。★ 若配对改成另外三种 ⇒ 每块 `2` 次 ⇒ 前向 `4` 次（**两倍**）。

★★★ **一条必须接住的缺口**：`performance-models/02:223` 写的是
「attention 后、FFN 后**各一次** all-reduce」—— 那是**前向的 2 次**，
**漏了 backward 那 2 次**。**后向 2 次的逐字出处就是上面那句**（`and two in the backward path`）
⇒ 全模型的通信量账（`8bsh((t−1)/t)` 里的那个 `8` 怎么来）在
[`03-saturation-and-limits.md`](03-saturation-and-limits.md)（**回链**）。
★ **本文对 `:223` 的处置正是「复述它哪一句、补它哪一句」**：**复述**的是「每层 `2` 次」
这个**结论**、**补**的是它没给的**后向出处** —— ★ 两者都**不是**另起一处正文
（边界声明见 §5 与本文末尾）。

### 1.7 ★ B 类：局部部分和的**量级** —— 证伪「一片是零、一片是全」

一个很自然的直觉是：「既然每张卡只算一部分，那大概是**有的卡算得多、有的卡算得少**」。
**它不成立**。本机实测（`B.1`，`t=4`，行并行的局部部分和 vs 合并后的结果，Frobenius 范数）：

```
各卡局部部分和的范数：8.345833  9.131478  8.908721  9.092361
合并后（单卡）的范数：17.505843
占比：              0.476746  0.521625  0.508900  0.519390   （均值 0.506665）
```

⇒ ★★ **每一片都贡献了【同阶】的一份**（占比全在 `[0.35, 0.75]`，实测均值 `0.507`）：
**既不是「某一片没有贡献」，也不是「某一片代表全部」**。
★★ **这条判据是【两侧】的**：把一片置零 ⇒ 占比 `0.0` **落在区间外** ⇒ 判据能失败
（这就是它的守卫）。

## 2. 执行映射

按框架层切入：**同一个 `Linear`，两种切法在「谁手里有哪一块、什么时候通信」上的差别**。

| 阶段 | 列并行（切输出维） | 行并行（切输入维） |
|---|---|---|
| **进去之前** | `X` 在每个设备上**完整复制**；`W` 的一段 | `X` 与 `W` **都要**按同一维切开 |
| **本地算** | 每个设备算出一段**输出** `Y_i = X W_i` | 每个设备算出一份**部分和** `P_i = X_i W_i` |
| **通信** | **`0`**（本地算完就完） | **一次 all-reduce**（Σ 各卡的部分和） |
| **出来的东西** | 输出**被切**在各设备上 | 输出在每个设备上**完整**（all-reduce 的结果） |
| **为什么它在那个位置** | 点积维（`d_in`）**没被切** ⇒ 每个输出元素仍是同一次点积 | 点积维被切成 `t` 段 ⇒ 必须把各部分**加起来** |

★★★ **这就是「配对」的机械含义**：列并行**留在设备上**的是**被切的输出**，
而**行并行正需要「被切的输入」** —— 于是中间那一步**不需要任何搬运**：

```
每卡本地：  φ(X A_i)          ← 列并行的输出，被切在 d_ff 上
每卡本地：  φ(X A_i) · B_i    ← 行并行要的正是「被 d_ff 切的输入」 ⇒ 直接接上
出口：      Σ_i (…)           ← 全程只有这【一次】通信
```

★ **具体组件名（`CONTRIBUTING` §5 的「系统细节」要求）**：
**`W₁` 的列切轴（`axis=1`）**、**`W₂` 的行切轴（`axis=0`）**、
**块出口的那一次 `all-reduce`**、以及**非线性放在两个 GEMM 之间的哪个位置** ——
这四者是本文里真正被改动的对象（框架层）。
★ 注意**没有**「输入侧的 all-gather」：本方案要求 `X` 在 TP 组内是**复制的**（残差流是复制的），
所以**进这一层之前不需要任何集合通信** —— ★★ 这也正是「列并行免通信」这句的**前提**。
★ 而那个 all-reduce **在每一层里都发生一次**，这就是 `:223` 说的
「通信发生在**每一层内部**」（**正文在彼，本文回链**）。

★ **一个数量级**（本文尺度）：`b=2`、`s=8`、`d_in=64`、`d_ff=128`、`d_out=32` 时，
一次 all-reduce 搬的是 `b×s×d_out` 级的量；★ 换成真实尺度（`s=2048`、`h=1024`、bf16）
每次搬 `b·s·h` 元素 = **每元素 `2` 字节** ⇒ 单次 all-reduce 的量级是 **`MB` 级**
（完整账在 [`03-saturation-and-limits.md`](03-saturation-and-limits.md)，
那里有 `8bsh((t−1)/t)` 的公式与饱和表）。

## 3. 实现与演进

| 阶段 | 做法 | 它换来了什么、付了什么账 |
|---|---|---|
| **单卡** | 一个 `Linear` 一次算完 | 简单；★ 模型放不下就没有下一步 |
| **只切输出维** | 列并行 | ★ **免通信**，但输出被切在各卡上 ⇒ **下游必须知道这一点** |
| **只切输入维** | 行并行 | ★ 输出完整（对下游友好），但**每次都要一次 all-reduce** |
| **两层配对** | `Linear₁` 列并行 + `Linear₂` 行并行（Megatron 的做法） | ★★ **把中间那一次通信去掉**（[C] 逐字：`removes a synchronization point`）⇒ 一个 transformer 层只剩 `2` 个块各 `1` 次 |
| **配上非线性** | 把非线性**放在**列并行之后（本地做） | ★★★ **它决定了「列并行必须在前面」**：非线性在中间 ⇒ 行并行先做会多一个同步点（§1.3） |
| **头切分** | QKV 按列切，每个 head **本地算** | ★ 注意原文的词是 `doesn’t require any immediate communication` —— **「立即」**：紧接着的 output `Linear` 仍按行并行，那次 all-reduce 照旧 ⇒ 见 [`02-heads-and-vocab.md`](02-heads-and-vocab.md) |
| **vocab 并行** | 输出 embedding 列切 | ★★ 这一支的代价在**输出侧**（`b×s×v` 的 all-gather）⇒ 同上那篇 |

★ 这一步的演进方向不是「切得更细」，而是**让相邻的两刀互相接住** ——
本域主线落点 ①（「切在哪个轴」）在这里的形态是：**轴选对了，通信就没了**。

## 4. 踩坑与失败模式

**① ★★★ 把「列并行 == 单卡」当 A 类判据。**
- **现象**：测试跑过、数字漂亮（`0.000e+00`），但**什么也没检查**。
- **成因**：列并行是**纯搬运**，那条判据**只重述了定义**（§1.5）；
  而且这个 `0.0` **还是形状依赖的**（换 `(b,s)` 就可能变成 `1.4e-14` 的 BLAS 噪声）。
- **规避**：A 类只钉在**改变了求值顺序**的地方（行并行、MLP 组合、四格的次数表）；
  纯搬运处改用 C 类（证明「搬运做错会失败」）；且**把「它恒真」这件事本身写成一条机械检查**
  （`01`/`02` 的 `D.10`）。

**② ★★ 忘记 all-reduce（把一片的部分和当成结果）。**
- **现象**：形状完全对，训练照跑，但结果**完全错**。本机实测：差 **`2.462544`**
  （对比：机器精度档是 `8.882e-16`）⇒ 大了 **15 个数量级**。
- **成因**：行并行的每张卡手里只有**一份部分和**，它有**正确的形状**、
  也在**正确的量级**（§1.7：约 `0.5×`）⇒ 它看起来「像那么回事」。
- **规避**：把「通信」写成一个**显式的搬运**（本库的做法：`all_reduce = Σ局部`），
  让「少写一行」变成「少调用一个函数」，然后**用一条断言钉住那个函数被调用过**
  （`D.7c` 的调用计数器：被测路径跑一次必须 > 0）。

**③ ★★ 切错轴 —— 形状不匹配（会抛错，但只挡住一半）。**
- **现象**：把 `X` 按输入维切开、却仍与**整个** `W` 相乘 ⇒
  `ValueError: matmul: Input operand 1 has a mismatch in its core dimension 0, …`。
- **规避**：★ **这一条【不需要】额外判据**（类型层已经挡住）；
  ★★ **真正需要判据的是它的兄弟** —— 见 ④。

**④ ★★★ 交错切（形状**完全**相同、索引错位）—— 形状检查挡不住。**
- **现象**：按 `x[..., i::t]` 交错切输入维再拼回来，形状与**分块切完全相同**
  （本机实测：都是 `(2, 8, 64)`），而数值差 **`3.372601`**。
- **成因**：`W` 的行是**分块**切的，而 `X` 的列是**交错**切的 ⇒ 索引**整体错位**。
  ★ 这类错误在**任何形状检查**下都是「合法」的。
- **规避**：只有**数值判据**能抓住它（`A.1`/`A.4`）；★ 这也是本文把
  「形状对」与「切对了」分开说的原因 —— **形状对不等于切对了**。

**⑤ ★ 以为「配对」是正确性要求。**
- **现象**：花了力气论证「配错会算错」，结果论证站不住（四格结果其实**全对**，§1.4）。
- **成因**：把**代价**约束记成了**正确性**约束。★ 代价不高、但会误导维护者：
  以为只要配错就会报错，于是**不做**代价侧的检查。
- **规避**：把两个量分开记（块内总次数 / 非线性之前的次数），并把四格的表**跑出来** ——
  它是「代价约束」这个判断的**唯一证据**。

## 5. 判据表

> ★ 本表是**闭合的**：每一行都是「**可机械判定的条件 → 结论**」，读完能照着做判断。
> 全部数值为**本机实测值**（`code/01_column_row.py` 的 `make run`，
> `python3 3.13.5` + `numpy 2.4.4`、macOS arm64、**无 GPU/无多卡/无 NCCL**）。
> ★★ **口径**：`b=2`、`s=8`、`d_in=64`、`d_ff=128`、`d_out=32`、`t=4`；差用 `max|·|`；
> **非线性是 `relu`（论文里是 GeLU，机制只要求「非线性」）**；通信是**显式张量搬运**
> （`all_reduce = Σ局部`、`all_gather = concat`）。

| 可机械判定的条件 | 结论 |
|---|---|
| MLP 用「第一层列并行 + 第二层行并行」与单卡一次算完比 | **相同**（本机 `max|diff| = 8.882e-16`，量级 `2.036`）⇒ 这一刀切对了 |
| 把参照的第二层权重行序**故意改错** | 差 `2.416e+00` ⇒ ★★ **上面的等价性判据【能失败】**（`CONTRIBUTING:235` 的守卫） |
| 函数在规约**之后**（列并行先做）、`φ = relu`，与 `relu(XW)` 比 | 差 **`8.882e-16`**（机器精度档）⇒ **对** |
| 函数在规约**之前**（行并行先做）、`φ = relu`，与 `relu(XW)` 比 | 差 **`1.286880`** ⇒ **错**（不可交换） |
| **线性对照** `φ = 3u`：两种位置都与 `3(XW)` 比 | 差都是 **`2.665e-15`**（机器精度档）⇒ ★★★ **两种位置【都对】** |
| 两格**互差**（线性 / 非线性） | **`8.882e-16`** / **`1.286880`** ⇒ ★★★ **不可交换性来自非线性本身**（这就是「列并行必须在前面」的理由） |
| 四格（第一层切法 × 第二层切法）的**结果** | **全对**（都在机器精度档）⇒ ★★ **配对是【代价】约束，不是正确性约束** |
| 四格的**块内通信次数** | `列+行 = 1`、其余三种 `= 2` ⇒ ★★ **只有「列 + 行」把块内通信压到 `1` 次** |
| 四格的**非线性之前**的通信 | `列+行 = 0`、`列+列 = 0`、两个「行先」的格 `= 1` ⇒ 「有没有同步点在非线性之前」与「一共几次」是**两个量** |
| 行并行单独一层与单卡比 | **相同**（`8.882e-16`），★ 且这个差**不是 `0`**（它改变了求和顺序） |
| 列并行单独一层与单卡比 | **`0.000e+00`** ⟹ ★★★ **这条判据恒真，不能当 A 类**；★ 且 `0.0` 是**形状依赖**的（换形状可得 `1.4e-14`） |
| 行并行的局部部分和的量级 | 每片占总量的 **`0.4767 ~ 0.5216`**（均值 `0.506665`）⇒ ★★ **证伪「一片是零、一片是全」**（把一片置零 ⇒ 占比 `0.0` **落在 `[0.35, 0.75]` 之外**） |
| 每层前向的 all-reduce 次数 | `2`（`2` 个块 × 每块 `1` 次）⇒ 与 [C] `1909.08053` 的逐字 `two all-reduces in the forward path and two in the backward path` 对拍 ✓ |
| 配对改成另外三种 | 每块 `2` 次 ⇒ 前向 **`4`** 次（**两倍**） |
| 忘记 all-reduce（拿一片的部分和当结果） | 差 **`2.462544`** ⇒ **真的会错**（比机器精度档大 15 个数量级） |

## 6. 小结与延伸

**一句话**：TP 的一刀切在**权重矩阵的哪一维**上 —— 列并行（切输出维）拿到的是一段**输出**、
**免通信**；行并行（切输入维）拿到的是一份**部分和**、要**一次 all-reduce**；
★★★ **两者必须配对**，而配对的理由是**代价**（块内通信 `1` vs `2` 次）、**不是正确性**
（四格结果全对）；★ 而**列并行必须在前面**的根因是**非线性不可交换**（原文逐字）。
