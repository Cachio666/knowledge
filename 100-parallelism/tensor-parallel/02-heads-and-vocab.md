# 头切分、vocab 并行与「不整除」的三种处置

> **TP 的两处「不整」要用两种完全不同的办法处理。**
> **头**能整除（`8` 个头分给 `4` 张卡）：QKV 按列并行，**每个 head 的矩阵乘在本卡本地算**
> —— 原文用的词是 `doesn’t require any **immediate** communication`，★ **「立即」是关键**。
> **词表**经常不能整除（`50257` 不是 `1024` 的倍数）：只有三种处置 ——
> **`np.split` 直接抛错**（★ **这是一道防线**）· **静默截断**（★ 部分 token **恒不可预测**）·
> **补齐**（★ **必须配一个「屏蔽」**，否则概率算错）。
> ★★★ **而「补齐后与单卡逐位相同」【不成立】**（本机实测差 `2.132e-14`）——
> **判据只能写「机器精度档」**。

## 0. 背景与动机

### 一个具体的对照场景

一个 transformer 层的两头各有一个「大矩阵」：**attention 的 QKV 投影**（`h × 3h`）
与**输出 embedding / logits**（`h × v`，`v` 是词表大小，几万到几十万）。
把它们切到多卡上时，**「能不能整除」这件事的答案不一样**：

```
头：      8 个 head 分给 4 张卡      ⇒ 每卡 2 个（整除）—— 天然可切
词表：    v = 50257 分给 8 张卡      ⇒ 每卡 6282.125 个（不整除！）
          ★ 而这【不是】一个可以四舍五入的小数 —— 它意味着「有些 token 没有主人」
```

本机在玩具尺度上复现同一个处境（`code/02_heads_vocab.py`，`TP = 4`）：
**`N_HEADS = 8` 能整除、`VOCAB = 30` 不能**（`30 % 4 = 2`）。
★★ **同一篇里这两种处境要分开处理** —— 这正是本文的正题。

## 1. 原理

### 1.1 ★★ 头切分：每张卡算「自己的那几个 head」

[C] `1909.08053`（**不确认同行评审**）§3 的 self-attention 段逐字：

> `in a column parallel fashion such that the matrix multiply corresponding to each attention head is done locally on one GPU`

⇒ **QKV 的投影按列并行**，于是**每个 head 的 Q/K/V 整块落在同一张卡上**，
那个 head 的 `softmax(QKᵀ)V` 就**本地算完**，不需要别的卡参与。

★★★ **一处极易被外推错的措辞 —— 作用域必须写清**：原文的完整说法是
`doesn’t require any **immediate** communication to complete the self-attention`。
**「立即」这个词是关键**：紧接着的 output `Linear` **仍然按行并行**
⇒ 那次 all-reduce **照旧发生**（只是可以**晚一点**发）。
⇒ ★★ **不得写成「头切分不需要通信」** —— 那是一句**错的**话。

★ **本机实测**（`D.10`）：头切分的差 **`0.000e+00`**（逐位相同）。
★★ **这是一条恒真的判据**：每张卡做的**就是**单卡时那几个 head 的**同一批运算**、
**形状也没变** ⇒ 「切分 == 单卡」在这里只重述了定义，**不能当 A 类**。

### 1.2 ★★ vocab 并行：两侧的代价完全不同

[C] `1909.08053` §3 的 vocab 并行段给了**三段**逐字（本文按它们出现的顺序引用）：

**(a) 输入 embedding 列切 ⇒ 需要一次 all-reduce**：

> `Since each partition now only contains a portion of the embedding table, an all-reduce (`

★ 每张卡只持有词表的一段 ⇒ 一个 token 的嵌入向量只在**持有它的那张卡**上是非零的。
★★★ **本机实测（`A.3`）：这次 all-reduce 是【逐位】精确的** ——
在 `16` 个随机 token 上，每张卡的贡献里**非零的段数恰好是 `1`**
（其余是**结构性的零**：不是「算出来是 0」，而是「这张卡根本没有这一列」）⇒
「把 `t` 个分片加起来」与「直接查表」**逐位相同**（实测差 `0.000e+00`）。
⇒ ★★ **所以「输入 embedding 列切 == 单卡」这条判据也恒真**（它的**成因**已被本条钉住）。

**(b) 输出侧若直接 all-gather ⇒ 通信量 `b×s×v`，而且「巨大」**：

> `which is huge due to vocabulary size being large.`

**(c) 把并行 GEMM 与交叉熵融合 ⇒ 降到 `b×s`**：

> `with the cross entropy loss which reduces the dimension to`

**本机实测**（`B.1`，`b=3`、`s=4`、`v=30`；补齐那一支的 all-gather 实际搬 `b×s×32`）：

| 口径 | 搬多少个元素 | 实测张量 `size` |
|---|---|---|
| **未融合**（all-gather 全部 logits） | `b×s×v` | **`360`**（`3×4×30`）★ 补齐支实际 `384` |
| **与交叉熵融合** | `b×s` | **`12`**（`3×4`） |
| **比值** | `v` | **`30`** |

⇒ ★★★ **vocab 并行的代价在【输出侧】，且它随 `v` 线性放大** ——
这就是那句 `huge` 的定量含义。★ **口径**：这里量的是**元素个数**（`size`），不是字节数 ——
换精度要乘 `itemsize`，但**比值与精度无关**（同一种 dtype 下）。

### 1.3 ★★★ 「不整除」的三种处置（本文的核心）

`VOCAB = 30`、`TP = 4`：`30 // 4 = 7`，**余 `2`**。这三个数字决定了后面的一切。

#### (a) `np.split` —— **它直接抛错**（★ 这是一道**防线**）

```python
np.split(emb, 4, axis=1)
# ValueError: array split does not result in an equal division
```

★★★ **为什么「抛错」值得单独列一条**：它把「不整除」变成**立刻可见的失败**。
⇒ 凡是**用了它**的地方，不整除**不可能静默通过** ——
另外两种处置（截断 / 补齐）**都是【主动】写出来的代码**。
★★ **一句话**：**「不整除」在这条路径上不是风险，是异常。**
★ 而这也解释了后两种处置的危险：**它们把「异常」改写成了「正常返回」**。

#### (b) 静默截断 —— **部分 token 恒不可预测**

```python
per = emb.shape[1] // tp          # 7
emb_trunc = emb[:, :per * tp]     # 只留 28 列 ⇒ 第 28、29 个 token 被【删掉】
```

**本机实测**（`C.2`）：截断后词表 `(64, 28)`、logits `(3, 4, 28)`（原 `(3, 4, 30)`）。
★★★ **后果的直接演示**：造一个「第 `29` 个 token 的 logit 是 `999`」的输入 ——
单卡下 `argmax = 29`（正确），截断后 `argmax = 0` ——
**`29` 永远不可能是答案**（它的 logits **根本不存在**）。

⇒ ★★ 本机 `VOCAB=30` 时是 **`2/30`** 个 token 恒不可预测；
★ 真实规模（`50257` 与 `1024`）下是 `81` 个（见 §1.4）。
★★ **这条路径不报错、也不崩** —— 它只在训练后表现为「有些 token 从来预测不出来」，
**这才是它比 (a) 危险的地方**。

#### (c) 补齐 —— **必须配一个「屏蔽」**（否则概率算错）

[C] `1909.08053` §5.1 逐字给了 Megatron 的处置（**真实规模**）：

> `pad the vocabulary such that it is divisible by` 〔公式 `128×8=1024`〕
> `, resulting in a padded vocabulary size of 51,200.`

同段还有把那组配置交代清楚的一句：

> `The configuration with 1.2 billion parameters fits on a single GPU whereas the 8 billion parameter model requires 8-way model parallelism (8 GPUs).`

★ **本机实测**（`B.2`）：每卡词表大小的倍数 `128` × TP 度 `8` = **`1024`**；
原词表 `50257 % 1024` = **`81`**（不整除）；补齐后 `51200 % 1024` = **`0`**（整除）；
多算 **`943`** 个 token 的 logits（`81 + 943 = 1024`）。
★ 玩具尺度上同一件事：`30` 补到 `32`（`16` 的倍数）⇒ 多 **`2`** 个。

★★★ **但「补齐」不是免费的，它有【两个】代价**：

**代价 ①：「补齐后与单卡逐位相同」【不成立】。**
本机实测（`A.1`/`A.2`，`b=3`、`s=4`、`v=30` 补到 `32`）：
差 **`2.132e-14`**（`y` 的量级 `30.630`），`np.array_equal` = **`False`**。
**成因**：补齐改变了**张量的形状与内存布局**（`(3,4,30) → (3,4,32)`）
⇒ BLAS 可能走**不同的路径**（分块/向量化不同）。
⇒ ★★ **纪律**：这条等价性的判据**只能写「机器精度档」** ——
写「逐位相等」会在**本机**上直接失败，**而实现是正确的**。

**代价 ②：pad 那些位置**会分走概率**（除非你明确屏蔽它们）。**
**本机实测**（`C.3`）：补齐到 `32` 列后，**不屏蔽**地做 softmax ⇒
前 `30` 列的概率和平均降到 **`0.712621`**（最大漏失 **`0.972872`**）、
与「屏蔽版」的概率差 `max|·| = 0.895289`。
★★ **一个必须写出来的量法口径**：若 pad 位置的 logits **恰好是 `0`**，
漏失只有 **`1.982e-05`** 量级 ⇒ **这个失败会被「太小」掩盖**。
⇒ ★★★ **因此判据必须把「pad 位置取什么值」写清楚** ——
本程序**显式地**把 pad 位置取成与真 logits **同量级**的值（真实系统里那些词表行
会带着任意的权重继续参与训练），否则 `C.3` 会变成一条**看起来成立、实际什么也没检查**的判据。

★★ **一处出处纪律（必须写明）**：Megatron **具体怎么**屏蔽 pad 位置
（置 `−inf`？换 loss 的 index？只取前 `v` 列？）在 `1909.08053` 里**没有取到**
⇒ 已登记 `specs.UNSOURCED`：`tensor_parallel_pad_logits_masking_mechanism`。
**本程序里的屏蔽那一支是【本库的构造】**，**不是「Megatron 的做法」**。
★ 同理，**`128` 这个倍数为什么是 `128`**（tile 宽度？对齐？那组实验调出来的？）
原文只写了「对 GEMM 有利」⇒ 已登记 `tensor_parallel_vocab_pad_multiple_128_rationale`。

### 1.4 ★★★ 三种处置的对照表（本文的结论）

| 处置 | 它报错吗 | 输出形状 | 后果 | 本机实测 |
|---|---|---|---|---|
| **(a) `np.split`** | **抛 `ValueError`** | —— | ★★★ **这是一道防线**：不整除不可能静默通过 | `array split does not result in an equal division` |
| **(b) 静默截断** | **不报错** | `(3, 4, 28)`（原 `30`） | ★★ **`2/30` 个 token 恒不可预测**（真实规模：`81` 个） | `argmax` 从 `29` 变成 `0` |
| **(c) 补齐** | 不报错 | `(3, 4, 32)` → 取前 `30` | ★★ **必须配屏蔽**；且**逐位相等不成立** | 差 `2.132e-14`；不屏蔽漏 `0.712621` |

★★ **一句话记住三者**：**(a) 让错误变成异常；(b) 让错误变成沉默；(c) 让错误变成另一个错误**。

★ **本机实测：vocab 列切的等价性判据本身是【形状依赖】的**（`D.10`，五种形状）：

```
(b=3, s=4)  ⇒ 1.421e-14      (b=2, s=8)  ⇒ 0.000e+00
(b=4, s=8)  ⇒ 0.000e+00      (b=1, s=16) ⇒ 0.000e+00
(b=8, s=4)  ⇒ 1.421e-14
```

⇒ ★★★ **两处「纯搬运」的性质其实不同**：
**头切分**的 `0.0` 是**结构性的**（同一批运算被重新分配、形状没变）⇒ **真恒真**；
**vocab 维列切**的差**随形状变** ⇒ 它**不是恒真，而是「BLAS 路径依赖」**
（`GEMM` 的 `N` 与 `M` 变了，BLAS 可能换分块/向量化路径）。
⇒ ★★ **两条都不能当 A 类，但理由不同** —— 这一点必须分开记。

## 2. 执行映射

按框架层切入：**这三处「大矩阵」在前向/反向里分别被谁碰、什么时候通信**。

| 阶段 | 谁手里有哪一块 | 通信 |
|---|---|---|
| **QKV 投影（列并行）** | 每张卡拿到**若干整 head** 的 Q/K/V | **无立即通信**（★ 但 output `Linear` 的 all-reduce 仍会发生） |
| **attention 本地算** | 每张卡算自己那几个 head 的 `softmax(QKᵀ)V` | **无** |
| **output `Linear`（行并行）** | 每张卡算出**部分和** | **一次 all-reduce**（把它与前一个 MLP 块的合计起来，一层的**前向**共 `2` 次） |
| **输入 embedding（列切）** | 每张卡只持有词表的一段 | **一次 all-reduce** —— ★★ 而且是**逐位精确**的（只有一个分片非零） |
| **输出 logits（列切）** | 每张卡算出一段 logits | ★★★ **这里就是那个 `huge`**：未融合要 all-gather `b×s×v` 个元素 |
| **与交叉熵融合** | 每张卡只把 `b×s` 个标量交给 loss | ★★ **量级差 `v` 倍**（本机 `360 → 12`，比值 `30`） |
| **不整除时** | 取决于**你选哪种处置** | ★★★ 三种处置的后果见 §1.4 |

★ **具体组件名（`CONTRIBUTING` §5 的「系统细节」要求）**：
**输入侧的 `all-reduce`**（embedding 列切）、**输出侧的 `all-gather`**（logits）、
**`np.split` 这道防线**、以及 **softmax 前的 pad 屏蔽** —— 这四者是本文里真正被改动的对象。
★ **一个数量级**：真实尺度下，未融合的 all-gather 搬的是 `b·s·v` 个元素 ——
[C] 给的量级依据是逐字 `Since the vocabulary size is on the order of tens of thousands of
tokens for modern language models`（同段还给了一个具体值：`GPT-2 used a vocabulary size
of 50,257`）⇒ 它是本层里**最大**的一次通信；融合之后它降到 `b·s`
⇒ ★ **量级差就是 `v` 本身**（本机玩具 `30` 倍；真实规模是 **`10⁴`** 量级）。
★★ **不得把这个倍数写成 `10⁵` 或更大** —— 原文给的是「**tens of thousands**」与 `50,257`。

★★ **注意这是「切分的账」而不是「通信的账」** —— 带宽/延迟/链路规格的正文在
`20-gpu-architecture/interconnect/`（**本文一行都不写**）。

## 3. 实现与演进

| 阶段 | 做法 | 它换来了什么、付了什么账 |
|---|---|---|
| **单卡** | 一个 `QKV`、一个 `h×v` 的输出矩阵 | 简单；★ `v` 大时这一步本身就很贵 |
| **头切分** | QKV 按列切 ⇒ 每卡算自己的 head | ★ **免立即通信**（★ 但 output `Linear` 要 all-reduce）；★★ **前提是 head 数能被 TP 度整除** |
| **vocab 列切 + all-gather** | 输出 logits 按词表维切 | ★ 算得动了；★★ **代价是 `b×s×v` 的 all-gather** |
| **与交叉熵融合** | 并行 GEMM 后直接算 loss，只把 `b×s` 交出去 | ★★★ **通信量差 `v` 倍**（[C] 逐字：`reduces the dimension to`） |
| **不整除 → 截断** | `emb[:, :per*tp]` | ★ **不报错**，但**部分 token 消失** ⇒ §4 的 ③ |
| **不整除 → 补齐** | 补到 `128 × t` 的倍数（Megatron） | ★ **能整除**了；★★ **代价**：多算一点 + **必须屏蔽** + **逐位相等不成立** |
| **掩码 / fuse** | pad 位置在 softmax 前置 `−inf`（或换 loss 的 index） | ★★ **这一支的具体做法原文没给**（`specs.UNSOURCED`）⇒ 本文只给**本库构造的反例** |

★ 这一步的演进方向是**把「不能整除」从数据特性变成工程约定** ——
而**每换一种处置，都要重新问一遍「什么被静默地改掉了」**（§1.4 那张表就是这个问题）。

## 4. 踩坑与失败模式

**① ★★★ 用「切分 == 单卡」当 A 类判据（头切分与 vocab 列切两处）。**
- **现象**：测试通过、数字漂亮（`0.000e+00`），但**什么也没检查**。
- **成因**：头切分是**同一批运算被重新分配**（真恒真）；vocab 列切是
  **BLAS 路径依赖**（差**随形状变**，有时 `0.0`、有时 `1.4e-14`）——**两者都没有信息量**。
- **规避**：A 类改钉在**不整除**这条线上（补齐的档位、输入的逐位成因、三种处置的后果）；
  ★ 且把「它恒真」和「它形状依赖」这两件事**各写成一条机械检查**（`D.10`）。

**② ★★★ 补齐之后拿「逐位相等」做判据。**
- **现象**：判据在**正确的实现**上失败，于是有人去改实现（把实现改坏以迁就判据）。
- **成因**：补齐改变了张量的**形状与内存布局** ⇒ BLAS 走不同路径（本机实测 `2.132e-14`）。
- **规避**：判据写**机器精度档**（容差）；★ 并且**把这条「档位」本身写成一条断言**
  （`A.2`：差 `> 0` 且 `≤` 容差）—— 它会在「某个 BLAS 恰好给出逐位相同」时失败，
  那时说明**档位的来源变了**，是**有用**的信号，不是误报。

**③ ★★★ 用静默截断处理「不整除」。**
- **现象**：训练跑得通、loss 在降，只是某些 token **从来预测不出来**（本机 `2/30`，真实规模 `81` 个）。
- **成因**：`emb[:, :per*tp]` 不报错、不崩，只是**把词表的尾巴删了** ⇒
  那些 token 的 logits **根本不存在**。
- **规避**：**优先用 `np.split`**（它会把不整除变成异常）；若确实要截断，
  必须**明写**「哪几个 token 被放弃了」，并**在评测里把它们的指标单独剔出来**。

**④ ★★ 补齐之后忘记屏蔽 pad 位置。**
- **现象**：概率略偏、loss 偏高，但**看不出哪里错**（本机实测：漏到 pad 列上的概率质量最大达 `0.972872`）。
- **成因**：softmax 的归一化**在 pad 列上也算了一遍** ⇒ 概率质量被分走。
  ★ 而**pad 位置恰好是 `0` 时这个失败会变得很小（`1.98e-05`）** ⇒ 更容易被忽略。
- **规避**：把「屏蔽」当成**补齐的必要组成部分**（不是一个可选项）；
  ★ 并且**判据里必须写明 pad 位置取什么值**（否则判据自己会失效）。

**⑤ ★ 把原文的「不**立即**通信」读成「不需要通信」。**
- **现象**：在文档/代码注释里写「头切分不需要通信」。
- **成因**：原文的词是 `doesn’t require any immediate communication` ——
  **「立即」限定的是时机**；紧接着的 output `Linear` 仍按行并行，那次 all-reduce 照旧。
- **规避**：引用时**把限定词一起引**（本文 §1.1 两处都标了粗）；★
  并且记住：**一个层的 all-reduce 次数是 `2`**（两个块各一次，见
  [`01-column-and-row.md`](01-column-and-row.md) 的 `B.2`）。

> ★ 本表是**闭合的**：每一行都是「**可机械判定的条件 → 结论**」，读完能照着做判断。

| 可机械判定的条件 | 结论 |
|---|---|
| 补齐（补到 `16` 的倍数 = `32`）后**取前 `30` 列**与单卡比 | **相同**（本机 `max|diff| = 2.132e-14`，量级 `30.630`）⇒ 补齐**不改变数学** |

| 补齐后与单卡**逐位**相同吗 | **不是**（`array_equal = False`，差 `2.132e-14`）⇒ ★★★ **判据只能写机器精度档**（成因：形状变了 ⇒ BLAS 路径变） |
| 输入 embedding 列切 + all-reduce 与单卡查表 | **逐位相同**（差 `0.000e+00`）；★ **成因可验证**：每个 token 的**非零分片数恰好是 `1`**（`16/16` 个 token）⇒ ★★ **这条判据在这一处恒真** |

| 与交叉熵融合后 | `b×s` = **`12`** 个元素 ⇒ **比值 `30`** == `v` ⇒ ★★★ **量级差 `v` 倍** |

| `np.split(emb, 4, axis=1)`（`v=30`） | **抛 `ValueError`**：`array split does not result in an equal division` ⇒ ★★★ **一道防线** |

## 6. 小结与延伸

**一句话**：头**能整除**（QKV 列切 ⇒ 每个 head 本地算，★ `immediate` 这个词的作用域要留住），
词表**经常不能整除** ⇒ 只有三种处置：**抛错（一道防线）· 静默截断（token 消失）·
补齐（必须配屏蔽）**；★★★ 而**补齐之后「逐位相等」不再成立**
（形状变 ⇒ BLAS 路径变）⇒ **判据只能写机器精度档**。

- **列/行的配对约束与「列并行为什么非得在前面」** ⇒
  [`01-column-and-row.md`](01-column-and-row.md)。
- **TP 的通信量为什么【也饱和】（`8bsh((t−1)/t)`）** ⇒
  [`03-saturation-and-limits.md`](03-saturation-and-limits.md)。
- **注意力变体的结构**（MHA / MQA / GQA 的定义、KV head 与 Q head 的**配比**） ⇒
  `80-model-architectures/attention-variants/01-mha-mqa-gqa.md`（**正文在彼**，
  ★ 本文只写「头怎么分给设备」）。
- **补齐在真实实现里的做法**（怎么屏蔽 pad 位置） ⇒ ★★ **原文没有取到**
  （`specs.UNSOURCED` 的第 2 项）；本文给的是**本库构造的反例**。
- **`128` 这个倍数为什么是 `128`** ⇒ ★★ **原文只写了「对 GEMM 有利」**
  （`specs.UNSOURCED` 的第 1 项）；**本文不解释它**。
- ★★ **一处必须写明的让步**：本文的判据**全部**是「本机玩具规模的真跑」
  （`python3 3.13.5` + `numpy 2.4.4`、**无 GPU、无多卡、无 NCCL、无真实网络**）
