# 微批与气泡：流水线并行的空闲时间，以及它的两个口径

> **PP 的一刀切在【层】上**：`p` 台设备各拿一段层，数据像流水线一样依次流过。
> **切完立刻出现一个只属于 PP 的代价 —— 气泡**：流水线的头尾必然有人闲着。
> ★★★ **而「气泡率」这个词在本库有【两个】口径**：**GPipe 除以【总时间】**、**Megatron 除以【理想时间】**。
> **两者不矛盾**（可用一条恒等式互相换算），但**混用**会让同一组参数算出两个数、
> 而且**看起来像「改善了」**。这是本文最要紧的一件事。

## 0. 背景与动机

把 32 层模型切到 4 台设备上，每台 8 层。现在跑一个 batch：

- 设备 0 算完第 1 层，交设备 1；设备 1 算的时候设备 0 **在等**；……设备 3 开始算时，
  前三个都在等。等设备 3 算完、梯度往回传时，**同样的事情反向再来一遍**。
- 头尾这两段谁都不干活的时间就是**气泡**。它**不是**「调度没做好」——
  **它是「切成 `p` 段」这个动作的代数后果**，与实现质量无关。

**气泡有多大**？直觉说「约等于 `p` 分之一」—— 对一半。真正决定它的是
**一个 batch 被切成多少片**（`m`，即 micro-batch 数）：

- `m = 1`（一个 batch 就是一个 micro-batch）：气泡**几乎吃掉全部时间**；
- `m = 32`：气泡只占一小截。

★ 而这就是**微批（micro-batch）**的用途：把一个 batch 切成 `m` 份，让流水线里
**同时有多个 micro-batch 在飞**，把气泡摊薄。**代价**是每一份都要单独走一遍流水线
（通信次数与调度复杂度上升）—— ★ 而**每一份的激活都要留着**（那是 `02` 的主题）。

本文只回答一个问题：**给定 `(p, m)`，气泡占多少？**
★★ 而这个问题**有两个官方答案**，它们的差别**只是分母**。

## 1. 原理

### 1.1 先把「气泡」写成一个可算的量

设一个 micro-batch 走**一级**的前向、后向时间分别是 `t_f`、`t_b`。`p` 级流水线、`m` 个 micro-batch：

- **每个 stage 的忙时间** = `m × (t_f + t_b)`（它要做 `m` 次前向 + `m` 次后向）；
- **理想时间**（没有任何气泡）= 上面这个数 —— 因为 `p` 个 stage **并行**做，瓶颈就是单个 stage；
- **实际总时间** = `(m + p − 1) × (t_f + t_b)` —— 第一个 micro-batch 要走完 `p` 级（`p` 步），
  剩下的 `m − 1` 个各多一步（`m − 1` 步），后向同理。

⇒ **气泡时间** `= 实际 − 理想 = (p − 1) × (t_f + t_b)` —— ★★ **注意它【与 `m` 无关】**：
加 micro-batch 不改变气泡的**绝对长度**，只改变**它占的比例**。

**本机实测**（`code/01_bubbles.py` 的 `A.1`，7 组 `(p, m)`）：
离散事件模拟的总时间与闭式 `(m+p−1)(t_f+t_b)` **差 `≤ 5.551e-17`**（机器精度档）。
★ 那个模拟器**只编码两条串行约束**（同一 stage 上前向串行、后向也串行），
**闭式的任何形式都不出现在它的源码里** —— `D.3` 用 `inspect.getsource` 机械地证明了这一点
（★ 否则「模拟 ↔ 闭式对拍」就是**把同一个式子写两遍**，那是本域的头号错误模式）。

### 1.2 ★★★ 两个口径：差别只在【分母】

| 口径 | 公式 | 分母是什么 | 出处 |
|---|---|---|---|
| **GPipe** | `(K−1)/(M+K−1)` | **总时间**（`实际`） | `1811.06965 §2.3`（**NeurIPS 2019**） |
| **Megatron-LM** | `(p−1)/m` | **理想时间** | `2104.04473 §2.2.1`（**SC '21**） |

★ 记号换写：`K ↔ p`（分区数 ↔ 流水线级数）、`M ↔ m`（micro-step ↔ micro-batch）。

**两者不矛盾** —— 因为「总时间 = 理想 + 气泡」，所以

```text
b_megatron = b_gpipe / (1 − b_gpipe)
```

**本机实测**（`code/01_bubbles.py` 的 `B.2`）：5 组 `(p,m)` 下这条恒等式**差 `≤ 5.551e-17`**。
例如 `(p, m) = (4, 8)`：`b_gpipe = 0.272727` ⇒ `0.272727/(1−0.272727) = 0.375000 = b_megatron` ✓

★★★ **为什么这条必须写清**：**同一组参数在两个口径下是两个数**（`0.273` vs `0.375`），
而**它们描述的是同一个气泡**。★ 不知道这件事的人会以为其中一个「改善了气泡」。

> ★★ **一条纪律**：**凡引用一个气泡率，必须写明用的是哪个口径**（分母是什么）。
> 本库的 `data-parallel/03` 记过同类的事：**量法口径是独立的出错环节**。

### 1.3 GPipe 的原文口径与它的边界

原文逐字（`specs.GPIPE_BUBBLE_QUOTE`）：

> `This bubble time is O((K−1)/(M+K−1)) amortized over the number of micro-steps M.`

★★ **两个必须写明的边界**：
1. **原文写的是 `O(...)`（Big-O），不是等式** —— 它是一个**量级陈述**，
   而「等式」是本文 §1.1 用**理想时间**的定义推出来的（★ 这一步属本库的 `[E]`）；
2. **分母是【总时间】** —— 与 Megatron 的口径**不同**（见 §1.2）。

**「气泡可忽略」的判据也是原文给的**（同节逐字）：

> `In our experiments, we found the bubble overhead to be negligible when M ≥ 4 × K.`

★ 这是**实验观察**（`In our experiments`），**不是定理** ⇒ 不得写成「`M ≥ 4K` 时气泡一定可忽略」。
★ **本机实测**（`B.3`）：`p = 4, m = 16`（即 `M = 4K`）时气泡占比 `0.2105` ——
**离「可忽略」还差得远**；★ 这个数**依赖 `t_b = 2·t_f` 这个设计假设**（见 §2.1），
所以**它只说明「`4×` 这个档在本库这组假设下不够」**，不构成对原文的否定。

### 1.4 ★★ `(n−d)/b'` —— 同一条式的另一种写法

Megatron-LM 的 §3.3.1 把 `(p−1)/m` 换写成（`specs.MEGATRON_N_OVER_D_QUOTE` 所在段）：

```text
(p − 1)/m = (n/d − 1)/(b'/d) = (n − d)/b'
```

（`n` = 总 GPU 数、`d` = DP 度、`b' = B/b` = 全局 batch 除以 micro-batch 大小。）

**本机实测**（`B.5`）：`n = 64, b' = 32` 下，`d = 2/4/8/16/32` 时两边**差 `0.000e+00`**。

★★★ **这条换写的价值在于它的【结论】**：在**固定总卡数** `n` 下，

> **把卡多分给 DP（`d` 增大）会【减小】PP 气泡** —— 因为 `p = n/d` 随之减小。

实测：`d = 2 → 1.937500`、`d = 8 → 1.750000`、`d = 32 → 1.000000`（**单调递减**）。
★ 这与「加 PP 级数会加大气泡」是同一件事的**两面** —— 而 `d = n` 时 `p = 1`，
气泡**恰为 `0`**（退化：没有流水线）。

### 1.5 ★★★ 一条**恒真**的判据：「`p = 1` 时气泡为 0」

**它当然成立** —— 没有流水线就没有气泡。★ 而正因为「当然」，**它不能当 A 类判据**。
`code/01_bubbles.py` 的 `D.2` **故意**把它标出来（像 `tensor-parallel` 处理「列并行 `0.0`」那样），
并因此**不拿它充判据**。

★ **它唯一的价值是「退化对照」**：若 `p = 1` 时算出了非零气泡，那说明**依赖方向写反了**。
⇒ 所以它是一条 **P 类（口径自检）**，不是 A 类。

### 1.6 ★★ 气泡与「重算」的关系：**因果不是想当然的那个**

原文在给出气泡公式之后，紧接着说（`specs.GPIPE_RECOMPUTE_CAUSAL_QUOTE`）：

> `This is also partly because re-computation during the backward pass can be scheduled earlier, without waiting for the gradients from earlier layers.`

★★★ **原文说的是「重算【可以被更早地调度】」** —— 一个**调度自由度**，
**不是**「重算降低了气泡率」。★ 常见转述把它说成后者，**那是错的**。

★★ **重算换显存的【机制】**（`O(√n)` 内存 vs `≈2n` 前向次数）**不在本文** ——
正文在 `90-training/autograd-and-backward/02-gradient-checkpointing.md`（**此处回链**）；
★ 本文只写「**PP 下用重算做显存均衡的取舍**」，那在 `03` 里。

## 2. 执行映射

### 2.1 本机怎么算这件事

`code/01_bubbles.py` 做两件事，**且两者互相独立**：

| 角色 | 是什么 | 依据 |
|---|---|---|
| **被测**（模拟器） | 一个**离散事件模拟**：`p` 级、`m` 个 micro-batch，**只编码两条串行约束** | 本程序的 `simulate()` |
| **参照**（闭式） | `(m+p−1)·(t_f+t_b)` | §1.1 的推导 |

★★★ **独立性是硬的**：`D.3` 断言「闭式的任何形式**都不出现**在 `simulate()` 的源码里」。
★ 且**参数是设计常量**：`t_f = 1.0`、`t_b = 2.0`（`specs.UNIT_F`/`UNIT_B`）：

> ★★ **`t_b = 2·t_f` 是本库的设计假设**（「后向是前向两倍」）——
> **不是任何模型的实测** ⇒ **本文的一切气泡数只在这一组假设下成立**。

★★ **为什么 `t_f` 与 `t_b` 的【比值】不影响气泡率**：气泡率的分母与分子都含 `(t_f + t_b)` 的因子
（§1.1），**它约掉了**。⇒ 本文的气泡率**只依赖 `(p, m)`**，
`t_b = 2 t_f` 这个假设只影响**绝对时间**、不影响**占比**。
★ 这一点让本文的结论比「一组建模参数」更稳 —— 但**仍然不是**对真实系统的结论（本机无 GPU）。

### 2.2 两种「气泡」别搞混

`00-meta/glossary.md:23`（`TLP` 条）里也有一个「**流水线气泡**」——
那是 **GPU 指令流水线**的气泡（SM 内部，靠多 warp 并发填补）。
★ 本文的「气泡」是**流水线并行**的气泡（**设备之间**的空闲时间），**不是同一个量**。
⇒ 本文一律写全「**流水线并行的气泡**」。

## 3. 实现与演进

### 3.1 从「不切微批」到「切微批」

- **不切微批**（`m = 1`）：气泡率 = `(p−1)/p` ⇒ `p = 4` 时 **`75%`**（几乎全在等）。
- **切微批**：气泡率随 `m` 单调下降，但**永远不为 0**（`p > 1` 时）。
  ⇒ ★ **要把它压到「可忽略」，`m` 必须远大于 `p`** —— 而那意味着
  **更多的通信次数**与**更多的在飞激活**（后者是 `02` 的主题）。

### 3.2 三种调度，两种改善方式

| 调度 | 它改善什么 | 正文 |
|---|---|---|
| **GPipe** | （基线）先全部前向、再全部后向 | 本文 |
| **1F1B** | ★★ **显存**（在飞 micro-batch 数从 `m` 降到 `p`）—— **气泡不变** | `02-schedules` |
| **interleaved** | ★★★ **气泡**（降 `v` 倍）—— 代价是通信 | `02-schedules` |

★★★ **本表的存在就是为了挡住一个流传很广的错**：
「1F1B 把气泡从 `(p−1)/(m+p−1)` 降到 `(p−1)/m`」——
**那两个公式的差别是分母口径**（§1.2），**不是任何改善**。

### 3.3 与 `performance-models/02` 的分工

`10-foundations/performance-models/02-amdahl-and-scaling.md` 已经逐字写了：

> 「张量并行……通信发生在**每一层内部**……**流水线并行**……是点对点」
> 以及「TP 与 PP 的通信模式完全不同，本文的结论**不能**直接套用」。

⇒ ★★ **本文一行都不重写它**。本文只写它**没写**的：**切层之后那个空闲时间怎么算**。

## 4. 踩坑与失败模式

### 4.1 ★★★ 把两个口径的数拿来比（把「口径差」当成「改善」）

- **现象**：报出「气泡率从 `0.273` 降到 `0.375`」——★ 而 `0.375 > 0.273`，
  于是有人改成「从 `0.273` 上升到 `0.375`」，两头都不对。
- **成因**：**两个数来自两个口径**（分母不同），**它们描述的是同一个气泡**。
- **规避**：**引任何气泡率都写明分母**；★ 要比较就**换到同一个口径**（`b_m = b_g/(1−b_g)`）。

### 4.2 ★★ 漏一条串行约束 ⇒ 气泡率**算出负数**

- **现象**：模拟器给出 `气泡率 = -0.33`（★ 物理上不可能）。
- **成因**：模拟器**漏了一条约束** —— 最典型的是「同一 stage 上 micro-batch 的**后向也必须串行**」。
  漏掉它，同一 stage 的后向会被算成**并行**，总时间**偏小**，气泡率于是变负。
- **规避**：把「气泡率 `≥ 0`」做成一条**真的会失败**的断言（`code/01_bubbles.py` 的 `C.1`，
  实测漏约束时 `-0.263158`）✓
- ★★ **这条是本文作者踩过的**（本库控制者在早期探测里得到 `-0.33`）。

### 4.3 ★★ 守卫选错：**对调 `t_f`/`t_b` 是一条恒真的「守卫」**

- **现象**：为了验证「`A.1` 能失败」，把 `t_f` 与 `t_b` 对调 —— ★ **总时间完全不变**，
  因为闭式 `(m+p−1)(t_f+t_b)` **对两者是对称的**。
- **成因**：守卫选的错法**不改变被判量**。
- **规避**：★★★ **守卫必须选一个「真的会改变被判量」的错法**。
  本程序改成「**漏掉同 stage 的【前向】串行**」（`C.2`）：
  实测总时间从 `33.00` 掉到 `26.00` ⇒ `A.1` **真的会失败** ✓
  ★★ **同样的坑在 `03` 里又出现一次**（「层数倒序」因首尾 embedding 对称而不改变比值）。

### 4.4 ★ 把 `O(...)` 当等式引

GPipe 原文写的是 `O((K−1)/(M+K−1))`。★ 引它时必须**照抄那个 `O`**，
因为「等式」的那一步（用理想时间作分母）**是本文补的**（标 `[E]`）。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 引用一个气泡率，**没写分母** | **不合格** —— 必须先落到某一个口径（GPipe 用总时间 / Megatron 用理想时间） |
| 两个气泡数要比较 | **先换到同一口径**：`b_megatron = b_gpipe/(1 − b_gpipe)`（实测差 `≤ 5.551e-17`） |
| 报「气泡率随 `m` 下降」 | **成立**，但要写清：**气泡的【绝对长度】`(p−1)(t_f+t_b)` 与 `m` 无关**，降的是**占比** |
| `p = 1` | 气泡**恰为 `0`**；★ 这条**恒真**（没有流水线就没有气泡）⇒ **只能当退化对照，不能当 A 类** |
| 让气泡率降下来 | 只有两条路：**加大 `m`**、**或换 interleaved 调度**（`02`）。**1F1B 不在其中** |
| 模拟器与闭式对拍 | **两者必须独立** —— 证明方式：闭式的形式**不出现**在模拟器源码里（源码级断言） |
| 模拟器算出**负**气泡率 | **一定是错的** —— 先查「同一 stage 的后向串行」那条约束还在不在 |
| 看到一个「守卫」 | ★★ 先问：**改错之后被判量真的变了吗**？（对调 `t_f`/`t_b`、层数倒序**都没变**） |
| 引用 `M ≥ 4K` 那句 | 必须写成「原文的**实验观察**」；★ 本库实测 `M = 4K` 时气泡占比 `0.2105`（**在那组设计假设下**） |
| 想把「重算」算进气泡 | **先读原文的因果**：重算是「**可以被更早地调度**」，不是「降低气泡率」 |
| 引 `(n−d)/b'` | 它的**结论**是「**固定总卡数下，`d` 越大气泡越小**」（实测 `d=2 → 1.938`、`d=32 → 1.000`） |

## 6. 小结与延伸

**一句话**：PP 的气泡是「切成 `p` 段」的代数后果；**它的占比只依赖 `(p, m)`**，
而**「占比」有两个官方分母** —— 混用它们会把一个口径差读成一次改善。

**三条可独立复用的结论**：

1. **气泡的绝对长度是 `(p−1)(t_f+t_b)`，与 `m` 无关** —— 加 micro-batch 只稀释它，不消除它；
2. **两个口径可用 `b_m = b_g/(1−b_g)` 互换**（实测差 `≤ 5.551e-17`），★ 引数必须写明用哪个；
3. **`(n−d)/b'` 说：固定总卡数下，把卡多分给 DP 会减小 PP 气泡**。

**延伸**：

- **1F1B 换的是什么**（★ 不是气泡，是显存）→ [02-schedules](02-schedules.md)；
- **各 stage 的负载不均**（★ 气泡之外的第二笔账）→ [03-memory-balance](03-memory-balance.md)；
- **重算换显存的机制** → `90-training/autograd-and-backward/02-gradient-checkpointing.md`（此处回链）；
- **多机扩展的天花板**（Amdahl / `N₅₀`）→ `10-foundations/performance-models/02-amdahl-and-scaling.md`。
