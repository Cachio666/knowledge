# AWQ 与 SmoothQuant：把量化难度从一维搬到另一维

> GPTQ 改的是「每个权重往哪边舍」；这两个方法改的是**「把哪一维的量化难度搬到哪一维」**。SmoothQuant 用 `s_j = max(|X_j|)^α / max(|W_j|)^(1−α)` 做逐通道缩放，把激活的离群值**卸到权重上**——本机实测 `max|X|` 从 **103.50 → 3.67**，代价是 `max|W|` 从 **0.233 → 3.667**，而 `(X diag(s)⁻¹)(diag(s) W)` 与 `XW` **逐元素等价**（float32 舍入量级）。AWQ 在同一个 `α` 上做 **20 点网格搜索**（**α = 1.0 取不到**）。**关键前提：SmoothQuant 是 8-bit 方法，W4A4 会崩。**

## 0. 背景与动机

先摆出这两个方法要解决的问题。

**问题一：激活比权重难量化。** 三条机理（引用，见 §参考）：① outlier 出现在**特征维（矩阵的列）**上；② 权重分布平坦、激活长尾；③ 权重的 per-channel 量化硬件允许，而**激活的 per-channel 会插进 GEMM 内维、硬件不可行**，只能退到 per-token。

**问题二：per-token 治不了持久性 outlier。** 某个通道有 outlier，它在**所有 token 上**都出现；token 内通道间方差很大，但**同一通道跨 token 的幅值方差很小**。于是「每行一个 scale」救不了「某一列特别大」。

**两篇论文给的答案方向相同、落点不同**：**既然难度是「分布」的属性，就把分布改一改。**

| | AWQ | SmoothQuant |
|---|---|---|
| 改什么 | `W ← W·diag(s)`，`X ← X·diag(s)⁻¹` | 同左 |
| `s` 怎么定 | `s = s_X^α`，`s_X = \|X\|.mean(0)`，**再按几何均值归一** | `s_j = max(\|X_j\|)^α / max(\|W_j\|)^{1−α}` |
| `α` 怎么定 | **20 点网格搜索**，判据 = 块输出 MSE | 固定 **0.5**（GLM-130B 用 0.75） |
| 目标位宽 | 权重 4-bit 一类（**W4A16**） | **激活 8-bit（W8A8）** |
| 为什么「训练无关」 | 只需一次前向 | 缩放可**离线融进前一层参数** |

**本机实测（同一份合成问题）：**

| 项 | 数 |
|---|---|
| AWQ 的 `argmin α` | **0.20** |
| AWQ 相对 RTN 的输出误差降幅 | **62.9%** |
| AWQ 在 `α = 0.95` 时 | **比 RTN 更差**（1.529361e0 vs RTN 的 **1.345403e0**；RTN 越小越好） |
| SmoothQuant 的 `argmin α` | **0.45**（甜蜜区 0.4–0.6 内） |
| `α = 0.5` 时 `max\|X\|` / `max\|W\|` | **103.50 → 3.67** / **0.233 → 3.667** |
| 迁移恒等式的最大相对偏差 | **2.432e-7**（float32 舍入量级） |

## 1. 原理

### 第一步：为什么「缩放不改变数学」是这两篇的地基

设 `Y = X·Wᵀ`，`s` 是任意**正的逐通道向量**。那么

```
Y = (X·diag(s)⁻¹) · (diag(s)·Wᵀ)
```

展开看第 `j` 个输入通道：`(x_j / s_j) · (s_j · w_j) = x_j·w_j`。**逐通道约掉了。** 这是**代数恒等式**，与数据无关、与 `s` 的取值无关。本机实测：连跑 21 个 `α`，等式的最大相对偏差 **1.945e-7**（float32 的舍入量级）。

但**量化**不是恒等式：`Q(x_j/s_j)` 与 `Q(s_j·w_j)` 各自带量化误差。于是整件事变成：

```
在「数学不变」这一条约束下，自由地选 s，使「量化后」的误差最小。
```

**这是这两篇论文共用的框架。它们的区别只在「怎么选 `s`」。** 这也解释了为什么它们「训练无关」：`s` 是一次前向统计出来的常数，不需要任何梯度。

### 第二步：SmoothQuant 的选择 —— 把两端配平

SmoothQuant 取

```
s_j = max(|X_j|)^α / max(|W_j|)^{1−α},     α ∈ [0, 1]
```

看两个端点：

- **`α = 0`**：`s_j = 1/max(|W_j|)`。这会把权重都压到 1 附近（**权重极好量化**），但激活被乘上了 `max(|W_j|)`——**离群值原封不动留在激活侧**。
- **`α = 1`**：`s_j = max(|X_j|)`。激活被压到 1 附近（**激活极好量化**），代价全压在权重上。

**所以 `α` 就是「谁承担多少」的旋钮。** 论文说 OPT/BLOOM 全系用 **`α = 0.5`**（"well-balanced point"），消融显示甜蜜区是 **0.4–0.6**；而 **GLM-130B 因为激活离群更多，用 `α = 0.75`**。

本机实测的曲线（8-bit，判据 = 层输出 MSE）：

| `α` | 0.00 | 0.25 | 0.40 | **0.45** | 0.50 | 0.60 | 0.75 | 1.00 |
|---|---|---|---|---|---|---|---|---|
| 输出 MSE | 9.548e-3 | 1.984e-3 | 1.148e-3 | **1.105e-3** | 1.180e-3 | 1.634e-3 | 3.816e-3 | 1.998e-2 |

**两端都比最低点差将近一个数量级。** 本机 `argmin` 落在 **0.45**，在论文的甜蜜区内。

### 第三步：AWQ 的选择 —— 网格搜索，而网格有边界

AWQ 的洞察是：**不是所有权重都一样重要**，只有 **0.1%–1%** 的显著权重承载了大部分信息；而**识别显著通道要看激活分布而不是权重分布**。它的误差分析写成

```
Err(Q(w)x) = Δ · RoundErr(w/Δ) · x
```

把通道 `j` 放大 `s` 倍（权重乘 `s`、激活除以 `s`）后：

```
新误差 / 原误差  =  (Δ'/Δ) · (1/s)
```

- **`Δ'/Δ`**：缩放后该通道所在**组**的步长变化。**只要被放大的通道没有变成组内最大值，`Δ' = Δ`**，这一项就是 1。
- **`1/s`**：激活侧被除掉的倍数。

于是**当 `s > 1` 且该通道不是组内最大时，误差按 `1/s` 下降**。本机实测验证了这个分界：

| `s` | `Δ'/Δ` | `1/s` | 乘积 | 现象 |
|---|---|---|---|---|
| 1.0 | 1.0000 | 1.0000 | 1.0000 | —— |
| 2.0 | 1.0000 | 0.5000 | **0.5000** | 未顶成组内最大 |
| 4.0 | 1.0000 | 0.2500 | **0.2500** | 仍未顶成 |
| 16.0 | **1.3498** | 0.0625 | 0.1687 | **顶成组内最大 ⇒ 开始伤别的通道** |

**最后一行就是 AWQ 的全部代价**：`s` 太大会抬高整组的 `Δ`，反而坑了同组其它通道。**这正是需要一个搜索的原因。**

**搜索怎么做的（官方实现，源码直取）：**

```python
n_grid = 20
for ratio in range(n_grid):
    ratio = ratio * 1 / n_grid                        # ★ α ∈ {0, 0.05, …, 0.95}
    scales = x_max.pow(ratio).clamp(min=1e-4).view(-1)
    scales = scales / (scales.max() * scales.min()).sqrt()   # ★ 几何均值归一（论文没写）
    ...加权、量化、跑一遍块、算 (org_out - out)² 的均值...
```

两处**论文里没有、只在实现里**的细节：

1. **`n_grid = 20` 且 `ratio = ratio * 1/n_grid`** ⇒ **`α = 1.0` 取不到**，网格最大值是 **0.95**。
2. **`scales / (scales.max()·scales.min())^0.5`**：先按几何均值归一，再进网格。没有这一步，`s` 的整体尺度会让所有 α 都偏向一端。

还有一处统计量的选择：`get_act_scale(x)` 的实现是 **`x.abs().view(-1, x.shape[-1]).mean(0)`**——**逐通道的平均绝对值**，不是最大值。本机实测 `mean(|X|)` 与 `max(|X|)` **不相等**，所以这个选择是可分辨的。

### 第四步：为什么 SmoothQuant 必须是 8-bit

这条容易被当成细节，其实是**前提**。看两端：

- **8-bit（256 级）** 时，把权重放大 15 倍也只是让权重的量化级数更充分地展开；非显著权重仍然有足够多的级数可用。
- **4-bit（16 级）** 时，`max(|W|)` 被抬高 15 倍意味着**非显著权重的有效级数被压到个位数**（同 `verify.py` 的 C.1 那条机理）。

本机实测（同一 `α = 0.5`、同一份数据，判据 = 归一化后的输出 MSE）：

| 位宽 | 相对输出 MSE |
|---|---|
| 8-bit | **8.7932e-05** |
| 4-bit | **2.8498e-02** |

**4-bit 比 8-bit 差 324 倍。** 而论文侧的一手对照（引用）是 Atom 论文 arXiv:2310.19102v3 Table 2：Llama-7B FP16 **5.68** vs SmoothQuant **W4A4 22.62**、W3A3 **2.7e4**。

**⇒ 把 SmoothQuant 说成「低位宽方案」是错的。它是把 8-bit 激活变得可行的方法。**

## 2. 执行映射

### 2.1 三个组件名与一个数值量级

- **`nn.Linear` 的权重与前一层**——SmoothQuant 的 `s` 是**逐输入通道**的，所以它**只作用在相邻两层之间**：`s` 可以离线吸收进前一层（`LayerNorm` / 上一个 `Linear`）的权重里（前一层输出乘上 `s⁻¹`），**不引入任何额外 kernel**。这就是它「零额外开销」的来源；
- **逐通道缩放作用的轴**——`s_j` 的下标 `j` 是**输入通道**，即 `W` 的**列**、`X` 的**特征维**。**写错这一维，整个方法就搬到错的维度上去了**（这一条与 `theory/02-granularity` 里「per-channel / per-token 标签写反不会报错、只会让结论与 KIVI 相反」是同一个坑）；
- **量级**：本机合成问题里 `max|X|` 的离群通道幅值是 `30×`（构造），真实模型里 LLM.int8() 报告可达 **比其它维度大 20×**；SmoothQuant 的迁移把本机的 `max(|X|)` 从 103.50 压到 3.67——**降了 28 倍**。

### 2.2 为什么两条路线分道扬镳（一位宽 vs 两位宽）

| | AWQ | SmoothQuant |
|---|---|---|
| 走的路 | **只动权重**（`s` 吸进权重的量化尺度里） | **同时动激活**（`s` 拆成两半，一边进权重、一边进前一层） |
| 激活保持 | FP16（W4A16） | **INT8**（W8A8） |
| 对硬件的诉求 | 只要权重解包 kernel | 要**真 INT8 GEMM**（上一代 GPU 缺 `s8×s8→s32`，所以论文标题里带 "and the Battle for 8-bit"） |
| 缩放能融进哪 | 权重本身 | **前一层**（Linear / LayerNorm） |

## 3. 实现与演进

**第一代：直接量化（per-tensor 激活）。** 崩。SmoothQuant Table 1 的对照（引用，OPT 系列 activation 量化平均精度）很直观：

| 模型 | FP16 | per-tensor | per-token | per-channel |
|---|---|---|---|---|
| OPT-6.7B | 64.9 | 39.9 | 42.5 | **64.8** |
| OPT-175B | 71.6 | 32.3 | 31.7 | **71.4** |

**per-channel 几乎无损，per-tensor 与 per-token 都崩**——这与 §0 的「问题二」是同一件事。
> ⚠ 这张表用 `pdftotext -layout` 提取时**行标有错位**，是按语义判定的对齐。**引用前建议在 PDF 阅读器里核一眼。**

**第二代：per-channel / per-group。** 粒度变细，但激活侧的 per-channel 会插进 GEMM 内维、硬件不可行——**这是「硬件约束决定算法设计」的一处实例**。

**第三代：改分布（AWQ / SmoothQuant）。** 不再跟量化粒度较劲，直接把分布搬一搬。

**演进的分叉**：`03-awq-and-smoothquant` 与 `04-rounding` 是同一件事的两条路——前者改**连续值的尺度**，后者改**离散化的决策**。

**效果（引用，AWQ Table 4，harness = WikiText-2 / g128）**：

| 方法 | Llama-2-7B INT3 |
|---|---|
| FP16 | 5.47 |
| RTN | 6.66 |
| GPTQ | 6.43 |
| GPTQ-R | 6.42 |
| **AWQ** | **6.24** |

> ⚠ **这张表的基线是 5.47，不是 5.12 也不是 5.68**。本域已发现**两套基线不同的 Llama-2-7B PPL 表（5.12 与 5.47）**，**不同基线的表不得并列**。

> ⚠ **SmoothQuant 的两处收益数字不同**：
> **摘要**写 "up to **1.56×** speedup and **2×** memory reduction"；
> **正文 §4.3** 写 "up to **1.51×** and **1.96×**"。**引用时须标明出处位置**——这是同一篇文章里两个不同的数，不是「估算 vs 实测」。

## 4. 踩坑与失败模式

### 4.1 把 SmoothQuant 当成 4-bit 方案

**现象**：把 SmoothQuant 与 GPTQ/AWQ 并排成「三种 4-bit 方法」，或直接拿它的 `α = 0.5` 去跑 4-bit。

**成因**：它的目标位宽是 **8-bit**。`s` 的迁移把 `max(|W|)` 抬高 15 倍，8-bit 下还有 256 个级数可用，**4-bit 下只剩 16 个**。

**规避**：本机实测同一个 `α = 0.5` 下 4-bit 的相对误差是 8-bit 的 **324 倍**；一手引用是 W4A4 → **22.62** vs FP16 **5.68**。**引用时写清位宽。**

### 4.2 拿「摘要」的数字去核「正文」的表

**现象**：看到摘要说 1.56×，正文表里算出 1.51×，以为其中一个错了。

**成因**：**两处都对**，它们是同一篇文章里两处不同的陈述（摘要 vs §4.3）。同理内存比是 2× vs 1.96×。

**规避**：引用**必须标出处位置**（「摘要」/「正文 §4.3」）。**两个数不得并列成「估算 vs 实测」**——它们不是同一个量。

### 4.3 把 `α = 1.0` 当成 AWQ 网格的端点

**现象**：写「AWQ 在 `α ∈ [0,1]` 上搜索」，或复现时取 21 个点。

**成因**：官方实现是 `n_grid = 20`、`ratio = ratio * 1/n_grid`，于是 `α ∈ {0, 0.05, …, 0.95}`——**1.0 不在网格里**。

**规避**：读实现，不读转述。判据是机械的：网格 20 个点、步长 0.05、最大值 0.95。**「21 点含端点」是另一个网格。**

### 4.4 漏掉几何均值归一

**现象**：自己实现 AWQ 的网格搜索，结果**所有 α 都差不多**，或者最优 α 总是在端点。

**成因**：官方实现在进网格前先做 `scales / (scales.max()·scales.min())^0.5`。**论文没写这一步。** 缺了它，`s` 的整体尺度会被量化器「吸收」掉，搜索退化。

**规避**：照实现写。归一后的判据是 `max(s) × min(s) == 1`。

### 4.5 在 `s` 的维度上写错

**现象**：把 `s` 当成 per-token（沿 token 维）而不是 per-channel（沿特征维）。

**成因**：`s_j` 的下标是**输入通道**。写成 per-token 时，形状检查可能仍然通过（方阵上尤其如此——同域的 `theory/02-granularity` 记录过 `torch.quantize_per_channel` 在方阵上 `axis` 写反**不报错**、SQNR 差近 20 dB 的实例）。

**规避**：把维度写进变量名，并在测试里用一个**非方阵**。

### 4.6 以为三者可以叠起来用

**现象**：写「GPTQ + AWQ + SmoothQuant 机制正交，可以任意组合」。

**成因**：**没有任何论文给出过严格实验。** 能确证的只有一件：AWQ 论文把 **GPTQ-R 当独立 baseline** 比（Table 4），不是当组件组合。而且 SmoothQuant 与 GPTQ/AWQ **没有直接精度对比**——它对照的是 ZeroQuant / LLM.int8() / Outlier Suppression。

**规避**：**不写「机制正交所以能任意组合」。** 要写组合效果，必须先找到给出该组合实验的来源。

## 5. 实测数据

**测量条件**：Apple M1 Pro（10 核）/ macOS / **CPU-only，无 GPU 数字**；python 3.12.9；**torch 2.11.0**。五个解释器（2.6.0 / 2.7.1 / 2.8.0 / 2.11.0 / 2.13.0）都跑过；`2.9 / 2.10 / 2.12` 本机无解释器。数值逐条记在 `code/specs.py`。

**问题设定**（判据逐条写出，P9）：`torch.manual_seed(0)`；`X: [128, 512] ~ N(0,1)`，**通道 `{5, 17, 33, 70, 101}` 幅值 ×30**；`W: [256, 512] ~ N(0,1)×0.05`；误差口径 = `mean((Y − Y_q)²)`，`Y = XWᵀ`。激活量化是 **per-token 非对称**（`lo/hi` 沿 `dim=1`），权重量化是 **per-output-channel 对称**（`amax` 沿 `dim=1`）。

### 5.1 SmoothQuant 的迁移恒等式

| `α` | 0.00 | 0.25 | 0.50 | 0.75 | 1.00 |
|---|---|---|---|---|---|
| `max\|Xs@Wsᵀ − Y\| / max\|Y\|` | 1.70e-7 | 1.46e-7 | **1.945e-7** | 1.95e-7 | 1.95e-7 |

**全部在 float32 舍入量级**（`verify.py` 用 float64 跑同一恒等式，偏差 < 1e-12）。⇒ 这是**代数恒等式**，不是近似。

### 5.2 SmoothQuant 的 α 扫描（8-bit，判据 = 输出 MSE）

| `α` | 0.00（不迁移） | **0.45（argmin）** | 0.50（论文默认） | 1.00（全搬） |
|---|---|---|---|---|
| 输出 MSE | 9.548409e-3 | **1.104506e-3** | 1.179543e-3 | 1.997518e-2 |

迁移的代价（同一次测量）：`max|X|` **103.50 → 3.67**；`max|W|` **0.233 → 3.667**。

### 5.3 SmoothQuant 的位宽依赖

| 位宽（`α = 0.5`） | 相对输出 MSE（除以 `mean(Y²)`） |
|---|---|
| 8-bit | **8.7932e-05** |
| 4-bit | **2.8498e-02** |

比值 **324×**。

### 5.4 AWQ 的 α 网格搜索（3-bit per-output-channel RTN）

| `α` | RTN（不缩放） | **0.20（argmin）** | 0.50 | 0.75 | 0.95 |
|---|---|---|---|---|---|
| 输出 MSE | 1.345403e0 | **4.991030e-1** | 1.014564e0 | 1.461601e0 | 1.529361e0 |

## 6. 小结与延伸

- AWQ 与 SmoothQuant 共用一条地基：**`Y = (X·diag(s)⁻¹)(diag(s)·W)` 是代数恒等式**（本机 float32 下偏差 1.945e-7）。它们改的不是量化器，是**待量化量的分布**。
- 它们与 GPTQ 的分工是清楚的：**GPTQ 是权重-only（W4A16）**，用二阶信息换舍入决策；**SmoothQuant 是 W8A8**，把激活的量化难度等价迁移到权重上；**AWQ 是 W4A16**，用激活统计选缩放。
- **`α` 是「谁承担多少」的旋钮**，两端都差一到两个数量级；SmoothQuant 的甜蜜区 0.4–0.6（本机 argmin 0.45），AWQ 靠 20 点网格搜（本机 argmin 0.20，**网格里没有 1.0**）。
- **SmoothQuant 是 8-bit 方法**：本机 4-bit 的误差是 8-bit 的 **324×**。
- **引用收益数字必须标出处位置**：同一篇 SmoothQuant 的摘要是 1.56×/2×，正文是 1.51×/1.96×。
- **「三者能否叠加」没有论文给过严格实验**，不得写「机制正交所以能任意组合」。

**延伸**：`04-rounding` 走另一条路——不改尺度，改**离散化的决策**，并给出一个「最近舍入不是最优」的实测。`kv-cache-quantization` 的主题则把同一套「难度在哪一维」的思路用在 KV cache 上（K 必须 per-channel、V 可以 per-token）。
