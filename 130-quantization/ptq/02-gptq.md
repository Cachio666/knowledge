# GPTQ：用二阶信息换舍入决策，以及两个常被混淆的 size

> 校准只决定「`amax` 定在哪」，GPTQ 决定的是**「每个权重各自往哪边舍」**——它拿校准集上的二阶矩 `H = (2/n)XᵀX`，逐列量化、把每一列的舍入误差**补偿到还没量化的列上**。本机实测：层输出误差比 RTN 低 **46.6%**，而**权重误差反而大 4 倍**——**这两个结论都对，因为它们不是同一个量**。另有两处必须分清：`blocksize`（计算批处理，**不改数学结果**）≠ `group_size`（量化粒度）；`dampening` 的默认值在论文（1%）与 transformers（0.1）之间**差 10 倍**。

## 0. 背景与动机

拿一个具体的对照。4-bit 对称量化一张 `256×512` 的权重 `W`，校准集 `X` 是 `1024×512`：

| 方法 | **层输出**误差 `mean((XWᵀ − XW_qᵀ)²)` | **权重**误差 `mean((W − W_q)²)` |
|---|---|---|
| RTN（逐列最近舍入） | 1.0519e-01 | **3.4273e-05** |
| GPTQ（逐列补偿，`gs=128`） | **5.6128e-02** | 1.7147e-04 |

**两个判据给出相反的排名。** 按输出看，GPTQ 好 **46.6%**；按权重看，GPTQ **差 4 倍**。这不是测量误差——**GPTQ 本来就不优化权重空间**，它优化的是「把这一层的输出算对」。

这就带出本篇要回答的问题：

1. 逐列补偿的公式是怎么来的？为什么「补偿」比「就近舍入」好？
2. 为什么权重误差变大反而是对的？它的代价记在哪一栏？
3. 校准集数据进哪里？为什么需要一个 Hessian，为什么它要加 `dampening`？
4. Cholesky 在这件事里扮演什么角色？
5. `blocksize` 与 `group_size` 各是什么？`act-order` 从哪来，它真的有用吗？
6. ★ `dampening` 的默认值到底是 1% 还是 0.1？——**两个都是，看你读的是哪一份。**

## 1. 原理

### 第一步：把「量化」写成一个优化问题

逐层量化可以写成：给定权重 `W`、校准输入 `X`，找量化后的 `Ŵ` 使

```
argmin_Ŵ  ‖WX − ŴX‖²
```

注意 ① 是**层输出**的误差，不是权重的误差；② 对 `X` 的分布加权，所以校准集在这里进场。

把 `X` 的**二阶矩**写成 `H = (2/n)·XᵀX`（`n` 是校准样本数；判据：**含这个 `1/n` 因子**，换约定就换了一个量）。因为 `W` 的各列（输出通道）在 `H` 之下**相互独立**，问题可以逐列解：对第 `i` 列，

```
argmin_{w_q}  (w_i − w_q)ᵀ H (w_i − w_q)
```

**这是一个「在度量 `H` 下的最近点」问题。** 如果 `H = I`，解就是「最近舍入」——也就是 RTN。**`H` 的非对角元就是「某些输入通道一起出现」这件事，而 GPTQ 的全部收益都来自把它们用上。**

### 第二步：逐列量化的误差补偿（论文式 2/4/5）

GPTQ 按列（沿**输入维**）从左到右扫。设当前处理第 `q` 列，`H⁻¹` 已知，令 `w` 为这一列的（已被前面各列修正过的）值：

```
1.  w_q ← quant(w)          # 就近舍入到量化格点
2.  δ   ← (w − w_q) / [H⁻¹]_{qq}
3.  对还没处理的列 j > q：  W[:, j] ← W[:, j] − δ · [H⁻¹]_{q, j}
4.  记住这一列的结果 w_q
```

**第 3 步就是「补偿」**：这一列舍出去的误差没有丢掉，而是按 `H⁻¹` 的形状**分摊给还没量化的列**，让它们提前「让位」。最后一行（`j > q` 那一部分）走的是惰性批量更新，`blocksize` 决定一次算多少列。

第 2 步里的 `1/[H⁻¹]_{qq}` 是**这一列在 `H` 度量下的代价权重**：`[H⁻¹]_{qq}` 越小，这一列越重要（对输出的影响越大），补偿幅度就越大。论文把它写成 `ε_m = w_m² / [H⁻¹]_{mm}`——**误差按「该列的重要性」排序**。

> ⚠ **最常见的误引**：把 `[H⁻¹]_{qq}` 说成「Hessian 的对角元」。它是 **`H⁻¹` 的对角元**，两者差了整整一个逆矩阵。判据很简单：`H` 的对角元是 `(2/n)Σx²`，是个正数（量级 ~2）；`H⁻¹` 的对角元在 `H ≈ I` 时约等于 `1/2`。**用错会在小规模测试里看不出来（因为那时 `H ≈ I`），在真实模型上才炸。**

### 第三步：为什么权重误差变大是**对**的

回到 `argmin ‖(W − Ŵ)X‖²`。展开：

```
‖(W − Ŵ)X‖²  =  trace((W − Ŵ) H (W − Ŵ)ᵀ) · (n/2)
```

- RTN 最小化的是 **`‖W − Ŵ‖²`**（无度量），也就是那个「权重误差」。
- GPTQ 最小化的是 **`trace((W−Ŵ)H(W−Ŵ)ᵀ)`**（`H` 度量下）。

**两个目标不同，最优解就不同。** `H` 有非对角元（输入通道相关），于是 `H` 度量下的「近」与欧氏度量下的「近」不是一回事：GPTQ 会**故意**把某些权重舍到更远的格点上，以换取「在 `X` 实际出现的那些方向上」更小的和。

**这就是「用权重误差换输出误差」的准确含义**——不是 GPTQ「不精确」，是它优化的是另一个量。

### 第四步：`dampening` 与 Cholesky

`H⁻¹` 直接算有两个问题：

1. **`H` 可能奇异或不正定**。极端情形是校准集里有某个输入通道恒为 0（`diag(H)` 为 0），或两个通道完全共线（`H` 秩亏）。此时 `H⁻¹` 不存在。
2. **`H` 可能只是「接近奇异」**——**这比精确奇异更危险**。实测（本机）：`H = [[1, 1−ε], [1−ε, 1]]`、`ε = 1e-9` 时 Cholesky **顺利通过**，而 `H⁻¹` 的最大元素是 **5.000e+08**（真值 ≈ `1/(2ε)`）。**它会给你一个数，而那个数是垃圾。**

`dampening` 的做法是给对角加一个偏置：

```
H ← H + percdamp · mean(diag(H)) · I
```

论文的原话是「**we always choose 1% of the average diagonal value**」，即 `percdamp = 0.01`。

> ⚠ **这是 P8 的一处真岔口**：`dampening` 的默认值在**两份实现**里不一样——
> 论文与官方仓库（IST-DASLab/gptq `quant.py`）是 **`percdamp = .01`**；
> 而 **transformers 的 `GPTQConfig.damp_percent` 默认是 `0.1`（= 10%）**，
> 且它的 docstring 还写着 `"Recommended value is 0.1."`（本机装的 transformers 4.57.1，
> `transformers/utils/quantization_config.py` 第 715–717 行）。**引用时必须说清是哪一个。**
> 本机实测（同一设定、`gs=128`）：`percdamp` 从 0.0 涨到 0.5，输出 MSE 从 **5.540717e-2** 单调涨到 **8.561905e-2**——**dampening 是纯代价，它买的不是精度，是可解性与数值稳定。**

**Cholesky 的作用。** 论文指出：对大模型（> 几十亿参数）会在至少几层上让 `H` 变不定，原因是**反复施加的累积数值误差**；而「删行」这个操作对对称的 `H⁻¹` 等价于一次 Cholesky 分解，于是可以**直接用 Cholesky 核预计算全部所需行**，不必真的逐行删。

本机把它们分成了两条可分辨的路径（实测，同一份数据）：用 `cholesky(H⁻¹)` 的上三角 vs 直接用 `H⁻¹`，输出 MSE 是 **5.612819e-2 vs 5.719218e-2**，量化结果 `max|ΔW| = 3.159e-2`。**两者不是同一个算法**，不是一个恒等变换。

### 第五步：★ `blocksize` ≠ `group_size`，`act-order` 不在论文里

这三个词经常被混着用，它们其实是三件事：

| 名字 | 是什么 | 改变它会发生什么 |
|---|---|---|
| **`blocksize`** | **纯计算批处理**：一次惰性更新多少列 | **数学结果完全不变**（实测 `bs ∈ {8,16,32,64,256}` 的逐元素差 = **0.0**） |
| **`group_size`** | **量化粒度**：多少列共享一个 scale | 改的是量化本身（实测 `gs=128` 比 `gs=32` 差） |
| **`act-order`** | 列的**处理顺序**：按 `argsort(diag(H))` 降序 | 改结果，**但收益不稳定** |

**`blocksize` 与 `group_size` 的混淆有具体来源**：官方实现里它们是**两个独立的参数**（`blocksize=128, groupsize=-1, percdamp=.01, actorder=False`），而 **transformers 的 `GPTQConfig` 只暴露 `group_size`，`blocksize` 这个字段根本不存在**（本机 grep 确认）。于是只看 transformers 的人会把「128」当成一个东西——**它其实是两个不同参数各自的一个常见取值**。

**`act-order` 的处理顺序来自 `perm = argsort(diag(H), descending=True)`。** 准确的说法是「按校准集上该**输入通道**的**激活二阶矩**降序」：

```
H = (2/n)·Σ x xᵀ   ⇒   diag(H)_j = (2/n)·Σ_i x_{i,j}²   ∝  该通道的 Σx²
```

**不是「按激活大小」**（那是一阶量 `Σ|x|`），也不是「按权重重要性」。本机实测确认 `diag(H)[7] = 2.0 · mean(x²)`（差 < 1e-3）。

**★ 而 `act-order` 不在 GPTQ 论文里。** 它是**实现层特性**——论文全文检索没有这个词。它的收益**高度模型相关**：AWQ 论文 Table 4 里，INT3 g128 下 LLaMA-7B 从 **8.81 → 6.53**（收益巨大），而 Llama-2-7B 从 **6.43 → 6.42**（几乎无效）。

本机的合成实验给出的是**第三种答案**：同一实现、同一份数据，只换 `group_size`，`act-order` 的收益符号就翻了

| 配置 | 关闭 act-order | 打开 act-order | 变化 |
|---|---|---|---|
| `gs=128` | 5.612819e-2 | 5.877019e-2 | **−4.71%**（变差） |
| `gs=32` | 3.564161e-2 | 3.728726e-2 | **−4.62%**（变差） |
| `gs=-1`（per-column） | 7.320047e-2 | 7.231066e-2 | **+1.22%**（变好） |

**⇒「act-order 有效」不是一个可以断言的结论。** 能说的是：它是一个实现提供的可选顺序，收益随模型与配置变号。

## 2. 执行映射

### 2.1 三个组件名与一个数值量级

- **`torch.linalg.cholesky`** —— 论文说的「删行等价物」就是它（本仓库五个 torch 版本都有）；
- **`torch.linalg.cond`** —— 用来看 `H` 病到什么程度（实测本机合成问题的 `cond(H) = 1.149e5`）；
- **`torch.argsort`** —— `act-order` 的 `argsort(diag(H), descending=True)`；
- **量级**：校准集按论文是 **128 条 C4 片段 × 2048 token**，`block size B = 128` **列**。做一个 `512×512` 的矩阵逆是 `O(512³) ≈ 1.3e8` 次浮点运算——**这正是 GPTQ 能在几小时内跑完 175B 模型的原因：它不训练，只做一次逐层的线性代数。**

### 2.2 一次 `forward` 里发生了什么（权重侧）

GPTQ 是**离线**算法：量化完把 `Ŵ` 存下来，推理时走普通的 int4 GEMM。所以这里的「执行映射」是**离线那一次**：

```
for 每个 Linear 层:
    X ← 用校准集跑一遍，收集该层的输入        # ★ 这就是「校准集进场」的地方
    H ← (2/n) XᵀX                             # 逐层一个 512×512 的矩阵
    H ← H + percdamp·mean(diag(H))·I          # dampening
    Hinv ← cholesky_inverse(cholesky(H))       # 或再取一次上三角 Cholesky（论文的「删行」）
    for 每 128 列一块:                          # blocksize = 128（纯批处理）
        for 块内每一列: 量化 + 把误差按 Hinv 补偿到后面的列
```

**注意「逐层」这个词的分量**：`H` 是**每个 Linear 层各自的**，不是全局一个。这就是为什么 175B 模型要跑几个小时——**每一层都要收集输入、都要做一次矩阵分解**。

## 3. 实现与演进

**第一代：RTN。** 逐列最近舍入。简单、快，但完全不用校准信息。

**第二代：逐列补偿（GPTQ 本体）。** 引入 `H` 与 `H⁻¹`，把误差分摊。本机实测：输出误差降 **46.6%**。

**第三代：工程化。** 三处：
- **`blocksize` 惰性批量更新**——把 `O(C²)` 的逐列更新摊成块，`blocksize=128` 时省下大量小矩阵运算，**而数学结果一字不变**；
- **Cholesky 替代逐行删除**——见 §1 第四步；
- **`act-order`**——实现自己加的可选顺序。

**第四代：与其他技术组合。** GPTQ 是**权重-only**（W4A16 一类）的：它只解决「权重怎么量化得更好」。
> ⚠ **「GPTQ + AWQ + SmoothQuant 能叠加」这个说法没有论文支撑。** 能确证的只有一件：AWQ 论文把 **GPTQ-R 当作独立 baseline** 来比（AWQ Table 4），**不是**把它当组件组合。**不得写「机制正交所以能任意组合」。**

**效果（引用，harness = GPTQ 论文 Table 5，WikiText2）**：

| 配置 | OPT-175B |
|---|---|
| FP16 基线 | 8.34 |
| RTN 4-bit | 10.54 |
| **GPTQ 4-bit** | **8.37** |
| RTN 3-bit | 7.3e3 |
| **GPTQ 3-bit** | **8.68** |

**注意这张表里的两个数不是一个基线**：FP16 是 8.34，GPTQ 4-bit 是 8.37——**它们可以直接比，因为同表同协议**。但**不要把这张表的 8.34 与别的论文里 OPT-175B 的 FP16 数字并列**（§0.7.B 已发现两套基线不同的 Llama-2-7B PPL 表：5.12 与 5.47）。

## 4. 踩坑与失败模式

### 4.1 拿「权重误差」当判据，会给 GPTQ 判错

**现象**：跑完 GPTQ 一测 `mean((W − W_q)²)`，发现比 RTN 还差，于是以为实现有 bug。

**成因**：GPTQ 优化的目标里带一个 `H` 度量（§1 第三步），它与无度量的权重误差**不是同一个量**。本机实测两者方向相反：输出 MSE `1.3766e-1 → 7.3200e-2`（降 46.8%），权重 MSE `4.5301e-5 → 2.2520e-4`（升 397%）。

**规避**：**引用 GPTQ 的收益时必须写明判据是层输出还是权重。** 这两组数**不得并列**——它们不是「估算 vs 实测」，是**两个不同的量**（P9）。

### 4.2 把 `[H⁻¹]_{qq}` 写成 `[H]_{qq}`

**现象**：照着二手材料实现，小矩阵测试通过；换到真实模型上精度崩。

**成因**：`ε_m = w_m²/[H⁻¹]_{mm}` 里的下标是**逆矩阵**。在小规模合成数据上 `H ≈ I`，于是 `H` 与 `H⁻¹` 的对角元都 ≈ 常数，**写错看不出来**。

**规避**：写完之后量一下 `cond(H)`。本机合成问题是 `1.149e5`——**只有 `cond` 明显大于 1 时，这个错才会暴露**。测试里必须包含一个病态的 `H`（本程序的做法：让通道 1/2/3 与通道 0 强相关）。

### 4.3 `blocksize` 与 `group_size` 混用

**现象**：读 `group_size=128` 的文档，以为 128 也是「计算块大小」；或者反过来，以为 `blocksize` 影响精度。

**成因**：两个参数在官方实现里都存在、都常取 128，而 **transformers 的 `GPTQConfig` 只暴露 `group_size`**（`blocksize` 没有这个字段，本机 grep 确认）。

**规避**：记住判定方法——**改 `blocksize` 后逐元素结果完全不变**（本机实测 `bs ∈ {8,16,32,64,256}` 的 `max|ΔW| = 0.0`）。**任何「变了」的参数才是量化粒度参数。**

### 4.4 `dampening` 引用时不说是哪一份

**现象**：写「GPTQ 的 `dampening` 默认 0.1」或「默认 0.01」，都有人反对。

**成因**：**两个都是真的**——论文与官方仓库是 1%，transformers 是 0.1（差 10 倍）。

**规避**：引用时带出处。判据很清楚：**同一设定下 `percdamp=0.01` 的输出 MSE 是 5.612819e-2，`0.1` 是 6.701501e-2**——这不是同一个数。

### 4.5 以为 `act-order` 总是有用

**现象**：把 `act-order` 当成「GPTQ 的必备开关」，开了就更好。

**成因**：它的收益高度模型相关（§1 第五步）。在实现层它就是一个可选的处理顺序。

**规避**：引用收益时带上模型名。**本机合成实验里它的符号有三个方向**：`gs=128` 与 `gs=32` 下变差约 4.7%，`gs=-1` 下变好 1.22%。

### 4.6 以为 `H` 精确奇异才会出问题

**现象**：看到 `cond(H)` 有限、Cholesky 不抛异常，就放心了。

**成因**：**接近奇异比精确奇异更危险**——精确奇异至少会抛异常（`torch.linalg.cholesky` 抛 `_LinAlgError`），而接近奇异会**顺利通过并给出一个巨大的 `H⁻¹`**（本机：`ε=1e-9` 时 `max|H⁻¹| = 5.000e+08`）。

**规避**：`dampening` 不是「让它能跑」，是「让它给对」。

## 5. 实测数据

**测量条件**：Apple M1 Pro（10 核）/ macOS / **CPU-only，无 GPU 数字**；python 3.12.9；**torch 2.11.0**。五个解释器（2.6.0 / 2.7.1 / 2.8.0 / 2.11.0 / 2.13.0）都跑过，`2.9 / 2.10 / 2.12` 本机无解释器。数值逐条记在 `code/specs.py`。

**问题设定**（判据逐条写出，P9）：`torch.manual_seed(0)`；`W: [256, 512] ~ N(0,1)×0.05`；`X: [1024, 512] ~ N(0,1)`，**通道 1/2/3 = 0.98·通道 0 + N(0,0.2)**（造出病态 `H`），**通道 7 幅值 ×50**；`H = (2/n)XᵀX`（**含 `1/n`**）；4-bit 对称（可用整数范围 `[−8, 7]`）；`percdamp = 0.01`；`blocksize = 128`；`cond(H) = 1.149e5`。误差口径 = `mean((XWᵀ − XW_qᵀ)²)`。

### 5.1 RTN vs GPTQ：两个判据方向相反

| `group_size` | 输出 MSE（RTN → GPTQ） | 输出降幅 | 权重 MSE（RTN → GPTQ） | 权重升幅 |
|---|---|---|---|---|
| 128 | 1.0519e-1 → **5.6128e-2** | **46.6%** | 3.4273e-5 → 1.7147e-4 | +400.3% |
| 32 | 6.5618e-2 → **3.5642e-2** | **45.7%** | 2.3539e-5 → 1.0683e-4 | +353.8% |
| −1（per-column） | 1.3766e-1 → **7.3200e-2** | **46.8%** | 4.5301e-5 → 2.2520e-4 | +397.1% |

### 5.2 `blocksize` 是纯计算批处理（代价 0）

`blocksize ∈ {8, 16, 32, 64, 256}`、其余设定不变：**逐元素差 `max|ΔW| = 0.0`**（二进制相同）。而 `group_size` 从 128 换到 32 会**改变结果**。⇒ 两者是不同的东西。

### 5.3 `dampening` 是纯代价

| `percdamp` | 0.0 | 0.001 | **0.01**（论文/官方仓库默认） | 0.05 | **0.1**（transformers 默认） | 0.5 |
|---|---|---|---|---|---|---|
| 输出 MSE | 5.540717e-2 | 5.544126e-2 | 5.612819e-2 | 6.140117e-2 | 6.701501e-2 | 8.561905e-2 |

单调递增。**dampening 买到的是可解性与数值稳定，不是精度。**

### 5.4 `act-order` 的收益不稳定

| 配置 | 关闭 | 打开 | 变化 |
|---|---|---|---|
| `gs=128` | 5.612819e-2 | 5.877019e-2 | −4.71% |
| `gs=32` | 3.564161e-2 | 3.728726e-2 | −4.62% |
| `gs=-1` | 7.320047e-2 | 7.231066e-2 | **+1.22%** |

### 5.5 数值稳定性（本机实测）

| 场景 | 结果 |
|---|---|
| `H = [[1,1],[1,1]]`（精确奇异），`torch.linalg.cholesky` | 抛 `_LinAlgError` |
| 同上加 `percdamp = 0.01` | 分解成功 |
| `H = [[1,1−ε],[1−ε,1]]`，`ε = 1e-9` | Cholesky **成功**，`max|H⁻¹| = 5.000e+08`（真值 `1/(2ε)`） |
| `cholesky(H⁻¹)` 上三角 vs 直接 `H⁻¹` | 输出 MSE 5.612819e-2 vs 5.719218e-2；`max|ΔW| = 3.159e-2` |

### 5.6 库默认值（**引用值 + 本机源码核对**）

| 参数 | 论文 / 官方仓库 | transformers 4.57.1 |
|---|---|---|
| `blocksize` | 128 | —— **`GPTQConfig` 里没有这个字段** |
| `group_size`（`groupsize`） | **−1**（per-column） | **128** |
| `dampening` | **0.01**（1% of the average diagonal value） | **0.1**（docstring：`Recommended value is 0.1`） |
| `desc_act`（act-order） | `False` | `False` |
| 校准集 | 128 条 × 2048 token，C4 | —— |

transformers 一列的来源是**本机源码**（`transformers/utils/quantization_config.py` 第 715–717 行，逐字读过）；论文/官方仓库一列**属引用值**——本实现者直取到的 `quant.py`（7330 字节）**不含 `fasterquant`**，**未能逐字核到那组默认值**，按引用值处理。

## 6. 小结与延伸

- GPTQ 把「量化」写成一个**带 `H` 度量的最近点问题**，逐列解、把误差补偿给后面的列。
- 它换来的是**层输出**误差（本机 −46.6%），代价是**权重**误差变大（本机 +400%）。**两个判据方向相反，引用必须写明是哪一个。**
- `blocksize`（计算批处理，**不改数学结果**，实测逐元素差 0.0）与 `group_size`（量化粒度）是**两个参数**；transformers 只暴露后者。
- `dampening` 在论文（1%）与 transformers（0.1）之间**差 10 倍**；它是纯代价。
- **接近奇异的 `H` 比精确奇异更危险**：Cholesky 会过，`H⁻¹` 会给你 `1/ε` 量级的垃圾。
- `act-order` 不在论文里，收益高度模型相关；本机合成实验里它的符号随 `group_size` 变号。

**延伸**：`03-awq-and-smoothquant` 走的是另一条路——不逐列决策，而是**先把难量化的那一维放大**；`04-rounding` 则问「舍入一定要取最近吗」，并给出一个任务判据下的否定答案。
