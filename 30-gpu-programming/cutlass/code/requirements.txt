# 30-gpu-programming/cutlass 的第三方依赖
#
# ★ 只有一个：**numpy**。启用方式：`python3 -m pip install -r requirements.txt`
#
# ── numpy 在本主题里干什么（不是装饰，三个程序都在用）──────────────────────
#   · 01_layout_algebra.py  B 类的「地址空洞」统计用 **int64 数组**：
#       `np.array([cosize - size for ...], dtype=np.int64)` 一次算完整个 layout 池，
#       再 `arr.max()` 找最坏的那个。
#       ★ 选 int64 不是随便挑的：这些量是**小整数计数**，用浮点会给
#         「423」这种整数染上本不必要的近似口径（本程序用 `==` 直接断言）。
#   · 02_tiling_decompose.py  B 类的重名统计用 **numpy 的 `unique(..., return_counts=True)`**
#       复核本仓库自己用 `collections.Counter` 数出来的那两个数
#       （93 个不同的 `procedural_name()`、最多的一个出现 6 次）——
#       **两条不同的计数路径必须给出同一个答案**。
#   · 03_swizzle_probe.py  「非平凡比例」的闭式复核用 int64 数组：
#       `(np.array(...) != np.arange(size)).sum()` 与逐点循环**两条路径**比对。
#
# ── 本主题**明确不需要**的东西（写出来是为了让「没装」不等于「忘了写」）────────
#   · **不需要 torch / triton / numba / cuda-python** —— 一个都不 import。
#     `make lint` 用 `ast` 对这条做**机械检查**（含 `specs.py` / `meta_falsify.py` /
#     `mutate.py`，含 `import_module` 这类动态导入）；注释与 docstring 里出现这些词
#     不算违规。
#   · **不需要 GPU、不需要 CUDA 工具链、不需要 nsight / ncu** —— 本机是 Apple M1 Pro，
#     无 GPU、无 nvcc / cuobjdump / nvdisasm / ptxas / ncu。
#     ★ **本目录不写 `.cu`**：没有 `ptxas` 就连语法都无法验证。
#   · **不需要网络** —— 本主题**没有** `make anchors` 之类的联网目标：
#     真值是**本机的一棵 CUTLASS 源码树**，全程离线。
#   · ★★ **不要照抄 `cutlass/pyproject.toml` 的 `dependencies`（6 条）。**
#     它列出了 `cuda-python` / `networkx` / `numpy` / `pydot` / `scipy` / `treelib`，
#     而其中 **networkx / pydot / treelib / cuda-python 本机都没装**，
#     本主题用到的两个子包（`pycute` / `cutlass_library`）**依然全部导入成功** ——
#     说明那些依赖是**懒加载**的，只有生成器的 CLI 路径才需要。
#     ⇒ 本文件只写**实测需要**的那一条。（计划 §0.7 C2 已核实这一点。）
