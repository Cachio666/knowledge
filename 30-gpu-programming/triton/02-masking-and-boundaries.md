# 边界掩码：越界检测抓不到的那一半

> **掩码写错有两个方向。写宽会被越界检测抓住；写窄——既不越界、也不报错，只是静默地把数据算成 `other`。** 本篇用 `N = 1000`、`BLOCK = 256`（最后一个块有 **24** 个位置越界）把这个不对称性算到逐位，并给出四条带数字的结论：
>
> 1. ★★ **越界检测只覆盖一半的失效模式。** 掩码**写宽**（把 1024 个位置全当有效）⇒ 越界访问被检出 ⇒ 抛 `OutOfBoundsError`；掩码**写窄**（拿块长度当上界）⇒ **既不越界也不报错**，误差从 **2.384e-07** 涨到 **4.499e+00**。**唯一能抓住它的是 A 类逐元素比对**（`code/02_masking.py` 的 `C.5`/`C.6`）。
> 2. ★★ **`other=None` 的官方语义是「未定义」，不是 0。** 不给 `other` 时，24 个越界位置的毒值**真的一路流进归约结果**：`max` 从 **149.75** 变成 **1.000000e+30**（`C.3`）。官方原文逐字引出（§2.1）——这是本主题**最容易误读的一句**。
> 3. ★ **五种掩码写法在 1024 个位置上逐位一致**（5120 次比较、不一致 **0** 次）：`offs < N`、`offs <= N-1`、`N > offs`、`offs - N < 0`、以及「把 `pid*BLOCK` 展开写」——它们**在一个具体形状上的等价**不等于**在所有形状上的等价**，所以程序另做了一次 **60 个 `(N, BLOCK)` 组合 / 25600 个位置**的扫掠（不一致 **0**，其中 **5655** 个是越界位置）。
> 4. ★ **`masked load` 的那三处零误差是有意义的**：读回来的就是源里**同一个 f32**，没有任何算术参与——**0 是应该的，非 0 就说明模型错了**（`A.6` 用**位模式**相等而不是「误差足够小」来钉这一条）。
>
> ★ **★ 本篇的「反直觉量化结论」**：**越界检测抓不到「掩码写窄」**——写宽 ⇒ 抛 `OutOfBoundsError`；写窄 ⇒ **既不越界也不报错**，只是静默把数据算成 `other`（误差从 **2.384e-07** 涨到 **4.499e+00**）。**唯一能抓住它的是 A 类逐元素比对。**
>
> ★ 本主题的 **B 类全部是模型值，本机无 GPU，一条实测都没有**；A 类是**本仓库程序在本机跑出的解释器结果**（测的是本模型，不是真实 Triton）。
> ★ **自造真值的对策**是元检验（`make falsify`）：注入 D1（掩码被忽略）后，本篇的 `A.2` **必须**失败——本机跑出的结果正是如此。

> ★ **本主题的三条限定语，在本篇的落点**（域 README 规定逐篇写明，不得省略）：
> 1. **「本模型的规则是自造的」**——本篇涉及的摊维规则、属主算法、三相 ops 计数都是**本模型自定**的（`code/specs.py` 的 `MODEL_OWN_RULES`，共 5 条），**不声称是 Triton 的规定**。
> 2. **「本主题无实测，只有模型值」**——B 类（越界位置数、谓词数、占比）是**本模型按位置逐个记账**算出来的，不是硬件读数。
> 3. **「不是硬件，也不是 Triton 编译器」**——本程序**不执行任何 GPU 代码**。★ 尤其：**「掩码为真却越界就抛错」是本模型的一处加强**（`specs.MODEL_SIMPLIFICATIONS["S2"]`），真实 GPU 上那是一次**未定义行为**。加强让「忘了加掩码」可证伪，但**不能反过来读成「真实系统也这样」**。
> 4. ★ **一处已记录的简化**：本模型要求 `spt×tpw×wpc == shape`（精确切分），真实 Triton 允许覆盖不足。

## 0. 背景与动机

### 0.1 一个具体的对照场景：`N = 1000`，`BLOCK = 256`

块级程序里最普通的分块写法是：`grid = ceil(N / BLOCK)`，每个 program 处理 `BLOCK` 个位置。取 `N = 1000`、`BLOCK = 256`：

```text
总位置数 = 4 × 256 = 1024；有效 = 1000；越界 = 24
越界位置的分布：pid 0/1/2 → 0 个；pid 3 → 24 个（全局下标 1000..1023）
```

**24 个位置**看起来微不足道（**2.3438%**），但它们是这个主题的全部难点：

- 如果不加掩码，这 24 个位置会读到数组之外——**本模型把这件事变成可证伪的异常**（`C.1`）。
- 如果掩码**写宽**（`offs < 1024`），它们会被当成有效 ⇒ **抛错**（`C.2`）。
- 如果掩码**写窄**（`offs < 256`），它们**连同 768 个有效位置一起**被掩掉 ⇒ **一个信号都没有**（`C.5`）。

**场景**：把最后那 24 个位置的处理写成 `offs < BLOCK`（本意可能是「块内偏移」）而不是 `offs < N`。程序照常跑完、照常退出 0，**输出里的 768 个位置变成了 `other`**——与源的最大偏差 **1.498e+02**，和源的值域 `[-100.0, 149.8]` **同阶**。

### 0.2 本篇覆盖什么、不覆盖什么

| 覆盖 | 落点 |
|---|---|
| 五种掩码写法的逐位等价性（含扫掠） | `A.1`、`A.12` |
| `masked load` 的取值与**两条**独立参照逐元素比对（零误差的意义） | `A.2`–`A.6` |
| 越界位置对 `max` / `sum` 的贡献（`-inf` / `0`） | `A.8`、`A.9` |
| 全行 softmax 在非整除形状上的 32000 个输出位置 | `A.10`、`A.11` |
| `other` 的官方语义（**「未定义」不是 0**）与隐式广播 | `C.3`、`C.8`、`C.9` |
| 写窄 / 写宽 / 不给掩码 三种失败行为的**不对称** | `C.1`、`C.2`、`C.5`、`C.6` |
| 掩码的记账口径（每元素一个谓词） | `B.1`–`B.4` |

**不覆盖**：真实硬件上越界访问会发生什么（**本仓库不主张**——本机无 GPU，那是一次未定义行为）；共享内存 bank 冲突（回链 `20-gpu-architecture/memory-system/03-shared-memory-bank-conflict`）；`softmax` 本身的数值稳定性推导（回链 `40-kernels/softmax-normalization/01-softmax-stability` 与 `10-foundations/floating-point/03-summation-and-accumulation`）。

### 0.3 本篇在本域主线上的位置

主线是「**你写的程序、编译器生成的东西、硬件执行的东西，是三个不同的程序**」。上一篇（`01-block-program-model`）讲「块内元素归谁」这件**你没说**的事；本篇讲另一半**你没说**的事：

> **边界怎么处理**——而这正是「掩码」这个词承诺要替你解决的问题。

## 1. 原理

### 1.1 掩码是一个**谓词张量**，不是一个函数

`tl.load(ptr, mask=..., other=...)` 里的 `mask` 是一个**与指针同形状的布尔张量**，逐元素决定「这次访存做不做」。它没有「跳过这一块」这种块级语义——**块级程序里没有块级控制流的细粒度版本**，掩码就是全部。

本模型里，一条掩码读做的三件事（`code/minitriton.py` 的 `load`）：

```text
m    = broadcast(mask, shape)                 # 掩码逐元素广播到指针形状
bad  = 掩码为真却越界的位置数                   # 记账：oob_allowed
vals = 越界位置指向毒区首元素、其余读真实内容     # 越界索引被**显式接住**
return where(m, vals, fill)                   # fill = other，或（other=None 时）毒值
```

**每次 `load` 都会记账**：`oob_allowed`（掩码为**真**却越界——真 bug）、`oob_masked`（掩码为**假**而越界——合法）、`other_undefined`（`other=None` 且掩码不全为真）。

**为什么要有「毒区」**：越界位置不是「随便读点什么」——本模型给每个缓冲区尾挂一段**毒值**（`POISON = 1.0e30`，一个任何正常计算都产生不出的 f32）。于是「越界的内容漏进了输出」可以被一条断言判出来：**输出里出现 ≥ 1e29 的值，就是毒值**（`A.7`）。

★ **`other` 的隐式广播是官方明写的**：`C.8` 断言形状 `(1,)` 的 `other` 能广播到 `(256,)` 的掩码；`C.9` 断言形状不相容的 `other`（`(3,)` vs `(256,)`）**由广播规则抛错**，不静默截断。★ 同时如实记录本模型的一处缺口：`other` **不接受 `Tile`**（真实 Triton 的 `other` 是 Block）。

### 1.2 ★ 多步推导：为什么 `other` 该取什么是**由归约算子决定的**

越界位置必须对结果**没有贡献**——但「没有贡献」对不同的归约算子意味着**不同的值**。设被归约的块内张量是 `x`（长度 `BLOCK`），其中 `k` 个位置越界。要让最终结果**精确等于**「只在有效元素上算」，`other` 必须满足：

**第一步（`max` 的幺元）**。`max` 的幺元是 `−∞`：`max(x, −∞) = x` 对一切 `x` 成立。⇒ `other = −inf` 时

```text
max(有效元素 ∪ {−∞} × k)  =  max(有效元素)
```

本模型里这是**精确相等**，不是近似：`A.8` 断言 `max 本模型 = 149.750000` **恰等于**独立算出的 `149.750000`。★ 这也是「`max` 归约的初值不是 0」的同一件事的另一面（`cuda` 主题的 `01` 篇有一对成对文件，那里少了 `−∞`、多了 `0`，全负数输入就返回 `0.0f`）。

**第二步（`sum` 的幺元 + 一个浮点补充）**。`sum` 的幺元是 `0`，但 `−inf` 不能用：`sum` 里出现 `−inf` 会把结果变成 `−inf`。所以**同一个掩码、不同的 `other`**：

| 归约 | `other` | 理由 |
|---|---|---|
| `max` / `min` | `∓inf` | 幺元 |
| `sum`（以及任何在线递推的指数和） | `0` | 幺元；且 `exp(−inf) = 0`，对在线 softmax 用 `−inf` 也**恰好**等于 0 |

**第三步（唯一不精确的那一步，容差按机器 epsilon 推）**。`sum` 的 `other = 0` 带来的是「多加了 `k` 个 0」——**这不引入误差**（`x + 0 = x` 精确）。真正的误差来源是**重结合**：有效元素是 `n = N − 3·BLOCK = 232` 项，f32 上求和的相对误差上界取

```text
n × 2⁻²³ × 64  =  232 × 1.192e-07 × 64  =  1.770e-03
```

（`2⁻²³` 是 f32 的机器 epsilon；`64` 是一个**保守的**重结合松弛因子，写在 `refs.rel_err_bound` 里。）**本仓库程序在本机跑出的**相对误差 **2.354e-08**（测的是本模型），比上界小近五个数量级（`A.9`）。★ **容差是推出来的，不是拍脑袋的**——`04-reduction-cost` 的 `C.5` 会把这个容差**两侧都验一遍**（把上界收紧到实测误差的一半，判据立刻失败）。

### 1.3 五种掩码写法的等价性：为什么要在**两个尺度**上验

五种写法（`VARIANTS`）：`offs < N`、`offs <= N - 1`、`(pid*BLOCK + arange) < N`、`N > offs`、`offs - N < 0`。

**单形状上的一致性**（`A.1`）：`4 × 256 = 1024` 个位置 × 5 种写法 = **5120 次比较，不一致 0 次**——与**纯 Python 的逐位置判断**（`0 <= i < N`）比，不是两两互比。

**多形状上的扫掠**（`A.12`）：`12` 个 `N`（含 `1 / 31 / 32 / 33 / 255 / 256 / 257 / 511 / 512 / 1000 / 1001` 这些**紧贴边界**的值）× `5` 个 `BLOCK` = **60 个组合**，逐位置比对掩码**与取值**，共 **25600 个位置**、其中 **5655 个**是越界位置，不一致 **0**。

★ 为什么两个尺度都要：**单形状上的等价可能是巧合**（比如 `N` 恰好是 `BLOCK` 的整数倍时，`offs < N` 与 `offs <= N-1` 在整型上恒等而无需掩码起作用）。`12 × 5` 的组合里包含 `N = 1`、`N = 1001`（比 `BLOCK` 大 1）、`N = 255`（比 `BLOCK` 小 1）这些**故意贴在边上的**值。

## 2. 执行映射

### 2.1 ★ 官方语义：`other=None` 是「未定义」，**不是 0**

这是本主题**最容易误读的一句**。`tl.load` 的 API 页（`https://triton-lang.org/main/python-api/generated/triton.language.load.html`）逐字：

> 「mask (Block of `triton.int1`, optional) – if `mask[idx]` is false, **do not load the data at address `pointer[idx]`**」
> 「other (Block, optional) – if `mask[idx]` is false, return `other[idx]`. **If `other` is None, the masked-out value is undefined.**」

这两句各自钉住一件不同的事（完整引文与 `covered_by` 见 `code/specs.py` 的 `LOAD_QUOTES`）：

| 锚点 | 它说的是什么 | 本篇的可证伪形式 |
|---|---|---|
| `L1` | `other=None` ⇒ **未定义** | `C.3`：不给 `other` 时 24 个位置的毒值**流进结果**（`max` 从 149.75 变 1.000000e+30） |
| `L2` | 掩码为假 ⇒ **不读那个地址** | `B.2`：掩码把 **24 次访存**从「读」降级成「取常量」 |

**★ 本模型必须给「未定义」一个具体的坏值**（`POISON = 1.0e30`）——否则它**没法被断言**。这一步是**本模型自定的**（`specs.MODEL_SIMPLIFICATIONS["S3"]`），官方只说「未定义」。

**★ `L2` 的作用域也要写清**（P7）：它说的是**不做这次访存**，**没有**说「掩码全真时越界会被检出」——后者是本模型的**加强**（`S2`），不是官方语义。

### 2.2 参与的部件与量级

| 量 | 值（`N=1000`、`BLOCK=256`） |
|---|---|
| 总位置数 | `4 × 256 = 1024` |
| 有效位置 | **1000** |
| 越界位置 | **24**（占比 **2.3438%**） |
| 最后一个块的有效位置 | **232**（不是 256） |
| 掩码谓词求值次数 | **1024** = 每元素一个 |
| 被掩码省掉的访存 | **24** |
| 毒值 | `1.000e+30`（`np.float32(1.0e30)`） |
| 输出里出现的最大值 | `1.498e+02`（= 源的最大值，**无毒值泄漏**） |

**参与的部件**：谓词化访存（predicated load）、掩码的逐元素广播（`np.broadcast_to` 等价物）、以及归约算子的**幺元**（§1.2）。在真实硬件上，掩码为假时那 24 次访存**根本不发出去**——这正是锚点 `L2` 的字面意思。

**★ 这里必须克制**：`1024` 个谓词 vs `24` 次省掉的访存是 **42.67 倍**的关系，但**本仓库不主张**「掩码有 42 倍开销」——谓词求值的实际代价、以及它是否被融进地址计算，本机一个都没测（无 GPU）。

### 2.3 为什么「写窄」在结构上不可检出

| 失效方向 | 越界访问发生吗 | 模型里抛错吗 | 输出错吗 |
|---|---|---|---|
| 忘了掩码（`mask=None`） | **发生** | **抛** `OutOfBoundsError` | 会错（但先抛了） |
| 掩码**写宽**（`offs < 1024`） | **发生** | **抛** | 会错（但先抛了） |
| 掩码**写窄**（`offs < 256`） | **不发生** | **不抛** | **静默错** |
| 掩码写对 | 不发生 | 不抛 | 对 |

**根因**：越界检测的判据是「**掩码为真却越界**」。写窄让**更多**位置落进 `mask=False`，于是**越界检测的输入变少了**——它**只会更安静**。⇒ **这一整类错误对越界检测是「不可见」的，不是「难检」，是判据的方向不对。**

## 3. 实现与演进

### 3.1 三处零误差：为什么「0」在这里是有意义的证据

`A.2` / `A.3` 断言 `masked load` 的 1024 个取值与**两条**独立参照的最大绝对误差**恰为 0.000e+00**：

| 参照 | 代码路径 |
|---|---|
| `refs.masked_block_ref` | **纯 Python 标量循环** + 显式 `if` 判断 |
| `refs.masked_index_np_ref` | **numpy 花式索引 + `np.clip`** |

★ **这个 0 与「容差内相等」是两件事**。掩码读回的就是源里**同一个 f32**——没有任何算术参与、没有任何重结合的可能。⇒ **0 是应该的；非 0 就说明模型错了**（模型多算了一步，或索引算错了）。`A.6` 把这条钉死：它比较的是**位模式**（`np.float32(got).view(np.int32) == src.view(np.int32)`），而不是数值差——**1024 个位置里 1000 个有效位置的位模式必须逐位相同**。

★ 与之对照：`A.9` 的 `sum` 只有「在 epsilon 上界内」的精度（本机跑出 2.354e-08）——因为那一步**真的发生了加法**。**两类断言的强度不同，写成同一种（都用容差）会把前者白白弱化。**

### 3.2 三次迭代

| 版本 | 做法 | 被什么逼着改 |
|---|---|---|
| v1（探针） | `N=1000` 单形状、95 个位置逐位比 | 样本太窄：`N` 是 256 的倍数 ±24，**没有任何一个 `N` 是 `BLOCK` 的整数倍** |
| v2 | 补上 5 种写法 + 3 条参照 | 断言里**没有**「写窄」这一支——只有「写宽会被抓住」，于是**最危险的失效模式没有任何断言** |
| v3（本篇） | 加 `C.5`/`C.6`（写窄 ⇒ **不抛错**且**偏差同阶**）、60 组合扫掠、位模式比对 | 「零误差」的**意义**没有被写下来——`A.2` 原本只说「误差很小」，改成**恰为 0** 并把理由写进正文 |

### 3.3 演进：从「检查掩码」到「让掩码不必存在」

1. **写对掩码**（本篇的程序）——判据是 A 类逐元素比对。它覆盖写窄、写宽、写错 `other` 全部三支，**代价是必须有一条独立参照**。
2. **让越界不可能发生**——把最后一维补齐到 `BLOCK` 的整数倍（padding），或用 `N` 的整数倍形状。代价是**额外的内存与带宽**，收益是**整类错误在结构上消失**。
3. **把边界移出内核**——`40-kernels` 里那些 `.cu` 的做法是 grid-stride + 守卫；在块级语言里对应「让块形状整除形状」。**这不是同一件事**：块级程序没有 per-thread 守卫，**边界只能靠掩码**。

## 4. 踩坑与失败模式

### 4.1 ★★ 掩码写窄：越界检测抓不到的那一半

- **现象**：把最后一块的掩码写成 `offs < BLOCK`（块长度）而不是 `offs < N`。程序**正常跑完、退出 0**，768 个位置被静默算成 `other`，与源的**最大偏差 1.498e+02**——与源的值域 `[-100.0, 149.8]` **同阶**。
- **成因**：越界检测的判据是「掩码为真却越界」。写窄让更多位置落进 `mask=False` ⇒ **越界检测的输入变少** ⇒ 它只会更安静。这不是「难检」，是**判据的方向不对**（§2.3 的表）。
- **规避**：**必须有 A 类逐元素比对**，而且参照必须走**独立代码路径**（`refs.py` 的纯 Python 标量循环 / numpy 花式索引），**不能**用被测代码自己的输出当参照。★ 程序里为此做了两处**可证伪性自检**：`C.7` 把 `refs.masked_block_ref` 的边界判据从 `i < n` 改成 `i <= n`，参照输出**逐位改变**、`A.2` 的 0 误差判据立刻失配。
- **为什么它值得单列**：**能暴露缺陷的必须是静默缺陷。** 抛异常的那一半（写宽）任何一个「跑一遍试试」的人都会碰到；不抛的那一半会一路进生产。

### 4.2 把 `other=None` 读成「默认 0」

- **现象**：以为不给 `other` 就等于 `other = 0`，于是归约结果「看起来合理」。
- **成因**：官方原文说的是 **undefined**（§2.1 逐字）。本模型把它具体化为毒值，于是 24 个越界位置的值**一路流进归约结果**：`max` 从 **149.75** 变成 **1.000000e+30**（`C.3`）。★ 如果模型把 `None` 读成 0，这里会**恰好**得到 149.75——**看起来完全正确**。
- **规避**：**任何掩码读都必须显式给 `other`**，并按归约算子选值（`max → −inf`、`sum → 0`，§1.2 的表）。★ 这条规矩的强度来自「未定义」这个词——**不是「大概是 0」**。
- **为什么它藏得住**：毒值是**模型**的选择（`S3`）。真实硬件上「未定义」的表现可能是**上一次访存的残留**——那比毒值**更难发现**，因为它常常「看起来像个合理的数」。

### 4.3 `max` 用 0 当 `other`，或 `sum` 用 `−inf` 当 `other`

- **现象**：全负数输入上的 `max` 返回 `0`；或 `sum` 返回 `−inf`。
- **成因**：**幺元与算子不匹配**（§1.2 第一步）。`0` 是 `+` 的幺元，`−∞` 是 `max` 的。
- **规避**：把「`other` 的取值」和「归约算子」**绑在一起读**，不要单独看掩码那一行。

### 4.4 用「误差很小」代替「恰为 0」

- **现象**：`masked load` 的比对写成「误差 ≤ 1e-6」。写窄的偏差是 **1.498e+02**，当然也被抓住——但**索引算错一个位置**这种更小的错误会被容差吃掉。
- **成因**：**掩码读回的就是源里同一个 f32**，没有任何算术参与 ⇒ 误差**应该恰好是 0**。给它一个容差，等于**主动放弃**这条判据的强度。
- **规避**：`A.2`/`A.3` 用 `== 0.0`，`A.6` 用**位模式**相等。**容差只给真的发生加法的地方**（`A.9`）。

### 4.5 ★ 那个「别处」在哪里

本域主线说：**抽象层的价值与它的泄漏是同一件事的两面**。那么这一篇里，代价被藏到了哪里？

> **被藏进了「安全网」这个词里。**
>
> 掩码 + 越界检测合起来给人一个印象：**「越界这件事我检查过了」**。`OutOfBoundsError` 是一条**很响**的信号——它确实抓住了「忘了加掩码」和「掩码写宽」这两类。问题在于，**这两类恰恰是更容易被别的办法发现的两类**（程序会崩、会给出离谱的数）。
>
> 而**写窄这一类一个信号都没有**——它不在越界检测的作用域里（§2.3）。于是「我检查过了」这句话的**实际覆盖面**比它听起来小一半，**而那一半正好是没有其它信号的**。
>
> **这就是那个「别处」：代价被转移到了一个不在任何检查器视野里的地方——「有 A 类逐元素比对」这件事上。** 这条边界能不能守住，取决于你的参照是不是**真的独立**（`refs.py` 与解释器、numpy 是三条代码路径），而不是取决于你有没有加 `try/except`。

## 5. 判据表

> ★ 按本域约定（域 README），§5 的位置与编号保留，内容**不是实测数据**而是**判据表**。
> ★★ **本主题无实测，只有模型值**——本机**无 GPU**、`triton` 包**全机器不存在**。
> 下表的每一行都是「**可机械判定的条件 → 结论**」；带数字的结论是**本模型算出来的**。

| # | 可机械判定的条件 | 结论 |

## 6. 小结与延伸

- ★★ **越界检测只覆盖一半的失效模式。** 写宽 ⇒ 抛错；**写窄 ⇒ 一个信号都没有**，偏差 **1.498e+02**（与源值域同阶）。**唯一能抓住它的是 A 类逐元素比对**，而这条判据的有效性**完全取决于参照是否独立**。
- ★★ **`other=None` 的官方语义是「未定义」，不是 0。** 不给 `other` 时 24 个越界位置的毒值**流进结果**：`max` 从 149.75 变成 **1.000000e+30**。★ 若把 `None` 读成 0，结果会**恰好**是 149.75——**看起来完全正确**。
- ★★ **`other` 该取什么由归约算子决定**：`max → −inf`、`sum → 0`。`A.8` 的 `max` 是**精确相等**（`-inf` 不参与取最大），`A.9` 的 `sum` 才是「在 epsilon 上界内」。
- ★ **「零误差」在这里是有意义的证据**：掩码读回的是源里**同一个 f32**（1000 个有效位置的位模式逐位相同）——**0 是应该的，非 0 就说明模型错了**。容差只给真的发生加法的地方。
- ★ **五种掩码写法在 1024 个位置上逐位一致**（5120 次比较、不一致 0），并在 **60 个 `(N, BLOCK)` 组合 / 25600 个位置**上复验（不一致 0，其中 5655 个越界位置）。
- ★ **元检验对本篇的意义**：注入 **D1（掩码被忽略）** 后，`A.2` **必须**失败——**本机跑出的结果正是如此**（`make falsify` 的基线全过、五个缺陷全部被抓住）。⇒ 「我用自己写的模型证明了掩码有用」这个质疑，被这条反证回答了。
- ★ **本模型的两处加强/简化必须一起读**：越界抛错是**加强**（真实 GPU 是未定义行为，`S2`）；毒值是**本模型的选择**（官方只说「未定义」，`S3`）。二者都让判据可证伪，**都不能反过来读成真实系统的行为**。

**延伸**：

- 块内元素归谁管、以及三相归约的相位：`30-gpu-programming/triton/01-block-program-model`。
- layout 转换的代价与那个「离得很远的关键字参数」：`30-gpu-programming/triton/03-layout-and-leaks`。
- softmax 的数值稳定性推导（本篇只讲掩码与幺元）：`40-kernels/softmax-normalization/01-softmax-stability`。
- 浮点求和的误差模型（`n × eps` 这条上界的来源）：`10-foundations/floating-point/03-summation-and-accumulation`。
- 「先有独立参照再谈验证」的方法论：`45-kernel-lifecycle/implementation/02-verification-matrix`。
