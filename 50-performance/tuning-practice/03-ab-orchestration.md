# A/B 的实验编排：两个配置比较时，两个时间段不可比

> **A 与 B 逐字等价（真实差异严格为 0）时，顺序编排（先跑完 A 再跑完 B）
> 在本机给出的 |差| 均值是交错的 10 倍以上；交错把它压到 0.1% 以下。**
> **★ 而且两条【否定】结论同样重要：那个效应不是「周期性干扰」造成的，
> 也不是「前 k 次冷启动」——** 预热之后它仍在。**

### 0.3 一个具体的对照场景

**A 与 B 的源码逐字相同**（`s = 0; for i in range(5000): s += i`），
**真实差异严格为 0**。每组测 2000 次取中位，每种编排重复 8 轮：

| 编排 | 8 轮的「B 相对 A」 | \|差\| 均值 | 轮间极差 |
|---|---|---|---|
| **顺序**（先跑完 A，再跑完 B） | +0.099 / −1.648 / −1.676 / −0.449 / **+3.289** / +0.622 / +0.065 / +0.360 % | **1.0262%** | **4.9652%** |
| **交错**（A/B 交替，且 ABBA） | −0.065 / 0.000 / −0.395 / −0.065 / +0.134 / −0.131 / 0.000 / 0.000 % | **0.0989%** | 0.5294% |

**真实差异是 0，而顺序编排在 8 轮里给出过 +3.289% 的「改进」。**
两个编排用的是**同一份代码、同一台机器、同一个时段**。

> ★ **限定语（本篇强制）**：本篇所有数字都是**本仓库在本机
> （Apple M1 Pro / macOS / `python3 3.13.5` / `numpy 2.4.4`）跑出的**，
> **是 CPU 上的测量，不是 GPU、不是 Nsight Compute**。

## 1. 原理

### 1.1 重尾噪声下，均值失效、中位数仍然活着

`A` 段实测（6 万个样本，见 §3.1）：`max/中位 = 596.1`，而 **`p90` 只比中位高 1.83%**。

**推导**：设一批样本里有一个量级为 `M` 的尖峰、其余都在 `m` 附近。
- 它对**均值**的贡献是 `M/n`。`M = 596 m`、`n = 60000` 时，这一项就是 `m` 的 **1%**；
  有几个这样的尖峰，均值就被抬走几个百分点。
- 它对**中位数**的贡献是 **0** —— 除非尖峰的个数超过一半。

**⇒ 一个样本就能把均值挪走 1%，而永远挪不动中位数。**
本机实测的直接形态：**均值比 `p90` 还大 1.1449 倍**（§3.1 的 `A.4`）。

### 1.2 交错为什么能消除「时间段的系统差异」

**顺序编排下**，A 与 B **各自占据一个连续的时间段**：

```
时间 ──────────────────────────────────────────▶
       [   A 的 2000 次  ][   B 的 2000 次  ]
        时段 1（系统状态 S1）  时段 2（系统状态 S2）
```

于是「B 相对 A」这个量里混进了 **`S2 − S1`（时段差）**，而**它与 A、B 本身无关**。

**交错编排下**，A 与 B 的点**穿插在同一个时间窗口里**：

```
时间 ──────────────────────────────────────────▶
       A B B A A B B A …（ABBA：两种先后都出现）
       └────── 两者面对同一批系统状态 ──────┘
```

**⇒ 时段差被摊平到两个组上**，做差时大体抵消。

**★ 一处必须写清的口径**：这里交替的不只是「轮流出现」，
而是**「两种先后都要出现」（ABBA）**。实施者实测：
若永远「先 A 后 B」，**交错编排自己会留下一个残余的顺序效应** ——
交错 |差| 均值从 **0.02% 涨到 0.186%**，`B.1` 的比值从 **20 掉到 3.6**。
**⇒ 「交替」= 让先后对称，不是「轮流」。**

### 1.3 交错为什么**不能**消除「时间无关的噪声」

交错消掉的是**两个组之间的系统性差**。它对**同一时刻**落在哪个组上的噪声无能为力：

设噪声 `ε(t)` 在时间上**平稳且与分组无关**，那么交错后每个组的样本仍然是 `ε` 的同分布抽样 ——
**A 与 B 的差里仍然有 `ε` 的方差**。交错**不改变**这一项。

**⇒ 交错有没有用，取决于干扰是「时间相关」还是「时间无关」。** 这就是 §5 判据表的那两行。
本机实测（§3.1）：尖峰在**时间上近似均匀**（三等分计数 **1087 / 914 / 907**，最大/最小 **1.20**）
—— 所以 §3.3 的 `B.5` 用**构造的周期干扰**去检验它，结果是**造不出效应**。

## 2. 执行映射

| 组件 | 它在这里的角色 | 数值量级 |
|---|---|---|
| **操作系统的调度器** | 它是「时段差」的物理来源：CPU 频率、别进程的占用、缓存状态、内存带宽都随时间变 | 顺序 vs 交错：**\|差\| 均值 1.0262% vs 0.0989%** |
| **中位数（`statistics.median`）** | 它是本程序用的**统计量**。选它而不是均值，正是因为本机噪声是重尾的 | `max/中位 = **596.1**`，而 `p90/中位 = 1.0183` |
| **`ABBA` 交替** | 它让「同一对里先测哪个」的效应在两个方向上各出现一半 | 不做 ABBA：交错 \|差\| 均值 **0.186%**；做 ABBA：**0.021%–0.099%** |
| **`threading` 的周期干扰** | 它是**被否掉的那一项**：每 100 ms 忙 20 ms，用来检验「时段差是不是它造的」 | 干扰下交错 \|差\| 均值 **0.0209%**（无干扰时 0.0989%） |

## 3. 实现与演进

**朴素：`t_A = 跑完 A；t_B = 跑完 B；报 (t_B−t_A)/t_A`。**
它**能跑**，而且**特别容易给出一个像样的结论** —— 本机实测它在真实差异为 0 时给出过 **+3.289%**。

**第一步：把「一组测几次、取哪个统计量」显式化。**
**为什么需要下一步**：统计量选对了只是让**每一轮**更准，**不改变时段差**。

**第二步：把「两组的点交替跑」加进来。** 这就是 §3.3 的交错。
**为什么需要下一步**：交替本身还不够 —— 见 §1.2 的 ABBA。
**为什么还需要一步**：有了交错，你还需要知道**它到底值不值得**、
以及**它是不是在治一个不存在的病**（§3.1 的尖峰分布是否时间相关）。

**第三步：把「交错治的是什么」实测出来。** 这就是 §3.3 的 `B.4`（预热）与 `B.5`（周期干扰）
——**两条【否定】结论和正面结论同等重要**。

### 3.1 本机实测：噪声的形状（`A` 段）

★ **A 段自己拉起 `cpu_count()-1 = 9` 个忙进程**：实施者实测，
**在闲机上 `max/中位` 只有 4–23**（阈值 100 直接失败）——
那时这条判据测的是「这台机器当时忙不忙」，不是「噪声的形状」。
**判据必须把自变量握在自己手里。**

同一份固定工作量（900 次乘法加法）重复 **60000 次**：

| 统计量 | 本机实测 | 计划 §0.7 D-8 |
|---|---|---|
| 中位 | **0.0319 ms** | 0.0730 ms |
| **max** | **18.9994 ms** | 43.9210 ms |
| **max/中位** | **596.1×** | **601.66×** |
| 超 1.5×中位的占比 | **4.847%** | 3.475% |
| 按**时间**三等分的尖峰计数 | **1087 / 914 / 907**（比值 1.20） | 686 / 697 / 702 |
| **均值 / 中位** | **1.1659** | — |
| **均值 / p90** | **1.1449** | — |
| `(均值−中位)/中位` vs `(p90−p50)/p50` | **16.59% vs 1.83%**（**9.1 倍**） | — |

**读法（三句话）**：

1. **`max/中位 = 596.1`** —— 与计划 D-8 记录的 **601.66** 几乎相同。
2. **尖峰在时间上近似均匀**（比值 **1.20**）⇒ 不是漂移、不是热降频
   （`45` 的 R1 也独立否掉了热降频：120 轮 ±1.4%、无单调趋势）。
3. **均值被尾部支配**：**均值比 p90 还大 1.1449 倍** —— 一个统计量比它自己 90% 的分位点还高，
   这是重尾最直白的形态。

### 3.2 本机实测：顺序 vs 交错（`B` 段）

A 与 B 逐字等价，每组 **N = 2000** 取中位，每种编排 **8 轮**：

| 编排 | \|差\| 均值 | 轮间极差 | 中位 | 同号轮数 | 单轮最大 \|差\| |
|---|---|---|---|---|---|
| **顺序** | **1.0262%** | **4.9652%** | +0.0820% | 5/8 | **3.2894%** |
| **交错** | **0.0989%** | 0.5294% | −0.0327% | 1/8 | 0.3953% |
| **比值** | **10.4 倍** | **9.4 倍** | — | — | 8.3 倍 |

**★ 一条必须写清的口径**：判据用的是 **\|差\| 的均值**与**轮间极差**，
**不是「中位」** —— 因为**中位的符号在本机是不稳定的**（见 §3.4）。
`regret` 那种「两点之差」型的量在低重复下会给出相反的符号（本域 `01` §4.2 踩过这个坑）。

**★ 与计划 §0.7 D-12 的对照：**

| | 计划 D-12 记录 | 本机复跑 |
|---|---|---|
| 顺序中位 | **+0.863%**（**8/8 轮为正**） | +0.0820%（**5/8 为正**） |
| 交错中位 | −0.015% | −0.0327% |
| 比值 | 约 57× | **10.4 倍**（\|差\| 均值之比） |

**⇒ 「顺序编排**稳定地偏高** 0.86%」这一条在本机不复现**：复跑 12 轮是 **5/12 为正、中位 −0.081%**。
**正确的机制表述是**：**两个时间段各自带走一段系统状态，于是差值里混进一个「时段差」** ——
它的**量级**是 0.5%–1%（可达 3%），而**符号由当时的状态差决定，不由编排决定**。

### 3.3 本机实测：交错**治的不是什么**（`B.4` / `B.5`，两条【否定】）

> ★★ **这两条与正面结论同等重要**：不写它们，读者会以为「交错是在对付周期性干扰」。

**【否定一】构造的周期干扰造不出可观测效应**
（后台线程每 **100 ms** 忙 **20 ms**）：

| 条件 | 交错 \|差\| 均值 | 顺序 \|差\| 均值 |
|---|---|---|---|
| 无干扰 | 0.0989% | 1.0262% |
| **有干扰** | **0.0209%**（**0.21 倍**） | 0.5993% |

**⇒ 干扰开着时交错编排仍然准。** 如果那个效应真是被某个周期性干扰源驱动的，
那么干扰应该**同样**打坏交错编排 —— 而实测**没有**。

**【否定二】不是冷启动**：先预热（A、B 各先跑 1000 次），再跑同样的 8 轮：

| 条件 | 顺序 \|差\| 均值 | 交错 \|差\| 均值 | 比值 |
|---|---|---|---|
| 预热后 | **0.7088%**（> 0.2%） | 0.0369% | **19.2 倍** |

**⇒ 预热之后效应仍在** ⇒ **机制不是「前 k 次冷启动」**，
**`45/01` 的解法（丢掉前 k 次）在这里不够用。**

### 3.4 本机实测：从同一批数据里能直接算出的设计判据（`C` 段）

| 量 | 顺序编排 | 交错编排 |
|---|---|---|
| \|差\| 均值 | 1.0262% | 0.0989% |
| 轮间极差 | 4.9652% | 0.5294% |
| 单轮最大 \|差\| | 3.2894% | 0.3953% |
| **同号轮数** | **5/8** | 1/8 |

**读法**：

1. **顺序编排单轮最大 \|差\| = 3.2894%** ⇒ 它**足以制造一个看起来「像样」的结论**
   （真实差异是 0）。
2. **交错编排单轮最大 \|差\| = 0.3953%** ⇒ 交错后的最大值仍落在「真实差异为 0」的合理范围里。
3. **★★ 顺序编排的符号并不稳定**（合计 10/16 轮为正，见 `C.3` 的断言口径）——
   这一条**断言的正是「符号不稳定」**：若计划 D-12 那个「8/8 轮为正」的说法成立，它会失败。
4. **判定「要不要交错」的机器化判据**：若你要检出的真实效应是 **0.2%**，
   而顺序编排的 \|差\| 均值是 **1.0262%**，那么**它落在同一量级上** ——
   **你报出的差异可能整个都是时段差。**

## 4. 踩坑与失败模式

### 4.1 现象：真实差异为 0，而你把两头分别跑，得到一个 3% 的「改进」

- **现象**：8 轮里有一轮报出 **+3.289%**。
- **成因**：A 与 B 各自占据一个连续的时间段，**时段差**被整个记进了「B 相对 A」里。
  本机实测：顺序的 \|差\| 均值是交错的 **10.4 倍**。
- **规避**：**交错 + ABBA**（§1.2）。这是本篇唯一一条「必须做」的动作。

### 4.2 现象：做了交错，但残余的顺序效应还在

- **现象**：交错 \|差\| 均值 **0.186%**（而不是 0.02%–0.1%）。
- **成因**：`inter_round` 里**永远先 A 后 B** —— 那么「同一对里第二个被量的那个」会稳定地偏慢。
  **交错编排自己变成了一个新的系统偏差源。**
- **规避**：**ABBA** —— 一半的点「先 A 后 B」，另一半「先 B 后 A」。
  **「交替」= 让先后对称，不是「轮流出现」。**

### 4.3 现象：以为交错是在对付某个「周期性干扰」

- **现象**：为了「演示交错有用」，加一个后台干扰线程。
- **成因**：**时序搞反了**。`B.5` 实测：**干扰开着时交错编排照样准**（0.0209%）。
  原因是本机的尖峰在**时间上近似均匀**（§3.1：1087 / 914 / 907），
  **时间无关的噪声交错治不了，也不需要治**。
- **规避**：把交错理解成「**消除两组之间的时段差**」，而不是「抗干扰」。
  §5 判据表的两行（时间相关 / 时间无关）就是这条的落地。

### 4.4 现象：用「顺序编排系统性地偏高」去解释那个效应

- **现象**：计划 §0.7 D-12 记的是「**8/8 轮为正、中位 +0.863%**」。
  本机复跑 12 轮是 **5/12 为正、中位 −0.081%**。
- **成因**：那个效应是**时段差**，它的**符号由当时两个时段的状态差决定**，
  **不由编排决定**。把它说成「系统性偏高」是把一个**随机的方向**说成了一个**确定的机制**。
- **规避**：判据落在**量级**上（\|差\| 均值之比、轮间极差之比），
  **不落在符号上**；并且 `C.3` **把「符号不稳定」本身写成了一条断言** ——
  **若那个「8/8」的说法成立，这条断言会失败。**

### 4.5 现象：在**闲机**上跑 `A.1`（`max/中位 > 100`）

- **现象**：闲机上 `max/中位` 只有 **4–23**，判据当场失败。
- **成因**：那条判据测的是「**这台机器当时忙不忙**」，而程序没有把「忙」握在自己手里。
- **规避**：**A 段自己拉起 `cpu_count()-1` 个忙进程**，并且**稳定 4 秒后再开始测**
  （实施者实测：稳定 2 秒时间三等分是 116 / 301 / 492，比值 4.24 ⇒ `A.3` 失败）。
  **等待时间也是量法的一部分，不是可以省的。**

## 5. 判据表

| 条件 | 结论 |
|---|---|
| `max/中位 > 3`（重尾，本机实测 **596.1**） | **用中位数，不要用均值**（本机：**均值比 p90 还大 1.1449 倍**） |
| `σ/中位 ≫ (p90−p50)/p50`，或**去尾后 σ 变化 ≫ p90 变化** | σ 被尾部定义（回链 `50-performance/tuning-practice/01-measuring-sigma-and-tau`）⇒ **不要把 σ 当分布的充分描述** |
| 干扰在时间上**均匀**分布（本机实测三等分 **1087 / 914 / 907**，比值 1.20） | **交错不带来优势** —— 它是针对**时间相关**干扰的对策，而这里没有可治的东西 |
| 干扰**时间相关**（漂移、周期、温升） | **必须交错 + 配对分析**；否则顺序编排会给出系统性错误的结论（本机 \|差\| 均值 **1.0262%** vs 交错 **0.0989%**） |
| 两组样本数不等 / 未配对 | 交错的优势**丧失**；必须配对（每一对里 A、B 各一次） |
| 交错时**永远**先测同一组 | **交错失效**（本机实测：交错 \|差\| 均值从 0.02% 涨到 **0.186%**）⇒ 必须**ABBA** |
| 只报了均值与 σ，没报分位数 | **不可判定** —— 重尾下这两个量不足以描述分布（本机：`max = 3185×` 最小值，而 `p90/中位 = 1.0183`） |
| 你打算报的效应与顺序编排的 \|差\| 均值**同量级** | **先交错再报**。本机：顺序 \|差\| 均值 **1.0262%**，足以制造一个 3.3% 的假结论 |
| 预热过了，所以「冷启动已经排除了」 | **不够**。预热后顺序 \|差\| 均值仍 **0.7088%**（= 交错的 **19.2 倍**）⇒ 机制不是冷启动 |
| 想用「加一个周期干扰」来演示交错有用 | **演示不出来**（本机：干扰下交错 0.0209%，与无干扰无可辨差别）。交错治的是**时段差**，不是干扰 |
| 只有一个配置、要判「它稳不稳」 | 这不是本篇的问题 —— 回链 `45-kernel-lifecycle/convergence-and-tuning/01-benchmark-hygiene`（warmup / 丢前导，**正文在那边**） |

## 6. 小结与延伸

**一句话**：**在比较两个配置时，「先后」本身就是一种系统偏差 —— 必须让它对称。**

本域主线在这里的形态：**你测到的不是「B 比 A 快多少」，而是「时段 2 比时段 1 快多少」。**

- **姊妹篇**：`01-measuring-sigma-and-tau`（σ 与 τ 怎么测）、
  `02-noise-and-search`（噪声下搜索会怎么选错）。
- **往上游回链**：`45-kernel-lifecycle/convergence-and-tuning/01-benchmark-hygiene`
  （**单个配置**内的 warmup 与丢前导 —— 与本篇不是同一件事）、
  `45-kernel-lifecycle/convergence-and-tuning/02-significance`（拿到 \|差\| 之后怎么判它可不可判定）、
  `45-kernel-lifecycle/convergence-and-tuning/03-convergence`（多步调优里的假胜利累积）。
- **往下游**：任何「改了一处、重测、报收益」的流程，**在报出那个百分比之前先问一句
  「我是先跑完 A 再跑完 B 的吗？」**
