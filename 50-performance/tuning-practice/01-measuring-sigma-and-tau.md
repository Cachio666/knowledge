# 测出 σ 与 τ：45 声明为「表外输入」的那两个量

> **`45-kernel-lifecycle/convergence-and-tuning` 三篇的「闭合性检查」都写着：
> σ 与 τ 是「表外输入」，**必须测、不能查** —— 而它不教怎么测。本篇就是那个「怎么测」。**
> **本机实测：计时器的量化步长 `τ_q` = 41.6667 ns（不是 250 ns）；
> 而「该重复多少次」不是一个可以推导的公式 —— `t/N` 对 N 是一条左端被固定开销抬高的曲线。**

## 0. 背景与动机

### 0.1 这三句话就是本篇的存在理由

`45` 的三篇各有一句「表外输入」，**逐字**如下：

| 来源 | 行 | 逐字 |
|---|---|---|
| `01-benchmark-hygiene.md` | **262** | 「**唯一的表外输入**是「本次会话的稳态 σ」——它必须**测**（同一批测量自身就能给），不能查。」 |
| `02-significance.md` | **246** | 「**表外输入**是「本批测量的 `σ` 与 `τ`」——它们必须测（材料从同一批数据来）。」 |
| `03-convergence.md` | **260** | 「**唯一表外输入**是「本机当前的 `σ` 与 `n`」——必须测。」 |

**`45/02:246` 是唯一同时点到 `τ` 的那一句**，而它只说「必须测」——
**没有说 `τ` 是什么，也没有说怎么测**。本篇补的就是这一格。

**不用它的代价**：`45/02` 的判据 `δ* = 2.801585218112968 · σ · √(2/n)` 要求 σ
是一个**有意义的量**。若你手里的 σ 是从别处抄来的、或是在另一个口径下测的，
那么 `δ*` 算出来的分辨极限**与你正在做的比较无关** —— 而**它不会报错**，
它只会让你的判定看起来有依据。

### 0.2 一个具体的对照场景

同一个操作（一次约 **275 ns** 的短操作），只改「一次测量里重复几次」（记作 N）：

| N | 本程序实测 `t/N` |
|---|---|
| 1 | **333.2 ns** |
| 100 | 263.8 ns |
| 200 | **263.3 ns**（谷底） |
| 5000 | 275.0 ns |

**同一个操作，报出来的「单次耗时」在 N=1 与 N=200 之间差 26.5%。**
两个数都是真的、都是同一台机器测的 —— **它们是两个不同的量**。

> ★ **限定语（本篇强制）**：本篇所有数字都是**本仓库在本机
> （Apple M1 Pro / macOS / `python3 3.13.5` / `numpy 2.4.4`）跑出的**，
> **是 CPU 上的测量，不是 GPU、不是 Nsight Compute**。它们支撑的是
> 「**σ 与 τ 怎么量、量出来受什么影响**」这类**机制**结论。
> **GPU 侧只能引 §4 的规格事实（`code/specs.py` 的 F1–F15）**，两者**不得互证**。

## 1. 原理

### 1.1 τ：单次测量的量化步长 τ_q 与「重复平均能达到的精度」是两个量

`time.get_clock_info("perf_counter")` 直接给出刻度：

```
implementation = 'mach_absolute_time()'
resolution     = 4.166666666666666e-08 s   ⇒  τ_q = 41.6667 ns
```

**这是单次测量的量化步长**：读数只能落在 **τ_q 的整数倍**上，所以**任何短于 τ_q 的差异，
单次测量在原理上就看不见**。

**★ 但「分辨率」这个量有两种口径，混起来就是 P9（同名不同指）：**

| 口径 | 是什么 | 本机值 |
|---|---|---|
| **单次测量的量化步长** | 读数的最小非零差 | **τ_q = 41.6667 ns** |
| **重复 N 次求平均的精度** | 均值的标准误 | 远好于 τ_q，**但它随 N 变化的方式不是自由的**（§1.2） |
| **`timeit.timeit("pass")` 的单次成本** | **被测操作自身的成本** | **5.48 ns** —— ★ **这不是「计时器的精度」** |

第三行是最容易混进来的：`"pass"` 的 5.48 ns 比 τ_q 还小 **7.6 倍**。
**若把它当成「计时器能分辨 5.48 ns」，就错了** —— 它测的是循环体有多便宜。

### 1.2 「该重复多少次」不是自由参数

把 N 次 `op()` 的总耗时记作 `t(N)`。**若 `t(N) = a + b·N`（a = 固定开销、b = 单次成本）**，
那么

$$\frac{t(N)}{N} = b + \frac{a}{N}$$

**这个式子说：`t/N` 是 N 的单调递减函数，渐近于 `b`。** 本机实测拟合出来的
`a ≈ 75–87 ns`（§3.2），而 **`a` 的物理来源可以直接量出来**：`N = 0` 的「空循环」
（两次 `perf_counter` 读数 + 一个空的 `range(0)`）实测 **83.0 ns**。

**⇒ 于是 N 的选取直接决定你报出的「单次耗时」偏多少**：
N=1 时 `a` 全额计入，N=200 时只摊掉 0.4%。**这是「系统性偏差」，不是噪声** ——
多测几次只会让你更确信那个偏高的数。

### 1.3 σ：它不是分布的属性，是（操作 × N × 仪器）的联合属性

对**同一个操作**、只改 N，测出来的相对离散度差 **12.3 倍**（§3.4：N=1 时 11.70%，
N=1000 时 0.95%）。

**为什么会这样**：N=1 时每一次测量只有 `t ≈ 357 ns`，而量化步长 τ_q = 41.67 ns ——
**光是量化就贡献了 `τ_q / t ≈ 11.7%` 的相对下界**。N 增大后，
这个下界按 `τ_q / t(N)` 缩小，真实的机器抖动才露出来。

**⇒ 引用 σ 时必须连口径一起引用**（在哪个 N 下、测的哪个操作）。
`45/02` 的 `n ∝ σ²` 里的那个 σ，指的是**与你打算做的比较同一口径**下的 σ。

### 1.4 σ 的分解：`σ²_total = σ²_run-to-run + σ²_within-run`

一批测量有两个方差来源，可以用**组内 / 组间**把它拆开：

- 把测量分成 `R` 组、每组 `m` 次；
- **`σ_within`** = 各组的**组内标准差**的均值 —— 「同一次运行内部反复测」的抖动；
- **`σ_between`** = **组间均值**的标准差，**扣掉组内噪声能解释的那部分**：
  `σ_between = √(σ²_between_raw − σ²_within / m)`（小于 0 时取 0）。

**为什么这个分解有用**：它回答「我该加运行次数，还是加单次内的重复数」。
**加 `m` 只压 `σ_within/√m`；`σ_between` 一点都不动** —— 后者只能靠**换一次运行**（换时间、换机器状态）来采样。

## 2. 执行映射

| 组件 | 它在这里的角色 | 数值量级 |
|---|---|---|
| **`mach_absolute_time()`（内核）** | `perf_counter` 的底层实现。它给的是**整数 tick**，Python 再乘 `125/3 ns` 转成秒 —— 刻度就是从这里来的 | **41.6667 ns = 125/3**，时基 **24 MHz** |
| **CPython 的 `for` 循环** | 它是 `a`（固定开销）与「相邻迭代间隔」的来源。`range(0)` 的建立 + 两次 `perf_counter` 调用 ≈ 83 ns | **a ≈ 75–87 ns**；空循环体的一次迭代 ≈ **42 ns**（= 1 个 tick） |
| **操作系统的抢占** | 它是**尾部**的来源：一次抢占就能让单个样本变成中位的 **317 倍**（§3.3），而 **p90 只比中位高 0.89%** | 本机 **max/中位 = 317.02**；`σ/中位 = 225.57%` 而 `(p90−p50)/p50 = 0.89%` |
| **1.4826 × MAD（稳健尺度）** | 对照量：一个**对尾部不敏感**的宽度估计。它和 σ 的差距就是「σ 被尾部定义了多少」 | **σ / (1.4826·MAD) = 1010.9**（本机，负载下） |

## 3. 实现与演进

**朴素：`t0 = perf_counter(); f(); dt = perf_counter() - t0`。**
它**能跑**、能打印一个像模像样的 ns 数，**而且对短操作完全误导** ——
你在 N「不存在的」尺度上报了一个数（§0.2）。

**第一步：把「重复 N 次再除以 N」显式化。** `t(N)/N` 才是「单次耗时」这个量。
**为什么需要下一步**：`t/N` **不是常数**（§1.2）—— 一个 N 给不出判断。

**第二步：把 `t/N` 对 N 的曲线跑出来。** 这就是 §3.2。
**为什么需要下一步**：曲线告诉你「谷底在哪」，但**不告诉你 σ 是什么样的** ——
那是另一件事。

**第三步：把「一批测量的分布」量出来。** 这就是 §3.3（6 万个样本的分位数、偏度、峰度）。
**为什么还需要一步**：分布告诉你 σ 可不可信，但**不告诉你 σ 是哪一层的抖动** ——
那是 §3.4 的方差分解。

### 3.1 本机实测：τ_q 与「相邻迭代间隔」

| 量 | 本机实测 | 说明 |
|---|---|---|
| **τ_q**（`get_clock_info().resolution`） | **41.6667 ns** | ★ 这才是**刻度**；**不是 250 ns**（见 §4.1） |
| 相邻迭代间隔（**空循环体**）中位 | **42.14 ns = 1.011 tick** | 就是这个循环的节奏 |
| 相邻迭代间隔（**循环体多一次函数调用**）中位 | **83.82 ns = 2.012 tick** | ★ **时钟一点没变** |
| 相邻迭代间隔的**最小非零**值 | **40.98 ns = 0.983 tick** | 「两次读数的最小非零差 = 1 个刻度」 |
| `timeit.timeit("pass")` 单次 | 5.48 ns | **操作成本**，不是刻度 |

**读法（三句话）**：

1. **刻度只能从 `get_clock_info` 读**。同一台机器、同一个测量动作，
   **只把循环体加一次函数调用，间隔就从 42.14 ns 变成 83.82 ns（1.99 倍）** ——
   所以「相邻间隔」测的是**循环的节奏**。
2. **但刻度的存在是可观测的**：可观测到的**最小非零**间隔是 **40.98 ns = 0.983 个 tick**。
   读数确实被量化在 τ_q 的格子上。
3. **`250 ns` 这个数怎么来的**：它是「某个循环里连续两次 `perf_counter()` 之差」的众数之一。
   计划初稿把它当成了刻度 —— 见 §4.1。

> ★★ **一处口径警告（本程序 `A.2` 的判据不用上表的「中位」）**：
> 相邻迭代间隔被 `τ_q` **量化**，而空循环体的真实间隔落在 **≈1.5 个 tick** 处 ——
> 它的**中位**因此骑在「1 tick」与「2 tick」两个台阶之间的 **50/50 边界**上，
> 会整块翻转：本机实测（同一份代码、连续 6 次）空体中位在 **42.14 ns 与 82.89 ns 之间抛硬币**，
> 而 `1-tick` 桶的占比只动了 **1.1 个百分点**（0.494 → 0.505）。
> ⇒ `A.2` 判的是「**交错采样 + 配对比较**、每对的统计量取**块内均值**」的那个比值
> （均值把亚 tick 的量化误差在块内平均掉）；上表的中位**只作报告**。
> 这与「两组先后测」是**两件不同的事**：后者是本域 `03` 讲的编排偏差（§5 的 `A.2` 行里写着）。

### 3.2 本机实测：`t/N` 对 N 的曲线（本程序 `B` 类）

`op()` = 20 次加法（一次约 275 ns = 6.6 个 tick），每个 N 取 **60 次中位数**：

| N | 本程序实测 `t/N` | 计划 §0.7 D-4b 记录 |
|---|---|---|
| 0（空循环） | **83.0 ns**（不是 0） | 84.0 ns |
| 1 | **333.2 ns** | 375.0 ns |
| 2 | 292.0 ns | 333.5 ns |
| 5 | 283.2 ns | 316.6 ns |
| 10 | 270.8 ns | 304.1 ns |
| 20 | 266.7 ns | 297.9 ns |
| 50 | 264.2 ns | 293.3 ns |
| 100 | 263.8 ns | 292.1 ns |
| **200** | **263.3 ns**（谷底） | 291.9 ns（计划记的谷底） |
| 500 | 271.6 ns | 294.2 ns |
| 1000 | 271.3 ns | 297.6 ns |
| 2000 | 274.1 ns | 296.0 ns |
| 5000 | 275.0 ns | 316.2 ns |

**最小二乘拟合 `t(N) = a + b·N`**（N ∈ [0, 100]）：**a = 74.8 ns**、b = 262.9 ns。
**N=0 的空循环实测 83.0 ns** —— 它就是 `a` 的物理来源。

**读法**：

1. **左端被固定开销抬高**：`t/N(N=1) = 333.2 ns` 比 N∈[100,2000] 的最小值
   （263.3 ns）高 **26.5%**。这就是 `a/N` 那一项。
2. **右端有一个小幅回升**：把「高 N 段（{2000, 5000}）」与「平台段（{100, 200, 500}）」
   的 `t/N` 中位相比，本机实测 **1.0163**（8 组不同设置下复跑落在 **1.0067–1.0482**，8/8 为正）。
   **⚠ 这个效应只有 0.7–4.8%，比计划 §0.7 D-4b 记的 `+8.3%` 小一个量级**，
   而且**在低重复、单点比较下会给出相反的符号** —— 见 §4.2。
3. **所以 `t/N` 的形状是「降下来、进平台、再微微抬起」**，不是一条水平线。

> ★★ **一处必须写清的口径**：B.4 用的是**分段中位之比**（每段几百到两千个样本，
> 且两段的点是**交替**跑的），**不是两个点之差**。
> 实施者第一版用 N=200 与 N=5000 两个点直接比 —— 在低重复下同一个程序两次跑出过
> **1.020 与 0.992 两个相反的结果**。这与本域 `03` 的论点是同一件事：
> **顺序采样会让两段各自占据一个时间段。**

### 3.3 本机实测：σ 被尾部定义（本程序 `C` 类，**在负载下测**）

★★ **本类必须自己拉起 CPU 负载**：实施者实测，**在闲机上这个 27 µs 测量的分布几乎是高斯的**
—— 那时 `σ / (1.4826·MAD)` 掉到 1 附近、而「去尾 1% 后 p90 的变化 > σ 的变化」，
**两条判据都会失败**。而计划 §0.7 D-10 记录的分布（σ/中位 45%、偏度 62.8、峰度 4469）
本身就是在有背景负载的机器上测出来的。
**⇒ 「机器有多忙」是这条实验的自变量，必须握在自己手里** ——
否则这条判据测的是「这台机器当时忙不忙」，不是「σ 会不会被尾部定义」。
（这与 `03` 的 A 段是同一个做法，也同一条理由。）

**6 万次测量**，每次 = 「`op()` 重复 100 次求平均」（单次测量约 27 µs）：

| 统计量 | 本程序实测 | 相对中位 |
|---|---|---|
| min | 27.62 µs | −1.34% |
| **p50（中位）** | **28.00 µs** | — |
| p90 | 28.25 µs | **+0.89%** |
| p99 | 70.00 µs | +150.00% |
| p99.9 | 192.62 µs | +587.95% |
| **max** | **8.876 ms** | **+31601.81%** |
| **max/中位** | **317.02×** | （计划 §0.7 D-10 记 36.16×） |
| **σ/中位** | **225.57%** | |
| **偏度** | **+83.33** | （正态 = 0） |
| **超额峰度** | **+8867.6** | （正态 = 0） |

**★ `max/中位` = 317×，而 `p90` 只比中位高 0.89%** —— **主体的宽度与尾部的长度是两个量。**

**去尾实验**（去掉**最大的 1%**，也就是 600 个样本）：

| 量 | 原值 | 去尾后 | 相对变化 |
|---|---|---|---|
| σ | 63159.58 ns | 7489.80 ns | **+743.27%** |
| p90 | 28250.04 ns | 28250.04 ns | **0.0000%** |
| p50 | 27999.98 ns | 27999.98 ns | **0.000000%** |

**另一条对照**：`1.4826 × MAD`（一个对尾部不敏感的稳健尺度）在本次是 62.48 ns，
而 σ = 63159.58 ns —— **σ / (1.4826·MAD) = 1010.9**。
**σ 里几乎没有「主体宽度」这一部分。**

> ★★ **去尾实验只报告、不作断言**（实施者换过**三版**判据，**三版都在负载下失败过**）：
> - **第一版**判 `σ 变化 > 1.5 倍`、**第二版**判 `> 1.2 倍` —— 都失败过，
>   因为「尾巴有多重」**随会话变化**（这个比值实测落在 1.06–7.09）；
> - **第三版**判「一个序」`p50 变化 ≤ p90 变化 < σ 变化` —— **机器被占满时也失败过**
>   （那时三个量的变化都被单次尖峰主导，序不再成立）。
> **⇒ 三版留下的是同一条教训**：「尾巴当时有多重 / 机器当时有多忙」是这条实验的**自变量**，
> 而这三版判据都想对它们下断言。**代码因此把它降级为报告**（三个数仍然印在输出里）。
> 本类**剩下的判据**是 `C.1`（`σ/(1.4826·MAD) > 2` —— 由 σ 与**全部样本的中位绝对偏差**
> 共同决定，反复复跑全过）与 `C.2`（偏度 / 峰度）。

> ⚠ **口径边界**：本实验测的是**一个约 28 µs 的测量**（被测操作约 275 ns）。
> **不得外推成「所有性能测量的 σ 都不可用」** —— 长 kernel 的相对噪声远小于此。
> 这一条只作为「先用本方法看一眼自己的分布」的理由。

### 3.4 本机实测：σ 的两个成分，以及它随 N 的变化（本程序 `D` 类，**静息下测**）

★ **C 类在负载下跑，D 类在静息下跑** —— 这是有意的，而且它本身是一个结论（见末尾）。
对每个 N：**12 组 × 每组 25 次测量**。

| N | `t/N` 均值 | σ_within | σ_between | σ_between / σ_within |
|---|---|---|---|---|
| 1 | 351.46 ns | 41.13 ns（**11.70%**） | 14.99 ns（4.26%） | 0.36 |
| 20 | 273.34 ns | 2.01 ns（0.74%） | 0.80 ns（0.29%） | 0.40 |
| 1000 | 282.95 ns | 2.69 ns（**0.95%**） | 3.41 ns（1.21%） | 1.27 |

**读法（两句话）**：

1. **两个成分都非零** ⇒ σ² 确实是「运行之间」与「运行内部」两层叠起来的
   —— 这正是 `45/02` 里 `n ∝ σ²` 面对的东西。
2. **σ/中位 本身随 N 变化 12.3 倍**（11.70% → 0.95%），而 **N=1 时它被量化步长顶着**：
   `τ_q / t̄(N=1) = 41.67 ns / 351 ns = 11.86%` —— **实测的 11.70% 几乎就是那个下界**
   （跨多次复跑，实测比值 **0.68–1.01**）。

> ★★ **D.2 只报告、不作断言**（实施者换过**四版**判据，**四版都在负载下失败过**）：
> 前两版判的是「`σ/中位` **随 N 的走向**」；第三、四版改判「`σ/中位(N=1)`
> **被量化步长顶着**」——即它与 `τ_q / t̄(N=1)` **同量级**，
> 阈值从 `∈ [0.5, 2.0]` 一路放宽到 `∈ [0.3, 10.0]`，**仍然失败**
> （实测跑出过 2.3 与 > 4）。**真因**：`σ_within(N=1)` 与 `t̄(N=1)`
> **在机器被占满时都会被负载污染**，而它们的比值对本机那一瞬间的负载很敏感。
> **⇒ 代码把它降级为报告**（两个数与比值仍然印在输出里，读数 **0.68–1.01** 是静息那批、
> 本次负载下跑出 **2.58**）。机制那一句仍然成立 —— **短测量的 σ 不是「机器的抖动」，
> 是「尺子的刻度」** —— 它由 §3.3 的 `C.1`（σ 远大于稳健尺度）与这里的读数共同支撑；
> 但 **D 类剩下的可证伪判据只有 `D.1`**（两个成分都非零）。
>
> 而**σ 随 N 的走向**反而不能判：静息下 `σ/中位(N=1) / σ/中位(N=1000)` 实测 **7.4–12.3 倍**
> （τ_q ∝ 1/t 主导），**负载下会翻转**（0.4–1.4 倍 —— 长测量被抢占的次数更多）。
> **⇒ σ 连它随 N 的走向都不能跨机器状态搬运。**（前两版判据判的正是这个走向，都失败过。）

## 4. 踩坑与失败模式

### 4.1 现象：把「相邻两次调用的间隔」当成了「计时器的刻度」（★ 本域最该引以为戒的一次）

- **现象**：计划初稿把 `perf_counter` 的「量化步长」写成 **250 ns**，
  同一张表里又写着「最小非零 **84 ns**」。**这两个数互相矛盾** ——
  若步长真是 250 ns，最小非零间隔不可能只有 84 ns。
- **成因**：**数字是真跑出来的，标签是错的**。「相邻两次调用的差值」听起来自然，
  但它测的是**循环迭代的节奏**（含循环体开销）。
  本程序 `A.2` 给出的直接证据：**只把循环体加一次函数调用，间隔就翻倍**，
  而**时钟一点没变**。真正的刻度要从 `time.get_clock_info().resolution` 读：
  **41.6667 ns**（`125/3 ns`，mach 时基 24 MHz）。
- **规避**：**先做一致性检查**。本程序把这件事写成了可执行的断言（`A.3`/`A.4`）：
  「最小非零间隔」必须是 **1 个 tick**，而且必须**小于**那个被撤回的 250 ns。
  **两个数不可能同时成立** —— 这就是 P13 判据第②句说的「这个数荒谬吗」，
  在这里它表现为「**它内部一致吗**」。

### 4.2 现象：用「两点的差」去判定一个 2% 的效应，得到相反的符号

- **现象**：右端回升只有 0.7–4.8%。实施者第一版直接比 `t/N(N=200)` 与 `t/N(N=5000)`
  两个点，在低重复下**同一个程序两次跑出 1.020 与 0.992 两个相反的结果**。
- **成因**：**两个点各自只由一个样本集合决定**，而这个量本身带 ~2% 的会话波动。
  这与 `bottleneck-diagnosis` 那条「极差判据在正确实现下会随机失败」是**同一类错**。
- **规避**：换成**分段中位之比**（每段几百到两千个样本），并且**两段的点交替跑**
  —— 顺序采样会让两段各自占据一个时间段，那是 `03-ab-orchestration` 讲的偏差来源。
  本程序实测：同一件事换成这个口径后，**8 组不同设置 8/8 为正**。

### 4.3 现象：把 `σ/中位` 与 `(p90−p50)/p50` 的比值当成「σ 被尾部定义」的判据

- **现象**：计划 §3.1 的断言⑥是「`σ/中位 ≫ (p90−p50)/p50`」。
  实施者实测：**这个比值本身会随会话翻转** —— R=60000 时它是 6.7–85，
  而 R=12000 时出现过 **0.6**（σ 反而比 p90 的偏离**小**）。
  拿它当判据，**在正确实现下会随机失败**。
- **成因**：它是否大于 1，取决于**这一轮有没有撞上抢占尖峰** ——
  而那是**由机器负载决定的**，不是由被测对象决定的。
  ★ 同一个原因还让 **C 类的另外两条判据在闲机上失败**（§3.3）—— 所以 C 类现在**自己拉起负载**。
- **规避**：换成**两个**不依赖「这一轮尾巴有多重」的量：
  ① `σ / (1.4826 × MAD)`（MAD 是**由全部样本决定的**分位数型统计量）；
  ② **去尾 1% 后的敏感度序** `p50 变化 ≤ p90 变化 < σ 变化`。
  本程序**仍然把那个被换掉的比值打印出来**，但**不对它下断言** ——
  **撤回的东西要留在原地可见**（与 `A.4` 保留 250 ns 是同一个做法）。

### 4.4 现象：拿 `timeit("pass")` 的 5.5 ns 当成「计时器的有效精度」

- **成因**：它是**被测操作（循环体）自身的成本**。本机 τ_q = 41.6667 ns，
  而它只有 5.48 ns —— **比刻度还小 7.6 倍**。一个「分辨率」不可能小于刻度。
- **规避**：分清**两个量**（P9）。要量「有效精度」，应当量
  「对同一个固定时长反复测量，**均值的误差如何随 N 收缩**」——
  而本程序 `D` 类给出的答案是：**这个过程不是纯粹的 `1/√N`**，
  因为 N 本身还会改变被测量的定义（§1.2）。

### 4.5 现象：把一个 `µs` 级操作的 σ 外推成「所有 σ 都不可用」

- **成因**：本程序 `C` 类测的是一个约 **27 µs** 的测量，尾部由**抢占**主导。
  长测量的相对抖动远小于此。
- **规避**：引用 σ 时**连口径一起写**（哪个操作、哪个 N、哪台机器）。
  本程序 §3.3 末尾的口径边界就是这条的落地。

## 5. 判据表

| 条件 | 结论 |
|---|---|
| 被测操作的耗时 < 单次量化步长 τ_q（本机 **41.6667 ns**） | 单次测量**不可用**；必须重复 N 次求平均。**但 N 本身要标定**（§1.2：N 过小被固定开销抬高） |
| 你手里的 σ 是**从别处抄来的**，或不知道它的 N | **不可用**。σ 是（操作 × N × 仪器）的联合属性（§1.3：本机只改 N，σ/中位 差 **12.3 倍**，**连走向都会翻转**） |
| 同一配置**多次运行**的 σ 远大于**同一次内重复**的 σ | σ 的主导成分是 **run-to-run** ⇒ 增加**运行次数**，而不是单次内的重复数（§1.4） |
| `σ/(1.4826·MAD) > 2`，或**去尾 1% 后 σ 的变化大于 p90 的变化** | σ **被尾部定义**（§3.3：本机 **1010.9 倍**）⇒ **不要把 σ 当分布的充分刻画**；回链 `45/02` 的判据前先看分位数 |
| 去掉最大的 1% 样本后 σ 变化很大而中位数不动 | 同上：这是「σ 被尾部定义」的**可机械判定**形态（本机 σ **+743%**、p90 **0%**、p50 **0.000000%** —— **敏感度是单调的**） |
| 报告的差异 < 由该 σ 算出的 `δ*` | 差异**不可判定**——回链 `45-kernel-lifecycle/convergence-and-tuning/02-significance`（正文在那边，本篇只回链） |
| 你要判定一个 **< 5%** 的效应，而 `t/N` 的 N 还没标定 | **先标定 N**。本机 N=1 与 N=200 之间 `t/N` 差 **26.5%**，比你要测的效应大得多 |
| `t/N` 在两个相距很远的 N 上直接比较 | **不要用两点之差**（§4.2：它会给出相反的符号）。改用**分段中位之比**，且两段**交替采样** |
| 想把 `timeit("pass")` 的耗时当成「计时器精度」 | **错的口径**（§4.4）。它是**操作成本**；刻度只能从 `get_clock_info().resolution` 读 |
| 想从「相邻两次 `perf_counter()` 的间隔」推断刻度 | **做不到**（§4.1）。那个数随循环体变化（本机 42.14 → 83.82 ns，时钟没变）；刻度只有一个来源 |

## 6. 小结与延伸

**一句话**：**σ 与 τ 都不是「从别处查得到的常数」，而是「在你自己这台机器、这个口径下测出来的量」。**

本域主线在这里的形态：**「σ」不是一个关于你的程序的数，是关于你的程序的一次测量的性质** ——
本机实测：只改重复次数 N，同一个操作的「单次耗时」差 26.5%、「σ/中位」差 12.3 倍，**而且它随 N 的走向还会随机器忙不忙翻转**。

- **姊妹篇**：`02-noise-and-search`（把噪声加回来之后，搜索会怎么选错）、
  `03-ab-orchestration`（两个配置比较时，**两个时间段不可比**）。
- **往上游回链**：`45-kernel-lifecycle/convergence-and-tuning/02-significance`
  （`δ*` 的推导与 MDE 判据，**正文在那边，本篇只代入不重推**）、
  `45-kernel-lifecycle/convergence-and-tuning/01-benchmark-hygiene`
  （warmup / 丢前导 / 统计量选择 —— **那是单个配置内部的事**，与 `03` 讲的「两个时间段」不是同一件事）、
  `45-kernel-lifecycle/convergence-and-tuning/03-convergence`（停止判据；它的 `n` 就是本篇 §1.2 的那个 N）。
- **横向回链**：`60-compilers/auto-tuning`（**它主动冻结了测量噪声**：`MEASURE_NOISE = 0.0`，
  把「测量方法论」交给本域 —— 见 `02-noise-and-search` §0）。
