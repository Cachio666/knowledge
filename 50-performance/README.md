# 50-performance 性能工程

跨层的性能方法论。本域不回答「这个算子**怎么写快**」（那是 `40-kernels`），
也不回答「这个算子**该不该停**」（那是 `45-kernel-lifecycle`）。
它回答：**你看到的那个数，是在什么口径下、从你的程序的哪一部分拿到的。**

## 本域覆盖什么

| 主题 | 内容 | 状态 |
|---|---|---|
| [profiling-tools](profiling-tools/) | **工具作为仪器**：三种采集机制 / replay 与多 pass / 默认值不中立 / 归因 | **已完成**（3 篇） |
| [bottleneck-diagnosis](bottleneck-diagnosis/) | **从读数到判据**：延迟 vs 带宽 / 读计数器的反模式 / 一次完整诊断 | **已完成**（3 篇） |
| [tuning-practice](tuning-practice/) | **σ 与 τ 的标定** / 真实测量噪声下的搜索 / A-B 的实验编排 | **已完成**（3 篇） |

**统一主线**：

> **工具的每一个输出都带口径。你看到的不是你的程序，是关于你的程序的一次测量。**

三个主题是这条主线的**三次穿越**，构成「采集 → 解释 → 决策」的顺序：

| 主题 | 层 | 边界（泄漏点） |
|---|---|---|
| `profiling-tools` | 采集 | **数是怎么被拿到的** → 采集机制、replay、默认值、归因 |
| `bottleneck-diagnosis` | 解释 | **数怎么变成判据** → 延迟/带宽、读计数器的反模式 |
| `tuning-practice` | 决策 | **判据怎么进入决策** → σ/τ 的标定、噪声下的搜索、A/B 编排 |

**这条主线直接产出的一个推论**，三篇主题都要用到：

> **每一个 profiling 数字都是三重污染的产物：观测者效应（测本身改变被测）、口径（inclusive/exclusive、单次/重复）、归因（时间算给了谁）。**
> **三者都不报错——它们只是让那个数变成另一个数。**

**本域的定位（一句话）**：

> **`45-kernel-lifecycle` 把 σ 当作输入，并明说「必须测、不能查」——本域就是那个「怎么测」。**
> **`10-foundations/performance-models/03` 造好了尺子却从未使用（§5 全篇留空）——本域是用尺子的人。**

## 本域**不**做什么

本域上下都紧挨着已建成的域，边界必须写死，否则会与它们大量重复。

| 相邻域 | 它讲什么 | **本域不讲什么** |
|---|---|---|
| `10-foundations/performance-models` | roofline/Amdahl 模型；**探针的构造方法论**（03，但从未执行） | 不重推导 roofline 公式、不重讲探针构造陷阱。**本域用它造好的尺子，并补上本机实测** |
| `20-gpu-architecture` | 硬件是什么（SM、存储层次、计数器原理） | 不重讲硬件原理。**本域讲工具怎么读它** |
| `30-gpu-programming` | 语言层；**读 SASS 的方法与 ISA 语义**（`ptx-sass`） | 不重讲 ISA 语义、不重讲语言层的承诺与泄漏。**本域回链 `ptx-sass` 作为「下钻到 SASS」的手段** |
| `40-kernels` | 具体算子怎么写快 | **本域不出现任何算子的完整实现**。诊断对象是**本机真实程序**（CPU），不是 GPU kernel |
| `45-kernel-lifecycle` | 做哪个、什么时候停；**warmup/统计量/MDE/停止判据** | ★ **不重讲任何判据**。**本域提供 45 声明为「表外输入」的 σ 与 τ 的测法** |
| `60-compilers` | 编译器内部；**搜索空间/代价模型/搜索算法** | ★ **不重讲搜索算法**。**本域讲「真实测量噪声下搜索会怎么选错」**——那是 auto-tuning 主动冻结（`MEASURE_NOISE = 0.0`）让出的那块 |
| `120-inference` | 引擎层的调度与显存 | 不重讲 serving 栈 |

**与三个最近邻的分工，各一句话**：

1. **vs `10-foundations/03`**：它讲**怎么造尺子**（探针构造四陷阱），本域讲**用尺子读数**（工具机理、口径、归因）。
2. **vs `45`**：它给**判据**（σ 是输入），本域给**测量**（σ 是输出）。
3. **vs `60/auto-tuning`**：它讲**无噪声的搜索**，本域讲**有噪声的搜索**。

## 代码约定：**真值有两个来源，标签必须分开**

本机的硬约束（已实测）：**无 GPU，无 `ncu`/`nsys`/`nvprof`/`nvidia-smi`/`CUPTI`/`perf`**，
但**有 `sample`（免 root）、`dtrace`、`xctrace`、`clang`**。
**⇒ 本域一切实测都是 CPU 上的**，**不得支撑任何关于 GPU 的结论**（`CONTRIBUTING:90`）。

| 真值来源 | 内容 | 必须写明的限定语 |
|---|---|---|
| **① 本机实测值** | **CPU 上的真实测量**：采样、计时、计数、访存微基准 | `python3` / `numpy` / `clang` 版本 |
| **② 规格值** | **NVIDIA 文档事实**（F1–F15） | **URL + 章节 + 抓取日** |

**两者不得互证**：规格事实只能支撑「工具是怎么设计的」，**不能支撑「你这台机器的性能」**——
后者本机没有。

| 文件 | 性质 | 构建 |
|---|---|---|
| `NN_*.py` | 编号程序，**与文档一一对应**，纯 `python3` + `numpy`，**默认解释器下可跑** | `make run` |
| `specs.py` | 非编号辅助模块，**F1–F15 与上游契约常量**，每条带 `# 来源：` 与来源等级 | 被编号程序读 |
| `meta_falsify.py` + `make falsify` | **反向测试**：往**测量引擎**里注入缺陷，**按各主题注入项表里写明的「期望结果」判定**——多数项是「**必须失败**」，**但有一项是期望「通过」的反向测试**（它证明断言检查的是那个机制，不是无条件怪癖） | `make falsify` |
| `mutate.py` + `make mutate` | 叶级变异，报**测 N / 捕获 M / 漏网 K** + harness 异常数 + **对照组**，断言捕获与崩溃捕获**分开计数** | `make mutate` |
| `Makefile` · `requirements.txt` | 构建 | — |

**本域特有的两条**：

1. **访存微基准要真实代码生成**——C 源码作为字符串**内嵌在 `.py` 里**，运行时用 `clang`
   编到 `tempfile.mkdtemp()` 下的临时目录再执行。
   **`clang` 找不到时以可操作的错误退出**，**不得静默跳过、不得回落到 Python 循环**。
2. **`ASSERT_FAIL_MARK` 不得跨主题照抄**——三个主题的标记字面形态**各自定义、写死在各自程序里**，
   且每个主题**必须加一条「标记自检」断言**。

**本域不设 `verify.py`**——编号程序本机可跑，断言在程序内部。

## 文档的 §5 是「**判据表**」，不是「实测数据」

`CONTRIBUTING` 的 §5 被定义为「**实测数据**」（可选章节），并给出**三种合法形态**。
本域取第二种——**判据表**，理由是**无 GPU、且知识对象是方法**。
**先例已存在**：`30-gpu-programming`、`45-kernel-lifecycle` 同此。
**本域照做，不修改 `CONTRIBUTING` 的 §5 定义。**

判据表每一行必须是**「可机械判定的条件 → 结论」**形式，**表要闭合**（读完能照着做判断），
**不得**出现「视情况而定」「根据情况判断」。

**本机实测值放正文别处（§2/§3），不并入 §5。**

> ⚠ **这是「按同精神类推」，不是「规范原文直接适用」。**
> `CONTRIBUTING:384-385` 那句限定语的原文限定的是「**外部参考实现**在本机跑出的结果」；
> 而**本域的本机实测值来自本仓库自己的程序**，不是外部参考实现。

## 与其他域的关系

- **上游**：`10-foundations/performance-models`（造好的尺子）、`20-gpu-architecture`（硬件计数器）、`45-kernel-lifecycle`（σ 与 τ 是它的**表外输入**）。
- **下游**：`40-kernels`、`60-compilers`、`120-inference` 的调优都引用本域的方法论。
- **横切**：本域是**测量域**——它不产出新的硬件知识，而是给出「拿到一个数之后怎么读它」。
- **与 `30-gpu-programming` 的关系**：瓶颈定位常需下钻到 SASS；**读 SASS 的方法与 ISA 语义**在 `30-gpu-programming/ptx-sass`（正文在那边，此处回链），本域不重复 ISA 语义、也不重复语言层的承诺与泄漏。
- **与 `45-kernel-lifecycle` 的关系（本域与它最容易打架，边界写死）**：`45` 给**判据**（σ 是输入），本域给**测量**（σ 是输出）。本域**不重讲** `45` 的 warmup、统计量选择、MDE、噪声带与停止判据；本域只提供它声明为「**表外输入**」的 σ 与 τ 的测法。
