# 一次完整诊断：四步，顺序不能乱

> **诊断有固定顺序：① 先量端到端（否则不知道值不值得查）→ ② 再定位到函数（否则不知道改哪）
> → ③ 再判 bound 类型（否则不知道怎么改）→ ④ 改一处、重测，
> 最后必须用 `45` 的 δ\* 判定改动是否落在噪声外（否则会把噪声当成果）。**
> **四步里任何一步跳过，后面的数就都不可用。**

## 0. 背景与动机

一个具体的对照场景：一段**故意写慢的** python + numpy 程序，
对一个 8 MiB 的 `float64` 数组求平方和。慢版本用 **Python 层循环**，快版本用 **`np.dot`**。

本机实测（§3）的四个数：

| 步 | 观测 | 本机实测 |
|---|---|---|
| ① 端到端 | 慢版本一次要多久 | **0.1697 s**（向量化后 **0.000179 s**） |
| ② 定位 | 热点是哪个函数 | `cProfile` 最热点 = **`slow_sum_sq`**，exclusive 占比 **100%** |
| ③ 判 bound | 内存能解释多少 | 即便按**延迟限**算，内存也只能解释总耗时的 **1/46** |
| ④ 判 δ\* | 改动算不算成果 | 真实改动 `|Δ|/δ* = 20.3`（**可判定**）；安慰剂改动 `0.11`（**不可判定**） |

**不用它的代价**：跳过 ① 你会花一天优化一个只占 0.3% 的部分；
跳过 ② 你会改错函数；跳过 ③ 你会去调并发度而真正该做的是换算法；
**跳过 ④ 你会把一个 `0.2%` 的抖动写成「优化了 0.2%」。**

> ★ **限定语（本篇强制）**：本篇所有数字都是**本仓库在本机
> （Apple M1 Pro / macOS / `python3 3.13.5` / `numpy 2.4.4` / `Apple clang 21.0.0`）跑出的**，
> **是 CPU 上的测量，不是 GPU、不是 Nsight Compute**。

## 1. 原理：四步各自的前置条件

四步不是清单，是**依赖链**：第 k 步的输入是第 k−1 步的输出，**跳一步，后一步的输入就没了**。

### 1.1 ① 端到端计时

- **前置条件**：无（这是入口）。
- **产出**：**一个总时间**，以及它的**分布**（n、σ、分位数）。
- **跳过它会怎样**：你不知道**这个改动值不值得做**。
  你会在一个占比 0.3% 的部分上花掉一天，总时间只动 0.3% ——
  而 0.3% 大概率**落在噪声里**（这就要靠第 ④ 步来判）。

### 1.2 ② 定位到函数 / 行

- **前置条件**：① 给出「总时间是可分的」（也就是热点存在）。
- **产出**：**一个函数名**（或一行代码），它独占大头。
- **跳过它会怎样**：你知道「慢了」，但**不知道该改哪一行**。
  典型后果是**改了一个看起来可疑、但不占时间的东西** —— 然后第 ④ 步会告诉你没变化，
  而你**不知道为什么没变化**。

### 1.3 ③ 判 bound 类型

- **前置条件**：② 给出热点函数，且它的**访问模式**是可描述的
  （本机例子里：顺序读一个 8 MiB 数组）。
- **产出**：**「这个热点受什么限制」** —— 内存带宽？访存延迟？还是**根本不在内存这一侧**？
- **跳过它会怎样**：你不知道**该怎么改**。
  在「解释器开销主导」的热点上调并发度、改向量化宽度、降低 cache miss，
  全是**无效动作**。

**这一步的做法**（本篇用的）：**用微基准给这个访问模式量出边界**
——`01-latency-and-bandwidth.md` 那台仪器就是干这个的。
`10-foundations/performance-models/03-measuring-roofline.md:187` 把这件事的分工写成一句话：
「**微基准与 profiler 的分工是：前者给出边界，后者给出当前位置。**」

### 1.4 ④ 改一处、重测、判 δ\*

- **前置条件**：③ 给出「该往哪个方向改」；并且你已经有**一批**测量（不是一次）。
- **产出**：**一个判定** —— 这个改动**落在噪声外**（可判定）还是**在噪声里**（不可报）。
- **跳过它会怎样**：**把噪声当成果。** 这是本域里最常见、也最容易自我欺骗的一种。

**判据从 `45` 代入，本域不重推**：

$$\delta^{*} = 2.801585218112968 \cdot \sigma \cdot \sqrt{2/n}$$

（双侧 α = 0.05、检定力 80% 的两组比较；逐字来源见「参考」。
正文在 `45-kernel-lifecycle/convergence-and-tuning/02-significance`，此处回链。）

**★ 一个必须写在明处的口径：σ 怎么估。**
本程序用的是**稳健尺度** `1.4826 × MAD`（各组先减掉自己的中位数再合并），
**不是样本标准差**。理由不在本篇发明 —— 它是本域自己的实测结论：

> 本域 §0.7 **D-8 / D-10** 实测：同一份固定工作量的耗时分布是**重尾**的
> （`max/中位 = 601.66×`、偏度 **+62.8**、超额峰度 **+4469.5**），
> **样本标准差会被那 0.1% 的尾部定义**（`σ/中位 = 45%`，而 `p50 → p90` 只差 `4.6%`）。
>
> **实施者实测的后果**：同一次实验里，把 σ 从稳健尺度换成样本标准差，
> `|Δ|/δ*` 会从 **52.3 掉到 3.51**（同一次实验里的两个读数）——
> `|Δ|` 一点没变，**变的全是 δ\***。
> 拿一个**被尾部定义**的 σ 当门槛，等于让「这一轮恰好撞上一次调度抖动」
> 决定你的结论是红是绿。

**⇒ `45` 把 σ 列为「表外输入」，并明说「必须测、不能查」——
而「用一个不被尾部支配的估计量去测它」，就是本域在那句话上补的那半句。**

## 2. 执行映射

| 步 | 组件 | 数值量级 |
|---|---|---|
| ① | **`time.perf_counter`**（本机是 `mach_absolute_time`，时基 24 MHz） | 单次量化步长 **41.6667 ns**；本程序的每轮测量是 **0.15 s** 量级 |
| ② | **`cProfile` / `_lsprof` 的 hook** | 最热点的 exclusive 占比本机实测 **100%**（这段负载只有一层循环） |
| ③ | **乱序执行窗口 / MSHR**（延迟限那一端）、**DRAM 带宽**（带宽限那一端） | 同一规模上，延迟限 **0.0037 s** vs 带宽限 **0.00017 s** ⇒ **21.7 倍** |
| ④ | **`45` 的 δ\*** 与**交错编排** | 本程序的 `n = 13`；真实改动 `|Δ|/δ* = 20.3`、安慰剂 `0.11` |

## 3. 实现与演进

### 3.1 本机实测：一次完整诊断（真跑 `code/03_diagnosis_walkthrough.py`）

被测程序**就在那个 `.py` 文件里**（纯 python + numpy）：

```python
def slow_sum_sq(x):          # 热函数（v1）：Python 层循环
    s = 0.0
    for i in range(len(x)):
        s += x[i] * x[i]
    return s

def fast_sum_sq(x):          # 改一处之后的版本（v2）：交给 numpy
    return float(np.dot(x, x))
```

**① 端到端**（交替编排，重复 15 轮、丢掉前 2 轮）：

| 版本 | 中位 | 测量内部重复 |
|---|---|---|
| `v1_loop`（Python 循环） | **0.169679 s** | 1 次 |
| `v2_vec`（向量化） | **0.000179 s** | **64 次**（见下） |

> ★ **为什么快版本要在一次测量里重复 64 次再除以 64**：一次 0.18 ms 的操作，
> 其相对噪声被调度抖动支配（实测 σ 可到 **50%**），而一次 **0.17 s** 的操作 σ 只有 **1%** 量级。
> **两组的相对噪声不可比，`δ*` 就没有意义。**
> 这是本域讲的「重复次数不是自由参数」在**比较两个版本**时的形态：
> 量短操作时，**先把一次测量的时长做到与对照组同一量级**。

**② 定位**：`cProfile` 报的 exclusive 时间排序第一名是 `slow_sum_sq`，
占比 **100.0%**（这段负载只有一层循环，没有任何别的函数分摊时间）。
**断言 `A.1`**：最热点**就是**它，且占比 > 50%。

**③ 判 bound**：用 `code/microbench.py` 的 C 微基准，
在**同一个规模**（8 MiB）上量这条访问模式的两端：

| 那一端 | 耗时 | 含义 |
|---|---|---|
| **延迟限**（K=1，一次只有一个未完成的独立读） | **0.003688 s** | 内存能提供的**最慢**的合法速度 |
| **带宽限**（K=48，本机实测的平台起点） | **0.000170 s** | 内存能提供的**最快**速度 |

慢版本中位 **0.169679 s** ⇒ 是延迟限的 **46.0 倍**、带宽限的 **998 倍**。

**断言 `A.2`**（本篇最承重的一条）：**即便按最慢的那种访存方式算，
内存也只能解释总耗时的 2.2%** ⇒ **瓶颈不在内存**。
**这一条把 `③` 从一个「感觉」变成了一个可证伪的判断。**

**④ 改一处、重测、判 δ\***：

| 改动 | 合并组内 σ（稳健） | δ\*（n=13） | `\|Δ\|` | **`\|Δ\|/δ*`** | 结论 |
|---|---|---|---|---|---|
| **真实改动** v1 → v2（向量化） | 4.49% | 4.93% | **99.89%** | **20.3** | **可判定** ⇒ 报 |
| **安慰剂改动** v1 → v1′（**只把局部变量改名**） | 0.72% | 0.79% | 0.089% | **0.11** | **不可判定** ⇒ 不报 |

**断言 `A.3`**（改一处有效）：向量化后中位 < 慢版本的 1/10（实测 **948 倍**）。
**断言 `A.4`**：真实改动 `|Δ|/δ* > 3`（本机 7 次实测 **20.3–69.6**）。
**断言 `A.5`**：安慰剂改动 `|Δ|/δ* < 2`（本机 7 次实测 **0.03–0.39**）。
**断言 `A.6`**：`A.4` 的比值 > 5 × `A.5` 的比值 —— **同一条判据对两种改动给出相反结论**。

> ### ★ 安慰剂对照是**实施者加的**（计划 §2.3 的第四步只要求「改一处」）
>
> 加它的理由：`45` 的 δ\* 判据**存在的意义**就是「不让噪声变成成果」。
> 只演示「大改动可判定」是**看不出这件事的** —— 任何门槛都能让一个 948 倍的改动通过。
> ⇒ 必须配一个**逐字等价、真实差异严格为 0** 的改动，
> 展示**同一条判据把它拦下来**。
>
> **它的窗（`< 2`）是宽的，理由与 §3.2 那条一样**：这一条是**冒烟检查**，
> 有区分力的是 `A.6` 的**对照**，不是 `A.5` 单独的阈值。

**改完之后它在哪儿？** 向量化版本 0.000179 s ÷ 带宽限 0.000170 s = **1.05**。

> ⚠ **这个比值不是「超过了物理极限」。** `microbench` 的那段 C 与 numpy 的 BLAS 内核
> 是**两个不同的实现**（同规模下 numpy 版实测 **46.9 GB/s**、C 探针 **49.4 GB/s**），
> 比较的是**量级**，不是同一个数的两次测量。
> 这正是本域 `P13` 的判据第③句：**换一种量法，还得到同一个数吗？**
> —— 在这一格上，答案是「不能，而这是**预期的**」。

### 3.2 编排：为什么每组都要交错

第 ④ 步的每一轮里，三个版本**各跑一次**，并且**偶数轮正序、奇数轮倒序**。

理由不是惯例，是本域自己量出来的（§0.7 **D-12**）：
**A 与 B 逐字等价（真实差异严格为 0）时，顺序编排仍稳定给出约 +0.86% 的虚假差异
（8/8 轮同号），交错编排把它压到 0.015%（约 57 倍）。**
⇒ **顺序编排会把「两个时间段的系统状态差异」记到「改动效果」头上。**

> ★ **与 `45/01` 的分工写死**：`45/01` 讲的是**单个配置内**「丢掉前 k 次」；
> 本段讲的是**两个配置比较**时「两个时间段不可比」—— **不是同一件事**。

## 4. 踩坑与失败模式

### 4.1 现象：花了一天优化一个只占 0.3% 的部分

- **成因**：**跳过了 ①**。没有端到端读数，就没有「这个部分占多少」的分母。
- **规避**：**先量端到端**，并且**把分布一起量出来**（n、σ、分位数）。
  然后只对**占比大**的部分做后面的三步。

### 4.2 现象：改了一处，重测快 0.3%，于是写下「优化了 0.3%」

- **成因**：**跳过了 ④**（或者只跑了一次就下结论）。
  重尾分布下，「快 0.3%」与「慢 0.3%」是同一批噪声的两个面。
  **本程序实测的安慰剂对照**（逐字等价的改动）给出的 `|Δ|` 就有 **0.09–0.7%** 量级。
- **规避**：**算 σ、算 δ\*、看 `|Δ|/δ*`**。`45/02` 的公式逐字抄过来（本篇只代入）。
  ★ 而且 **σ 要用不被尾部支配的估计量**（§1.4），否则这个比值本身不可复现。

### 4.3 现象：`|Δ|/δ*` 今天 52、明天 3.5，而 `|Δ|` 一点没变

- **成因**：**σ 的估计量被尾部定义**（本域 §0.7 D-8/D-10）。
  样本标准差会被偶发的一次调度抖动抬高几倍，于是 `δ*` 跟着抬高。
- **规避**：用**稳健尺度**（`1.4826 × MAD`，各组先减自己的中位数再合并）。
  这样变的是「噪声本身有多大」，而不是「这一轮谁撞上了离群点」。

### 4.4 现象：③ 判成了「内存受限」，于是去调并发度，但一点没变快

- **成因**：把**「有访存」**当成了**「受访存限制」**。
  判定「受限」需要一条**边界**：这个访问模式在这台机器上**最快**能多快。
  没有那条边界的「内存受限」只是一个印象。
- **规避**：**用微基准给这条访问模式量出边界**（`01-latency-and-bandwidth.md` 的仪器），
  再拿热点耗时与边界比。本机实测：慢版本是**延迟限**的 46 倍 ⇒ 内存不可能是瓶颈。

### 4.5 现象：按「先跑完 A 再跑完 B」编排，A/B 号称有 0.86% 的差异

- **成因**：**顺序编排**把两个时间段之间的系统状态差异记到了 A 与 B 的头上（§3.2）。
- **规避**：**交错**（A/B/A/B…），并把每一轮的顺序也轮换。
  ⚠ 交错**消不掉**「负载影响」——它防的是**时间相关的漂移**。

## 5. 判据表：诊断顺序

每一行是「**当前观测 → 下一步做什么 → 为什么不能跳**」。

| 当前观测 | 下一步做什么 | 为什么不能跳 |
|---|---|---|
| 只知道「慢了」 | **① 量端到端**：n 次重复、报中位与分布 | 没有分母就不知道哪个部分值得查 |
| 端到端读数是**一次**测量 | 先补成一批，算 σ 与 δ\* | 单次读数分不出「真实差异」与「抖动」 |
| 端到端测出来了，不知道时间花在哪 | **② 用 `cProfile` 按 exclusive 时间排序** | 没有热点就不知道怎么改；改错函数会白花一轮 |
| 报告里最热点是**你没写过的符号** | 换采集路线或下钻（正文在 `02-reading-counters.md`） | 归因失效时「最热点」不是你的函数 |
| 找到了热点函数，不知道能不能优化 | **③ 用微基准量这条访问模式的边界**（延迟限 / 带宽限） | 「有访存」≠「受访存限制」，没有边界就没有判断 |
| 热点耗时 ≫ **延迟限**（本机 > 10 倍），且随并发度不变 | 瓶颈**不在内存**；去查解释/调度/算法层 | 在内存侧调参是无效动作（本机实测 46 倍，**2.2%** 都解释不了） |
| 热点耗时在**带宽限**附近（本机实测比值 **1.05**） | 已经贴着内存的边界 ⇒ **改算法**，不是调参数 | 贴着边界时，同访问模式内的调参空间已经用尽 |
| 改了一处，想出结论 | **④ 算 σ、算 δ\*、看 `\|Δ\|/δ*`** | 否则会把噪声当成果（本机安慰剂对照 `\|Δ\|` 就有 0.089%） |
| 备选：A 与 B **逐字等价**，却测出稳定的差异 | 先查**编排**：顺序还是交错 | 顺序编排会稳定造出约 +0.86% 的虚假差异（本域 D-12 实测） |
| `\|Δ\|/δ*` 在 **1 附近** | **不可报**。要判定它，先**把 σ 稳定住**（固定机器负载、加大重复次数） | 比值跨 1 时，红绿由 σ 的批次间漂移决定，不由效应决定 |
| 只报了均值与 σ，没报分位数 | **不可判定**：重尾下这两个量不足以描述分布 | 本域 D-8/D-10 实测：`max/中位 = 601×`，而 `p50→p90` 只差 4.6% |

## 6. 小结与延伸

**一句话**：**诊断有固定顺序，而且顺序不能乱**——
端到端 → 定位 → 判 bound → 判 δ\*。每一步的**输入**都来自上一步的**输出**，
**跳过任何一步，后面的数就不可用**（不是「不精确」，是**没有意义**）。

本域主线在这里收束：**你看到的不是你的程序，是关于你的程序的一次测量**——
而这四步，就是把「一次测量」变成「一个能站得住的判断」的全部流程。
