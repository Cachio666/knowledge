# 45-kernel-lifecycle/implementation 的第三方依赖
#
# ★ 本主题**需要 numpy**，与同域的 `operator-design` 相同（`requirement-discovery`
#   连 numpy 都没用）。启用下面这一行即可：`pip install -r requirements.txt`
#
# ── 为什么三个程序都需要 numpy ────────────────────────────────────────────────
#   · 01 用 numpy 构造**数组**（被测实现与两个参考实现都是数组变换：补位、分组、求和）。
#     这些是「共享子表达式」这个代数结构的最小可运行模型，与 GPU 无关。
#   · 02 需要 **fp16 的存储舍入**（`np.float16` 是原生 dtype，可以当**另一条独立路径**
#     来交叉复核我们自己的舍入实现）与 fp32 累加。
#     ⚠ **numpy 没有 `bfloat16` 这个 dtype**（2.4.4 实测）。本主题的处置是：
#       在程序里**写两条机制不同的 bf16 舍入实现**（位操作 + 数值舍入）并断言逐位一致
#       —— 这是本主题「参考实现必须独立」那条论断**在自己身上的应用**，
#       而不是「随便写一个然后用它」。
#   · 03 需要 **fp32 的标量累加**（确定性那一段：顺序累加 vs 随机顺序累加）
#     与随机置换（模拟 `atomicAdd` 的非确定到达顺序）。
#     浮点加法不满足结合律是 IEEE 754 规定的**真实性质**，所以「不同顺序给出不同结果」
#     不是仿真出来的假象。
#
# ── 本机的运行条件（写进文档的「编译与运行」小节的测量条件）──────────────────
#   python3 = 3.13.5；numpy = 2.4.4（本机实测，三个程序都在输出里打印实际版本）
#   ★ 本主题**不产出实测性能数字**：本机 macOS 无 GPU，域 README 明令
#     「本域任何一篇都不得声称有实测数据」。
#   ★ 三个程序都用**固定种子**（`SEED = 20260920`）⇒ 输出逐字节可复现。
#     换 numpy 版本**不会**改变 fp16/fp32 的舍入行为（IEEE 754 规定死了），
#     但可能改变 `default_rng` 的流与 `random.Random` 的置换流——
#     若换了版本导致断言失败，先看是不是这两条。
#
# ── 明确**不**需要的（写出来是为了让「没装」不等于「忘了写」）──────────────────
#   本主题**不 import torch**、不碰 GPU、不需要 CUDA 工具链、不需要 compute-sanitizer。
#   ★ 提到 `compute-sanitizer` 的地方是**文档层的事实引用**（本机无 GPU，跑不了它），
#     不是本目录的依赖。`make lint` 用 `ast` 对「不 import torch」做机械检查。

numpy>=2.0
