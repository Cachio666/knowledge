# 45-kernel-lifecycle/requirement-discovery 的第三方依赖
#
# ★ 本主题的三个编号程序**没有第三方依赖**——它们只 import `specs`（同目录）与标准库。
#   所以下面**没有任何一行被启用**，`pip install -r requirements.txt` 会安装 0 个包。
#
# 为什么保留这个文件：CONTRIBUTING §2 规定 `.py` 形态的构建入口是
# `Makefile` + `requirements.txt`；文件在、内容为空，与「文件不在」是两回事——
# 后者会让读者以为我们忘了写。
#
# ── 与本域其余主题的基线差异（**写出来，避免读者以为这里漏了 numpy**）─────────
# 域 README 写的口径是「纯 python3 + numpy」，而本主题的三个程序**连 numpy 都没用**：
#   · 01 只做整数与浮点算术（算子清单 / FLOPs / 参数量）；
#   · 02 只做一次除法（峰值 ÷ 带宽）与有限个算子的算术强度；
#   · 03 只做排序与比较。
# 这些量在本机 python3 的双精度浮点下**精确可算**，引入 numpy 只会把
# 「推导值」这件事包在另一个库的版本里，没有任何收益。
# ⚠ **这是本主题的例外，不是本域的口径变更。** 域 README 的「纯 python3 + numpy」
#   仍然描述本域其余主题；本主题只是更小的一个子集。
#
# ── 本机的运行条件（写进文档的「编译与运行」小节的测量条件）──────────────────
#   python3 = 3.13.5；numpy 未使用（本机装的是 2.4.4，与本主题无关）
#   ★ 本主题**不产出实测性能数字**：本机 macOS 无 GPU，域 README 明令
#     「本域任何一篇都不得声称有实测数据」。
#
# 参考：若将来某个编号程序确实需要 numpy，取消下面这行的注释即可。
#
