# ★ 本主题**需要 numpy**，与同域的 `requirement-discovery` 不同（那一主题连 numpy 都没用）。
#   启用下面这一行即可：`pip install -r requirements.txt`
#
#      numpy>=2.0
#
# ── 为什么这一主题需要 numpy 而上一主题不需要 ──────────────────────────────────
#   · 01 只用标准库：字典、元组、`ast`（读同目录另外两个程序的 `COVERED_*` 元组）。
#   · 02 需要 **fp16 / fp32 的标量累加**——它是本主题 C 类的核心（「打乱顺序结果就变」
#     与「fp16 累加 vs fp32 累加」）。用 Python 的 `struct` 手写 fp16 舍入也可以，
#     但那会把「我们自己的舍入实现对不对」变成一个额外的怀疑对象；numpy 的
#     `float16` 是**另一条实现路径**，用它可以**交叉复核** specs 里的 `u` 与 `65504`。
#   · 03 需要**整数矩阵乘**（判「只在最后一 tile 出错」的缺陷）与逐元素比对。
#
# ── 本机的运行条件（写进文档的「编译与运行」小节的测量条件）──────────────────
#   python3 = 3.13.5；numpy = 2.4.4（本机实测，两个程序都在输出里打印实际版本）
#   ★ 本主题**不产出实测性能数字**：本机 macOS 无 GPU，域 README 明令
#     「本域任何一篇都不得声称有实测数据」。
#   ★ 02 篇的随机序列用**固定种子**（`SEED = 20260920`）⇒ 输出逐字节可复现；
#     换 numpy 版本**不会**改变 fp16/fp32 的舍入行为（IEEE 754 规定死了），
#     但可能改变 `default_rng` 的流——若换了版本导致断言失败，先看是不是这一条。
#
# ── 明确**不**需要的（写出来是为了让「没装」不等于「忘了写」）──────────────────
#   本主题**不 import torch**、不碰 GPU、不需要 CUDA 工具链、不需要 cuDNN。
#   `make lint` 用 `ast` 对这条做机械检查。
#
