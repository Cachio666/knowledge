# 显著性判定：「快了 3%」需要什么条件才成立，以及为什么「太干净」反而可疑

> **两条反直觉的结论，每一条都能算出来：**
>
> ① **单次测量判胜负 = 抛硬币**。真实差异为 0 时，「跑一次 A、跑一次 B，看谁快」的**假阳性率是 50.0%**（实测 `49.948%`）——不是 5%，也不是 1%。换成每组 5 次 + 正确的临界值，才回到 **2.5%**。
>
> ② ★★ **临界值用 `z` 还是 `t` 直接改变结论**。两组各 `n = 5`、真实差异为 0 时，假阳性率：`z = 1.645` → **6.93%**、`z = 1.96` → **4.28%**、`t(4) @ 0.95 = 2.132` → **3.28%**、`t(8) @ 0.975 = 2.306`（**本题的正确自由度**）→ **恰好 2.50%**、`t(4) @ 0.975 = 2.776` → 1.20%。
> ⇒ **报「显著」时必须写明用的是哪个临界值、自由度怎么算**；本设计的正确自由度是 **`2n − 2`**，写成 `n − 1` 会把假阳性率从 2.5% 抬到 3.28%（1.31 倍）。
>
> ③ ★★ **「紧得可疑的标准差反而可疑」有一个机械形态**：`cudaEventElapsedTime` 的分辨率是 **0.5 µs**（[A] 级，NVIDIA 官方）。测一个真实时间 **0.30 µs** 的 kernel 时，读数**恒为 0.5 µs** ⇒ 实测 `σ = 0` ⇒ **最小可检出差异也变成 0** ⇒ 判定阈值退化，**任何**被报出来的差异都「显著」。而计时器**能报出的最小非零差异是一个刻度 = 167% of 真实时间**——比真实可分辨的 3.0% 大 **56 倍**。

## 0. 背景与动机

### 0.1 「快了 3%，我优化成功了」这个结论需要什么条件

一个可判定的版本是三个条件**同时**成立：

| 条件 | 表现形式 | 不成立时会发生什么 |
|---|---|---|
| ① 差异**大于**可检出阈值 | `δ > δ* = (z_{α/2}+z_β)·σ·√(2/n)` | 在噪声带里宣称胜利（本篇 §C.1） |
| ② 用的是**说清楚了的**临界值 | 临界值 + 自由度 + 单/双侧 | 同样的数据给出 2.5% / 3.28% / 4.28% 三种假阳性率（§C.2） |
| ③ 组内标准差**不是被测量方式压平的** | `σ` 与计时器分辨率同量级 | `σ = 0` ⇒ 阈值退化 ⇒ 任何差异都「显著」（§C.5） |

**本篇的行文顺序就是这三个条件的顺序**：先给公式，再给临界值的后果，最后给「σ 本身可能是假的」。

### 0.2 关于「噪声带」的口径（来源等级必须随数字一起走）

| 数字 | 等级 | 条件 |
|---|---|---|
| 会话内 A/B 噪声带 **±10–15%** | **[D]**（hipfire，**单一项目、未被独立复现**） | gfx1100（RX 7900 XTX）、**新进程**、受 DPM 状态/热余量/固件影响 |
| 亚毫秒尺度上 **四类 GPU 落在零的 ±20% 以内**，A100 SXM4 被共享宿主机启动方差支配 | **[C]**（arXiv:2607.02541，**预印本、未确认同行评审**） | 五类 GPU：RTX 3060 / A10 / L40S / A100 SXM4 / H100 NVL |
| `cudaEventElapsedTime` 分辨率 **0.5 µs** | **[A]**（NVIDIA 官方，**两次检索一致**） | CUDA Runtime API 与 Best Practices Guide 两个页面 |

> ⚠ **本库不把这三档混成一句「噪声带大约百分之几」**：它们的对象、条件、等级都不同（P7 引文作用域 + P9 同名不同指）。
> ⚠ 规格里那条「亚毫秒尺度 Δ 约 ±5%」**本库检索不到来源**，已按规格自己的订正换成 **[C] 的 ±20% / 四类**。

### 0.3 本篇在本域主线上的位置

`requirement-discovery` 问「上界在哪」，`operator-design` 问「怎么抬高上界」，`implementation` 守「上界的前提（算对）」，**本篇守的是「剩下的距离有多小才看得见」**——它决定了下一篇的停止判据能不能成立。

## 1. 原理：噪声带 → 最小可检出差异

### 1.1 公式与它的系数

两组**独立**样本、每组 `n` 次，要检出差异 `δ`（单侧、检定力 `1−β`、显著性水平 `α`）：

```text
δ* = (z_{α/2} + z_β) · σ · √(2/n)
   = (1.9599639845400534 + 0.8416212335729144) · σ · √(2/n)      （α = 0.05、β = 0.20）
   = 2.801585218112968 · σ · √(2/n)
   ≈ 2.80 · σ / √n
```

**每个因子都要说清**：

| 因子 | 为什么 | 写错会怎样 |
|---|---|---|
| `z_{α/2} = 1.95996…` | 双侧 5% ⇒ 每侧 2.5% | 用 1.645（单侧 5%）会放宽 1.19 倍 |
| `z_β = 0.84162…` | 检定力 80% ⇒ β = 0.20 | 漏掉它会把阈值压小 42% |
| **`√(2/n)`** | **两组独立样本之差的标准误是 `σ·√(2/n)`** | ★★ **写成 `√(1/n)` 会让解析值系统性偏小 `√2 ≈ 1.414` 倍** |
| 系数 `2.80` | 上面两项之和 | ★ 规格把约简形式写成 `≈ 4σ/√n`，那是 **+42.8% 的保守放大**（不是精度问题：它会让停止步数变一个数，见下一篇 §A.2）|

**检验这个公式的方式是代回具体数**（程序 §A.2）：`σ = 3%`、`n = 25` 时

```text
√(2/n) 版：2.801585218112968 × 0.03 × 0.28284 = 0.02377  ⇒ 2.38%
√(1/n) 版：2.801585218112968 × 0.03 × 0.20000 = 0.01681  ⇒ 1.68%   ← 规格初稿（漏 √2）
```

而规格的预跑值是 **2.4%** ⇒ **只有 `√(2/n)` 给得出它**。

### 1.2 解析式 vs 蒙特卡洛

用二分法找「检出率 = 80%」的 `δ`（每组 `n` 次、`σ = 3%`）：

| `n` | 解析式 | 蒙特卡洛（`z` 临界） | 相对差 | 规格的解析 / MC |
|---|---|---|---|---|
| 5 | 0.0532 | 0.0536 | **+0.86%** | 0.0531 / 0.0548 |
| 25 | 0.0238 | 0.0238 | +0.25% | 0.0238 / 0.0239 |
| 100 | 0.0119 | 0.0119 | −0.10% | 0.0119 / 0.0119 |

**规格那一格 `n = 5` 的 MC 给 0.0548，本库给 0.0536，差 2.17%**。成因不是模型差异，是**二分时用的临界值**：本库用 `z`，若改用 `t(8) = 2.306`，同一构造给 **0.0609**（+14%）。⇒ **「蒙特卡洛值」这个说法不够精确，必须连同它用的检验一起写**。

### 1.3 「需要多少次重复」是公式解，不是经验值

```text
n = 2 · (2.801585218112968 · σ / δ)²
```

| `σ` | 要检出 `δ` | `n`（每组） |
|---|---|---|
| 3% | 3% | 15.70 ⇒ **16** |
| 3% | 1% | 141.28 ⇒ **142** |
| 6% | 3% | 62.79 ⇒ **63** |

两条可推导的比例关系（程序 §B.1 断言）：

- **`n ∝ σ²`**：噪声翻倍 ⇒ 需要的重复次数**翻四倍**；
- **`n ∝ 1/δ²`**：要检出的差异减半 ⇒ 次数**翻四倍**。

**用规格的 `≈ 4σ/√n` 会**：`n` 放大 `(4/2.8016)² = 2.039` 倍 ⇒ 每组从 16 次变 32 次。那个「≈」是保守的，**但代价是真的**。

### 1.4 ★★ 临界值与自由度：同一份数据，三种假阳性率

两组各 `n = 5`、真实差异为 0、单侧检验。**正确的事实是**：`n` 相等且方差相等时，Welch 统计量与合并统计量**代数恒等**

```text
√(s²ₐ/n + s²_b/n) = √((s²ₐ+s²_b)/n) = s_p·√(2/n)        ← 两条路径逐位相同（程序 §C.3 验收）
```

所以统计量**恰好**服从 `t(2n−2) = t(8)`，**假阳性率只由临界值决定**：

| 临界值 | 它是什么 | 理论 `P(t₈ > 临界值)` | 蒙特卡洛 |
|---|---|---|---|
| 1.644854 | `z` 单侧 5% | 6.931% | 6.908% |
| 1.959964 | `z` 单侧 2.5%（**用 z 近似 t**） | 4.283% | 4.221% |
| 2.131847 | `t(4)` 单侧 5% ⇒ **用了一样本自由度 `n−1`** | 3.280% | 3.241% |
| **2.306004** | **`t(8)` 单侧 2.5% ⇒ 本题的正确自由度 `2n−2`** | **2.500%** | **2.503%** |
| 2.776445 | `t(4)` 单侧 2.5%（过严） | 1.203% | 1.210% |

★★ **规格把 `2.132` 标成「t(4) 单侧 2.5%」——标签是错的**：`t(4)` 的单侧 2.5% 是 `2.776`，`2.132` 是 `t(4)` 的 **0.95** 分位（单侧 5%）。

★★ **规格还把这 3.28% 归因于 Welch 自由度「小于 2n−2」——这个机制不成立**：固定的临界值下，假阳性率**完全不涉及自由度**；而且**方向相反**——真的用 Welch 自由度当临界值（均值 `6.853 < 8` ⇒ 临界值均值 `2.3916 > 2.306`）会让检验**更保守**，本库实测 **2.220% < 2.5%**。

> **[C] 级佐证（作用域要写清）**：已发表的模拟研究显示，Welch 近似**没有解析误差界**，在 `n ≤ 20–30` 且两组方差比 `> 2:1` 时**变自由**，观察到的最大第一类错误膨胀 **+58%**；用合并自由度配 Welch 统计量（或反之）**都不稳健** ⇒ Satterthwaite 自由度是必需的。
> ⚠ **本库的等方差情形不受这条影响**（统计量恒等），引用时必须带这个前提——否则就是 P7（引文作用域不匹配）。

### 1.5 显著性不是「效果大」

`δ*` 是**能看见的最小量**，不是**重要的量**。两件事必须分开：

| 问题 | 工具 | 本篇/下一篇的分工 |
|---|---|---|
| 这个差异**看得见**吗 | `δ*` 与检定力（本篇） | 决定「停不停手」 |
| 这个差异**值得做**吗 | 距上界的距离、占总时间的比例（`requirement-discovery`） | 决定「做不做」 |

**[C] 级的一个反例**：arXiv:2607.02541 里 `gelu_triton_buggy`（丢掉一个 0.5 因子，少 8 条指令与 8 个寄存器）在 RTX 3060 上实测 `Δperf% = +3.2%` —— **功能真坏了，性能读数却落在噪声带里、方向还是正的**。⇒ 性能「显著」与功能正确**没有**蕴含关系。

## 2. 落地：三件工具与它们的适用条件

### 2.1 区间估计优先于点估计

报「快了 3%」不如报「快了 3%，95% 置信区间跨过 0」。区间是否跨过 0 是一个**机械可判定**的判据，而点估计需要读者自己补这一步（`δ*` 就是那条「区间刚好不跨 0」的边界）。

### 2.2 离群点与稳健统计量

- **中位数优于均值**：冷启动污染下均值偏差是 `+0.4000` 而中位数是 `+0.0072`（01 篇 §2.2，**相差 56 倍**）。
- **最小值可用于 A/B**：它的偏差与冷启动倍数无关、且在两边抵消（01 篇 §2.2）。官方工具的低分位（`0.2`）是同类做法。
- **[D] 级的机械判据**：hipfire 用 `(max − min)/median > 0.20` 判 `unstable`，**按测量失败处理，不当作胜/负**（**经检索转述**）。
- **[C] 级的两条前提**：NIST TN 1826 指出动态频率特性（Turbo Boost / SpeedStep）**破坏观测的独立同分布假设**，且小样本容易被离群点毁掉。

### 2.3 报显著的**模板**（缺一项即不可判定）

```text
「变体 B 比 A 快 3.1%（每组 n = 25，单侧 t 检验，
  临界值 t(48) = 2.0106，Welch–Satterthwaite 自由度（等 n 等方差时统计量恒等，自由度只影响临界值的取法），
  检定力 80%；δ* = 1.19% ⇒ 3.1% 大于阈值」
```

## 3. ★ 元线索：为什么「过于干净的结果」是采集方式的问题

**三条独立来源指向同一件事**——本域**唯一**一处「本库自身经验与外部经验互相印证」的地方：

| 来源 | 等级 | 内容 |
|---|---|---|
| 本库的 `130-model-optimization` 变异测试记录 | **[E]** | 第一轮跑出「**95/95 全捕获**」，**全是假的**（`verify.py` 里一个 `KeyError` 让每次变异都「被捕获」）；真实轨迹是 **66 捕获 / 29 漏网** → 逐条补强 → **95/95**。⇒ **「一上来就 100%」是最可疑的信号，不是最好的结果** |
| 计时器分辨率 | **[C]**（HPEC / arXiv:1608.04295，已确认同行评审；NIST TN 1826） | 计时器**精度**会把方差压平 ⇒ 读数看起来「确定性」是**测量伪影**；最优重复次数受「准确率 / 精度」之比约束；动态频率特性破坏 i.i.d. |
| 测量偏差的经典研究 | **[C]**（ASPLOS 2009，已确认同行评审） | 只改一个**未被使用**的环境变量大小，性能变化**约 33%、最多近 300%**；只改**链接顺序**就让 `-O3` 看起来比 `-O2` 快 **8%** 或慢 **7%**（**结论翻转**）；调查 **133 篇**论文，**0 篇**充分考虑了测量偏差 |

⇒ **共同结构**：一个「干净得不像话」的结果，第一嫌疑是**采集方式**，不是对象本身的性质。所以本篇 §1.4 那张表的意义不只是「选对临界值」——它同时是一个**体检指标**：如果你报出的假阳性率显著低于名义值，先怀疑阈值、不要庆贺。

## 4. 踩坑与失败模式

### 4.1 用单次测量做判定

**现象**：跑一次新版本、跑一次旧版本，快的那个就是「优化成功」。
**成因**：`δ = 0`、每组 `n = 1` 时，`P(B 更快) = 1/2`（对称分布）。
**规避**：**实测值 49.948%** ⇒ 这不是「有噪声」，是**抛硬币**。

### 4.2 在噪声带内宣称胜利

**现象**：「+3%」被写成「优化成功」。
**成因**：`σ = 3%`、每组 `n = 5` 时 `δ* = 5.97%`（用正确的 `t(8)`）——**3% 连阈值的一半都不到**。
**规避**：先算 `δ*` 再决定要不要报；`n` 按 §1.3 的公式解取。

### 4.3 ★★ 把「确定性输出导致的极低方差」当作「测量很稳」

**现象**：`σ` 看起来极小（甚至为 0），于是「这个数很准」。
**成因**（三个不同的机制，**方向不同**）：

| 机制 | 表现 | 判据 |
|---|---|---|
| 计时器分辨率把抖动压平 | 读数**恒为同一个值**（`σ = 0`），而真实抖动 > 0 | `τ / 真实时间` 与 1 同量级（例：`0.5 / 0.30 = 1.67`）|
| 读数恰好落在**刻度边界**（`T ≈ τ/2`） | `σ` **被高估十几到几十倍** | 读数取值只在 `{0, τ}` 两点上跳（实测 σ 是真实 σ 的 **50 倍**）|
| 输出**真的确定性**（无原子操作、同输入） | `σ = 0` 是真的 | 此时 `δ* = 0`：**任何**被报出来的差异都「显著」——判据本身失效，必须换测量方式 |

**规避**：先算 `τ / 真实时间` 与 `σ_实测 / τ`，**再看结论**；`σ` 反常时（过大或过小）都不下结论。

### 4.4 跨架构外推

见下一篇 §B.3：同一改动在 L40S 是 `+9.4%`、在 A100 SXM4 是 `−50%`（**[C] 级预印本**，措辞用「已有报告显示」）。

## 5. 判据表

| # | 可机械判定的条件 | 结论 |
|---|---|---|
| 1 | 每组只测 1 次就判胜负 | 假阳性率 **50%**（对称分布）⇒ 这不是测量，是抛硬币 |
| 2 | 差异 `δ < (z_{α/2}+z_β)·σ·√(2/n)` | **不可判定**——先加大 `n` 或降噪，再谈结论 |
| 3 | 要用 `δ* ≈ k·σ/√n` | 系数 `k = 2.80`（80% 检定力、α=0.05）；写 **4.0** 会让样本量多 2.04 倍、停止步数变一个数 |
| 4 | 公式里用了 `√(1/n)` | **错**——两组独立样本要用 `√(2/n)`，否则解析值偏小 1.414 倍 |
| 5 | 报「显著」但没写临界值 | **不可判定**——同数据在 `z=1.96`/`t(4)`/`t(8)` 下分别是 4.28% / 3.28% / **2.50%** |
| 6 | 两组 `n` 相等 | 正确自由度是 **`2n − 2`**（Welch 统计量与合并统计量**代数恒等**）；写成 `n − 1` 会把假阳性率抬到 **1.31 倍** |
| 7 | 两组 `n` 不等或方差比 > 2:1 | 用 Welch–Satterthwaite 自由度（它**没有解析误差界**，小样本可能变自由，最大膨胀 +58%）；此时它是**必需**的 |
| 8 | 实测假阳性率**低于**名义值 | 先怀疑阈值/分辨率，**不要**庆贺——过严的门限会把真差异也挡掉 |
| 9 | `σ_实测 = 0` | `δ* = 0` ⇒ **任何**差异都「显著」⇒ 判据失效；先看是不是计时器分辨率压平了 |
| 10 | 计时器分辨率 `τ` 与真实时间同量级 | 一个刻度就是 167% of 真实时间（`τ = 0.5 µs`、`T = 0.3 µs`）⇒ **读数没有分辨力** |
| 11 | 真实时间 ≈ `τ/2` | `σ` 会被**高估几十倍**（本库模型实测 50×）⇒ 真实差异检不出（与上一行**方向相反**，都要防） |
| 12 | 报「快了 X%」 | 同时报 `n`、`σ`、`δ*`、临界值、自由度；缺一项即不可判定 |
| 13 | 想靠增加重复次数解决一切 | `n ∝ σ²` ⇒ 噪声翻倍要多 4 倍样本；分辨率不足时**加样本无用** |
| 14 | 想引用「噪声带 ±N%」 | 必须连**条件与等级**一起写：`±10–15%` 是 **[D] 且限 gfx1100/新进程**；亚毫秒 ±20%/四类是 **[C] 预印本** |
| 15 | 看到「σ 极其干净」的测量 | 检查 `σ` 与 `τ` 的**关系**（不是 `σ` 的大小）：`σ=0`、`σ≈τ`、`σ` 为 `τ` 的整数倍都是伪影的形态 |
| 16 | 把「性能显著改善」当成「功能正常」 | **无蕴含关系**：`gelu_triton_buggy` 功能真坏了，读数还是 `+3.2%`（落在噪声带内）|
| 17 | 给「解析式 vs 蒙特卡洛」定容差 | 用 **`5σ`**，不许用魔数：比例类 `σ_pp = 100·√(p(1−p)/R)`（`R` = 抽样次数）、t 分位数自检用**引文末位的半格**。★ **两个要求一起才能定出 `R`**：容差 ≥ `4σ`（否则**随机失败**）、且要**窄到抓得住该抓的偏移**。例：单次测量那条 `R = 2×10⁵` 时 `4σ = 0.447`，而「把常量改到 50.5」需要容差 `< 0.42` ⇒ **不可能同时满足**，`R` 必须提到 `2×10⁶`（`5σ = 0.177`）。★ 反面教训：容差宽到噪声的 9 倍时，常量在带内漂移 1% 也测不出来 |

**闭合性检查**：读完能判定「这个差异能不能报、该怎么报、σ 可不可信」。**表外输入**是「本批测量的 `σ` 与 `τ`」——它们必须测（材料从同一批数据来）。

## 6. 小结与延伸

- ★★ **单次测量判胜负的假阳性率是 49.948%**——抛硬币，不是「有噪声的结论」。
- ★★ **临界值约定改变结论**：同数据（`n = 5`、`δ = 0`）在 `z=1.96` / `t(4)@0.95` / `t(8)@0.975` 下分别是 **4.28% / 3.28% / 2.50%**；本设计的正确自由度是 **`2n−2`**。
- ★★ **规格的两处错**：`2.132` 被标成「t(4) 单侧 2.5%」（实为 0.95 分位）；把 3.28% 归因于 Welch 自由度（固定临界值下假阳性率与自由度无关，且真用 Welch 自由度会**更保守**：实测 **2.220%**，自由度均值 6.853 < 8）。
- ★★ **`σ = 0` 让判定阈值退化成 0**：`cudaEventElapsedTime` 的 0.5 µs 分辨率配 0.30 µs 的 kernel ⇒ 读数恒为 0.5 µs、`σ` 实测为 0，而一个刻度 = **167% of 真实时间**。
- ★ **`σ` 反常有两个相反方向**：分辨率压平 ⇒ `σ = 0`；落在刻度边界 ⇒ `σ` 被高估 **50 倍**。判据要看 `σ` 与 `τ` 的**关系**。
- ★ **`δ* = 2.80·σ/√n`**：因子是 `√(2/n)`（不是 `√(1/n)`），系数 2.80（不是 4.0 —— 那是 +42.8% 的保守放大，且会改变停止步数）。
- ★ **需要多少次重复是公式解**：`n = 2(2.80σ/δ)²`；`n ∝ σ²`、`n ∝ 1/δ²`。
- ★ **元线索**：本库的「一上来就 100% 是最可疑的信号」（**[E]**）+ 计时器分辨率的测量伪影（**[C]**）+ ASPLOS'09 的测量偏差（**[C]**，133 篇 0 篇考虑）——**三条独立来源**指向同一件事：过于干净的结果通常是采集方式的问题。
