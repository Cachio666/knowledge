# 45-kernel-lifecycle/convergence-and-tuning 的第三方依赖
#
# ★ 本主题**需要 numpy**（与同域的 `operator-design`/`implementation` 相同）；
#   `requirement-discovery` 连 numpy 都没用。启用下面这一行即可：
#   `pip install -r requirements.txt`
#
# ── 为什么三个程序都需要 numpy ────────────────────────────────────────────────
#   · 01 需要构造**池化样本**（`reps × n` 的矩阵一次算三个统计量）并按名次取分位数。
#     这些是「冷启动污染」这个机制的最小可运行模型，与 GPU 无关。
#   · 02 需要**向量化的两样本检验**（几十万次重复的 t 统计量与 Welch 自由度），
#     以及用**分辨率量化**模拟计时器把方差压平的过程。
#   · 03 需要向量化的 A/B 检验来累计「假胜利」次数并统计其**幅度分布**。
#
# ── 本主题**额外自带**的数值工具（不是依赖，是程序内的实现）──────────────────
#   · 02 里有一个 **t 分布**实现（正则化不完全 beta 的连分式展开 + 二分求分位数）。
#     它**不是**第三方依赖：Python 标准库里只有正态分布，而本主题的核心论断之一是
#     「临界值用 z 还是 t 会改变结论」，所以必须自己实现，**并用已知分位数自检**
#     （02 的 §A.4：t(1)/t(2)/t(4)/t(8)/t(30)/t(48) 六档逐条对齐，误差 < 5e-6）。
#     ★ 03 用到的两个每步假阳性率（2.50% / 3.28%）是**解析率**，作为常量放在
#       `specs.py` §7，并注明「与 02 篇同一口径」——**避免把蒙特卡洛噪声误读成模型差异**。
#
# ── 本机的运行条件（写进文档的「编译与运行」小节的测量条件）──────────────────
#   python3 = 3.13.5；numpy = 2.4.4（本机实测，三个程序都在输出里打印实际版本）
#   ★ 本主题**不产出实测性能数字**：本机 macOS 无 GPU，域 README 明令
#     「本域任何一篇都不得声称有实测数据」。
#   ★ 三个程序都用**固定种子**（`SEED = 20260920`；01 另用 SEED+1 生成一批共享稳态样本）
#     ⇒ 输出逐字节可复现。换 numpy 版本可能改变 `default_rng` 的流——
#     若换了版本导致断言失败，先看是不是这一条。
#   ★ 01 的断言容差处处写明**是 MC 噪声还是模型差异**：
#     例：均值的解析式与蒙特卡洛「吻合到 1e-3」而不是「逐位相等」，
#     因为解析式给的是**期望**、蒙特卡洛给的是**样本估计**（残差 ≈ σ/√(reps·m) ≈ 1e-4）。
#
# ── 明确**不**需要的（写出来是为了让「没装」不等于「忘了写」）──────────────────
#   本主题**不 import torch**、不碰 GPU、不需要 CUDA 工具链、不需要 nsight。
#   ★ 提到 `cudaEventElapsedTime` 的地方是**文档层的事实引用**（A 级：NVIDIA 官方文档的
#     0.5 µs 分辨率），本机跑不了它，也不假装跑过。`make lint` 用 `ast` 对
#     「不 import torch」做机械检查。

numpy>=2.0
