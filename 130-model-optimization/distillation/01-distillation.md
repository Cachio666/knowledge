# 知识蒸馏：温度不改变信息，只把「极小概率的比值」放大到能被损失看见

> 蒸馏的损失里有一个 `T²` 因子，几乎每份实现都有它，而**它常被当成调参惯例**。原文给的是**理由**：软目标产生的梯度幅度按 `1/T²` 缩放，所以要乘回来。本机在真 torch 上把这件事量成了可证伪的两条：**带 `T²` 时「软目标梯度/硬目标梯度」在 `T=1…64` 上只漂移 4.0%**；**不带 `T²` 时它按 `1/T²` 塌缩、T=64 时只剩 2.343e-04**。塌缩是**静默的**——于是「调温度」会不知不觉变成「调软硬目标的配比」。另有一条常被写错的引文事实：**2015 年的原论文里根本没有 `α` 这个符号。**

## 0. 背景与动机

[sparsity/01](../sparsity/01-sparsity-granularity.md) 与 [pruning/01](../pruning/01-pruning-criteria.md) 讲的都是**从同一个模型里减去什么**。蒸馏走的是另一条路：**保留一个大模型教出的小模型**。

它在本域的位置由两件事决定：

1. **它是压缩的一条独立路径**——DistilBERT 少 40% 参数、推理快 1.6×，而**不改一个比特的精度**（§3 第一步）；
2. **它能用在已经量化的模型上**——LLM-QAT 用**未量化的预训练模型当教师**，把 4-bit 权重的困惑度从 RTN 的 **151.4** 拉回 **11.6**（§5.5）。

而这条路径的机制与「用比特交换」**无关**：温度不改变任何信息，它只是**换了一个能被损失函数看见的尺度**。

本文要回答四件事：

1. 温度 softmax 是什么、梯度长什么样；
2. ★ **`T²` 从哪来**——原文的理由与它在数值上的可证伪后果；
3. ★ **原论文里没有 `α`**——流传的两种写法的换算是 `β = (1−α)/α`（**不是互为倒数**），引用必须写清是哪一种；
4. ★ **软标签比硬标签多出来的那部分信息是什么**——这是蒸馏**自己的主线**，**不要硬套到比特三角上**。

## 1. 原理

### 第一步：温度 softmax 与它的两个极限

```
q_i = exp(z_i / T) / Σ_j exp(z_j / T)
```

- `T = 1`：普通 softmax。
- `T → ∞`：`q → 均匀分布`。

**训练学生与生成软标签用同一个 `T`，推理时 `T = 1`。** 这两句都要写出来——把两边用不同的 `T` 是实践中真实会犯的错。

### 第二步：损失与梯度

软目标损失（对教师分布 `p` 的交叉熵，等价于到 `q` 的 KL 的一个常数平移）：

```
C = −Σ_i p_i · log q_i,   p = softmax(v/T),  q = softmax(z/T)      （v 教师 logits，z 学生 logits）
∂C/∂z_i = (1/T)·(q_i − p_i)
```

**本机用真 autograd 核对过这一式**（§5.2）：三条温度上最大差都 **< 1e-15**。

⚠ **一个不能省的因子**：实现里软目标损失通常按 **`batchmean`** 归约，于是外面还有一个 `1/B`：

```
∂/∂z_i [ (1/B)·KL(p‖q) ] = (1/T)·(q_i − p_i)/B
```

本机实测：**去掉 `1/B`，解析式的相对误差正好是 `(B−1)/B = 0.75`**（`B = 4`）——这不是小数点后的事，是**四分之三**。

### 第三步：★ `T²` 的来源（原文逐字）

原文的理由是：

> "Since the magnitudes of the gradients produced by the soft targets scale as **1/T²** it is important to multiply them by **T²** when using both hard and soft targets. This ensures that the relative contributions of the hard and soft targets remain roughly unchanged if the temperature used for distillation is changed while experimenting with meta-parameters."

**逐项读一遍**：`∂C/∂z = (1/T)(q−p)`，而高温下 `q − p` 自身还带一个 `1/T`（因为 `q` 相对均匀分布的偏离是 `O(1/T)`）——**合起来是 `1/T²`**。乘回 `T²` 之后，那个「调温度不会顺带改变两个损失项配比」的性质才成立。

> ⚠ **来源档位**：本实现者**没有逐字读到原文**（本轮 `WebFetch` 被策略拦截、`curl` 被 hook 拦截）。
> `WebSearch` 在多个独立站点上取到**逐字相同**的这句，故按「引用值 + 检索佐证」标注。

**它在数值上的后果是可证伪的**（§5.3）：软件目标项写成 `T²·KL` 时，「软目标梯度 / 硬目标梯度」在 `T = 1…64` 上**基本恒定**；写成 `KL` 时**按 `1/T²` 塌缩**。

### 第四步：★ 原论文里**没有 `α` 这个符号**

原文只说损失是两个目标函数的 *"a weighted average of two different objective functions"*，并说 *"best results were generally obtained by using a considerably lower weight on the second objective function"*。**通篇没有 `α`。**

流传很广的两种写法：

| 写法 | 含义 |
|---|---|
| `L = α·CE_hard + (1−α)·T²·KL` | 权重挂在**硬**项上 |
| `L = CE_hard + β·T²·KL` | 权重挂在**软**项上 |

**两者的换算是 `β = (1−α)/α`**——把第一式除以 `α`（常数缩放不改变最优点）即得第二式。`α = 0.5` 时 `β = 1`；`α → 1` 时 `β → 0`。

> ⚠ **不是「互为倒数」。** 倒数是 `1/α`，而这里多减了一个 `1`（`(1−α)/α = 1/α − 1`）。
> 计划基线把这条写成「互为倒数」——**本实现者按上式重算后订正**。
> 所以引用时**必须写清是哪一个约定**；本主题的文档与程序一律写「软目标项的权重」，**不用符号 `α`**。

### 第五步：★ 软标签比硬标签**多出来的那部分信息**是什么

这是蒸馏**自己的主线**，与「用比特交换」无关。

原文的论证：软标签的熵高时，「每个样本提供的信息远多于硬标签，且训练样本间梯度方差小得多」；而关键在于——**「关于所学函数的大部分信息存在于软标签里那些极小概率的比值中」**：

> 一个「2」被给成「3」的概率是 `10⁻⁶`、被给成「7」的概率是 `10⁻⁹`。这个**比值** `10³` 定义了「哪些 2 像 3」的结构；但它对交叉熵的贡献**几乎为 0**（`−log` 在小概率处的绝对数值差异极小）。

⇒ **所以必须升温**：把那些比值抬到损失函数的动态范围里。**温度不改变信息，它改变的是信息的可见性。**

**形式化**：硬标签是软标签的**确定性多对一压缩**（`argmax`），由**数据处理不等式**：

```
I(X; hard) ≤ I(X; soft)
```

——**软标签保有的互信息不少于硬标签**。这是「多出来的那部分信息」的严格说法。

### 第六步：★ 「梯度掉了几倍」**不是一个定律，是一个判据相关量**

`T²·g` 的极限是 `(z − v − mean)/N`（下面 §5.2 有实测）。但「从 `T=1` 到 `T=64` 梯度幅度掉了几倍」这个数**取决于教师的 logit 尺度**：

| 教师 logit 尺度 `σ_v` | `‖g(1)‖/‖g(64)‖`（20 次均值） |
|---|---|
| 0.02（近均匀） | **4097.53** |
| 0.10 | 4120.14 |
| 0.30 | 4296.88 |
| 1.00 | 7025.01 |
| 2.00 | **14473.15** |

**同一个问题，答案从 4098 到 14473**——差 3.5 倍。**唯一可称为「定律」的是渐近值 `64² = 4096`**（`T→∞` 的极限）；有限的比值全部由教师尺度决定。

> ⚠ **报一个「掉了几倍」而不报教师尺度，那个倍数就没有意义**（P9：数都对、来源都对，错在**它们不是同一个量**）。
> 计划基线里记的「≈4216 倍」落在 `σ_v ≈ 0.25` 附近——**是一个具体判据下的一个点**，
> 而那个判据没有写出来，本实现者也无法复现它。**因此本文只给上表**（判据写在 §5.4）。

### 第七步：高温极限等价于「logit 匹配」

`T → ∞` 时 `T²·g → (z − v − mean(z−v))/N`。而 `½·mean((z−v)²)` 对 `z` 的梯度正是 `(z − v)/N`（逐样本）。

⇒ **「直接匹配 logits」（通常被当作一种独立的蒸馏方法）是蒸馏在高温极限下的特例。** 去均值那一项不神秘：softmax 只对 logits 的**差值**敏感，加一个常数不改变 `q`。

## 2. 执行映射

### 2.1 梯度路径上的三个具体对象

| 对象 | 是什么 | 本篇关心什么 |
|---|---|---|
| `torch.nn.functional.softmax(z/T)` | 温度 softmax | 温度**只**进分母；`T=1` 时退化成普通 softmax |
| `torch.nn.functional.kl_div(log_q, p, reduction="batchmean")` | KL 损失 | ★ **`batchmean` 带来一个 `1/B`**；输入必须已经是 `log_softmax` |
| `torch.autograd.grad` | 反传 | 用来**核对** `(1/T)(q−p)/B` 这一式，不是用来「相信」它 |

### 2.2 一个数值量级

本机在 `B = 4`、`N = 1000` 类、`δ ~ N(0, 0.01²)` 上量到：`T = 1` 时软目标梯度与硬目标梯度的比值是 **3.319e-04**；`T = 64` 时（**带 `T²`**）是 **3.186e-04**。

**同一批数在「不带 `T²`」下是 7.777e-08** —— 小 4 个数量级。而这个差别**不会报错、不会 NaN**：损失照样下降，只是**下降的方向不再是你要的那个**（§4.1）。

## 3. 实现与演进

**第一代：Hinton 2015 的软目标。** 教师与学生用同一个 `T`，损失是硬标签交叉熵与软目标项按权重相加，软目标项乘 `T²`。**原文通篇没有 `α`**（§1 第四步）。

**第二代：DistilBERT（2019）——把蒸馏从「模型集成」变成「压缩」。** 三项损失之和：

```
L = L_ce + L_mlm + L_cos
```

**三项，仍然没有 `α`**——这是这一代的特点：**结构化的辅助损失代替了「一个权重超参」**（`L_cos` 是隐状态余弦距离，`L_mlm` 是掩码语言建模）。结果：参数 **66M vs 110M**（少 40%）、推理快 **1.6×**、保留 BERT **96.9%** 的能力（GLUE 77.0/79.5）。

**第三代：TinyBERT（2020）——同时压宽与压深。** 小 **7.5×**、推理快 **9.4×**、GLUE 达到教师的 **96.8%**。它的蒸馏是**逐层**的（教师每一层的隐状态都当监督信号），所以压缩率能上一个量级。

**第四代：把蒸馏用在量化模型上。**

| 工作 | 做法 | 关键数字 |
|---|---|---|
| **LLM-QAT**（arXiv:2305.17888） | ★ **用未量化的预训练模型当教师**，对自己生成的样本做**数据无关**蒸馏 | LLaMA-7B 4-8-4：稠密 **10.4** / RTN **151.4** / SmoothQuant **163.6** / **LLM-QAT 11.6**（WikiText2） |
| **BitDistiller**（**arXiv:2402.10631**） | 3-bit / 2-bit 超低精度，提出 **CAKLD**（置信度感知 KL）做**自蒸馏** | 本文只引编号与定性描述 |

> ⚠ **编号必须写对**：BitDistiller 是 **arXiv:2402.10631**（ACL 2024 long paper）。计划里记的备选号 **2402.19115 是粒子物理论文**——这是一个**纯粹靠检索就能避免、却极易混过去**的错误。
> ⚠ **`DualGraD` 未找到任何来源**（`WebSearch` 零命中）——**不得引用**。

**第五代（本篇范围之外）：** 用稀疏/量化后的模型当教师去教更小的学生，或把蒸馏与剪枝放在同一个 pipeline 里——它们都属于「同一条主线换个组合」。

> ⚠ **演进不等于「越来越准」。** 上面四代的目标函数**互不相同**（软目标 / 三项损失 / 逐层监督 / 置信度感知 KL），**没有一条「哪一种更好」的普适结论**——能确认的只是它们的**损失不同**，而不同的损失会训出不同的学生。

## 4. 踩坑与失败模式

### 4.1 ★ 漏掉 `T²`

**现象**：实现里写 `loss = CE + KL(p_T ‖ q_T)`，调 `T` 时发现「温度越大软目标越不起作用」，于是把温度调小——**而这不是温度的错**。

**成因**：软目标项的梯度按 `1/T²` 缩放。`T = 64` 时它的**有效权重只有 T=1 时的 1/4096**——于是「调 `T`」实际上变成了「调软硬配比」。

**规避**：软目标项乘 `T²`。**判据是可证的**（§5.3）：带 `T²` 时比值在 `T=1…64` 上只漂移 4.0%；不带时塌缩到 2.343e-04。⚠ **`T = 1` 处两种写法逐位相同**——所以在 `T=1` 上做的任何调试**发现不了这个坑**。

### 4.2 把 `T²` 乘到**硬标签项**上

**现象**：看到「梯度按 `1/T²` 缩放」之后，把 `T²` 加到整个损失（或硬项）上。

**成因**：那句话只说了一件事——**软目标产生的梯度**缩放。硬标签项的梯度**不随 `T` 变**。

**规避**：`T²` **只乘软目标那一项**。本机实测：乘错项会让梯度**随 `T` 放大**（`T=1` 时 0.49989、`T=64` 时 2047.6，**方向与塌缩正好相反**）。**两个方向都错，而两者都不会报错。**

### 4.3 引用「原论文里的 α」

**现象**：写「Hinton 原文的损失是 `α·CE + (1−α)·T²·KL`」。

**成因**：这个式子流传太广，几乎所有的二手材料都这么写。**但 `α` 是后来的社区约定**——原文没有这个符号。

**规避**：写「原文说它是一个**加权平均**，并说第二项的权重应当**明显更低**」；要用符号，就**写清是哪种参数化**（两种写法的换算是 `β = (1−α)/α`，**不是互为倒数**）。

### 4.4 把 BitDistiller 的 arXiv 编号写错

**现象**：写 `arXiv:2402.19115`。

**成因**：凭印象记编号。**那一篇是粒子物理的。**

**规避**：写 **arXiv:2402.10631**，并核一次题名（*BitDistiller: Unleashing the Potential of Sub-4-Bit LLMs via Self-Distillation*）。同理：**`DualGraD` 未找到任何来源，不得引用。**

### 4.5 把「`T²·g` 的收敛速率」与「梯度幅度按 `1/T²` 缩放」混为一谈

**现象**：写「`T²·g` 以 `1/T²` 的速率收敛到 `(z−v)/N`」。

**成因**：两句都带 `1/T²`，但说的是**两件不同的事**：
- **「梯度幅度按 `1/T²` 缩放」**：`‖g(T)‖` 与 `‖g(1)‖` 之比 ≈ `1/T²`（这是 §5.3 量到的 4267.5× ≈ 64²）。
- **「`T²·g` 收敛到极限的速率」**：本机实测是 **`O(1/T)`**（`T` 每翻 4 倍，相对误差约掉 4 倍，§5.2）——因为 `q` 相对均匀分布的偏离本身就是 `O(δ/T)`。

**规避**：两个量**分别写、分别给判据**。**结论：两个都对，但它们是两个量。**

### 4.6 把「蒸馏是压缩」当成「蒸馏不损失精度」

**现象**：写「蒸馏能无损压缩模型」。

**成因**：DistilBERT 的 96.9% 与 TinyBERT 的 96.8% 容易被读成「几乎无损」。

**规避**：写**保留率**并给出基线：DistilBERT 的 GLUE 是 **77.0 vs 教师的 79.5**。这是**有损**压缩，只是损失小。

## 5. 实测数据

**测量条件**：Apple M1 Pro（10 核）/ macOS / **CPU-only，无 GPU 数字**；python 3.12.9；**torch 2.11.0**。五个解释器（2.6.0 / 2.7.1 / 2.8.0 / 2.11.0 / 2.13.0）都跑过本篇全部断言，**逐格一致**。数值逐条记在 `code/specs.py`。

> ⚠ 本程序**不训练任何模型**（没有语料、没有 GPU）。下面的「压缩账」是**参数量与配置的算术**，「梯度表」是真的 autograd；**准确率一律是引用值**（§5.5）。

### 5.1 压缩账：**参数量不随层数线性缩**（判据：BERT-base 配置 `vocab 30522 / h 768 / FFN 3072 / 12 层 / 位置 512`）

| 项 | 本程序算出 | 论文印值 |
|---|---|---|
| 每层参数 `4h² + 2h·FFN` | **7.078M** | — |
| embedding `vocab·h + pos·h`（**与层数无关**） | **23.834M** | — |
| 12 层（BERT-base） | **108.8M** | 110M |
| 6 层（DistilBERT） | **66.3M** | 66M |

⇒ **层数比 = 0.500，而参数比 = 0.610**；由配置推出的「少 **39.0%** 参数」≈ 论文自报的 **40%**。**差的那部分全部是 embedding**。

**推理侧是另一个量**：DistilBERT 自报少 40% 参数、快 **1.60×**——**参数量比与提速比不是同一个数**（TinyBERT 上更明显：小 7.5× 而只快 9.4×，两个数不可互换）。

### 5.2 梯度式与极限（判据：`B=4`、`N=1000`、`δ ~ N(0,0.01²)` 且**逐样本零均值**、`σ_v = 0.25`、显式播种）

**（a）`∂KL/∂z = (1/T)(q−p)/B`**（与真 autograd 逐元素比）：

| `T` | 最大差 |
|---|---|
| 1.0 / 4.0 / 64.0 | **< 1e-15**（三条都通过） |

**去掉 `1/B` 的后果**：解析式的相对误差 = `(B−1)/B = 0.75`（`B = 4`）。

**（b）`T²·g → (z − v − mean)/N` 的收敛**（相对误差，判据同上）：

| `T` | 16 | 64 | 256 | 1024 | 4096 |
|---|---|---|---|---|---|
| `max\|T²g − δ/(B·N)\| / max\|δ/(B·N)\|` | 0.022815 | 0.005632 | 0.001403 | 0.000351 | 0.000088 |

**`T` 每翻 4 倍、误差约掉 4 倍 ⇒ 收敛是 `O(1/T)`**（不是 `1/T²`——见 §4.5）。

## 6. 小结与延伸

- ★ **温度不改变信息，它改变信息的可见性**：关于所学函数的大部分信息在软标签里那些**极小概率的比值**中（`10⁻⁶` vs `10⁻⁹`），这些比值对交叉熵几乎无影响——**所以必须升温**。形式化：硬标签是软标签的确定性多对一压缩，`I(X;hard) ≤ I(X;soft)`。
- **梯度是 `(1/T)(q−p)`**（本机与真 autograd 吻合到 `<1e-15`）；按 `batchmean` 归约时**还有一个 `1/B` 不能省**（去掉它相对误差 0.75）。
- ★ **`T²` 不是装饰**：带它时软/硬梯度比在 `T=1…64` 上只漂移 4.0%；**不带时塌缩 4267.5×**。而且**塌缩是静默的**——`T=1` 处两种写法逐位相同，所以那个温度上的调试发现不了它。
- ★ **原论文里没有 `α`**；流传的两种写法换算是 **`β = (1−α)/α`**（**不是互为倒数**），引用必须写清哪一种。
- ★ **「掉了几倍」不是定律**：渐近值 `64² = 4096` 是，有限比值由**教师 logit 尺度**决定（实测 4098 → 14473）。
- **两个都叫「`1/T²`」的量不是同一个**：「梯度幅度按 `1/T²` 缩放」（比值 ≈ 4096）与「`T²·g` 收敛到极限的速率」（实测 `O(1/T)`）。
- **蒸馏的压缩账不按层数线性缩**：DistilBERT 层数减半但参数只减 39%，因为 **embedding 不随层数缩放**。
- **BitDistiller 是 arXiv:2402.10631；DualGraD 来源未定位，不引。**

**延伸**：[13-fake-quant-and-lsq](../quantization/13-fake-quant-and-lsq.md) 给了「让模型适应量化误差」的另一条路（QAT），LLM-QAT 正是把它与蒸馏接在一起。[pruning/01-pruning-criteria](../pruning/01-pruning-criteria.md) 与 [sparsity/01](../sparsity/01-sparsity-granularity.md) 走的是「减去什么」那条线；**本篇是这三篇（稀疏 / 剪枝 / 蒸馏）里唯一不落在比特三角上的那一篇**——它的主线是「软标签多出来的那部分信息是什么」（这是它**自己的主线**，与比特三角无关）。
