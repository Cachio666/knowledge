# 组合的顺序：一条可证伪的判据，以及它在逐组 scale 下的失效

> 「先剪枝再量化」与「先量化再剪枝」不是「看情况」——在**逐张量** scale 下它有一条**充分的**
> 判据：**top-k 边界处没有并列 ⇒ 两序同解**（3000 组随机配置**零反例**）；而把 scale 换成
> **逐组**后，同样的前提下 **2258 / 2523 组两序不同解** ⇒ 这条判据**失效**，
> 此时不存在只看幅值的先验判据，只能直接比较两次掩码。

## 0. 背景与动机

六族可以叠加。叠加时最容易被一句「顺序大致无所谓」带过的，是
**剪枝与量化**这一对——它们动的是同一个张量 `W`，而且**互为对方的输入**：

- 剪枝改变 `W` 的**分布**，而量化要拿这个分布去定 scale；
- 量化改变 `W` 的**幅值**，而剪枝要拿幅值去排序。

于是同一个模型的两种 recipe 会给出两个不同的产物：

| | Recipe A（剪→量） | Recipe B（量→剪） |
|---|---|---|
| 第一步 | 用 `|W|` 选 top-k，得到掩码 `m_A` | 用全量 `W` 定 scale，得到 `Q(W)` |
| 第二步 | 在 `W ⊙ m_A` 上定 scale 并量化 | 用 `|Q(W)|` 选 top-k，得到掩码 `m_B` |

本题**不写「两者有差异」**——那没有信息量。本题把差异的**来源**定位到一处，
给出**可机械判定的条件**，并用程序在 3000 组随机配置上搜证。

示例（程序 B.2，32×64、`G=4`、剪 50% 的**推导值**）：掩码不同的位置 **52** 个；
层输出误差 `‖X(W−W_A)‖ = 139.5918` 而 `‖X(W−W_B)‖ = 140.6054`，比 **1.0073**。
差异存在，但**不是**「顺序总会带来大差异」——下面会看到 3000 组里只有一小部分出差异，
而且差异的来源单一到可以写成一条判据。

## 1. 原理

### 第一步：先把两个算子写死（口径不写死则结论无意义）

$$
Q(W) = \mathrm{rtn}\!\left(\frac{W}{s}\right)\cdot s,\qquad
s = \frac{\max|W|_{\text{scope}}}{q_{\max}},\quad q_{\max} = 2^{b-1}-1
$$

- **`rtn`**：round-to-nearest，**half away from zero**。★ 这一条必须写死：
  `np.round` 是 half-to-even，换一种舍入会移动**并列的位置**——而并列正是本题第 3 步的失效来源本身。
- **`scope`**：`逐张量`（一个 `s`）或 `逐组`（组沿**输入维**连续切，组不跨行）。
- **`P(W)`**：**全局 top-k，只按 `|W|` 取**，`k = (1−frac)·numel`，并列时取**平坦下标较小**者
  （`kind="stable"`）。★ 换成「逐行 top-k」或「按激活加权的判据」都会改变结论。

### 第二步：量化是**单调不减**的映射 ⇒ 同一个 scale 内次序不变

固定 `s` 时，`x ↦ rtn(x/s)·s` 是 `x` 的单调不减函数：
`x₁ < x₂ ⇒ Q(x₁) ≤ Q(x₂)`（只能**相等**，不会反转）。于是

> **在同一个 scale 的作用域内，`|W|` 的次序与 `|Q(W)|` 的次序一致，
> 唯一的例外是量化把两个不同幅值映到同一码（并列）。**

这一步解释了一个常在的实现事实：**`blocksize`（GPTQ 里那个计算批处理）不改变逐元素结果**，
因为它不改变 `s`；而 `group_size` 改变 `s`，于是改变次序——两者是同名不同指的两个旋钮
（正文在 `09-gptq.md`，此处回链）。

### 第三步：全局 top-k 有一个免费性质——**它从不只删掉组内最大值**

设 `m` 是某个组里幅值最大的元素。若组内**还有任一元素 `e` 存活**，则 `|m| ≥ |e|`，
于是 `m` 在全局排序中不低于 `e` ⇒ **`m` 也存活**。反过来：

> **要么一个组的最大值存活，要么这个组被整体删空。没有第三种可能。**

这条性质把评分函数（scale）**钉住**了：组 scale 由组内最大值决定，
而最大值要么活着（scale 不变）、要么整组清零（该组没有元素参与量化）。
⇒ **两序的差异只可能来自「支撑集 `m_A ≠ m_B`」，绝不可能来自「同一支撑上的数值不同」。**

程序把后半句做成了**反向断言**（C.4）：公共支撑上 `W_A` 与 `W_B` 的最大逐元素差
**恰好为 0.000e+00**（B.2）。★ 这条反向断言很重要——它把「差异来自数值」这个
看似合理的解释**排除掉**，否则下面的判据就没有落点。

### 第四步：支撑集何时不同？——只剩**并列跨在边界上**

`m_A` 是 `|W|` 的 top-k，`m_B` 是 `|Q(W)|` 的 top-k。由第二步，
`|Q(W)|` 的次序与 `|W|` **一致到并列为止**。于是：

> 若第 `k` 大与第 `k+1` 大的**量化幅值严格不等**，则两次 top-k 选出的是同一个集合；
> 若它们**相等**（并列恰好跨在边界上），取前 `k` 的规则（`stable` 取小下标）
> 可能把名额给「原本较小的那一个」。

⇒ **判据（per-tensor）**：`边界严格 ⇔ 两序同解`。

程序 A.3 在 **3000 组**随机配置上搜证：**反例 0 个**（「边界严格却不同解」）。
另有 14 组「有并列但仍同解」——这是**合法**的：并列未必真的改变集合
（例如并列的两个都被选中）。

### 第五步：把 scale 换成**逐组**，判据立刻失效

逐组 `s` 让单调性**只在组内**成立。跨组比较幅值时，两个组的步长不同：

$$
|W_i| < |W_j| \quad\text{但}\quad |Q(W_i)| > |Q(W_j)| \quad\text{完全可能}
$$

于是「边界无并列」**不再是充分的**。程序 B.1 / C.1 给出同一前提下的对照（**推导值**）：

| scale 口径 | 「边界严格」的组数 | 其中两序**不同解** | 反例率 |
|---|---|---|---|
| **逐张量** | 119 | **0** | 0% |
| **逐组 `G=4`** | 2523 | **2258** | **89.5%** |

★ 结论不是「逐组更差」，而是：**逐组的可交换性没有先验判据**。
要判断某个具体配置是否可交换，只能**真的比较两次掩码**（`O(numel)` 的检查），
或者干脆把它当成「不知道」——而不能把逐张量的判据套过来。

### 第六步：还有两类失效来源（本题只给判据，实现回链）

上面两条是**纯算术**的。真实流水线里还有两条，它们不出现在本题的模型里，
但必须知道：

1. **带误差补偿的量化**（GPTQ 的逐列补偿 / SparseGPT 的式 7 联合）。
   这时 `Q` 不是逐元素映射，而是**沿列贪心**：补偿量依赖**尚未量化的那些列**，
   而剪枝**移除了其中一部分** ⇒ 补偿的目标函数本身变了。正文在 `09-gptq.md`
   与 `pruning/01-pruning-criteria.md`，此处回链。
2. **判据依赖校准统计量**（Wanda 的 `|W|·‖X_j‖₂`）。若第二步用的是**重新采集**的 `X`
   （跨层误差传播后输入分布已变），则次序判据所依赖的 `‖X_j‖` 也变了。
   ★ 本文**不复现**这一步的漂移——它是**训练/校准流水线**的属性，不是单层算术的属性。

### 第七步：把账与顺序合成选型

选型 = 先按 [02](02-compression-accounting.md) 的账**定位约束**，再按本节的判据**决定顺序**：

| 约束在哪本账 | 该动哪族（按 [02](02-compression-accounting.md) 的归因表） | 与量化组合时的顺序注意 |
|---|---|---|
| decode 的权重字节 | 量化（W4） | — |
| decode 的 KV 字节 | KV 量化 | 与权重量化**互不影响**，可任意顺序 |
| 训练峰值（大头是优化器状态） | PEFT / 蒸馏 | PEFT 与量化正交（一个动训练、一个动推理） |
| prefill 的 FLOPs | 剪枝 / 稀疏 / 低秩 / 蒸馏 | **必须查可交换性**：逐组 scale + 剪枝是 89.5% 出差异的那一档 |
| 参数量本身 | 低秩 / 蒸馏 | 低秩在量化前做，量化 scale 会更「均匀」——但本文**没有**这条断言（未测） |

★ 最后一行特意留了一句「未测」：**低秩分解与量化的顺序**不在本题的程序里，
所以正文**不给结论**——这比给一条没有支撑的「经验上先低秩更好」要诚实。

## 2. 执行映射

- **量化侧的 scale 从哪来**：`torch.ao.quantization` 的 observer 在**校准**阶段
  收集统计量、`convert` 阶段把它们固化成 `s`；推理引擎侧则由 `quant_config`
  （vLLM 的 `--quantization`）选一组已离线算好 scale 的权重与配套 kernel。
  ★ **`s` 是离线算好还是在线算，决定了「先剪后量」有没有意义**：
  离线 `s` 的表在剪枝后**不会自动更新**，于是 recipe A 实际上退化成了 recipe B 的数值。
- **PEFT + 量化的组合**：`peft` 的 `LoraConfig` 配上 `bitsandbytes` 的 4-bit 基座
  （NF4 + double quantization）就是 QLoRA。它的两处算术在本题里都被复算：
  `32/64 = 0.5` → `8/64 + 32/(64·256) = 0.127` bit/参数，**省 0.373**（A.4）；
  含常量后整块宽度是 **4.1270** bit/参数 ⇒ `16/4.1270 = 3.8770×`，**不是 4×**（B.3）。
- **剪枝侧的掩码从哪来**：`torch.topk` / `argsort` 的**取前 k** 是唯一决定支撑集的地方，
  而 `stable` 与并列打破规则决定了「并列时谁活」——这就是 C.2 那个
  「秩 4 的名额给了 6.0 还是 5.9」的最小反例。

**一个数值量级**：示例配置下 `ρ = 0.002`（LoRA 常用的 0.2%，**引用值**）
把训练峰值从 `105.99 GiB` 压到 `18.31 GiB`，而 **decode 峰值不变**（`14.55 GiB`）——
这正是 §1 第七步「PEFT 与量化正交」那一格的算术依据。

## 3. 实现与演进

**第一代：手工 recipe + 相信顺序无关。** 先跑 AutoGPTQ 再跑 LLM-Pruner，
或反过来，都是「两个独立脚本串起来」。如果 scale 是**离线固化**的，
那么顺序事实上由脚本串联顺序决定，且第二条脚本**看不到**第一条的中间状态。

**第二代：写死判据。** 把「scale 的 scope（逐张量 / 逐组 / 逐通道）」与
「掩码的取法（全局 / 逐行 / 激活加权）」当成**接口的一部分**写进配置，
并在流水线里**显式检查**两次掩码是否一致。这一步的产物就是本题的判据：
`边界严格 ⇔ 同解`（逐张量），以及「逐组下没有先验判据，必须直接比较掩码」。

**第三代：联合优化。** 不再把两个算子串起来，而是**同时**决定掩码与量化码
（SparseGPT 的式 7 就是「稀疏 + 量化」联合的一个实例，正文在 `pruning/01-pruning-criteria.md`）。
联合优化**从根上取消了「顺序」这个问题**——代价是它必须自己解决两者耦合后的求解。

## 4. 踩坑与失败模式

### 4.1 现象：同一份代码两次运行，稀疏模式不同

**成因**：并列的打破规则不确定。量化必然产生并列（码值只有 `2^b` 个），
而「取前 k」在并列处需要一个确定性规则；用 `np.argsort(-x)` 的**默认** `kind`
（快速排序）时并列元素的下标次序不保证稳定。

**规避**：掩码一律用 `kind="stable"`，并把**舍入模式**（`rtn` 是 half-away 还是 half-to-even）
写进配置——C.2 那个手造反例的整个构造都建立在这两个口径上。

### 4.2 现象：把「逐张量的可交换判据」套到逐组配置上，结论反了

**成因**：逐组 `s` 只保证**组内**单调；跨组次序会被量化改变（§1 第五步）。
程序给出同一前提下的对照：逐张量反例 `0`，逐组反例 `2258/2523 = 89.5%`。

**规避**：判据必须与 `scope` 绑定。若用逐组/逐通道 scale，
**不要**用「边界是否严格」判断可交换性——直接比较两次掩码。

### 4.3 现象：把「NF4 = 4 bit/参数」写进显存预算，实际超了

**成因**：`4` 是**元素载荷**；常量还要付。double quantization 后常量是
`8/64 + 32/(64·256) = 0.127` bit/参数 ⇒ 整块宽度 `4.1270`（B.3）。
16-bit 对它的比值是 `3.8770×` 而**不是** `4×`；只算载荷会**高估 0.1230×**（C.3）。

**规避**：位宽一律分成两个数写：**载荷**与**整块宽度**。
同一个 4 bit 在「占原始数据」与「占压缩后载荷」两个分母下还差一倍
（见 `sparsity/01-sparsity-granularity.md` 的 metadata 条目）。

### 4.4 现象：把 LoRA 权重合并进基座之后，再量化，误差比预期大

**成因**：QLoRA 的基座是**冻结的量化权重** `W_NF4`，LoRA 走**另一条 16-bit 路径**
（`Y = doubleDequant(c₁,c₂,W_NF4) + X·L₁·L₂`）。一旦合并，`W + BA` 必须**重新量化**，
于是 (a) 量化误差作用在**已经改动过的**权重上，(b) 原来的 `c₁/c₂` 不再匹配新的幅值分布。

**规避**：把「合并」当成一次**新的量化**来评估，而不是当成「把两块加起来」。
★ 本文只给出这条机制与它的出处（QLoRA 式 5/6），**不给倍数**——
合并后的误差增量依赖具体权重，本文没有测它。

## 5. 判据表

| 条件（可机械判定） | 结论 |
|---|---|
| `Q` 是**逐张量**对称 RTN，`P` 是**全局** top-k（只按 `\|W\|`） | 两序**同解 ⇔ top-k 边界无并列**（充分必要；3000 组零反例） |
| `Q` 是**逐组 / 逐通道** scale | **没有**先验判据；必须直接比较两次掩码（逐张量那条判据在此有 89.5% 反例率） |
| 两序的**掩码相同** | 数值逐元素相同（公共支撑上最大差恒为 `0.000e+00`） |
| 两序的**掩码不同** | 差异**只在支撑集**上——不要去找「数值误差」，它不存在 |
| 要判断某个具体配置是否可交换 | 比较 `topk(\|W\|)` 与 `topk(\|Q(W)\|)` 两个集合，`O(numel)` |
| 掩码里有并列 | 必须指定**确定性**打破规则（`stable`）与**舍入模式**（half-away/half-to-even），否则结果不可复现 |
| `Q` 带误差补偿（GPTQ / SparseGPT） | 上面的算术判据**不适用**；顺序效应来自补偿的目标函数变了 |
| 剪枝判据含校准统计量（Wanda 的 `‖X_j‖`）且第二步重新校准 | 算术判据**不适用**；顺序效应来自 `X` 变了 |
| 报 NF4 的位宽 | 载荷 `4`、整块 `4.127` bit/参数；`16/4.127 = 3.877×`，不是 `4×` |
| 低秩分解与量化的顺序 | **本文无结论**（未测）；不要引用本文支持任何一侧 |

## 6. 小结与延伸

- 组合的顺序有**判据**，不是「看情况」：**逐张量 scale 下，边界无并列 ⇔ 两序同解**。
- 判据的**支撑**是一句话：**全局 top-k 从不只删掉组内最大值** ⇒ scale 不变 ⇒
  差异**只**来自支撑集（公共支撑上差值恒为 0）。
- 判据的**边界**也是一句话：**逐组 scale 破坏跨组单调性** ⇒ 判据失效（89.5% 反例率），
  此时只能直接比较掩码。
- 两类**算术之外**的失效来源（误差补偿、重校准）只给判据与出处，正文回链。
- NF4 的「4 bit」是**载荷**；整块宽度是 `4.127`，含常量后 `16/4.127 = 3.877×`。
