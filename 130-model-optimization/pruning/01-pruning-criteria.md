# 剪枝判据：magnitude、SparseGPT、Wanda，以及那条容易被写反的归约关系

> 剪枝的核心不是「剪多少」，是「**先剪谁**」。三条判据的差别可以用一句话概括：magnitude 只看权重，Wanda 加上输入列的范数，SparseGPT 再加一个 Hessian 的逆。三者的关系里有一条**很容易被写反**的式子：在「λ=0 且 Hessian 逆只取对角」两条前提下，**SparseGPT 判据 = Wanda 判据的平方**——**是平方，不是恒等**；而即便是取 sqrt 之后的「恒等」，本机实测到的最大相对差也是 **2.220e-16**，**不是 0.0**（0.0 只在「平方根可精确表示」这个更强的判据下出现）。

## 0. 背景与动机

[sparsity/01](../sparsity/01-sparsity-granularity.md) 说了硬件**只接受** N:M 形状。那么接下来的问题就是：**在必须剪掉一半的前提下，剪哪些元素？**

这个问题有一个看起来很自然的答案：**看权重谁小**。它的失败方式很具体——先看一个对照：

一个线性层 `y = Wx`，校准输入 `X`（`n × d`）里**第 7 列的范数比其它列大一个数量级**（这是 LLM 激活里的常态，叫 outlier 特征）。权重 `W` 第 7 列上的值**不大**。现在要剪掉一半元素：

- 按 **`|W_ij|`** 剪：第 7 列那些「不大」的权重**先被剪掉**；
- 按 **`|W_ij| · ‖X_j‖`** 剪：第 7 列的权重因为乘了 8 倍的列范数，**被保住**。

谁对？**判据是输出误差 `‖X(W − W_pruned)‖`**——本机实测，magnitude 的误差是 Wanda 的 **5.07 倍**（§5.4）。这就是本篇要讲的全部动机：**判据的差别不是学究式的，它直接决定剪完之后网络还剩多少。**

本文回答四件事：

1. 三条判据各自的**公式**与**计算成本**；
2. 它们之间那条**归约关系**——在什么前提下成立、成立到什么程度；
3. ★ **要写清这条关系，必须先写死两个定义**（判据带不带 sqrt、`H` 除不除以 `n`）——本机实测：不写死就写反；
4. 三条判据的**代价**：SparseGPT 比 Wanda 慢多少，以及为什么这个差距**随 `d` 变大**。

落到本文档所属主题的交换三角上，本篇覆盖两条边：**「用二阶信息换舍入决策的质量」**（SparseGPT / Wanda 相对 magnitude）与**「用精度换计算速度」**（Wanda 相对 SparseGPT）。

## 1. 原理

### 第一步：三条判据的公式

设 `X` 是 `(n_samples, d)` 的校准输入，`W` 是 `(d_out, d)` 的权重，`H := X^T X`（**不除以 n**——这条后面会变成一条判据）。

| 判据 | 公式 | 计算成本 | 需校准数据 |
|---|---|---|---|
| **magnitude** | `\|W_ij\|` | `O(1)` / 元素 | 否 |
| **Wanda** | `\|W_ij\| · \|\|X_j\|\|_2` | `O(d^2)` / 层 | **是** |
| **SparseGPT** | `\|W_ij\|^2 / diag((X^T X + λI)^{-1})_j` | `O(d^3)` / 层 | **是** |

`O(1)` 说的是**每个元素的判据值**的代价；另两条说的是**整层**的代价（`d` = 输入维；`O(d^3)` 来自 Hessian 求逆的 Cholesky 预计算）。三者都只需**一次**校准前向——不是迭代优化。

### 第二步：归约关系——**是平方，不是恒等**

当 `H` 是对角阵（即 `X` 的列两两正交）时，`diag(H^{-1})_j = 1/H_jj = 1/‖X_j‖²`，代入 SparseGPT 判据：

```
crit_SparseGPT = |W_ij|² / (1/‖X_j‖²) = |W_ij|²·‖X_j‖² = ( |W_ij|·‖X_j‖ )² = crit_Wanda²
```

于是在两条前提下——**`λ = 0`** 且 **Hessian 逆只取对角**——有：

```
crit_SparseGPT = crit_Wanda²        （在「判据 = |W|²/diag(H⁻¹)」这个定义下）
```

> ★ **这里是最容易写反的一处。** 原文的语气是「Wanda 的判据是 SparseGPT 的**平方根**」，
> 而本计划 §0.7.G 的统计表与本文用的定义下，正确的方向是 **`crit_SparseGPT = crit_Wanda²`**。
> 同一个事实的两种说法**方向相反**——所以**判据的定义必须先写死**：
> 本文（与 `specs.CRITERIA_FORMULA`）取的是 **不带 sqrt 的 `|W|²/diag(H⁻¹)`**。
> 换了定义，这句话的方向就反过来。

**本机实测（§5.2）**：列正交的 `X` 上，`crit_SG / crit_W²` 与 1 的最大相对差 **4.441e-16**（float64 舍入）；换成 `sqrt(crit_SG)/crit_W` 则是 **2.220e-16**。

### 第三步：★「最大相对差 = 0.0」还需要**再加一层判据**

到这里很自然会写一句话：「对两者都取 sqrt 之后，两判据**恒等**，最大相对差 **0.0**」。

**这句话本机复现不出来。** 实测三种构造（都取 sqrt 后比）：

| 构造 | 最大相对差 |
|---|---|
| `H = diag(2^k)`，**k 全为偶数** | **恰好 0.0** |
| `H = diag(2^k)`，k 全为奇数或混合 | 2.220e-16 |
| QR 造的正交列（列尺度跨两个数量级） | **2.220e-16** |

原因不神秘：`sqrt(2^k)` 只有在 `k` 为偶数时**精确可表示**；`sqrt(2^k · w²)` 与 `|w|·sqrt(2^k)` 是两条不同的浮点计算路径，只有前者恰好落到同一个数上时，相对差才是 0。

> **「恰好为 0」不是算子的性质，是判据的产物。**（这条教训在本域是通用的：
> `130-model-optimization` 的 `quantization` 里 QAT 那一组（12–14）也踩过同一个形状——见 [12-ste](../quantization/12-ste.md) 的掩码判据。）
> **判据没写出来的数字，不得与另一个数字并列。**

### 第四步：`H` 除不除以 `n`——同一句话差一个因子

归约关系还依赖 `H` 的定义：

| `H` 的定义 | 关系变成 |
|---|---|
| `H = X^T X`（**本文采用**） | `crit_SG = crit_Wanda²` |
| `H = X^T X / n` | `crit_SG = crit_Wanda² / n` |

本机实测：换成 `H = X^T X / n` 后，`crit_SG/crit_W²` 与 `1/n` 的最大相对差 **1.518e-18**（即确实只是差了一个因子）。**`n = 512` 时两者差 512 倍**——同一句话在两个约定下不是同一个量。

### 第五步：前提去掉任意一条，关系**立刻失效**

两条前提不是装饰。本机实测（判据同上）：

| 去掉哪一条 | `crit_SG = crit_Wanda²` 的最大相对差 |
|---|---|
| 去掉「H 只取对角」（改用一般相关的 `X`） | **0.1896** |
| 去掉「λ = 0」（加 `λ = 1` 的 dampening） | **1.0000** |

**所以「Wanda ≈ SparseGPT」这句话只在特定前提下成立**——而 `λ` 恰恰是实践中为了防止逆塌掉**必须**加的那个数。

### 第六步：一般相关时，两者选出的是不是同一批？

不是完全同一批，但很接近。本机实测（`X` 512×64、`W` 32×64、float64、显式播种；判据见 §5.3）：

| 度量 | 值 |
|---|---|
| top-50% 选中集合重合率（**展平**后 topk 的交集/基数） | **0.9931640625** |
| **逐行** Kendall τ 的均值（O(n²) 数对统计，**并列不计**） | **0.9907614087301587** |
| 同一个 τ 换成**展平**后整体算 | **0.9905139380801172** |
| 逐行 `argsort` 结果**逐元素相等**的行数 | **0 / 32** |

★ 四个数各绑定自己的判据，**不得互换**。最后一行尤其值得注意：**连续值几乎不会精确相等**，所以「`argsort` 完全一致」是一个几乎必然为 0 的度量——**要表达「排名高度一致但非完全相同」，用 τ 并写明它的定义**（逐行还是展平、并列怎么算）。

### 第七步：两者的其他差别（这些差别决定用哪个）

| | SparseGPT | Wanda |
|---|---|---|
| **权重更新** | **有**（用 OBS 的闭式解回补剩余权重） | **没有**（原文：*the pruned LLM can be used as is*） |
| 需校准数据 | **是** | **是**，且**用与 SparseGPT 完全相同的校准集**（C4 里 128 条、长度 2048） |
| 是否同时量化 | ★ **是**——稀疏与量化在**同一个 pass**里联合完成（论文式 7），且「后续剪枝决策受先前量化舍入影响，反之亦然」 | **否** |
| 血统 | 与 GPTQ **同源**：共用列式贪心框架、`H⁻¹` 的 Cholesky 预计算与 lazy batch update | 独立提出，用对角近似换来 `O(d^2)` |

**「SparseGPT 本身就同时做量化」这条最容易被漏掉**：它意味着把 SparseGPT 当成「纯剪枝工具」再单独量化一次，会与论文的设置不同。**Wanda 不做量化。**

算法的存储口径（SparseGPT §4，引用值）：`50% 稀疏 + 4-bit 权重 + 1-bit 位置掩码 = 3 bit/权重`——**与 3-bit 量化同存储量**。这条与 [sparsity/01](../sparsity/01-sparsity-granularity.md) §1 第四步是同一个量（3 bit/元素），可以互相校验。

## 2. 执行映射

### 2.1 判据在代码里的三个具体形态

| 判据 | 一行代码 | 代价落在哪 |
|---|---|---|
| magnitude | `W.abs()` | **纯逐元素**，无归约 |
| Wanda | `W.abs() * X.norm(dim=0)` | 一次**列范数**（`O(n·d)`）+ 一次广播乘 |
| SparseGPT | `(W*W) / torch.diagonal(torch.linalg.inv(X.t() @ X))` | 一次 `XᵀX`（`O(n·d²)`）+ **求逆**（`O(d³)`） |

### 2.2 一个数值量级：代价比**随 `d` 增长**

本机在真 torch 上扫 `d ∈ {128, 256, 512, 1024}`（`n = 256`、`d_out = 64`、float64、取 5 次最小值；判据见 §5.1）：

| `d` | magnitude | Wanda | SparseGPT | SparseGPT / Wanda |
|---|---|---|---|---|
| 128 | 0.002 ms | 0.078 ms | 0.138 ms | **1.8×** |
| 256 | 0.004 ms | 0.118 ms | 0.775 ms | 6.6× |
| 512 | 0.007 ms | 0.139 ms | 3.534 ms | 25.5× |
| 1024 | 0.046 ms | 0.281 ms | 18.015 ms | **64.1×** |

`d` 从 128 到 1024（**8 倍**）的总增长：SparseGPT **130.7×**、Wanda **3.6×**——**两者之比 36.3**。这就是 `O(d³)` 对 `O(d²)` 的可观测签名。

> ⚠ **这三个数在并发负载下会抖**：本机实测把 `repeats` 设成 3 时，6 路并发跑出过 `d=128` 处比值 **0.8×**（空载是 1.8×）。所以程序里的断言写成**跨度**（总增长比 > 4）而不是**逐点单调**——逐点断言在负载下会**假失败**。

## 3. 实现与演进

**第一代：magnitude。** 只看 `|W|`。`O(1)`、无需校准数据、一行代码。`O(1)`、无需校准数据、一行代码。它在**列范数均匀**时几乎与 Wanda 等价（§5.4 的对照组），但在**列范数不均匀**时会系统性丢掉「权重小、但对输出影响大」的元素（§4.1）。

**第二代：Wanda。** 加上 `‖X_j‖₂`，把「这个权重接的是哪个特征」也算进来。代价只多一次列范数——**`O(d²)`**。它**没有任何权重更新**，剪完直接用。

**第三代：SparseGPT。** 把 OBS 的闭式解用起来：`|W|²/diag(H⁻¹)`，并对未剪的权重做**一次**补偿更新。它同时把量化也放进同一个 pass。代价是 `H⁻¹`——`O(d³)` 的求逆加上逐列的 lazy batch update。

**第四代（本主题的范围之外但要知道）：** 把掩码本身变成可学习的（如 SparseGPT 之后的各类「稀疏训练」工作），或把非结构化剪枝配 CPU 引擎（DeepSparse，[sparsity/01](../sparsity/01-sparsity-granularity.md) §1 第五步）。

> ⚠ **演进不等于「越来越准」。** 引用表（Wanda 表 2，LLaMA-2 7B、50% 非结构化、零样本均值）里 magnitude 46.94、SparseGPT 54.94、Wanda 54.21、稠密基线 59.99——**排序是 SparseGPT ≳ Wanda ≫ magnitude**。而 **2:4 那一档 Wanda 稳定落后 SparseGPT 约 1–2 个点**（7B：50.60 vs 48.53）。**两条一起读才是结论**：Wanda 用 `O(d²)` 换来了接近 SparseGPT 的质量，但在**有结构约束**时差距会显出来。

## 4. 踩坑与失败模式

### 4.1 在列范数不均匀时仍然用 magnitude

**现象**：拿 magnitude 判据做 50% 剪枝，用重建误差评估「看起来还行」，部署后精度掉得比预期多。

**成因**：`y = Wx` 里每个元素的影响力是 `|w_ij| · ‖X_j‖`。当各列的 `‖X_j‖` 差一个数量级（LLM 激活的常态），**只看 `|w_ij|` 会在低范数列上过度剪枝**。

**规避**：换 Wanda 判据，或者至少用 `‖X_j‖` 做一次加权对照。本机实测：带 outlier 列时 magnitude 的输出误差是 Wanda 的 **5.07 倍**（§5.4）；**列范数均匀时两者几乎相同（比值 1.0000）**——**触发条件是「列范数不均匀」，不是「用了 magnitude」**。

### 4.2 ★ 把「平方」写成「恒等」，或者把方向写反

**现象**：文档写「Wanda 判据 = SparseGPT 判据在 λ=0 且对角近似下的**平方**」——**方向反了**；或者写「两者恒等」——**在本文的定义下不成立**。

**成因**：三个来源的说法方向不一致（原文语气是「Wanda 是 SparseGPT 的平方根」，计划 §0.7.G 的正文是「SparseGPT = Wanda²」，而计划的 Chunk 7 表里又写成了「Wanda = SparseGPT²」）。**这些说法在各自的定义下都能自洽，混起来就互相否定。**

**规避**：**先写死判据的定义**（带不带 sqrt、`H` 除不除以 `n`），再写结论。本文的定义是 `crit_SG := |W|²/diag(H⁻¹)`、`H := XᵀX`，结论是 **`crit_SG = crit_W²`**。

### 4.3 用随机 `X` 去验归约关系

**现象**：随手造一个 `X = randn(n, d)`，算两个判据，发现 `crit_SG ≠ crit_W²`，于是认为「那条关系是错的」。

**成因**：那条关系的前提是 **`H` 对角**（列正交）。随机 `X` 的 `H` 几乎必然非对角，这是**前提不成立**，不是关系错。本机实测：一般相关的 `X` 上最大相对差 **0.1896**。

**规避**：**用能让假设成立与不成立各出现一次的样本**。本机在编号程序里用的构造是**直接造正交列**（QR 的 `Q` 再按列缩放）——⚠ **注意 `randn @ Q`（右乘正交阵）不会让 `XᵀX` 对角**：它对 `XᵀX` 做的是**相似变换**。这个构造错误本机踩过一次。

### 4.4 把论文的 242×–376× 与本机量到的倍数并列

**现象**：写「SparseGPT 比 Wanda 慢 300 倍」，并把本机的一张 1.8×–64.1× 的表放在旁边当「验证」。

**成因**：**两个数不是同一个量**。论文那一档是 **LLaMA-7B/13B/30B/65B 的整层判据耗时**（A6000），两边同模型同硬件；本机的表是 **`n=256`、`d≤1024` 的合成矩阵**，而且**只算判据本身**。两者在两个维度上都不同（模型规模、是否含下游）。

**规避**：**并列即违规**。要么只引论文那一档（标为引用值），要么只报本机那张表并写明它的判据，**不要合成一句话**。

### 4.5 把逐行 τ 与展平 τ 混用

**现象**：写「两判据的排名一致性是 0.99」，读者复现出 0.9905。

**成因**：τ 有两种口径——**逐行**算再取均值（0.9907614087301587）与把整张判据表**展平**后算（0.9905139380801172）。**两者都对，但不是同一个量。**

**规避**：**把口径写进句子**：「逐行 Kendall τ（O(n²) 数对统计、并列不计）的均值」。本机实测这两个数差 **2.47e-4**——量级很小，但**不能互换引用**。

## 5. 实测数据

**测量条件**：Apple M1 Pro（10 核）/ macOS / **CPU-only，无 GPU 数字**；python 3.12.9；**torch 2.11.0**。五个解释器（2.6.0 / 2.7.1 / 2.8.0 / 2.11.0 / 2.13.0）都跑过本篇全部断言，**逐格一致**。数值逐条记在 `code/specs.py`。

> ⚠ 本章的数字**全部是本机实测值**。准确率表与判据耗时表是**引用值**（§5.5），不在本章。

### 5.1 判据代价值（判据：`n=256`、`d_out=64`、float64、5 次取最小值、显式播种）

| `d` | magnitude | Wanda | SparseGPT | 比值 |
|---|---|---|---|---|
| 128 | 0.002 ms | 0.078 ms | 0.138 ms | 1.8× |
| 256 | 0.004 ms | 0.118 ms | 0.775 ms | 6.6× |
| 512 | 0.007 ms | 0.139 ms | 3.534 ms | 25.5× |
| 1024 | 0.046 ms | 0.281 ms | 18.015 ms | **64.1×** |

**`d` × 8 的总增长**：SparseGPT **130.7×** / Wanda **3.6×** ⇒ 比值 **36.3**（`d³` 对 `d²` 的签名）。
⚠ **负载敏感**：6 路并发时这张表整体漂移（比值区间会变成 0.8×–60×），所以断言写成跨度。

### 5.2 ★ 归约关系（判据：列正交的 `X`，`H := XᵀX` 不除 `n`，**不带 sqrt** 的 `crit_SG`）

| 度量 | 值 |
|---|---|
| `XᵀX` 的非对角元最大值（列正交） | 0.000e+00 |
| `crit_SG / crit_W²` 与 1 的最大相对差 | **4.441e-16** |
| `crit_SG / crit_W` 与 1 的最大相对差（**不取 sqrt、直接比**） | 1.3e+01（**差一个数量级 ⇒ 不是恒等**） |
| `sqrt(crit_SG) / crit_W` 与 1 的最大相对差 | **2.220e-16** |

**「恰好 0.0」的判据依赖**（`H = diag(2^k)`，只换 k 的奇偶）：

| k | 最大相对差 |
|---|---|
| **全偶数** | **0.000e+00** |
| 全奇数 / 混合 | 2.220e-16 |

**`H` 定义的影响**：`H = XᵀX/n` 时，比值与 `1/n` 的最大相对差 **1.518e-18**（`n = 512`）。

**前提去掉任意一条**（同一构造）：非对角 `H` → 最大相对差 **0.1896**；`λ = 1` → **1.0000**。

### 5.3 一般相关 `X` 上的选中一致性（判据：`X` 512×64、`W` 32×64、float64、显式播种）

| 度量 | 判据 | 值 |
|---|---|---|
| top-50% 集合重合率 | 展平后 topk，交集/基数 | **0.9931640625** |
| 逐行 Kendall τ 均值 | 逐行 O(n²) 数对统计，**并列不计**，再取均值 | **0.9907614087301587** |
| 展平 Kendall τ | 整表展平后算同一式 | **0.9905139380801172** |
| `argsort` 逐元素相等的行 | 逐行比较 | **0 / 32** |

**列正交时**：`crit_SG` 与 `crit_W` 互为平方 ⇒ **选中集合完全相同**（掩码逐元素相等，判据：`torch.equal`）。

### 5.4 ★ C 类反例：magnitude 的输出误差（判据：列正交 `X`、第 0 列放大 1/20/100 倍、`W` 16×64 且第 0 列权重 ×0.3、50% 稀疏、量 `‖X(W−W_pruned)‖_F`）

## 6. 小结与延伸

- **三条判据的差别是「把什么算进重要性」**：`|W|` → `|W|·‖X_j‖` → `|W|²/diag(H⁻¹)`。代价从 `O(1)` 到 `O(d²)` 到 `O(d³)`。
- ★ **归约关系是「平方」不是「恒等」**：`crit_SparseGPT = crit_Wanda²`（在 `H` 对角、`λ=0`、判据不带 sqrt 的定义下）。**去掉任一条前提立刻失效**（实测相对差 0.1896 / 1.0000）。
- ★ **「取 sqrt 后恒等」的「0.0」是判据的产物**：本机实测 QR 正交列给 **2.220e-16**，只有「平方根可精确表示」的构造才给**恰好 0.0**。
- **`H` 除不除以 `n` 差一个因子**（`n=512` 时差 512 倍）——写结论前必须先写死定义。
- **一般相关时两者选出 99.32% 相同的元素**（展平 top-50%），逐行 Kendall τ **0.9908**；但 `argsort` 完全相等的行是 **0/32**。
- **magnitude 在列范数不均匀时失效：误差是 Wanda 的 5.07 倍**；列范数均匀时两者相同。**触发条件是数据，不是判据的名字。**
- **SparseGPT 有权重更新、Wanda 没有；SparseGPT 本身就同时做量化**——这两条决定了它们**不是可互换的两个实现**。

**延伸**：[09-gptq](../quantization/09-gptq.md) 是 SparseGPT 的同源兄弟——同一个 `H⁻¹` Cholesky 预计算与列式贪心框架，只是目标换成量化。[distillation/01](../distillation/01-distillation.md) 走的是另一条主线：**不通过剪枝，而是让学生模型去模仿一个更大的教师**——它是这三篇（稀疏 / 剪枝 / 蒸馏）里唯一不参与比特三角的那一篇（这是它**自己的主线**，与比特三角无关）。[sparsity/01](../sparsity/01-sparsity-granularity.md) 给了「剪完之后必须长成什么形状」。
