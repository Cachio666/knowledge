## 1. 原理

### 1.1 「能藏多少」这句话的定义

**记号**（与 [01](01-mechanisms.md) 同一套，★ 无量纲时间单位）：
`C` = 一次计算的总时长、`T` = 一次通信的总时长、`K` = 分块数。

| 量 | 定义 |
|---|---|
| **无重叠值** | `C + T`（两条时间轴**串起来**） |
| **总时间**（流水化后） | ★ `[E]` 级：`cf_pipeline(C,T,K) = (C+T)/K + (K−1)·max(C/K,T/K)` |
| ★★★ **可藏住的通信** | `可藏 = 无重叠值 − 总时间 = min(C, T)·(1 − 1/K)` |

★★ **「能藏多少」= 那个差值**。★ 它是**本库的定义**（`[E]` 级）——
★★ 它**依赖我们选的模型**，所以本文的每一句话都要能追到 `code/specs.py` 或 `code/02_…py`。

### 1.2 ★★★ 可藏的上限 = `min(C, T)`

★★★ **本文的核心结论**（`code/` 的 `A.4` 会在五档上断言它）：

```
可藏的上限 = min(C, T)        （K → ∞ 时取到）
```

★★ **为什么是 `min`**：★ 两条时间轴里**总有一条先跑完**。
**短的那条**跑完之后，**长的那条**再也没有东西可以陪它并行了 ⇒
**能藏住的总量，就是短的那条的长度**。这是**一句话的物理**，没有别的机制。

★★★ **分成两种情形**（★ 这一分是本文的关键）：

| 情形 | 可藏上限 | 暴露在外的通信 |
|---|---|---|
| **计算比通信长**（`C ≥ T`） | `= T` ⇒ **通信能【全】藏住** | 趋近 `0` |
| **通信比计算长**（`T > C`） | `= C` ⇒ **只能藏住「计算那么多」** | **≥ `T − C`**（★ **不可约**） |

★★★ **第二行是本文最容易被读漏的一句**：`T > C` 时，**再多分块也藏不掉 `T − C`** ——
`K` 增大只能把「首项 `C/K`」压小，**压不掉那一段**（★ `code/` 的 `C.1` 判这件事）。

### 1.3 ★★★ 三条免费守卫（判一个流水模型合不合格）

★★★ **这是一条【免费的】判据**（计划 `§D.3` 的 `P35`）：任何「流水化后的时间函数」`f(C,T,K)`
都必须过三关 —— **本机可跑，不需要任何外部来源**：

| # | 守卫 | 它挡住的错 |
|---|---|---|
| ① | **`K = 1` ⇒ 必须等于无重叠值 `C + T`**（★ **逐位**） | 「不开分块居然也能提速」 |
| ② | **`K → ∞` ⇒ 必须等于物理下界 `max(C, T)`** | 「分块能无限提速」 |
| ③ | **中间值不得小于下界 `max(C, T)`** | ★★★ **`P35` 本身**（漏掉首项） |

★★★ **守卫的期望值用的是两条【独立表达式】**（`C + T` 与 `max(C,T)`），**不是被测函数自己** ⇒
★★ **这不是自证**（本库 `§1.3.2b`）。

★★ **本库的模型过三关**（`code/` 的 `A.1`/`A.2`/`A.3`）：
① 在**模拟器**上**逐位**验；② 用 `K = K_INF`（★ **数值替身，不是真的取极限**，容差 `1/100`）；
③ 在**另一个网格**（`HIDE_C_T_GRID` × `HIDE_K_GRID`）上**零下穿**。

### 1.4 ★★★ 本库的 `[E]` 模型 vs 文献形态的差异

★★★ **这一节是计划点出、而【本轮第一次算出具体形态】的那件事**（计划 `§C.5` 的 `F8`）。

**先交代级别**（★ 本库的纪律：**每一条对照都要标级别**）：

| 侧 | 是什么 | 级别 |
|---|---|---|
| **本库的模型** | `max(C,T) + min(C,T)/K` | ★★★ **`[E]`（本库推导）** —— **不是**规范、**不是**论文 |
| **文献侧（Weave）** | 见下 | ★ **`[C]`，但【同行评审：未确认】**（预印本） |

**文献侧的载体**（★ `Weave`，`arXiv 2609.21483`，预印本，抓取日 **2026-10-08**）——
★★ 它的数学式在 arXiv 的 **HTML 版**里以 **LaTeX 的 `alttext` 属性**存在，
**那才是「提取形态」**（★ 与 `network-topology` 的「上标被压平」是同一条纪律）：

> 总时间（式 (7)）：`T_{\text{total}}(c,K)=\max\!\big(T_{\text{comp}}(c,K)+T_{\text{tail}}(c,K),\;T_{\text{comm}}(c)\big).`
> 尾项（式 (10)，分块版）：`T_{\text{tail}}=(1-\alpha)\cdot\frac{W_{\text{combine}}}{\text{BW}(c)\cdot K}.`
> 读法（散文逐字）：`The layer is bounded by whichever of the two paths is slower, plus the unhidden tail.`
> ★ 且原文逐字：分块把尾项**按 `K` 缩小**（`the tail is reduced by a factor of K relative to the unchunked case`）。

★★★ **本库把它化成可比的形态**（★ **这是 `[E]` 级化简**，**三条假设** —— ★ 引用它**必须带这三条**）：
1. **`α = 0`**（尾项完全不被藏）；
2. **忽略 dispatch**；
3. ★★★ **`eff_chunk(K) = 1`** —— 文献侧的计算项**显式依赖 `K`**，原文（`alttext` 逐字）：
   `T_{\text{comp}}(c,K)=\frac{W_{\text{comp}}}{\text{TFLOPS}(N{-}c)\cdot\text{eff}_{\text{chunk}}(K)},`
   且 `where eff_chunk(K)∈(0,1] is the ratio of chunked GEMM throughput to the unchunked case`
   ⇒ ★★ 把它写成与 `K` 无关的常数 `C`，**就额外假设了 `eff_chunk(K) = 1`**
   （★ 这使 `C` 成为**与 `K` 无关的常数**）。

```
文献侧（化简后）:   max(C + T/K, T)
本库（[E]）:        max(C, T) + min(C, T)/K      ← 也就是 max(C + T/K, T + C/K)
```

★★★ **差异的【具体形态】**（`code/` 的 `B.2` 真的算出来，下表是它的输出）——
★★ **它是【分段】的**，不是一个等式：

| `(C,T)` | `K` | 本库 | 文献侧 | 差 | 落在哪一段 |
|---|---|---|---|---|---|
| (12,4) | 2 | 14 | 14 | **0** | `T ≤ C` ⇒ 差 `0` |
| (12,4) | 8 | 12.5 | 12.5 | **0** | `T ≤ C` ⇒ 差 `0` |
| (4,12) | 2 | 14 | 12 | **2** | `T ≥ C·K/(K−1)` ⇒ `min/K` |
| (4,12) | 8 | 12.5 | 12 | **0.5** | `T ≥ C·K/(K−1)` ⇒ `min/K` |
| (7,7) | 2 | 10.5 | 10.5 | **0** | `T ≤ C` ⇒ 差 `0` |
| (7,7) | 8 | 7.875 | 7.875 | **0** | `T ≤ C` ⇒ 差 `0` |
| (1,20) | 2 | 20.5 | 20 | **0.5** | `T ≥ C·K/(K−1)` ⇒ `min/K` |
| (1,20) | 8 | 20.125 | 20 | **0.125** | `T ≥ C·K/(K−1)` ⇒ `min/K` |
| **(4,7)** | 2 | 9 | 7.5 | **1.5** | ★ **`C < T < C·K/(K−1)` ⇒ `(T−C)(1−1/K)`** |
| (4,7) | 8 | 7.5 | 7 | **0.5** | `T ≥ C·K/(K−1)` ⇒ `min/K` |

★★★ **一句话结论（★ 是【分段】的，不是一条等式）**：

```
T ≤ C                ⇒  本库 − 文献侧 = 0                     （两式完全相同）
C < T < C·K/(K−1)    ⇒  本库 − 文献侧 = (T − C)·(1 − 1/K)      ★ 中间段
T ≥ C·K/(K−1)        ⇒  本库 − 文献侧 = min(C, T) / K
★ 且 本库 ≥ 文献侧 恒成立
```

★★★ **特别注意中间段**（`C < T < C·K/(K−1)`）：★ 这里**差【不是】`min(C,T)/K`** ——
例如 `(C,T) = (4,7), K = 2` 时差是 **`3/2`**，而 `min(C,T)/K = 2`。
★ **只有当 `T` 跨过 `C·K/(K−1)`**（`K = 2` 时是 `2C`、`K = 8` 时是 `8C/7`）才取到 `min(C,T)/K`。

★★ **物理读法**（★ **这是本库的读法，不是文献的声称**）：
- 文献形态是 `max(计算工作量 + 尾项, 通信工作量)` —— 它是一个**资源界**
  （两条路谁慢由谁、**再加一个没被藏住的尾项**）；
- 本库的形态**多了【首项】`min(C,T)/K`** —— 那是**「第一块的通信要等它的计算」**的价格；
- ★★ **`T ≤ C` 时两式重合**：那时首项被 `min` 选到**通信侧**，**恰好等于**文献的 `T/K` 项；
- ★★★ **`T > C` 时两式【不】总差 `min(C,T)/K`**：靠近 `T ≈ C` 的**中间段**差得更少
  （`(T−C)·(1−1/K)`）—— 要等 `T` 跨过 `C·K/(K−1)` 才取到 `min(C,T)/K`。

## 4. 踩坑与失败模式

### 4.1 ★★★ `T > C` 时的处置：**暴露在外的通信 ≥ `T − C`**

- **现象**：以为「多分几块，通信总能藏完」；
- **成因**：★★★ 忽略了 **`T > C` 时短的那条轴是【计算】** ——
  计算跑完就**没有东西可陪通信并行了** ⇒ **`T − C` 这一段永远暴露**；
- **本机实测**（`code/` 的 `C.1`）：把「**总时间 = `C`**」（= 通信全藏住）当结论喂进去，
  **在 `T > C` 的三档上【一律被拒】**（★ 它落在物理下界 `max(C,T) = T` 以下）；
  ★ 真实暴露量 **≥ 不可约下限 `T − C`**（实测 `8` · `3` · `19`）；
- **规避**：★★★ **记住两件事**：
  ① **可藏上限 = `min(C,T)`**；② **`T > C` 时，`T − C` 是不可约的暴露量**。

### 4.2 ★★★ 漏掉首项：`C + T/K`（`P35`）

- **现象**：得到**比物理下界还小的「时间」**，程序**不报错**；
- **成因**：把「所有 `K` 块都能重叠」当前提 —— 漏了**第一块的计算与通信无法与任何东西重叠**；
- **本机实测**（`01` 的 `C.1`）：`(3,10,4) ⇒ 5.5 < max(3,10) = 10`；
- ★★★ **它最难防的一面**：**错式在 `T ≤ C` 时【恰好是对的】**
  （那时真值也是 `C + T/K`）⇒ ★ **它的错只在通信主导时显现**；
- **规避**：★★★ **过三条免费守卫**（§1.3）。★ 详细的机制侧正文在 [01](01-mechanisms.md) `§4.1`。

### 4.3 ★★ 把「能藏多少」说成「研究表明」

- **现象**：给 `[E]` 级的模型附一个不存在的外部出处，或写成「研究表明……」；
- **成因**：★★★ **全库没有**这条判据的一手来源（★ 上游也明说不给）——
  而**有一个真实的外部形态存在**（`§1.4` 的 Weave），**容易被顺手当成本库公式的出处**；
- **规避**：★★ **本库的模型标 `[E]`**；★ **若要引外部载体，必须带 URL + 版本 + 抓取日 + 级别**；
  ★★ 并且**把差异写出来**（`§1.4`）—— ★ **「有对照」不等于「有出处」**。

### 4.4 ★★★ 判据「全绿」却【绕开了反例区间】（`P6` 的现场）

- **现象**：`B.2` 的断言一路全绿，于是**以为**「本库 − 文献侧 = `min(C,T)/K`」是个**恒等式**
  （★ 本文 `§1.4` 第一版就是这么写的）；
- **成因**：★★★ 那条等式**只在 `T ≥ C·K/(K−1)` 时成立** —— 而 `HIDE_C_T_GRID` 里两个通信主导档
  `(4,12)` / `(1,20)` **恰好都落在成立区间内** ⇒ ★★ **测试网格【绕开了】反例区间**
  （`T ≤ C` 与中间段 `C < T < C·K/(K−1)`）；
  ★★★ **这不是自证**（断言确实在跑、参照也独立），而是「**核查范围大于实际范围**」
  （本库 `P6`）—— ★ 断言看着覆盖了「差异的形态」，其实只覆盖了它**成立的那一半**；
- **本机实测**：把 `(4,7)`（`K = 2` 时落进中间段 `C < T < 2C`）补进网格 ⇒ 差是 **`3/2`**，
  **不是** `min(C,T)/K = 2` ⇒ 断言**当场会失败**（★ 本轮补进来就是为了让它真的会失败）；
- **规避**：★★★ **别只问「断言在不在跑」，要问「反例区间在不在网格里」** ——
  网格的每一档都要能**落到判据的每个分支上**（★ 本库 `P6`，与 `P1`「订正不扩散」并列）。

### 4.5 ★★ 三个主题的 A 类【共用同一条调度规则】

- ★★ **本文的 A 类（`A.1` / `A.2`）与 [01](01-mechanisms.md) / [03](03-async-io.md) 的 A 类
  共用同一条调度规则**（`do_comm = (ki<K) and (comp[ki] >= C)`）⇒
  **它们共享同一个潜在偏差**（★ 若调度规则本身错，三章会一起错）；
- ★ 缓解是**同主题 [01](01-mechanisms.md) 的 `D.4` 守卫实验**（改坏依赖后结果必须变）。

## 6. 小结与延伸

**一句话**：**一次通信能藏住的上限是 `min(C, T)`** ——
**短的那条时间轴跑完，就没有东西陪它并行了**；
★★ **`T > C` 时，`T − C` 永远暴露在外，分块压不掉它**。

**三条可独立复用的结论**：

1. ★★★ **可藏上限 = `min(C,T)`**，`K → ∞` 时取到；★ 三种性态（计算主导 / 通信主导 / 平衡）；
2. ★★★ **三条免费守卫**：`K=1`⇒无重叠、`K→∞`⇒下界、中间值不下穿 —— ★ **任何**流水模型都要过；
3. ★★★ **本库的 `[E]` 模型与文献形态的差异是【分段】的**：`T ≤ C` ⇒ `0`；
   `C < T < C·K/(K−1)` ⇒ `(T−C)(1−1/K)`；`T ≥ C·K/(K−1)` ⇒ `min(C,T)/K`
   （★ **不是处处等于 `min(C,T)/K`**）—— ★ **「有对照」不等于「有出处」**。
