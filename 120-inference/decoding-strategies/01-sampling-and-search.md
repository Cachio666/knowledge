# 采样与搜索：greedy / beam / temperature / top-k / top-p 的语义差异

> **这几个名字常被并列成一张「采样器」菜单，其实它们分成两族：`greedy` 与 `beam` 是【搜索】，
> `temperature` / `top-k` / `top-p` 是【对同一份分布的三种改写】。**
> 本文要论证的是一条可算的差别 —— ★★ **`top-k` 的候选集大小是【定值】，`top-p` 是【动态】的**；
> 而 **`temperature` 什么候选集也没裁**。
>
> ★★★ **本文不写**：`GQA` / `MQA` / `split-KV`（那是**架构与 kernel 侧**，正文在
> `40-kernels/attention/05-decoding-attention.md` §1.1–1.2）·
> **自回归解码**的 roofline 账（`AI ≈ 1.0`，正文在 `10-foundations/performance-models/01-roofline-model.md:147-155`）。
> ★ **采样参数在某个框架里的名字与默认值也不在本域** —— ★★ **这是一条【边界声明】**：
> 框架侧的采样 API（参数名与默认值）**本库没有任何正文**（`70-frameworks` 的三个主题是
> dispatch / autograd / 内存，**不涉采样**）⇒ ★ **不是「正文在别处」**。
> ★★★ **本层是【解码算法的代数】**。**「不是任何真实引擎，也不是真机」** ——
> 本机**无 GPU、无任何目标 LLM**（实测，见计划 `§0.7 A`）；
> 本文的「模型」是一台**确定性的哈希打分器**，用来让结论**可复现**，它**不是**任何真实 LLM。

## 0. 背景与动机

### 一个具体的对照场景

设**搜索算例**的词表大小 `V = 4`、生成长度 `L = 4`。**自回归解码**每步都要从一份分布里挑一个 token。
「挑法」有五种常见写法，它们在这里的表现如下（同一个模型、同一个前缀）。
★★ **一处符号口径**（★ 一个符号一义）：`V` 是**搜索算例**的词表；而 **§2 的采样算例**用的是两个
**5 元素**分布，其**支集**大小记作 **`nvoc`**（`= 5`）—— ★ **两者不是同一个量**，下文分开写。

| 写法 | 这一步做什么 | 候选集大小 |
|---|---|---|
| **greedy** | 取 `argmax`（**确定性**） | `1` |
| **beam(`B`)** | 保留 `B` 条**候选序列**（**搜索**） | `B`（活束数） |
| **temperature(`T`)** | `softmax(logits / T)`（**重加权**） | **`nvoc`（不变）** |
| **top-k** | 保留概率最高的 `k` 个，再归一化 | **`k`（定值）** |
| **top-p** | 保留累积概率刚过 `p` 的**最小**集合，再归一化 | ★★ **动态**（随分布变） |

★★★ **一眼看不出差别的，是最后两行** —— 两者都「截断」，但一个的**大小是常数**、
一个的**大小是分布的函数**。本文用一台可穷举的玩具模型把这件事**算出来**。

### 为什么值得算这笔账

候选集大小**就是代价**：它决定了每步要保留多少个 token 的概率、要排序多大的数组、
以及在 `beam` 里同时维护多少条序列。★ 而这三件事的**代价形状不同** ——
`temperature` 是**免费的**（不裁任何东西），`top-k` 的代价是**常数**，`top-p` 的代价**随输入变**。
★★ 算出来的是**机制与上界**，不是任何真实模型的性能。

## 1. 原理

### 第一步：把「搜索」写清楚 —— 搜索空间是【可数】的

`greedy` 与 `beam` 都在一棵**树**上走：根是空前缀，每个节点有 `V` 个子节点（词表）。
长度为 `L` 的序列有 `V^L` 条 —— ★★ **这是一个有限的、可以逐条枚举的集合**。
这一条是本文 A 类判据的全部基础：**穷举是「精确搜索」的参照**。

### 第二步：`beam` 的规则与它的代价

`beam(B)` 每步做两件事：
1. 把当前 `B` 条束**各展开** `V` 个子节点（共 `B·V` 个候选）；
2. 按**累计对数概率**排序，**剪枝回 `B` 条**。

⇒ ★★ **每层剪枝后恰好剩 `B` 条**（程序 `B.1` 逐层断言）。

★★ 当 `B ≥ V^L` 时，**剪枝从不发生** ⇒ `beam(V^L)` 保留的就是**全部** `V^L` 条序列
⇒ 它的最优必然等于**穷举**的最优。这是 `A.1`。

### 第三步：`greedy` 是 `beam` 的退化点

`beam(1)` 每步只保留 1 条束 ⇒ 它每步选的**就是 argmax**。
★★ 于是「贪心」不是「另一个算法」，而是**搜索在束宽 1 处的取值**（程序 `A.2`，两条独立实现会合）。

### 第四步：temperature 改的是形状，不是候选集

`p_i(T) = softmax(z / T)_i`。★ 对**任何** `T > 0`，分母都遍历**整个支集**：

```
p_i(T) = exp(z_i/T) / Σ_{j=0}^{nvoc−1} exp(z_j/T)   —— 分母对【全部】nvoc 个 token 求和
```

⇒ ★★★ **`temperature` 一个候选也没裁掉**（程序 `B.3`：候选集大小恒为 `nvoc`）。
它把 `T` 调小使分布**更尖**（熵下降），调大使它**更平**（熵上升）——
★ 但**每步要处理的 token 数不变**。

### 第五步：`top-k` 与 `top-p` 的语义差在【候选集的定义】

```
top-k:  保留概率最高的 k 个              ⇒ 大小 = min(k, nvoc)       （★ 与分布无关）
top-p:  按概率降序累加，保留【累积刚 ≥ p 的最小集合】 ⇒ 大小 = 分布的函数（★ 动态）
```

★★★ **`top-p` 的不变式**（程序 `B.2` 断言它）：设被保留集合的累积概率为 `c`，
则 `c ∈ [p, p + p_max)`（`p_max` 是单个最大概率）—— ★ **下界**是因为「刚过 `p`」，
★ **上界**是因为「去掉最后一项就 `< p`」。

## 2. 执行映射

**请求调度器与本层的关系**：一个**在飞请求**每走一步就要选一个 token，
选法决定了**每步的算术规模**（本文的主题）；而**一步里有多少在飞请求**由调度器决定
（★ 详见 `120-inference/batching-and-scheduling/01-iteration-level-scheduling.md`）。

**采样器（sampler）与本层的关系**：引擎里**把 logits 变成下一个 token** 的那一层 —— ★ 本文的五种
写法就是它的**全部内容**；它的**每步算术规模** ∝ 本文量出来的**候选集大小**（见下）。
★ 这是本文 §2 点名的**第二个系统组件**（第一个是**请求调度器**）。

**★★ 两个「词表大小」不是同一个量（★ 一个符号一义）**：**搜索算例**的词表是 `V = 4`（穷举空间 `V^L`）；
**采样算例**的两个分布是 **5 元素**的（其**支集**大小记作 `nvoc = 5`，程序里 `nvoc = len(peaked)`）——
★ 下面凡涉**采样候选集**的都用 `nvoc`，**不用** `V`。

**（1）四个量级**（本文程序里的算例，`[E]` 级）：

| 组件 | 本文的量级 |
|---|---|
| **玩具词表（搜索算例）** | `V = 4`（★ 真模型的词表**远大于此** —— 本库无来源给出具体量级，**不写数**；这里取小是为了**可穷举**） |
| **穷举空间** | `V^L = 4^4 = 256` 条序列（`A.1` 的参照在此空间上全枚举） |
| **采样算例的支集** | `nvoc = 5`（★ 与 `V` **不是同一个量**；两个分布各 5 个元素） |
| **候选集** | `greedy` 1 · `beam(B)` `B` · `temperature` `nvoc` · `top-k` `k` · `top-p` **动态** |

**（2）★ 五种写法的代价**（程序 `B.1`/`B.2`/`B.3`）：

| 写法 | 每步保留的 token 数 | 形状 |
|---|---|---|
| `greedy` | `1` | 常数 |
| `beam(B)` | `B`（活束数，**逐层钉住**） | 常数（由 `B` 定） |
| `temperature(T)` | **`nvoc`** | ★★ **恒定 —— 不裁任何东西** |
| `top-k` | `min(k, nvoc)` | ★ 恒定 |
| `top-p` | **随分布变**（尖峰 `1` / 均匀 `5`） | ★★ **动态** |

**（3）本文的分布与它们的结果**（`[E]` 级，程序 `B.2` 逐格钉住 ★★ **六个格全钉**）：

| 分布 | `top-p = 0.5` | `top-p = 0.9` | `top-p = 0.95` |
|---|---|---|---|
| **尖峰** `(0.90, 0.05, 0.03, 0.015, 0.005)` | `1` | `1` | `2` |
| **均匀** `(0.2, …, 0.2)` | `3` | `5` | `5` |

★★★ **同一个阈值 `0.9`，在尖峰上给 `1`、在均匀上给 `5`** ——
★★ **这就是「动态候选集」的含义**：它的大小是**输入的函数**，不是配置的函数。
★ 而 `top-k` 在两种分布上都给 `min(k, nvoc)`（此算例里 `= min(k, 5)`）。

**（4）★★★ 这条链的产物是「机制与上界」，不是「真实性能」。**
★★★ **限定语**：「不是任何真实引擎，也不是真机」。
★ **采样参数在某框架里的名字与默认值不在本域** —— ★★ **这是一条【边界声明】（不是「正文在别处」）**：
框架侧的采样 API **本库没有任何正文**（`70-frameworks` 不涉采样）。

## 3. 实现与演进

**第一步：`greedy`。** 每步取 argmax。★ 代价最低（候选集 1），★ **但它会掉进局部最优** ——
★ 程序 `A.3` 实测：**12 个模型里有 8 个**，贪心解出的序列**不是**穷举最优。

**第二步：`beam`。** 维护 `B` 条候选。★ 加宽束能把最优找回来（`m1` 上 `beam(2)` 找回了穷举解），
★★ **但加宽不是万能的** —— 程序 `A.3` 实测：**`beam(2)` 在 12 个模型里仍有 2 个**错过穷举最优。
⇒ ★★★ **`beam` 是【近似搜索】，不是精确搜索**；★ 只有 `B ≥ V^L` 时它才**恰好**等于穷举（`A.1`）。

**第三步：从「搜索」转到「采样」。** `temperature` / `top-k` / `top-p` 不再比较序列分数，
而是**改写这一步的分布**再抽样。★ 三者的分工（`B.2`/`B.3`）：

- **`temperature`**：改**形状**（熵），**不改候选集**；
- **`top-k`**：裁到**定值** `k`；
- **`top-p`**：裁到**动态**大小。

★ **一条同名不同指的消歧**（`§2.2`）：**`batch`** 一词在本库另有「训练的 mini-batch / tile」之义 ——
★ 本文写「**推理批 / 在飞请求数**」全称，**不裸写 `batch`**。
★ 另一条：**`decode`** 在本库另有「数值 decode pass（`60-compilers`）」之义 ——
★ 本文一律写「**自回归解码**」全称。

## 4. 踩坑与失败模式

### 4.1 ★★★ 把 `beam` 当成「精确搜索」

- **现象**：认为「束搜索会找到最优序列」，据此断言产出质量；
- **成因**：★ `beam` 每步**剪枝**，**丢掉的分支不再回来** —— 它只在 `B ≥ V^L` 时才精确；
- **本机实测**（`code/` 的 `A.3`）：**贪心在 8/12 个模型上错过穷举最优**；
  **`beam(2)` 在 2/12 上仍错过**（`m7`/`m9`）；
- **规避**：★★ **要精确就用穷举**（空间可数时）或**记录「这不是最优」**；
  ★ 判据见 §5 第一行。

### 4.2 ★★ 以为 `temperature` 能降低代价

- **现象**：把 `temperature` 与 `top-k` / `top-p` 并列当成「三种减少候选的采样器」；
- **成因**：★ `softmax` 的分母**遍历整个词表** —— `temperature` **一个候选也没裁**；
- **本机实测**（`code/` 的 `B.3`）：`T ∈ (0.5, 1.0, 2.0)` 上**候选集大小恒为 `4`**，
  而**熵单调上升**（`1.203755 → 1.340090 → 1.374964`）；
- **规避**：★★ **分清「重加权」与「截断」** —— 降代价的是 `top-k` / `top-p`，不是 `temperature`。

### 4.3 ★★ 把 `top-p` 的候选集大小当常数

- **现象**：按 `top-p = 0.9` 预先分配一个「最多装 `0.9V` 个」的缓冲区；
- **成因**：★ `top-p` 的集合大小是**分布的函数**：尖峰上 `0.9` 只给 `1` 个、均匀上给 `5` 个；
- **本机实测**（`code/` 的 `B.2`）：同阈值下尖峰 `1`、均匀 `5` —— **差 5 倍**；
- **规避**：★★ **按最坏情况（整个词表）预留**，或**边算边扩**；
  ★ 而 **`top-k` 的 `k` 是常数**，可以静态分配。

### 4.4 ★★ 把 `temperature → 0` 当成「换了一种算法」

- **现象**：认为 `T` 很小时「采样退化成了一种新的贪心」；
- **成因**：★ 它**就是** greedy —— `T → 0` 时 `softmax(z/T)` 的极限把概率全压到 argmax 上；
- **本机实测**（`code/` 的 `B.3`）：取 `T` 极小 ⇒ `softmax(z/T)` 的**最大概率 → `1`**、`argmax` **不变**
  （★ 退化成 argmax 的 delta）；★★ **另一条退化路径**（`top-p → 0` / `k = 1`）**同归于 argmax** ——
  但那两条是 `C.1`/`C.2`（★ **不是**本条 `temperature` 的实测）；
- **规避**：★★ 把「退化点」写成**判据**而不是叙述 —— 见 §5。

## 6. 小结与延伸

**一句话**：**`greedy`/`beam` 是搜索（空间可数 ⇒ 可穷举对拍，且 `beam` 只是【近似】）；
`temperature`/`top-k`/`top-p` 是分布的三种改写 —— 前者只改形状，后两者才裁候选，
而 `top-p` 裁出来的集合大小是【分布的函数】。**

**三条可独立复用的结论**：

1. ★★★ **`beam` 不精确**：贪心错过最优 **8/12**、`beam(2)` 仍错过 **2/12**；
   ★ 只有 `B ≥ V^L`（不剪枝）时才**恰好**等于穷举（`A.1`/`A.3`）；
2. ★★★ **`top-k` 定值 vs `top-p` 动态**：前者恒为 `min(k, nvoc)`，后者随分布变
   （同阈值下尖峰 `1` / 均匀 `5`）；★ 二者都受不变式 `累积概率 ∈ [p, p+p_max)` 约束（`B.2`）；
3. ★★ **`temperature` 不降代价**：候选集**恒为 `nvoc`**，只改熵（`B.3`）；★ 而 `T → 0` 退化到 argmax。
