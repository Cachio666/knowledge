# 投机解码：三条独立路径与三条假设的边界

> **「用一个小草稿模型先写 `γ` 个 token，再让目标模型一次验证」—— 它的加速比有闭式。**
> ★★★ **但那个闭式只在三条明写的前提下落成立**；★★ **一旦接受率随位置变，闭式的偏差
> 【方向由序列形状决定】**（可能低估、也可能高估）。**本文把那三条前提与它的失效方式都算出来。**
>
> ★★★ **本文的载体**：`Leviathan, Kalman, Matias, "Fast Inference from Transformers via
> Speculative Decoding"`（arXiv **2211.17192**，arXiv 提交 2022-11-30）—— **`[C]` 级，同行评审：是**；
> 抓取日 **2026-10-09**（`specs.py` 第 1 节）。
> ★★★ **本机最强的一条限定语：**「**不是任何真实引擎，也不是真机**」——
> 本机**无 GPU、无任何目标 LLM**（实测，见计划 `§0.7 A`）。★★ **闭式里的 `c` 是【硬件与实现的属性】**
> （论文逐字：「the value of `c` depends on the hardware configuration and software implementation details」）
> ⇒ **本机给不出 `c`** —— 本文对 `c` 的一切数字都只是**几何演示**，**不得**称实测。
> ★★ **转写注**：论文 PDF 经 `pdftotext` 抽取时，`α` 的 `γ+1` 次幂被展平为 `αγ+1` 字样 ⇒
> **幂次由上下文与 Figure 2 的分式重排确定**，这是本条唯一的转写环节（`§0.7 C` 事实 13 已显式标注）。

## 0. 背景与动机

### 一个具体的对照场景

**自回归解码**每步产出 1 个 token，且每步都要让**目标模型**跑一次前向。
投机解码换成：让一个**小草稿模型**一次写 `γ` 个 token，再让**目标模型一次**评估这 `γ+1` 个位置
（`γ` 个草稿位置 + 它自己的一步）。**接受的**草稿 token 直接采用，第一个被拒的位置由目标自己产出。

设：`γ` = 草稿长度 · `c` = 草稿单次运行时间 / 目标单次运行时间 · `α` = 平均接受率。
本文的算例：`γ = 4`、`c = 0.25`、`α = 0.8`。

| 量 | 值 | 出处 |
|---|---|---|
| **期望产出 token 数** `E[#tokens]` | **`3.3616`** | `Eq.(1)`（闭式）· 解析 · MC **三者一致** |
| **墙钟加速比** | **`1.6808`** | `Thm 3.8` |
| **`c = 1`（草稿不比目标快）** | **`0.6723 < 1`** | ★★ **负收益**（免费守卫） |

★★★ **第二行与第三行是同一个闭式的两种代入**，但**只有加速比**回答「快了多少」；
★ 而**产出 token 数**回答的是「一次运行写几个」 —— ★ **两者不是同一个量**。

### 为什么值得算这笔账

「草稿一次写 `γ` 个、目标一次验完」听起来白赚。★★ 但目标要评 `γ+1` 个位置 ——
**代价是 `γc + 1`**（草稿写的 `γ` 次 + 目标验的 1 次，按 `c` 折算）。
⇒ **净收益 = 产出 / 代价**，而**两者都随 `γ` 长** ⇒ ★ 存在一个**最优点**（§1 第四步）。
★★ 算出来的是**机制与上界**，不是任何真实系统的加速比。

## 1. 原理

### 第一步：三条独立路径（★ 本域最好的 A 类）

同一个量 `E[#每轮产出 token]`，有三条**互不共享代码**的算法：

| 路径 | 式子 | 适用 |
|---|---|---|
| **闭式**（`Eq.(1)`） | `E[#tokens] = (1 − α^{γ+1}) / (1 − α)` | ★ **仅恒定 `α`** |
| **解析**（精确） | `E[每轮产出] = 1 + Σ_{j=1}^{γ} Π_{i≤j} α_i` | ★ **任意**接受率序列 |
| **蒙特卡洛** | 逐轮取样直到拒绝 | ★ 任意 |

★★ **解析式的读法**：`1` 是**目标模型自己产出的那一个** token；
第 `j` 项是「**前 `j` 个草稿 token 全被接受**」的概率。
★ 当 `α_i ≡ α` 时，`Σ_{j=1}^{γ} α^j = (α − α^{γ+1})/(1 − α)` ⇒
`E = 1 + (α − α^{γ+1})/(1 − α) = (1 − α^{γ+1})/(1 − α)` —— **正是闭式**。

⇒ ★★★ **恒定 `α` 时三条路径必然一致**（程序 `A.1`：闭式与解析在 `1e-12` 内，
MC 在 `4σ` 内）；★★ **`α` 随位置变时闭式不再成立**（第二步）。

### 第二步：★★★ 闭式成立的三条前提（论文逐字）

★★★ **本域最要紧的一条纪律**：**引用闭式必须连这三条前提一起引**（否则是**把条件当无条件**）。

> ① **「the βs are i.i.d.」** —— 接受率**独立同分布**，`α = E(β)`。
> ② **「we'll assume that we can run γ + 1 concurrent evaluations of Mp in parallel
> without increasing the walltime」** —— 有足够算力让 `γ+1` 次评估**并行而不增墙钟**。
> ③ **「long enough generations」** —— 生成**足够长**（否则改进因子被**生成的 token 数**封顶）。

★★ 这三句的逐字文本在 `specs.py` 的 `SPEC_ASSUMPTION_IID_QUOTE` /
`SPEC_ASSUMPTION_CONCURRENCY_QUOTE` / `SPEC_ASSUMPTION_LONG_GENERATION_QUOTE`，
★ 程序 `02` 的 `D.6b` **逐字钉住**它们。

★★★ **前提 ① 被破坏时会发生什么**（程序 `A.2`，本域最有方法论价值的一条）：
让 `α` **随位置变**（**前高后低** vs **前低后高**，**算术平均相同**）：

| 接受率序列 | 算术平均 | 几何平均 | **精确值（解析）** | 闭式（代入算术平均） | 结论 |
|---|---|---|---|---|---|
| **前高后低** `0.9 → 0.5` | `0.7000` | `0.6837` | **`3.2455`** | `2.7731` | ★★ **低估 `14.56%`** |
| **前低后高** `0.5 → 0.9` | `0.7000` | `0.6837` | **`2.2779`** | `2.7731` | ★★ **高估 `21.74%`** |
| **恒定** `0.7` | `0.7000` | `0.7000` | **`2.7731`** | `2.7731` | ★ 一致（这正是闭式的假设） |

★★★ **两条读法**：
1. **同一个算术平均 `0.7` 下，闭式给出【同一个数 `2.7731`】—— 而精确值不同** ⇒
   ★★ **偏差的【方向由序列形状决定】**：**降序 ⇒ 低估**、**升序 ⇒ 高估**；
2. ★★ **几何平均【也修不好】**：代入 `0.6837` 仍偏 **`17.14%`**（**仍是低估**，只是幅度变了）。

★★ **机理**：`E = 1 + Σ Π α_i` 对序列是**多线性**的，而**前缀乘积偏爱「大值在前」**
⇒ **降序**最大、**升序**最小，★ **只看平均值**的闭式落在**中间**。
⇒ ★★★ **只能精确求和** `1 + Σ Π`，**「率」不能代入乘积式**。

### 第三步：三条前提之外，还有两个【负收益】入口

★★ **免费守卫 ①（`c` 这条线）**：`c ≥ 1`（草稿不比目标快）时，闭式**必须**给 `< 1`：

| `c` | 加速比 |
|---|---|
| `0.25`（草稿快 4 倍） | `1.6808` |
| **`1.0`**（同速） | ★ **`0.6723`** |
| **`2.0`**（更慢） | ★ **`0.3735`** |

★★ **免费守卫 ②（`α` 这条线）**：固定 `γ = 4`、`c = 0.25`，解 `加速比 = 1` 得
**收支平衡接受率 `α* = 0.518790063676`** —— ★★ **`α < α*` 就是净亏**
（`α = 0.5` 时 `0.9688 < 1`；`α = 0.1` 时 `0.5556`）。
⇒ ★★★ **即使草稿快 4 倍，接受率 ≲ 0.52 也已经亏了**（程序 `A.4`，二分与线性扫描两条路径）。
★★ **降级声明**（`F4`）：`A.4` 的两条路径**共享目标函数 `closed_speed`** ⇒ 它**只证「根查找」的一致性**，
★ **是 `A.1`/`A.2` 那种「三条互不共享代码的路径」的弱化版** ⇒ ★ **不与它们并列称 A 类**。

### 第四步：`γ` 有一个最优点

`γ` 太小 ⇒ 每轮产出少；`γ` 太大 ⇒ **验证的浪费 `γc+1`** 压过产出。程序 `B.1` 的扫描：

| `γ` | 1 | 2 | **3** | 4 | 6 | 8 | 16 |
|---|---|---|---|---|---|---|---|
| **加速比** | `1.4400` | `1.6267` | ★ **`1.6869`** | `1.6808` | `1.5806` | `1.4430` | ★★ **`0.9775`（已亏）** |

⇒ ★★ **`γ* = 3`**（`α = 0.8, c = 0.25`）；★★ **`γ = 16` 已经 `< 1`** ——
★ 「草稿写长一点总没坏处」是**假的**。
★★ **这张表的七格全部逐格钉住**（程序 `B.1`，**不是只钉最优点**）—— ★ 见 §5 与「编译与运行」。

### 第五步：产出有上界 —— 加长 `γ` 换不来无限产出

★★ 被接受的草稿数**上界**是 `α/(1−α)`（几何级数）：
`E = 1 + 被接受数 → 1 + α/(1−α)`（`γ → ∞`）。本例 `α = 0.8` ⇒ `E → 5.0000`（程序 `B.3`）。
⇒ ★★ **产出不能靠加长 `γ` 无限提高**（这正是第四步那个最优点的来源）。

### 第六步：★ 一处【同名不同指】—— 两条定理是两个量

★★★ **`Thm 3.8` 与 `Thm 3.11` 不是同一个量，且方向相反**：

| 定理 | 给的量 | 式子 |
|---|---|---|
| **`Thm 3.8`** | ★ **墙钟【加速比】** | `(1−α^{γ+1}) / ((1−α)(γc+1))` |
| **`Thm 3.11`** | ★★ **算术运算量【增加】因子** | `(1−α)(γĉ+γ+1) / (1−α^{γ+1})` |

★ 前者 `< 1` 是「变慢」，后者 `> 1` 是「算得更多」—— ★ **引用必须写明是哪一条**（`F10`）。

## 2. 执行映射

引擎层。投机解码在**一步**里做三件事：**草稿跑 `γ` 次** → **目标跑 1 次评 `γ+1` 个位置** →
**从最长被接受的前缀处继续**。

**（1）三个量级**（本文程序里的算例，`[E]` 级）：

| 组件 | 本文的量级 |
|---|---|
| **草稿长度** `γ` | `4`（★ 本算例的取法；★ 不是任何实现的默认） |
| **成本系数** `c` | `0.25`（★ **几何演示值**；★★ **本机给不出 `c`**） |
| **目标前向次数 / 轮** | **`1`**（★ 前提 ② 的那一次「并行评估」） |

**（2）★★★ `c` 不是模型的属性，是【硬件与实现】的属性。**
论文逐字：「unlike α which is an intrinsic property of the models and the task,
the value of `c` depends on the hardware configuration and software implementation details」。
⇒ ★★ **同一对模型换一块卡，`c` 就变了** ⇒ 本文的一切加速比**都带这个前提**。

**（3）★ 前提 ② 是【假设】，不是实现保证。**
论文假设「`γ+1` 次评估并行**而不增墙钟**」。
★ **真实的 GPU 上这一条是否成立取决于 kernel 与批** —— ★ 那部分属别域：
**自回归解码的 roofline 账（`AI ≈ 1.0`）在 `10-foundations/performance-models/01-roofline-model.md:147-155`**
（**正文在彼处，此处只回链**）；`GQA`/`MQA`/`split-KV` 在 `40-kernels/attention/05` §1.1–1.2（**只回链**）。

**（4）★★ 这条链的产物是「机制与上界」，不是「真实性能」。**
★★★ **限定语**：「不是任何真实引擎，也不是真机」；
★ **KV 缓存量化**（推理加速的另一条路）→ `130-quantization/kv-cache-quantization/02,03`（**只回链**）。

## 3. 实现与演进

**第一步：单链草稿 + 验证。** 草稿一次写 `γ` 个 token，目标一次评 `γ+1` 个位置，
接受最长前缀。★ 本文的一切公式都针对**这一形态**。

**第二步：为什么它值得 —— 产出 / 代价。**
`E = 1 + Σ Π α_i`（产出），代价 `γc+1` ⇒ ★ 加速比 = 两者之比（`Thm 3.8`）。
★★ **两端都有守卫**：`c ≥ 1` ⇒ `< 1`；`α < α*` ⇒ `< 1`；`γ` 太大 ⇒ `< 1`。

**第三步：平行分支（候选树）—— ★ 那是下一篇。**
上面是一条**链**（每个位置一个候选）。**下一层**把它换成**树**（每个位置多个候选），
★ 于是「一次前向能接受几个 token」这件事有了新的自由度 ⇒
[03-parallel-decoding](03-parallel-decoding.md)。★ 本文**不重推**树的机制。

★ **一条同名不同指的消歧**（`§2.2`）：**`重算`** 在本库已有三义
（编译器的「物化 vs 重算」· 训练的「重算换显存」· ★ 本域的「**KV 重算**」）——
★ 本文写「**自回归解码**」和「**KV 缓存**」**全称**，**不裸写多义词**。

## 4. 踩坑与失败模式

### 4.1 ★★★ 把闭式当无条件

- **现象**：写「投机解码的加速比是 `(1−α^{γ+1})/((1−α)(γc+1))`」而不带前提；
- **成因**：★★ 它**只在**「`β` i.i.d.」+「`γ+1` 次评估不增墙钟」+「生成足够长」**三条**下成立；
- **本机实测**（`code/` 的 `A.2`）：**同一个算术平均 `0.7`**，前高后低 ⇒ 闭式**低估 `14.56%`**、
  前低后高 ⇒ **高估 `21.74%`**；★ **几何平均也修不好**（仍偏 `17.14%`）；
- **规避**：★★★ **引用连三条前提一起引**；★★ **要精确就精确求和** `1 + Σ Π`（程序 `A.3`）。

### 4.2 ★★★ 把 `Thm 3.11` 与 `Thm 3.8` 混用

- **现象**：把 `(1−α)(γĉ+γ+1)/(1−α^{γ+1})` 当成「加速比」；
- **成因**：★ 那是**算术运算量的增加因子**（`> 1` 表示**算得更多**），与**墙钟加速比**（`< 1` 表示变慢）
  **方向相反**；
- **本机实证**（`specs.py`）：两条式子**分别**钉在 `SPEC_THM38_WALLTIME_FORMULA` 与
  `SPEC_THM311_ARITHMETIC_FORMULA`，★ 程序 `D.6` **两条都逐字断言**；
- **规避**：★★ **写明是哪一条定理** —— 这是一条**可被变异测试抓住**的断言（`F10`）。

### 4.3 ★★ 把 `c` 当成模型的固有属性

- **现象**：引用「`c ≈ 0.25`」当作这对模型的常数；
- **成因**：★★ 论文逐字写了 `c` **取决于硬件与实现**；★ 而 `α` 才是模型与任务的属性；
- **本机条件**（★ **不是「实测」** —— 这是一条**测不出**的条件，`S5`）：★★★ **本机没有 GPU、没有目标模型**
  ⇒ **`c` 给不出** —— 本文所有 `c` 的取值都是**几何演示**；
- **规避**：★★ **凡引用加速比，必须写「`c` 从哪来」**；★ 本库只把它当**输入**，不当结论。

### 4.4 ★★ 以为「草稿写长一点总没坏处」

- **现象**：把 `γ` 调大以期更高加速比；
- **成因**：★ 验证代价是 `γc+1` —— `γ` 大时**验证的浪费**压过产出；
- **本机实测**（`code/` 的 `B.1`）：`γ* = 3` 时 `1.6869`，而 **`γ = 16` 只有 `0.9775 < 1`**；
- **规避**：★★ **`γ` 有内部最优点，且它在 `c` 与 `α` 上** —— ★ 换一组 `(α, c)` 就要重扫。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 见到闭式 `(1−α^{γ+1})/(1−α)` | ★★★ **必须连三条前提一起引**：i.i.d. · `γ+1` 次并行不增墙钟 · 生成足够长（`D.6b`；`F8`） |
| 见到「接受率恒定」 | ★★★ 三条路径一致：闭式 == 解析（`1e-12` 内）、MC 在 `4σ` 内（`A.1`） |
| 见到「接受率随位置变」 | ★★★ **闭式偏了，方向由形状定** —— **降序 ⇒ 低估**（`14.56%`）、**升序 ⇒ 高估**（`21.74%`）；★ **几何平均也修不好**（`A.2`）；★★ **只能精确求和 `1 + Σ Π`**；★★ **失败复现见 `C.4`** |
| 见到「加速比」而不写 `c` | ★★ **不成立**：`c` 是**硬件与实现的属性**，本机**给不出**（`D.6b` / §4.3） |
| 见到 `c ≥ 1` | ★★ **必须 `< 1`**（负收益）：`c=1 → 0.6723`、`c=2 → 0.3735`（`B.2`） |
| 见到「接受率很低但草稿快」 | ★★ **仍然亏**：`α* = 0.5188`（`γ=4, c=0.25`）；`α = 0.5 → 0.9688 < 1`（`A.4`） |
| 见到「把 `γ` 调大」 | ★★ **有最优点 `γ* = 3`**；★★ **`γ = 16` 已经 `< 1`**（`B.1`，★ **七格全钉**） |
| 见到 `Thm 3.11` 的式子 | ★★★ 它是**算术运算量增加因子**，**不是加速比** —— **方向相反**（§1 第六步；`F10`） |
| 见到「`E` 随 `γ` 无限增长」 | ★★ **不成立**：上界 `1 + α/(1−α)` = `5.0`（`B.3`） |
| 见到 `α → 0` | ★ `E → 1`（只剩目标自己那一个，`C.1`） |
| 见到 `α = 1` | ★ `E = γ + 1`（上限，`C.2`） |
| 见到 `γ = 0` | ★ `E = 1`、**加速比 `1`** —— 退化成**自回归解码**（`C.3`） |
| 见到「`decode` / `cache` 裸写」 | ★★ **本域写全称**：「**自回归解码**」/「**KV 缓存**」（`§2.2`） |

## 6. 小结与延伸

**一句话**：**投机解码的加速比有闭式，但那个闭式是【三条前提下的条件结论】；
一旦接受率随位置变，它偏的方向由序列形状决定 —— 降序低估、升序高估，几何平均也修不好。**

**三条可独立复用的结论**：

1. ★★★ **三条独立路径**（闭式 / 解析 / MC）在**恒定 `α`** 下一致；
   ★★ **`α` 随位置变时闭式偏了、方向由形状定**，★★ **几何平均也修不好**（`A.1`/`A.2`）；
2. ★★★ **负收益有两个入口**：`c ≥ 1`（草稿不比目标快）· `α < α* = 0.5188`（接受率太低）；
   ★ 且 `γ` 有**内部最优点** `γ* = 3`（`α = 0.8, c = 0.25`），★ `γ = 16` 已亏（`B.1`/`B.2`/`A.4`）；
3. ★★★ **`c` 是硬件与实现的属性** ⇒ 引用加速比**必须写 `c` 从哪来**（§2(2)）。
