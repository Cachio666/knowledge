# 并行解码：候选树与「验证 / 接受」的机制

> **上一层的草稿是一条【链】（每个位置一个候选）。这一层换成【树】（每个位置多个候选）——
> 目标模型仍然只跑【一次】前向，但接受的 token 可以更多。**
> 本文要把两件事算清楚：**「接受长度」是树上的一个【最长匹配前缀】**，
> ★★ **而它的验证代价是 `1` 次前向，不是「每条候选各一次」**。
>
> ★★★ **本文不写**：`GQA` / `MQA` / `split-KV`（**架构与 kernel 侧**，
> 正文在 `40-kernels/attention/05-decoding-attention.md` §1.1–1.2）·
> **自回归解码**的 roofline 账（`AI ≈ 1.0`，正文在 `10-foundations/performance-models/01-roofline-model.md:147-155`）·
> **投机解码的闭式与三条假设**（那是上一篇，`P37`：**本文不重推**）。
> ★★★ **本层是【解码算法的代数】**。**「不是任何真实引擎，也不是真机」** ——
> 本机**无 GPU、无任何目标 LLM**；本文的「目标 / 草稿模型」都是**确定性哈希打分器**，
> **不是**任何真实 LLM。★ `Medusa` / `lookahead` 只是**同名类的做法**，
> ★ **本文一行也不实现、不 import 它们**（本机**无任何引擎**）。

## 0. 背景与动机

### 一个具体的对照场景

**自回归解码**一步一个 token。**投机解码**（上一篇）让草稿一次写 `γ` 个、目标一次验证。
★ 但一条**链**只有一个候选 —— 第 `j` 个位置**猜错就断**。

**并行解码**把这条链换成**一棵树**：每个节点有若干个**候选子 token**（本文取草稿概率最高的 `b` 个）。
目标的**验证**是一次**沿树的下降**：每一步问「当前节点的子节点里，有没有我（目标）想要的 token」，
有就往下、没有就停。★ **接受的 token 数 = 这次下降走了多深。**

| 形态 | 每个位置的候选数 | 一次前向能接受的 token 数 |
|---|---|---|
| **链**（`b = 1`） | `1` | 平均 **`3.875`**（本文 8 个模型，树深 `6`） |
| **树**（`b = 2`） | `2` | 平均 **`6.000`**（★ **顶到树深**） |

★★★ **两者都只花【一次】目标前向** —— ★ 差别只在**接受长度**（程序 `B.3`）。
★ 这张表是本文的题眼：**并行解码提高的是「每次前向的产出」，不是「每 token 的算力」。**

### 为什么值得算这笔账

「一次前向验证多点东西」听起来只要加候选就行。★★ **但候选树的大小是 `b^D` 条路径**
（`b = 4, D = 6` 时是 `4096` 条）—— ★ 如果每条路径各要一次前向，账就崩了。
**真正的机制是**：目标在一次并行评估里把**整棵树**的每个前缀都评了
（`tree attention`），⇒ ★★ **验证代价是 `1` 次前向、`Σ b^d` 个节点的算术**。
★★ 算出来的是**机制与上界**，不是任何真实模型的吞吐。

## 1. 原理

### 第一步：把「候选树」定义清楚

- **深度** `D`：一次并行步里候选 token 的最大个数；
- **分支** `b`：每个节点有 `b` 个**互不相同**的候选子 token（取自草稿的 top-`b`）；
- **节点数** `Σ_{d=1}^{D} b^d`；**路径数**（根到叶）`b^D`。

★ 本文算例：`D = 6`、`b ∈ {1, 2, 4}` ⇒ 节点数 `(6, 126, 5460)`、路径数 `(1, 64, 4096)`（程序 `B.1`）。

### 第二步：验证 = 一次【沿树的下降】

给定目标模型（每步一个贪心 token `g(前缀)`）：

```
cur ← 根；acc ← 空
重复：
    t ← g(acc)                       # 目标在当前前缀下的下一个 token
    若 cur 的子节点里有 token == t：cur ← 该子节点；acc ← acc + t
    否则：停
接受长度 = len(acc)
```

★★ **它是贪心的下降** —— 每一步只看**一个**候选（目标自己要的那个），
★ 有就下、没有就停。★ 停滞条件不是「候选错了」，而是「**目标的 token 不在候选里**」。

### 第三步：它是【最长匹配前缀】（同样的事，另一条路径）

把树里**所有根到叶的路径**逐条枚举，对每条算「**从根开始的连续匹配长度**」，
取**全局最长** —— ★★ **这与第二步的下降给出同一个序列**（程序 `A.1`：**24 档逐位一致**）。
★★ 两条路径**互不共享代码**（一个查子节点表、一个全枚举），⇒ **这是一条真 A 类**。
★★★ **但 24 档里 `b = V = 4` 的 8 档是【恒真】**（全覆盖 ⇒ 两条路径都被迫给 `D`，`C.2` 已单独证过）——
★ **真正有信息量的是 `b ∈ {1, 2}` 的 16 档**（★ 不要把 24 档**全计**成独立判据）。

### 第四步：链是树的【退化】（`b = 1`）

`b = 1` 时每个节点只有一个子节点 ⇒ 树退化成一条路径 ⇒ ★ **它正是上一篇的草稿链**。
★★ 程序 `A.2` 让**三条路径**（沿树下降 / 路径枚举 / **单链验证**）在 `b = 1` 处会合。

### 第五步：★ 树 ≥ 链，而且接受长度以 `D` 为上限

★★ **候选集在每个位置更大 ⇒ 接受长度只能变多**。程序 `A.3` 实测（8 个模型，`D = 6`）：

| 模型 | `t0` | `t1` | `t2` | `t3` | `t4` | `t5` | `t6` | `t7` | 平均 |
|---|---|---|---|---|---|---|---|---|---|
| **链（`b = 1`）** | `2` | `6` | `6` | `4` | `1` | `0` | `6` | `6` | `3.875` |
| **树（`b = 2`）** | `6` | `6` | `6` | `6` | `6` | `6` | `6` | `6` | **`6.000`** |

★★ **树在每个模型上 `≥` 链**（★ **严格更长**的有 `4/8` 个）；★ `t5` 上链**一个都没接受**，
树却到 `6`。

★★★ **两端（程序 `C.1`/`C.2`/`C.3`）**：
- **根处失配**（根的子节点不含目标的第一个 token）⇒ 接受长度 **`0`**；
- **`b = V`**（每个位置放全词表）⇒ 覆盖率为 1 ⇒ 接受长度 **恒为 `D`**；
- **`D = 1`**（单层树）⇒ 接受长度只能是 **`0` 或 `1`**。
⇒ ★★ 合起来：**接受长度 `≤ D`，且 `D` 只在全覆盖时达到**。

## 2. 执行映射

引擎层。一个并行步里：**草稿一次给出整棵候选树** → **目标一次前向评估全部节点** →
**沿树下降取最长被接受的前缀**。

**（1）三个量级**（本文程序里的算例，`[E]` 级）：

| 组件 | 本文的量级 |
|---|---|
| **树深** `D` | `6`（★ 一次并行步最多接受 `6` 个 token） |
| **分支** `b` | `1`（= 链）/ `2` / `4`（= 全词表，覆盖率 1） |
| **目标前向次数 / 并行步** | **`1`** |

**（2）★★★ 代价账（程序 `B.1`）—— 「省在哪」**：

| 验证路线 | 目标前向次数 | 接受结果 |
|---|---|---|
| **树验证**（一次并行评估整棵树） | **`1`** | ★ 与朴素**相同** |
| **朴素逐条**（每条候选各评一次） | **节点数**（`b=2` 时 `126`） | ★ 与树**相同** |

★★★ **两条路线的接受结果【完全一样】（`A.1` 已证），差别【只在代价】** ——
★ `b = 2` 时是 **`1` 次 vs `126` 次**。⇒ **并行解码省的是【前向的次数】，不是算术量。**

**（3）★ 这条链的产物是「机制与上界」，不是「真实性能」。**
★★ 真实的「一次前向能不能评完整棵树而不增墙钟」取决于 **kernel 与 attention 的实现** ——
★ 那部分属别域：**自回归解码的 attention kernel（`GQA`/`MQA`/`split-KV`）在
`40-kernels/attention/05` §1.1–1.2**；**自回归解码的 roofline 账（`AI ≈ 1.0`）在
`10-foundations/performance-models/01-roofline-model.md:147-155`**（**两处都只回链**）。
★★★ **限定语**：「不是任何真实引擎，也不是真机」。

## 3. 实现与演进

**第一步：链（`b = 1`）。** 那就是**投机解码**的草稿链（★ 详见
[02-speculative-decoding](02-speculative-decoding.md)；★ 本文**不重推**它的闭式 —— `P37`）。

**第二步：多候选（树）。** 让每个位置的候选从一个变成 `b` 个。★ **收益**：接受长度提高
（`t5` 从 `0` 到 `6`）；★★ **代价**：候选成了 `b^D` 条路径 / `Σ b^d` 个节点 ——
★ 但它们**只花一次前向**（`tree attention` 把整棵树一次评完）。

**第三步：为什么这是「并行解码」而不是「投机解码的加强」。**
★ 两者的**验证对象**不同：前者验**一条链**，后者验**一棵树**；
★★ 而**接受规则**都归结为「**最长被接受的前缀**」—— ★ 树只是让它有了**分支**。

★★ **同名类的工程做法**（`Medusa` 的多头草稿、`lookahead` 的迭代式候选）在**别处**，
★ 本机**无任何引擎**，★ 本文**不实现、不 import 它们**；
★ 它们的**机制正文**不在本域（本域只写**解码算法**的代数）。

★ **一条同名不同指的消歧**（`§2.2`）：**`decode`** 在本库另有「数值 decode pass（`60-compilers`）」
之义 —— ★ 本文一律写「**自回归解码**」全称；
★ **`KV 缓存`** 不裸写 `cache`（`L1/L2 cache` 另有其义）。

## 4. 踩坑与失败模式

### 4.1 ★★★ 以为「树验证要跑多次前向」

- **现象**：按候选数（或路径数）估算验证代价，断定并行解码不划算；
- **成因**：★ 把**候选数**当成了**前向次数** ——
  ★★★ 目标是**一次**评估**整棵树**（每个前缀都在同一次并行评估里被评到）；
- **本机实测**（`code/` 的 `B.1`）：`b = 4` 时 **`5460` 个节点、`4096` 条路径**（★ 这两个数是**本机算出**的）；
  ★★ 而「**验证仍只要 `1` 次前向**」是**代价模型**，**不是实测**（★ 见「参考」）；
- **规避**：★★ **把「前向次数」与「节点数」分开写** —— 判据见 §5 第一行。

### 4.2 ★★ 以为「接受 0 个」等于「这一步没有输出」

- **现象**：看到某个并行步接受长度 `0`，认为这一步白跑了；
- **成因**：★ **接受长度只数【草稿 token】** —— 目标模型**自己产出的那一个 token 照样输出**；
- **本机实测**（`code/` 的 `C.1`）：根处失配 ⇒ 接受长度 **`0`**（★ 但这一步**仍产出 1 个 token**）；
- **规避**：★★ **把「接受长度」与「产出 token」分开数**（★ 与 `02` 的 `E = 1 + 被接受数` 同源）。

### 4.3 ★★ 把「路径数」当「节点数」

- **现象**：按 `b^D` 估内存；
- **成因**：★ 树的**节点数**是 `Σ_{d=1}^{D} b^d`，**路径数**（根到叶）是 `b^D` —— 两者**不同**；
- **本机实测**（`code/` 的 `B.1`）：`b = 4, D = 6` ⇒ 节点 `5460`、路径 `4096`；
- **规避**：★★ **写清是哪一个**；★ 验证的**算术**规模看**节点数**，**候选枚举**的规模看**路径数**。

### 4.4 ★★ 以为「分支越大越好」

- **现象**：把 `b` 加到词表大小以上（或以为可无限加）；
- **成因**：★ `b ≤ V`（子 token 互不相同）；★★ 且 `b = V` 时**覆盖率已经到 1**
  （接受长度**恒等于 `D`**）—— 再加**没有对象**；
- **本机实测**（`code/` 的 `C.2`）：`b = V = 4` ⇒ 接受长度 `[6, 6, 6, 6, 6, 6, 6, 6]`（**恒为 `D`**）；
- **规避**：★★ 把**覆盖率**与**树深**分开看 —— ★ 接受长度的上界是 `D`，不是 `b`。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 见到「并行解码要跑多次前向」 | ★★★ **不成立**：**树验证 = `1` 次前向**（`B.1`）；★ 朴素逐条才要**节点数次** |
| 见到「候选树」 | ★★ **接受长度 = 最长匹配前缀**；★★ **沿树下降 == 逐条枚举路径**（`A.1`，24 档逐位一致 —— ★ 其中 `b = V` 的 **8 档恒真**，**有信息量的是 16 档**） |
| 见到 `b = 1` | ★★ **树退化成链** ⇒ 三条路径（下降 / 枚举 / 单链验证）会合（`A.2`） |
| 见到「树比链多接受几个」 | ★★ **树 ≥ 链**；★ 实测平均 `3.875 → 6.000`（`b=1 → b=2`，`D=6`，`A.3`） |
| 见到「接受长度是 0」 | ★★ **不等于没有输出**：目标自己那一个 token **照样产出**（`C.1`） |
| 见到 `b = V` | ★★ **覆盖率为 1** ⇒ 接受长度**恒为 `D`**（`C.2`） |
| 见到 `D = 1` | ★ 接受长度只能是 `0` 或 `1`（`C.3`）—— ★ ★ **接受长度 `≤ D`** |
| 见到「`b^D` 条候选要多少前向」 | ★★ **不是 `b^D` 次**：★ 验证按**节点数**的算术、**一次**前向完成（`B.1`） |
| 见到「路径数 == 节点数」（★ **失败复现**） | ★★ **不成立**：`b ≥ 2` 时 `b^D ≠ Σ b^d`（`b=2`：`64` vs `126`）⇒ **混淆就代价账算错**（`C.4`） |
| 见到「`decode` / `cache` 裸写」 | ★★ **本域写全称**：「**自回归解码**」/「**KV 缓存**」（`§2.2`） |
| 见到「候选树在真实 GPU 上开不开销」 | ★★ **不在本域** —— attention kernel 侧回链 `40-kernels/attention/05` §1.1–1.2；roofline 回链 `10-foundations/performance-models/01:147-155` |

## 6. 小结与延伸

**一句话**：**并行解码把草稿从一条【链】换成一棵【树】——
接受长度成了树上的最长匹配前缀，而目标仍然只跑【一次】前向；
树提高的是「每次前向的产出」，不是「每 token 的算力」。**

**三条可独立复用的结论**：

1. ★★★ **验证 = 最长匹配前缀**：沿树下降与逐条枚举路径**逐位一致**（`A.1`，24 档 —— ★ 其中 `b = V` 的 8 档恒真）；
   ★ `b = 1` 时退化成链，与单链验证会合（`A.2`）；
2. ★★★ **代价是 `1` 次前向**（不是节点数 / 路径数次）：`b = 4` 时 `5460` 节点仍只要 `1` 次前向，
   ★ 树与朴素逐条的**接受结果相同、代价差一个量级**（`B.1`/`B.2`）；
3. ★★ **树 ≥ 链、且接受长度 `≤ D`**：平均 `3.875 → 6.000`；`b = V` 时**恒为 `D`**（`A.3`/`C.2`）。

**延伸**：

- ★★ **投机解码**（链形态 + 三条独立路径 + 三条假设的边界）→ [02-speculative-decoding](02-speculative-decoding.md)；
- ★ **采样与搜索**（greedy / beam / top-k / top-p）→ [01-sampling-and-search](01-sampling-and-search.md)；
- ★★ **`GQA` / `MQA` / `split-KV`**（自回归解码的 attention kernel 侧）→
  `40-kernels/attention/05-decoding-attention.md` §1.1–1.2（**正文在彼处，本文只回链**）；
- ★ **自回归解码的 roofline 账**（`AI ≈ 1.0`）→
  `10-foundations/performance-models/01-roofline-model.md:147-155`（**正文在彼处**）；
- ★ **一层里有多少在飞请求**（并行步与批的关系）→
  `120-inference/batching-and-scheduling/01-iteration-level-scheduling.md`。
