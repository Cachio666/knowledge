# 代价模型：排序能力比绝对值重要

> 有了搜索空间，下一个问题是「怎么不在每个点上真的测一遍」。代价模型就是答案：先在少量实测数据上训一个模型，用它给没测过的配置打分。而衡量它的关键指标不是预测得多准，**是排序排得多对**——本文用 Ansor 的实测数字和本仓库迷你 GBDT 的实跑，说明排序能力可以用一个数（pairwise comparison accuracy）来量化，也说明**一个排得对一半以上的模型，仍然会把搜索带进沟里**。

## 0. 背景与动机

### 本文与主线的关系：**③ 本文不涉及主线**

本域的主线是**物化（materialize）还是重算（recompute）**（口径与完整展开见 [01-search-space](01-search-space.md) §0）。

**本文为什么不在主线上**（选 ③，必须写明理由）：代价模型做的事情是**预测一个已经生成的程序的代价**。它不生成程序、不分配存储、也不决定哪个中间结果被融合掉——那些决策发生在**它上游**的搜索空间构造（[01](01-search-space.md)）与搜索过程（[03](03-search-algorithms.md)）里。

它确实**极大地影响**物化决策的结果（模型错了，搜索就会选错骨架），但「影响」不等于「是那条线的判据或代价项」：一个模型可以完全正确，同时整个搜索空间里根本没有融合骨架可选。**硬把「预测代价」说成「一种物化决策」就是硬凑。**

### 一个具体的对照场景

搜索空间的规模在 [01](01-search-space.md) 里量过了：本仓库的迷你空间有 **4596** 个真正能选的配置。要「不靠模型」地把它们排序，唯一诚实的办法是**逐个测**——4596 次测量。测量本身是**编译 + 执行**，一次几毫秒到几秒，乘上几千个配置就是几小时。代价模型的账就是拿这个换来的：一次训练（在已有数据上）加上每次打分（纯算术，微秒级）。

> Ansor 论文报的**搜索成本**（§7.4 的测量次数与墙钟）是**引用值**，正文位置在 [03-search-algorithms](03-search-algorithms.md) §5.1——**本文只回链、不复制**（CONTRIBUTING §7.1：一个知识点只有一处正文）。本文落正文的引用值只有 §1 第三步的**模型质量**四数（那是代价模型**自身**的性质）。

**但换来的东西有个前提**：模型得比随机排序更对。本文量这个前提，并给出它失效时的样子（§4 + C1 断言）。

## 1. 原理

### 第一步：代价模型要解决什么

搜索过程里有一个循环，代价模型是循环的一部分：

```text
重复：
  1. 从搜索空间里取一批候选程序
  2. 用**代价模型**给它们打分，挑出最值得测的几个
  3. 把挑出来的程序**真的测一遍**（编译 + 执行）
  4. 把新测到的数据并进训练集，重训模型
```

第 2 步是模型唯一的作用：**决定第 3 步测谁**。注意它不产出结论——最终成绩单永远来自第三步的真实测量。所以模型的价值可以用一句话度量：**它挑出来的那几个，比随机挑的那几个好多少。**

### 第二步：Ansor 的模型确切形态

下面六条全部来自论文（逐字处标注），是本仓库迷你 GBDT 对齐的目标：

| 项 | Ansor 的形态 |
|---|---|
| 模型类型 | **gradient boosting decision tree (GBDT)**，引文 [9] 即 **XGBoost**（Chen & Guestrin, KDD 2016） |
| 模型个数 | **所有 DAG 共用一个模型** |
| 训练目标 | Ansor 的设计是拿**硬件上测出来的**程序吞吐当标签，边搜边收集；规模口径是「less than 30,000」个程序 |
| 归一化 | **同一 DAG 内的吞吐归一化到 `[0,1]`** |
| 特征 | **arithmetic features + memory access features**，对每条 **innermost non-loop statement** 抽取 |
| 整程序得分 | **各语句预测之和**（`score(P) = Σ_{s∈S(P)} f(s)`） |
| 损失 | **weighted squared error，权重直接取吞吐 `y`**：逐字 `loss(f,P,y) = y(Σ_{s∈S(P)} f(s) − y)²` |

**★ 最容易说反的一条**（论文逐字，见 `code/specs.py` 的 `ANSOR_NO_INCREMENTAL_UPDATES`）：

> we train a new model every time **instead of doing incremental updates**

**每一轮都是从零重训，不做增量更新。** 循环里第 4 步的「重训」不是「在新数据上继续拟合旧模型」，而是**丢掉旧模型重新拟合**。这条常被写成「模型在线增量学习」——那是另一种设计，不是 Ansor 的。

**为什么「共用一个模型 + 按 DAG 归一化」值得单独指出**：这意味着一个新 DAG 的搜索起点，是**别的 DAG 上量出来的数据**。这是资源上的必然而不是设计偏好（为每个新图从零收集几千个测量点，代价就是 Ansor 论文报的那个量级——数字正文在 [03](03-search-algorithms.md) §5.1）。它的代价是本文 §4 的核心失败模式：**模型没见过这个图的某一类结构时，它会给出一组自信但错误的排序。**

### 第三步：★ 排序能力 vs 绝对值

论文 §7.5 报了一组模型质量的实测数字（**引用值，本仓库不复核其测量口径**）：在 ResNet-50 / Intel CPU 的调优过程中收集的 **25,000** 个程序（20,000 训练 / 5,000 测试）上：

| 指标 | 值 | 读法 |
|---|---|---|
| RMSE | **0.079** | 预测的归一化吞吐与真值平均差 0.079（量程 `[0,1]`） |
| R² | **0.958** | 解释了 95.8% 的方差 |
| **pairwise comparison accuracy** | **0.851** | 随机取两个程序，模型把「更好的那个」排在前面 85.1% 的时间 |
| recall@30 | **0.624** | 真实最好的 30 个里，有多少落进模型排的前 30 |

**本文的核心论点就是这里**：四个数里最关键的是 **pairwise 0.851**。

理由是**搜索怎么用这个模型**：搜索从来不问「这个程序要跑多少毫秒」，它问的是「这两个程序里哪个更值得测」。所以**模型的排序能力**才决定搜索去向，绝对值只在「跨 DAG 比较」或「判断还有多少提升空间」时才需要——而后者恰恰是没人拿它做的事。

反过来说：**0.851 不是满分**。模型每 6–7 次比较里就有 1 次排错。这个数字不吓人，但它意味着**「模型引导的搜索」不是一条只会变好的路**——误差会累积成方向性的偏差，§4 会看到这件事的实跑形态。

> ⚠ **引用值的口径（§0.6）**：上面四个数来自 Ansor 论文 §7.5，**本仓库不复核其测量口径**（那篇论文在其硬件、其实现、其数据集上量出来的）。它们的**正文位置就是本文**（这是代价模型**自身**的性质）；Ansor 的**搜索结果**（§7.4 Table 3 的搜索成本、§7.3 的加速比）的正文位置在 [03-search-algorithms](03-search-algorithms.md) §5，**两处不互相复制**（CONTRIBUTING §7.1）。

### 第四步：训练集的形状——小样本在哪一步开始坑人

把「所有 DAG 共用一个模型」与「每轮从零重训」放在一起，会得到一个不直观的推论：**训练集的构成决定了模型的盲点**。

模型的输入是逐语句特征。凡是**语句局部**的量（这条语句做多少浮点、访存多少字节、向量宽度多大、循环走多少趟）它都看得见。凡是**整程序级**的量——最典型的是「这个程序一共切出多少个块 / 网格有多大」——**从特征里就看不见**。

这不是实现缺陷，是特征**类别**的结果：论文列的两类是「arithmetic features」与「memory access features」，都是对**一条语句**抽取的。

于是：同一个 tile 大小、同一个向量宽度，在 512×512 的图和 128×128 的图上**抽出一模一样的特征**——哪怕前者切出 16 个块、后者只切出 1 个块，而块数不足会直接让 GPU 空转。**模型分不出这两张图。**

> ⚠ **这一条是推断，本文标注为推断**：论文列出的特征**类别**是逐语句的（有逐字依据），但「Ansor 的特征实现里确实不含块数/网格规模」**没有逐字依据**。本文据此设计的 C1 地形（§5）检验的是**这个机制**，不是「Ansor 具体怎么实现」。判据的可证伪性在 §5 逐条写明了。

## 2. 执行映射

这一节回答「这套东西在真实系统上由谁执行、规模是多少」。

**组件一：提升树（`XGBoost` 式的 GBDT）与它的损失。** 损失是**加权**平方误差，权重直接取吞吐 `y`——这不是装饰：它让「高吞吐的程序」在损失里占更大比重，也就是**让模型更在乎把好的程序排对**。本机实测里这一条是可以手算复核的：三个点 `y = [1, 2, 6]`、权重取同一个 `y` 时，单叶模型的输出必须是加权均值 `(1×1 + 2×1 + 6×2) / 4 = 3.75`，而不是算术均值 `3.0`（本仓库的程序把这两个数都打印出来对照）。

**组件二：逐语句的特征抽取。** 一个程序被摊平成「语句 × 特征」的矩阵，整程序得分是各语句预测的**和**。本机实测里这条也是可复核的：把某个配置摊成 2 条语句（矩阵里 2 行），再分别用「按语句循环求和」与「向量化累加」两条路径求和，结果逐项一致（最大差 `0.00e+00`）。

**一个数值量级**：论文的训练集规模口径是「less than 30,000」个程序；本仓库的迷你模型用 **1200** 个程序训练，在 600 个留出程序上的 pairwise 排序准确率是 **0.762**（见 §5）。把训练集缩到 **30** 个程序，同一个留出集上的 RMSE 从 0.160 涨到 **0.470**——这就是「小样本」在数字上的样子。

## 3. 实现与演进

**第一代：解析代价模型（roofline 式）。** 直接按公式算：访存字节数 ÷ 带宽 + 浮点运算数 ÷ 峰值算力，取较大者。它**不需要训练数据**，但要求人把每个算子的字节数与运算数写对——而这恰恰是最容易错的地方（一次布局变换、一次多出来的中间结果往返，公式里就少算了一项）。roofline 本身的正文在 [10-foundations/performance-models/01-roofline-model](../../10-foundations/performance-models/01-roofline-model.md)（回链，本文只代入）。

**第二代：基于搜索的实测（AutoTVM 式）。** 不再预测，直接**测**。代价是 Ansor 论文报的搜索成本那个量级（引用值，正文在 [03](03-search-algorithms.md) §5.1），而且这个成本**随空间大小线性增长**。

**第三代：学习出来的模型（Ansor 式）。** 在已有测量上训一个 GBDT，用它的排序去**决定下一个测什么**。这是本文的主题。它的前提在 §1 第三步写明了：模型的排序能力得比随机好，而且**得在没见过的图上仍然成立**。

**第四代：组件化。** TVM 的 MetaSchedule 把模型做成可替换组件（默认 `XGBModel`），与空间生成（`PostOrderApply`）、搜索（`EvolutionarySearch`）、数据库（`JSONDatabase`）并列。

> ⚠ **「MetaSchedule 是 Ansor 的工程化」是推断，不是引文**（TVM 源码无明文；能核到的是它由独立的 RFC（AutoTensorIR）提出，第三方文献用 `absorbs` / `unifies` 这类等价表述）。Ansor 在 TVM 里的位置、以及 AutoTVM 已被删除这件事，正文在 [tvm/04-auto-scheduling](../tvm/04-auto-scheduling.md)（回链，本文不复制）。

## 4. 踩坑与失败模式

### 坑 1：拿 RMSE 当唯一的模型质量指标

- **现象**：报告「模型 RMSE 0.16」就认为模型合格，不去量它的排序能力。
- **成因**：搜索**只用到排序**（§1 第三步）。一个 RMSE 小但排序乱的模型对搜索毫无价值；反过来，一个绝对值偏差大、但次序基本正确的模型可能非常好用。本机实测里这两个指标的分家很清楚：跨到新图之后 R² 从 0.057 掉到 **−0.162**（绝对值层面已经比「直接猜均值」还差），但 pairwise 只从 0.762 掉到 **0.685**。
- **规避**：报模型质量时**至少同时报 pairwise comparison accuracy 与 recall@K**。Ansor 论文报的就是四个数一起（RMSE / R² / pairwise / recall@30）。

### 坑 2：★ 小样本 + 共享模型 → 模型在搜索后期把搜索带进沟里

- **现象**：模型在别的图上训好，拿到新图上用，搜索**自信地**收敛到一个很差的区域；而且给它加预算它也不出来。
- **成因**：两个机制叠在一起。**其一**，特征里没有网格规模这一项（§1 第四步），所以模型分不出「16 个块」与「1 个块」。**其二**，搜索**只测模型喜欢的点**——它测过的数据全部落在模型偏好的那一侧，重训之后模型对这个盲点**一无所知**，于是下一轮继续挑同一个区域。这是一个自我确认的循环：**模型永远不会学到自己错过了什么。**
- **规避**：这是本文唯一一条「必须真的看到它发生」的失败模式，本仓库的程序把它跑出来了（§5）：在同一个 4596 点空间、同一份预算下，**模型引导的搜索在 3 个冻结种子上全部差于随机搜索**（regret 2.54 / 2.79 / 2.54 对 1.53 / 1.47 / 2.08）。判据必须能因「把模型换成正确的」而翻转——换成完美模型后，同一条搜索流程在 3 个种子上**全部**达到暴力枚举最优（regret 1.00）。**日常的规避手段**：在目标图上做一轮**随机暖机**、或者把模型只当作候选生成器而保留一个固定的随机配额。⚠ **注意：单纯「给搜索加一点探索项」救不回来**——本机实测里把「全空间取模型最优」换成「从 256 个随机候选里取模型最优」，两个变体**都**在全部种子上差于随机搜索（3/3 + 3/3）。原因是探索项只稀释了每次利用的强度，没有改变模型**在该维上排不对**这件事。

### 坑 3：把「每轮重训」理解成「增量更新」

- **现象**：把「模型边搜边训」写成「模型在线增量学习，逐步积累知识」。
- **成因**：论文逐字是 "we train a new model every time **instead of doing incremental updates**"。它是**从零重训**。
- **规避**：本仓库的程序把这条做成了一个可证伪的断言——先 `fit(A)` 再 `fit(B)`，结果必须与「新建一个模型只 `fit(B)`」**逐位相同**。若实现里偷偷保留了旧树（增量更新），这条断言会失败。

## 5. 实测数据

**测量条件**：`code/02_cost_model.py` 在本机 `python3 3.13.5` + `numpy 2.4.4` 上跑出的结果，`cd code && make run` 全绿（28 条断言：A 7 / B 15 / C 6）。

> **★ 限定语（本域强制）**：下面每一个数字都是**本仓库的迷你 GBDT** 在**本仓库人为构造的代价地形**上跑出来的，**不是 Ansor 的代价模型**、**不是 XGBoost**、**不是硬件**。迷你实现借用了 Ansor 的模型形状（GBDT / 共享模型 / 按 DAG 归一化 / 逐语句特征 / 得分求和 / 加权平方误差 / 每轮重训）以便对照，**树的棵数、深度、叶子下限、特征的具体构成、两个 DAG 的尺寸、代价地形的全部常数都是本仓库自己定的**。这些数字支持的是「一个学习出来的排序器可以怎样被训练、以及它的盲点会怎样改变搜索结果」这类**机制**结论，**不支持任何关于真实 Ansor 的结论**，**也绝不能与论文那四个数并列比较**——数据、特征、实现都不同。

**模型配置**：40 棵、`lr = 0.25`、深度 3、叶子下限 6 个样本。训练集 = `big` 图上 1200 个程序（吞吐在同一 DAG 内归一化到 `[0,1]`）；留出集 = 同一个 `big` 图上的 600 个程序。

**模型质量（同分布 vs 跨图）**：

| 指标 | 同分布（`big` 留出集） | 跨图（`small` 全体） |
|---|---|---|
| RMSE | **0.160** | **0.194** |
| R² | 0.057 | **−0.162** |
| pairwise 排序准确率 | **0.762** | **0.685** |
| recall@30 | **0.367** | **0.000** |

**这张表本身就是要讲的事**：跨到一张没见过的图上，模型的**绝对值**层面崩了（R² 变负，比「直接猜均值」还差），**排序能力**只掉了 0.077；而 **recall@30 从 0.367 掉到 0.000**——模型排出来的前 30 名与真实前 30 名**一个都不重叠**。搜索要的正是「前几名」，所以这个模型在新图上对搜索**毫无帮助**。

**小样本的代价**（同一留出集，只改训练集大小）：

| 训练程序数 | RMSE | pairwise |
|---|---|---|
| 30 | **0.470** | 0.646 |
| 120 | **0.409** | 0.726 |
| 1200 | **0.160** | 0.762 |

**C1：模型会误导搜索**（地形：模型在 `big` 图上训练，拿到 `small` 图上用；同一份预算 12 次测量；暴力枚举最优 `64519`，对应 `MultiLevelTilingWithFusion(tm=32,tn=64,tk=8,T=512,v=4)`）：

| 种子 | 随机搜索 | 模型引导（全空间取最优） | 模型引导·采样版 | **模型引导 + 完美模型** |
|---|---|---|---|---|
| 0 | 98927（regret 1.53） | **163856（2.54）** | **163856（2.54）** | **64519（1.00）** |
| 1 | 94635（1.47） | **163856（2.54）** | **180256（2.79）** | **64519（1.00）** |
| 2 | 134374（2.08） | **163856（2.54）** | **163856（2.54）** | **64519（1.00）** |

- **模型引导的搜索在 3 个冻结种子上全部差于同预算的随机搜索**（3/3）。「全空间取最优」与「采样池 256 取最优」两种利用强度**都**如此（3/3 + 3/3）——说明这不是「利用得太狠」造成的边角现象。
- **可证伪性（计划 §0.4 第 5 条）**：把代价模型换成**完美模型**（直接用地形本身打分，搜索流程一字不改），3 个种子上**全部**优于随机搜索、并且全部命中暴力枚举最优（3/3）。判定翻转了，所以上一条检验的是**模型**，不是地形。
- **机制可观察**：模型在 `small` 图上打分最高的配置，`tm = 128`；而暴力最优的 `tm = 32`。模型把「更大的 tile」排在前面——**正是它在 `big` 图上学到的偏好**（那张图上最优 tile 是 128×256）。

**A 类里两条可手算对照**：加权均值 `(1×1 + 2×1 + 6×2) / 4 = 3.7500`（实现给出 3.7500，若误写成算术均值会是 3.0）；加权平方误差 `1×1 + 1×0 + 2×1 = 3.0000`。**树集成不能外推**：在 `[0,10]` 上拟合 `y = x²`，`x = 10.5 / 100 / 1e6` 三个点的预测**全部等于** `x = 10` 处的值（`97.513`，最大差 `0.00e+00`）。

**第一版被实跑推翻的三项**：

1. **B 类的目标没有归一化，四个指标全错**。第一版直接拿模型输出与 `1/代价` 比，结果 R² 是 **−988441549708.851** 这种量级——因为模型预测的是**归一化吞吐**（`[0,1]`），而比较用的目标没归一化。修法是把目标按**本 DAG**归一化到 `[0,1]`（这正是 Ansor 的口径），两组数才是同一把尺子量出来的。
2. **特征集里漏了「语句的并行宽度」**。第一版只放了 flops / 字节数 / 向量宽度 / 归约行程 / 复用比。跑出来同分布 pairwise 只有 **0.593**——因为同一 tile 下**线程数**对真实代价影响很大，而它不在特征里，模型在这些配置之间只能乱排（而它们占配置对的大多数）。补上 `parallel_width` 之后同分布 pairwise 升到 0.762。**这次修改是有代价的**：它让模型在同分布上变好，而**网格规模的盲点一个没少**（块数是 program 级属性，仍然不在特征里）——C1 的结论因此没变，反而更干净：模型不是「什么都看不见」，而是**恰恰在网格规模这一维上看不见**。
3. **★ 第一版的「重训」把共享模型的训练集丢了**。这是三项里最要紧的一条。第一版的 `ModelGuided._refit` 只拿**本 DAG 上已测到的试次**重训，于是「所有 DAG 共用一个模型」在第二轮就被悄悄破坏：模型退化成一个「在十几个点上学出来的」本地模型。后果是 C1 的结论**不稳定**——最早那版里 3 个种子有 1 个种子模型引导反而更好（1.17 对 1.65，那一轮随机搜索恰好抽得很差）。修法是让重训**始终带上源 DAG 的共享训练集**（这正是论文「共用一个模型」的口径），之后误导在 3 个种子上**全部**成立，并且换成完美模型后**全部**翻转。**这条不是「调地形直到结论出现」**：地形、两个 DAG 的尺寸、预算、种子、阈值一字未动，改的是**搜索算法里对共享模型的用法**——而那本来是错的。

## 6. 小结与延伸

- **代价模型解决的是「不必每个点都测」**：一次训练 + 微秒级打分，换掉几千次编译 + 执行。
- **Ansor 的模型是 GBDT（XGBoost）**，**所有 DAG 共用一个**，吞吐**按 DAG 归一化到 `[0,1]`**，特征对**每条 innermost non-loop statement** 抽取，**整程序得分 = 各语句预测之和**，损失是**加权平方误差且权重直接取吞吐 `y`**。
- **★ 每轮从头重训，不做增量更新**——论文逐字 "we train a new model every time instead of doing incremental updates"。这条常被说反。
- **衡量模型的是排序能力，不是绝对值**：论文报的 pairwise comparison accuracy **0.851** 是本主题最该记住的那个数；它同时意味着**每 6–7 次比较就有 1 次排错**。
- **模型有结构性的盲点**：特征都是**语句局部**的，看不见「网格有多大」这种 **program 级**属性。（**本文标注为推断**——论文列出的特征*类别*是逐字的，具体实现不含什么是推断。）
- **盲点的后果是真的**：本机实测里，模型引导的搜索在 3 个冻结种子上**全部**差于随机搜索，而换成完美模型后**全部**翻转为最优。**「模型越好，搜索越好」不成立——「模型在排这一维上对不对」才成立。**
- **小样本的代价是可见的**：训练集 1200 → 30 个程序，同分布 RMSE 从 0.160 涨到 0.470。
