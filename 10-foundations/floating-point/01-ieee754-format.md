# IEEE754 格式：位宽决定一切

> 一个浮点格式的全部行为由两个整数锁定：指数位宽 `k` 决定它能表示多大、多小的数，尾数位宽 `m` 决定它有多准。同为 16 位的 fp16 与 bf16 行为相反，只是因为这两个整数分得不同。

## 0. 背景与动机

一个 7B 模型在 fp32 下训练完成，为了省显存改成 fp16 推理。跑起来之后，个别层的输出突然变成 `nan`，一路污染到最后的 logits。把权重换成 bf16，同样的代码、同样的参数量、同样是 16 位存储，问题消失。

位宽没变，为什么行为相反？因为 fp16 能表示的最大有限数是 **6.550e+04**，bf16 是 **3.390e+38**——同一个 16 位容器，上界相差三十多个数量级（推导值：`log10(3.390e+38 / 6.550e+04)`，两个操作数都取自 §5 表 1）。那份 fp32 权重里只要有一层的激活值超过 65504，fp16 下它不会饱和成最大值，而是直接变成 `inf`；`inf` 参与后续运算就是 `nan`。bf16 的 38 个数量级根本碰不到这个边界，所以「换个格式就好了」。

更隐蔽的是这个边界有多近。实测（§5 表）：输入 65519 还能表示，舍入到 65504；输入 65520 就溢出成 `inf`。**中间只差 1**——两个相邻整数，一个活一个死。这就是「16 位」这个说法为什么毫无用处：位宽只说明容器多大，不说明容器里能装什么。

所以选格式不能靠「16 位比 32 位省一半」这种算术，得回答一个更具体的问题：**给定一段数据的取值范围和需要的有效位数，哪个格式装得下？** 本文负责拆开这个问题的前半段——一个格式到底规定了什么。它只用到两个整数，能推的东西却包括：上溢边界、下溢边界、网格间距、相对精度、以及为什么 fp16 与 bf16 是两套取舍。至于「一次运算会错多少」，那是下一篇 [02-rounding-and-error-model](02-rounding-and-error-model.md) 的事。

## 1. 原理

### 第一步：位布局，以及隐藏位白赚的那一位

一个 IEEE754 格式把 `1 + k + m` 个比特分成三段：

```text
┌─┬──────────┬──────────────┐
│s│ 指数域 k 位│  尾数域 m 位  │   s = 符号，k = 指数位宽，m = 尾数位宽
└─┴──────────┴──────────────┘
```

指数域存的是**偏移后的指数** `e`，真实指数是 `e - bias`。规格化数（指数域既非全 0 也非全 1）的值是

```text
x = (-1)^s × 1.f × 2^(e - bias)
```

注意那个 `1.f` 里的 **1**：它没有存在任何比特里。来历是规格化的定义——把尾数规格化成 `[1, 2)` 区间的形式之后，首位**恒为 1**，存它等于存一个常量，纯属浪费。所以硬件约定它省略不存，读的时候自动补上。这叫**隐藏位**，等于白赚一位精度：

```text
有效精度位数  p = m + 1     ← 而不是 m
```

全文反复用到 `p`。fp16 的 `m = 10`，但它的有效精度是 **11** 位；fp32 的 `m = 23`，有效精度是 **24** 位。这一步的结论只有一句话，但它决定了后面 `u` 与 `eps` 的 2 倍差。

### 第二步：从 k 推出范围，从 m 推出精度

`bias` 由 `k` 唯一确定：

```text
bias = 2^(k-1) - 1
```

于是规格化指数的取值范围是 `[1 - bias, bias]`。记 `emin = 1 - bias`、`emax = bias`，两条边界各产出一个关键常数：

```text
tiny = 2^emin                  最小规格化数（下溢边界）
max  = (2 - 2^-m) × 2^emax     最大有限数（上溢边界）
```

`max` 的来历值得拆一下：`emax` 这一档里，尾数最大能取到 `1.111…1`（`m` 个 1），也就是 `2 - 2^-m`。再乘上 `2^emax` 就是上界。

用 fp16 与 bf16 各验算一遍（`k`、`m` 来自 §5 表 1）：

| | fp16 | bf16 |
|---|---|---|
| `k`, `m` | 5, 10 | 8, 7 |
| `bias = 2^(k-1) - 1` | 2^4 - 1 = **15** | 2^7 - 1 = **127** |
| `emin = 1 - bias` | -14 | -126 |
| `emax = bias` | 15 | 127 |
| `tiny = 2^emin` | 2^-14 = **6.104e-05** | 2^-126 = **1.175e-38** |
| `max = (2 - 2^-m) × 2^emax` | 1.9990234 × 32768 = **6.550e+04** | 1.9921875 × 1.7014e+38 = **3.390e+38** |

两列算出来的每一个数都与 §5 表 1 逐位一致。

精度那一侧由 `m` 单独决定，与 `k` 无关：

```text
eps = 2^-m     相邻两个 1.0 之间的距离（1.0 处网格的格宽）
```

fp16 的 `eps = 2^-10 = 9.766e-04`，bf16 的 `eps = 2^-7 = 7.812e-03`。**两条因果链互不干涉**——这是本文的主线：改 `k` 只动范围，改 `m` 只动精度。fp16 与 bf16 的全部差异就是「16 位怎么分」这一件事：fp16 给指数 5 位、尾数 10 位，bf16 给指数 8 位、尾数 7 位。

### 第三步：浮点是网格，不是数轴；`u` 与 `eps` 为什么差 2 倍

前两步把格式当成「一台能表示某些数的机器」，但真正决定舍入行为的是**这些数在实数轴上的分布形状**。它不是数轴，是网格，而且格子宽窄是分段的：**在同一个 binade 内格宽恒定，跨过一个 2 的幂才翻倍**。binade 指 `[2^e, 2^(e+1))` 这样的区间。

fp32 在 `[1, 2)` 这一个 binade 内的实测（§5 表 3）：`x = 1` 处 `ulp = 1.1920929e-07`，`x = 1.25`、`1.5`、`1.75` 处**全是同一个值** `1.1920929e-07`。格宽不随 `x` 变。

但**相对**格宽 `ulp(x)/x` 在变，而且变化范围恰好是 2 倍：

| `x` | `ulp(x)` | `ulp(x)/x` | 对照 |
|---|---|---|---|
| 1 | 1.1920929e-07 | 1.1921e-07 | = `eps = 2^-23`（上确界） |
| 1.25 | 1.1920929e-07 | 9.5367e-08 | |
| 1.5 | 1.1920929e-07 | 7.9473e-08 | |
| 1.75 | 1.1920929e-07 | 6.8120e-08 | |
| 1.99999988 | 1.1920929e-07 | 5.9605e-08 | = `u = 2^-24`（下确界） |

推导链条是这样的：分子是常数 `ulp = 2^(e-m)`，分母 `x` 从 `2^e` 涨到接近 `2^(e+1)`，于是在 `x = 2^e` 处比值最大、在 `x → 2^(e+1)` 处比值最小：

```text
ulp(x)/x |_(x = 2^e)     = 2^(e-m) / 2^e        = 2^-m  = eps   ← 上确界
ulp(x)/x |_(x → 2^(e+1)) = 2^(e-m) / 2^(e+1)    = 2^-m/2        ← 下确界
```

下确界就是 `u`，而它的指数是 `-(m+1) = -p`：

```text
u   = 2^-p = eps / 2     单位舍入误差（相对间距的下确界）
eps = 2^-m               相对间距的上确界
```

**这就是 `u` 与 `eps` 差 2 倍的全部来历**：它们是同一个 binade 内相对间距的两端。把两者混用会让误差估计整体差一倍，而这两个常量在文献和代码注释里被混用的频率相当高——`numpy` 只提供 `finfo.eps`，不提供 `u`，于是「随手抓一个」的默认结果通常是错的那个。本文只把结论摆在这里，`u` 怎么进入误差模型由 [02-rounding-and-error-model](02-rounding-and-error-model.md) 展开。

绝对格宽的变化则完全是另一回事。同一个 fp32，`1.0` 量级的 `ulp` 是 `1.192e-07`，`1e6` 量级的 `ulp` 是 **6.250e-02**——是前者的 `2^19` 倍。这意味着两个 1e6 量级的数只要相差不到 **3.125e-02**（半个 ulp），就会被舍入成同一个数。**相对误差不随量级变，绝对误差随量级线性涨**，这条对后面所有「比较两个数是否相等」的代码都有直接后果（§4 第 2 条）。

### 第四步：0 附近的空洞，以及用相对精度换来的填充

`tiny = 2^emin` 是最小规格化数。fp16 的 `tiny = 2^-14 = 6.104e-05`，而它下面是 0。如果不做任何处理，`0` 与 `6.104e-05` 之间就是一个宽 `6.104e-05` 的空洞——比这个量级本身还宽，相对精度在这里断崖。

**次正规数**（subnormal）的做法是：指数域锁定为**全 0**（代表 `emin`），同时把**隐藏位改成 0**。于是尾数只剩 `m` 个有效位，能表示的就不再是「`emax` 档往下每一档一个台阶」，而是把那个空洞切成等宽的小格：

```text
格数 = 2^m - 1              fp16: 2^10 - 1 = 1023 格
格宽 = 2^(emin - m)          fp16: 2^-24 = 5.960e-08，恒定
```

代价直接写在「恒定」两个字上：格宽不变而数值趋向 0，相对误差必然一路恶化。fp16 的实测（§5 表 4）：

| 值 `v` | 格宽 / `v` | 单次舍入相对误差上界 | 状态 |
|---|---|---|---|
| 6.1035e-05 | 9.766e-04 | 4.883e-04 | 与规格化数持平 |
| 7.6294e-06 | 7.812e-03 | 3.906e-03 | |
| 9.5367e-07 | 6.250e-02 | 3.125e-02 | |
| 1.1921e-07 | 5.000e-01 | 2.500e-01 | |
| 5.9605e-08 | 1.000e+00 | 5.000e-01 | 只剩最低一位 |

第一行的 `4.883e-04` 正是规格化区恒定的 `u`；最后一行涨到 `1/2`。**有效位从 11 位一路掉到 1 位**。再往下越过 `2.980e-08`（0 与最小次正规数的中点），就直接归零。对 LLM 来说，落在这一段的量（激活的小分量、梯度尾部）不是「不准」而是**永久消失**：0 乘任何数还是 0。

### 第五步：特殊值来自被保留的指数域组合

指数域的两个极端值被保留下来做别的事，这就是特殊值的全部来源：

| 值 | fp32 位模式 | 指数域 | 尾数域 | 回读结果 |
|---|---|---|---|---|
| +0 | 0x00000000 | 全 0 | 全 0 | 0.0 |
| -0 | 0x80000000 | 全 0 | 全 0 | -0.0 |
| +inf | 0x7F800000 | 全 1 | 全 0 | +inf |
| -inf | 0xFF800000 | 全 1 | 全 0 | -inf |
| quiet NaN | 0x7FC00000 | 全 1 | 最高位 1 | nan |
| signaling NaN | 0x7F800001 | 全 1 | 最高位 0 | nan |

规则是：**指数域全 0 + 尾数域非 0 → 次正规数**（第四步已用）；**指数域全 1 + 尾数域全 0 → 无穷大**；**指数域全 1 + 尾数域非 0 → NaN**，其中尾数域最高位为 1 的是 quiet NaN、为 0 的是 signaling NaN。

两个容易忽略的细节。其一，`-0.0 == 0.0` 为 True（实测），但 `1/-0.0 = -inf`，`np.signbit` 能区分二者——负数下溢到 0 时保留符号位，正是为了不让 `1/x` 在 x 跨过 0 时符号跳变。其二，`NaN != NaN` 为 True（实测），它是唯一不满足自反性的值，因此判空必须用 `isnan`。

### 第六步：fp8_e4m3 是标准的一个变体

前面五步的推导都假设「指数域全 1 保留给 inf/NaN」。OCP 的 fp8_e4m3 打破了这个假设，值得单独走一遍，因为它演示了**一个格式如何偏离 IEEE754 却仍然自洽**：

```text
k=4, m=3  ⇒  bias = 2^3 - 1 = 7,  emin = -6,  tiny = 2^-6 = 1.562e-02

按标准规则（全 1 指数域保留）：
    emax = bias = 7
    max  = (2 - 2^-3) × 2^7 = 1.875 × 128 = 240

e4m3 的实际规则（全 1 指数域是**有效**指数）：
    emax = bias + 1 = 8                       ← 多占一档
    top  = 2^(1-m) = 0.25                     ← 全 1 尾数被征用为 NaN
    max  = (2 - 0.25) × 2^8 = 1.75 × 256 = 448
```

代价与收益对称：**多得到一个指数档（240 → 448），代价是格式里没有无穷大**，并且全 1 尾数这一格被 NaN 占掉，所以上界不是 `2 × 256 = 512` 而是 `1.75 × 256`。这条修正有个直接的实用价值：`240` 是很多手算和文档里会出现的错值，而 `448` 才是实际能表示的最大数。相邻的 fp8_e5m2 不受影响——它沿用 IEEE 规则，上界 `5.734e+04`，有 inf。

## 2. 执行映射

格式不是纸面约定，它落到硬件上是三个地方：数据通路怎么打包、存储怎么打包、以及累加器用什么宽度。下面用到两个硬件名词，各需要一句定义：**SM**（流式多处理器，Streaming Multiprocessor）是 GPU 内独立调度与执行的硬件单元，一张卡由几十到上百个 SM 组成；**warp** 是硬件调度的最小单位，由 **32 个线程**组成，它们共享同一条指令流、只是各自持有不同的数据。

**数据通路侧。** SM 的 FP32 数据通路是 **32 lane 宽**——一条指令一次覆盖 32 个 lane。fp16 与 bf16 的算术靠**成对打包**塞进这条通路：两个半精度数合占一个 32 位寄存器，一条指令处理两个运算（CUDA 里的 `__half2` / `__hfma2` 系列）。于是「16 位」在寄存器层面是一个实在的物理事实——它决定了每线程的寄存器用量，也决定了同一份 kernel 能挂住多少 warp。

**寄存器文件侧。** 每 SM 的寄存器文件是 **65536 个 32 位寄存器，合计 256 KB**（Volta 起定型，至 Blackwell 未变；来源见参考）。这是本文所有精度结论最终要挤进去的预算：同一个模型，fp32 存需要 2 倍于 fp16 的寄存器/显存份额，而每个线程能用多少寄存器又直接换算成常驻 warp 数。**格式选型的收益，一半在精度，一半在这条预算上**（寄存器预算的完整推算见 [20-gpu-architecture/execution-model/01-sm-internals.md](../../20-gpu-architecture/execution-model/01-sm-internals.md)，此处回链）。

**Tensor Core 侧。** 矩阵乘的输入端口吃 fp16 / bf16（Hopper 起还吃 fp8，Blackwell 起原生支持 FP4 / FP6 微缩放格式），但**累加器是 fp32**——这不是实现选择，是硬件层面就不提供 fp16 累加的路径。原因要到 [04-low-precision-formats](04-low-precision-formats.md) 才能算清楚，这里先记住结论。

**数值量级**（三个可用于心算的锚点）：

| 量 | 数值 | 来源 |
|---|---|---|
| 每 SM 寄存器文件 | 65536 × 32 bit = **256 KB** | NVIDIA 各代 tuning guide，见参考 |
| bf16 的相对精度 | `p = 8` 位 ⇒ 十进制 **2.41** 位 | §5 表 1 |
| bf16 的范围跨度 | **76.5** 个十进制数量级 | §5 表 2 |
| fp16 的下溢边界 / 上溢边界 | **2.980e-08** / **6.550e+04** | §1 第四步（程序输出第 3 节）、§5 表 1 |

一眼看出分工：bf16 的范围跨度 `76.5` 与 fp32 **完全相同**（指数位宽一样），而它的十进制精度 `2.41` 只有 fp32 的 `7.22` 的三分之一。fp16 反过来——精度 `3.31` 位、范围只有 9 个数量级。

## 3. 实现与演进

每一步都是对上一步暴露出的问题的回应。

**fp32（IEEE754-1985，8 + 23 位）。** 通用计算的默认格式。范围 76.5 个数量级、精度 7.22 位十进制，两边都够用，代价是每一项数据占 4 字节。它没解决什么问题，它是起点。

**fp16（1990 年代，图形领域，5 + 10 位）。** 为纹理与颜色而生——那些数据的取值范围天然窄（颜色在 `[0,1]`，坐标在固定区间），10 位尾数够用，省下的带宽是直接收益。它在深度学习时代被重新捡起来，是因为 GPU 恰好有免费的 fp16 吞吐。但它留了一个坑：范围只有 **9 个数量级**（§5 表 2），且归零下限在 **2.980e-08**（§1 第四步）——而神经网络里的梯度会跑到 `1e-8` 以下，正好落在这一段的另一侧。这个「梯度实际会掉多少」的量化答案在 [04-low-precision-formats](04-low-precision-formats.md)。

**bf16（Google 为 TPU 提出，8 + 7 位）。** 回应上一个坑的手段是**把指数位宽直接对齐 fp32**：8 位指数 ⇒ 范围跨度也是 76.5 个数量级，归零下限低到 `4.592e-41`。同一批梯度样本里 **0** 个归零。代价写在尾数上：相对 fp16，`p` 从 11 掉到 8（相对 fp32 则从 24 掉到 8）。这是一次明确的交易——**用 3 位精度换 67 个数量级的范围**（范围跨度从 fp16 的 9.0 涨到 bf16 的 76.5，两者之差就是那 67），换来的工程后果是「训练不需要 loss scaling」。

**fp8（OCP 标准，e4m3 / e5m2）。** 再省一半。两个变体分工明确：e4m3 要精度（`p=4`、范围 4.5 个数量级），用于权重与激活；e5m2 要范围（`p=3`、范围 9.0 个数量级），用于可能需要表示较大动态范围的梯度。为了让 e4m3 的上界从 240 抬到 448，这里付出了「没有无穷大」的代价——**这是标准第一次为了动态范围主动牺牲 IEEE 一致性**（§1 第六步）。

**微缩放格式（mxfp，Blackwell 起原生支持）。** fp8 及以下的精度已经低到「一个格宽就代表一个数量级」的程度，全局共享一个指数不再划算。微缩放的做法是**块级共享指数**：一个块（如 32 个元素）共用一个指数，块内每个元素只存尾数。这样精度损失被局部化，而指数开销被摊薄。走到这一步，格式设计的主语已经从「一个数」变成了「一组数」——单个数的最优位布局已经没有多少可榨的了。

贯穿五代的一条线：**每往低精度走一步，省下的是存储与带宽，付出的是范围或精度，而且永远是两者之一，不可能都不付**。fp16 选了精度、bf16 选了范围、e4m3 选了精度、e5m2 选了范围——选型时唯一有指导意义的问题是「我的数据动态范围落在哪一段」。

## 4. 踩坑与失败模式

### 4.1 认为同为 16 位的 fp16 与 bf16 可以互换

**现象**：把一个 fp16 保存的 checkpoint 直接按 bf16 读进来，或者反过来——代码不报错，运行的 loss 是 `nan`；或更隐蔽地，训练能跑但收敛比预期差。

**成因**：位宽相同不代表能表示的数集相同。两者把 16 位分给了不同的地方：fp16 的上溢边界是 **6.550e+04**、下溢归零是 **2.980e-08**；bf16 的上溢边界是 **3.390e+38**、归零下限 **4.592e-41**——归零下限相差 **33 个数量级**。同一个比特模式在两边读出的数值完全不同（fp16 的指数域有 5 位、bf16 有 8 位，解码规则不一样），而且量级落在 fp16 上溢区间的权重在 bf16 里安然无恙，反之亦然。**位宽是容器大小，位布局才是容器内容。**

**规避**：按数据的动态范围选，而不是按位宽选。判据只有一条：把待表示数据的 `log10(|value|)` 分布画出来，看上溢边界和下溢归零边界是否都在分布之外。梯度尾部会跑到 `1e-8` 以下，因此 fp16 需要额外的缩放机制（见 [04-low-precision-formats](04-low-precision-formats.md)）；已经用 fp16 落盘的模型不要按 bf16 直接读，必须走显式转换（读到 fp32 再转 bf16），转换本身会丢失尾数低位但不会错位。

### 4.2 在大量级上用绝对容差判等

**现象**：一段用 `abs(a - b) < 1e-6` 判等的代码，在测试用例上表现良好，换成真实数据（量级 1e6）之后**恒为真**，所有本该被识别为「不同」的值都被判成相等。

**成因**：绝对格宽随量级线性增长，而绝对容差是个常数。fp32 下 `1.0` 量级的 `ulp` 是 `1.192e-07`，`1e6` 量级的 `ulp` 是 **6.250e-02**——相差 `2^19` 倍。两个 1e6 量级的数只要相差不到 **3.125e-02**（半个 ulp），就会在存储时被舍入成同一个数。此时 `1e-6` 这个容差比一个 ulp 还小三个数量级，**它永远大于真实差值**，判等退化成恒真。

**规避**：判等要用相对量级的容差，而不是绝对常数——常见形式是 `abs(a-b) <= tol * max(abs(a), abs(b))`，其中 `tol` 取 `u = 2^-p` 的量级或更大。注意 `tol` 该取 `u` 而不是 `eps`（§1 第三步，两者差 2 倍）。如果 a、b 本身就是 1e6 量级的输入，还要意识到**容差不可能小于半个 ulp**：小于它的差异在存储阶段就已经不存在了，不是算法的问题。

### 4.3 次正规数被 FTZ 模式静默刷成 0

**现象**：CPU 上验证过的 kernel，搬到 GPU 上之后小量级的输出整片变成 0；或者同一段代码在 `-O0` 下正常、开了优化就失真。

**成因**：CUDA 的 `--use_fast_math` 默认打开 `-ftz=true`（flush-to-zero），次正规数被硬件直接当作 0 处理。本文 §1 第四步已经说明次正规区是「相对精度从 `u` 崩到 `1/2` 的那一段」——把它整个抹掉，等于把 `2^-14` 这个量级以下**全部**变成硬归零，且这个削减发生在**每一次运算之后**，而不是只在函数边界。它与本文 §1 里的 `2.980e-08` 归零下限叠加，使实际的有效下限比规格更高。

**规避**：需要次正规语义时显式编译 `-ftz=false`（`--use_fast_math` 是可以按文件关闭的，把精度敏感的编译单元拆出来）。注意这与精度敏感度有关而与性能无关：`--use_fast_math` 同时还会关掉 `-prec-div` / `-prec-sqrt`，即除法和开方不再保证正确舍入——本文所有关于「每次运算精确舍入一次」的模型都会失效。这条线的另一半（编译器被允许做哪些重结合）在 [02-rounding-and-error-model](02-rounding-and-error-model.md) §4 展开。

## 6. 小结与延伸

本文只有一条主线：**位宽决定一切，指数管范围、尾数管精度**。围绕它有三个可独立复用的中间结论：

1. 一个格式由 `(k, m)` 两个整数锁定。`bias = 2^(k-1) - 1` 给出 `emin` / `emax`，于是 `tiny = 2^emin`、`max = (2 - 2^-m)·2^emax`——两条边界都可以纸笔算出来，并与 §5 表 1 逐位对上。有效精度是 `p = m + 1`，那多出的一位是隐藏位白赚的。
2. `u = 2^-p` 与 `eps = 2^-m` 差 2 倍，因为它们是一个 binade 内相对间距的两端：`eps` 在上确界、`u` 在下确界。**误差模型用 `u`，用错就是整体差一倍。**
3. 特殊值不是特例，是「指数域的两个极端组合被保留」的必然结果。fp8_e4m3 演示了反方向的操作：**主动放弃 inf，换来把上界从 240 抬到 448**。

下一篇 [02-rounding-and-error-model](02-rounding-and-error-model.md) 承接第三步的结论，回答「一次运算会错多少」——从 `fl(x) = x(1+δ)`、`|δ| ≤ u` 这个模型出发，走完四种舍入模式、单次运算模型、Sterbenz 引理，最后落到灾难性抵消这个最反直觉的失败形态。[04-low-precision-formats](04-low-precision-formats.md) 则把本文的格式参数表接到工程决策上：loss scaling、累加器宽度、tf32 这些问题的答案，全部由 §5 表 1 里那几个数决定。
