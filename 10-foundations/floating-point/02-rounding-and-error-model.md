# 舍入与误差模型：一次运算会错多少

> IEEE754 保证每一次基本运算的结果是「精确结果舍入一次」，由此得到的 `fl(a ∘ b) = (a ∘ b)(1 + δ)`、`|δ| ≤ u` 是全部误差分析的起点。而真正危险的从来不是运算次数多，是减法把**已有**的绝对误差除以一个塌陷的分母。

## 0. 背景与动机

一个 LayerNorm 实现用教科书上的单趟公式算方差：

```python
mean  = sum(x) / n
var   = sum(x*x) / n - mean * mean     # E[x²] - E[x]²，数学上恒等
```

在单元测试里（随机初始化、数值都在 0 附近）它工作正常。上线之后，某些层的方差算出**负数**，开根号得到 `nan`，整层输出报废。

这不是实现 bug——公式在实数上恒等，代码也忠实实现了公式。问题在于这段代码用两个**几乎相等的大数**相减，去求一个**很小的差**。实测（§5 表 5）把这三种算法放在同一批样本上：

| μ | A 单趟 fp32 | B 抵消隔离 | C 两趟 fp32 | 真值 σ² | A 的相对误差 |
|---|---|---|---|---|---|
| 1e+00 | 0.99809 | 0.99812 | 0.99812 | 1.0 | 1.912e-03 |
| 1e+02 | 0.99219 | 0.99805 | 0.99812 | 1.0 | 7.812e-03 |
| 1e+04 | 1.5648e+05 | 0 | 0.99811 | 1.0 | 1.565e+05 |
| 1e+06 | 2.5585e+08 | 0 | 0.99853 | 1.0 | 2.559e+08 |

μ = 1e+06 那一行，单趟算法给出 `2.5585e+08`，而真值是 `1.0`——**差了 255852543 倍**。而最扎眼的是 B 列：它把两个中间量先用 fp64 算到尽可能准、只把结果舍入到 fp32 再相减，误差不是「累加造成的」也不是「精度不够」——**它在 μ ≥ 1e4 时精确等于 0**。两个各自相当准确的数，只要在 fp32 里相减，答案就整个消失。

所以「一次运算会错多少」不是一道小题。本文要建立的是能**预测**这类失效的误差模型：一条运算规则、一个常数 `u`、一个放大因子。三样东西凑齐之后，你在写代码之前就能算出「这个公式在 μ/σ 多大时会崩」。

## 1. 原理

### 第一步：四种舍入模式，以及为什么默认那个是「取偶」

一个实数落到网格上时，最自然的规则是「选最近的格点」。当它恰好落在两个格点正中间时，需要一条附加规则。IEEE754 定义了四种模式，它们在被舍入值恰好等距时才分道扬镳：

待舍入的数取 `x = 1 + 2^-24`——fp32 的尾数只有 23 位，这个数正好卡在 `1.0` 与 `1 + 2^-23` 的正中间：

```text
x = 1 + 2^-24 = 1.00000005960464478
左邻居 1.0        = 1.00000000000000000
右邻居 1+2^-23    = 1.00000011920928955
```

| 舍入模式 | 结果 | 相对误差 |
|---|---|---|
| 就近舍入，取偶（round-to-nearest-even） | 1.00000000000000000 | -5.960e-08 |
| 向零舍入（round-toward-zero） | 1.00000000000000000 | -5.960e-08 |
| 向 +inf 舍入（round-toward-+inf） | 1.00000011920928955 | +5.960e-08 |
| 向 -inf 舍入（round-toward--inf） | 1.00000000000000000 | -5.960e-08 |

正数例子分不开「向零」和「向 -inf」——对正数两者本就等价。取负数才能把四种模式完全分开：

| 舍入模式（作用于 -(1+2^-24)） | 结果 | 偏离方向 |
|---|---|---|
| 就近舍入，取偶 | -1.00000000000000000 | 向 0 |
| 向零舍入 | -1.00000000000000000 | 向 0 |
| 向 +inf 舍入 | -1.00000000000000000 | 向 0 |
| 向 -inf 舍入 | -1.00000011920928955 | 远离 0 |

**默认模式是「就近取偶」**，规则是等距时选尾数最低位为 0 的那一个。这里 `1.0` 的尾数是 0（偶），`1+2^-23` 的尾数是 1（奇），所以舍向 `1.0`。换个位置就舍向另一边（实测）：

```text
1 + 1·2^-24 → 1.00000000000000000   (等距，取偶)
1 + 2·2^-24 → 1.00000011920928955   (本身就精确)
1 + 3·2^-24 → 1.00000023841857910   (等距，取偶)
1 + 4·2^-24 → 1.00000023841857910   (本身就精确)
```

**为什么不用直觉上的「四舍五入」**（等距时恒向上）？因为它有系统性偏差。考虑最坏情形——被舍入的值**总是恰好落中点**（定点小数、反复对半分的流水线、把十进制数批量转成二进制都会制造这种输入）：

```text
四舍五入：每次误差恒为 +ulp/2
          n 次之后累计偏差 = n × ulp/2        ← 线性增长，不抵消
就近取偶：中点处交替向上/向下，误差符号交替
          n 次之后累计偏差 ≤ ulp              ← 与 n 无关
```

「就近取偶」让中点上的误差有机会正负配对，把上界从 `O(n·ulp)` 压到 `O(ulp)`。注意这个论证只在中点上有意义——**非中点输入下这两种模式的舍入结果完全相同**（误差量级本来就是 `ulp/2`，符号由输入决定）。所以这条规则不是「更准」，而是「不引入额外的系统性偏差」，这正是它成为 IEEE754 默认模式的原因。

### 第二步：误差模型的地基——`fl(x) = x(1+δ)`

任何一次「实数 → 浮点」的映射都能写成一个**相对**形式：

```text
fl(x) = x · (1 + δ),    |δ| ≤ u
```

其中 `u = 2^-p`，`p` 是有效精度位数（含隐藏位，来自上一篇 §1 第一步）。这个常数叫**单位舍入误差**。

`u` 为什么是 `2^-p` 而不是 `2^-m`？回到上一篇第三步的结论：相对间距 `ulp(x)/x` 在一个 binade 内从 `eps = 2^-m` 单调滑到 `u = 2^-p`，两端恰好差 2 倍。**误差上界取的是那个更大的分母**（即更小的比值），所以是 `u`：

| 格式 | `p` | `u = 2^-p` | `eps = 2^-(p-1)` | `eps/u` |
|---|---|---|---|---|
| fp16 | 11 | 2^-11 = 4.8828e-04 | 2^-10 = 9.7656e-04 | 2.0 |
| fp32 | 24 | 2^-24 = 5.9605e-08 | 2^-23 = 1.1921e-07 | 2.0 |
| fp64 | 53 | 2^-53 = 1.1102e-16 | 2^-52 = 2.2204e-16 | 2.0 |

**误差模型用 `u`，不是 `eps`。** 把两者混用会让误差估计整体错一倍，而这个错误在文献和代码注释里都极常见——`numpy` 只暴露 `finfo.eps`，随手抓来的那个恰好是错的（§4 第 1 条）。

模型可以被实测检验：对 200 万个随机 fp64 值舍入到 fp32，看 `|δ|` 实际上确界能顶到多高：

```text
实测 max|δ| = 5.958108e-08
fp32 的 u   = 5.960464e-08
实测值 / u  = 0.999605            （应 ≤ 1，且随机取样时非常接近 1）
```

`|δ| ≤ u` 成立，而且这个上界是**紧的**——随机取样就顶到了 `u` 的 `0.999605`。这说明 `u` 不是保守估计，它就是网格几何本身。

### 第三步：单次运算模型，以及它为什么能复合

IEEE754 规定基本运算的结果是**精确结果舍入一次**：

```text
fl(a ∘ b) = (a ∘ b)(1 + δ),   |δ| ≤ u      （∘ ∈ {+, -, ×, ÷}）
```

这一步只有两行，但它带来两个后面反复用到的推论：

**推论一：相对误差有界，且与运算种类无关。** 加法、乘法、除法的相对误差上界都是同一个 `u`。这意味着误差分析的起点与具体运算符无关，只看运算的次数与结构。

**推论二：这是单次运算的界，不能直接乘以次数。** `n` 次运算串起来，误差既不必然线性累加（`√n` 可能更准），也不必然互相抵消（抵消可能更糟）——取决于运算顺序。

关键在于模型是**逐层复合**的。若 `a`、`b` 本身已经是舍入过的（误差 `δa`、`δb`），那么 `fl(a+b) = (a+b)(1+δ)` 里的 `δ` 已经包含了它们。把这一步展开就看得清楚：

```text
fl(fl(a) + fl(b)) = ( a(1+δa) + b(1+δb) ) (1 + δ)
                  = (a + b) (1 + δ) + (a·δa + b·δb)(1 + δ)
```

绝对误差项 `a·δa + b·δb` **不随结果变小而变小**——这就是下一篇要处理的全部难点。本文剩下的两节都围着它转。

### 第四步：Sterbenz 引理——减法这一步本身是精确的

一个流行但错误的说法是「两个相近数相减会丢精度」。**减法本身不产生误差**：

```text
Sterbenz 引理：若 y/2 ≤ x ≤ 2y，则 x - y 在浮点里精确无误差。
```

实测：在适用区间内取 100 万个随机点对，浮点减法的结果与「输入已舍入后的精确差」之间的最大偏差是 **0.000e+00**——一次都没有不精确。

那抵消为什么危险？因为它把**输入里已有的绝对误差**，除以一个塌陷的分母，放大成巨大的**相对误差**：

```text
设 fl(x) = x(1+δx)、fl(y) = y(1+δy)，|δ| ≤ u
绝对误差 = |x·δx - y·δy| ≤ (|x| + |y|)·u          ← 与 x-y 无关，不因相减而减小
相对误差 = (|x| + |y|)·u / |x - y|                 ← 分母塌了
```

**绝对误差不变，相对误差随分母塌陷而爆炸。** 这就是灾难性抵消的完整机制。放大因子 `(|x|+|y|)/|x-y|` 是可以提前算出来的——这正是能预测失效的原因。

### 第五步：把模型代入方差公式，得到失效条件

用 `E[x²] - E[x]²` 算方差。记数据均值 `μ`、标准差 `σ`（所以 `E[x²] = μ² + σ² ≈ μ²`，当 `μ ≫ σ` 时）。把第四步的放大因子逐项展开：

```text
两个被减量：  A = E[x²] ≈ μ²,      B = E[x]² ≈ μ²
              |A| + |B| ≈ 2μ²
绝对误差    ≤ 2μ² · u
相对误差    = 绝对误差 / |A - B| = 2μ² · u / σ²
```

代入实测用的参数 `μ = 1e6`、`σ = 1`、`u = 5.9605e-08`：

```text
相对误差 ≈ 2 × 1.000e+12 × 5.9605e-08 / 1 = 1.19e5      ← 推导值
```

**量级 `1.19e5` 意味着信息已经全部丢失**（这个数由上面三行推出，`2μ²u/σ²` 的代入结果；程序本身不打印它），而实测的 B 列给出的答案比这个估计还极端——它**精确等于 0**。原因是更硬的一条约束：`μ = 1e6` 时 `E[x²] ≈ 1.000e+12`，它在 fp32 里的 ulp 是 **6.554e+04**，而待求的方差只有 `σ² = 1`——**比一个 ulp 还小 65536 倍**。真值落在最后一位以下，没有任何计算方法能把它捞回来。

这就是 §5 表 5 里 B 列为什么必须是 0：它不是「不准」，是**精确地等于错误的值**。

唯一出路是**换公式而不是换精度**。C 列把减法提到前面：

```text
两趟：  mean = Σx / n           ← 第一步求均值
        var  = Σ(x - mean)² / n ← 第二步先减再平方，被减的两个量都缩到 σ 量级
```

`x - mean` 的两个操作数都在 `σ` 量级，第四步的放大因子 `(|x|+|mean|)/|x-mean|` 退化到 `O(1)`，抵消不再发生。实测 C 列在四个 μ 上稳定在 `0.99811 ~ 0.99853`。

## 2. 执行映射

**`u` 落在哪条通路上。** 每次基本运算的舍入发生在**执行单元的流水线末端**，不在内存里、也不在调度器上。SM 的 FP32 数据通路是 32 lane 宽，一条 `FADD`/`FFMA` 覆盖一个 warp 的 32 个 lane，每个 lane 各自把精确结果舍入到 fp32 网格——**舍入是 per-lane 的，与 lane 之间无关**。这意味着本文的误差模型可以逐 lane 套用，不需要为 SIMT 做任何修正。

**FMA 单元把「两次舍入」变成一次。** `a*b + c` 在两条指令的写法下含**两次**舍入（乘积一次、加法一次），误差界是 `2u`；FMA（fused multiply-add）在硬件里保留完整乘积、只在最后舍入一次，误差界是 `u`。**斜率直接减半**。这条的极端后果在 [03-summation-and-accumulation](03-summation-and-accumulation.md) §3 有实验：fp16 下两次舍入把结果整个抹成 0，一次舍入完整保留。

**比较与判等落在谓词寄存器上。** §4 第 1 条讲的「用绝对容差判等」在硬件上是一条比较指令写入**谓词寄存器**（`FSETP` 写 `P0`，后续指令按谓词选择执行）。判等退化不会报错、不会异常，只会让所有分支走同一条路——**这是本文所有失败模式里最难查的一种**，因为现象是「逻辑不对」而不是「数值不对」。

**编译器可以合法地破坏这些前提。** CUDA 的 `--use_fast_math` 一次性打开三件事：`-ftz=true`（次正规刷成 0）、`-prec-div=false`（除法不再保证正确舍入）、`-prec-sqrt=false`（开方同理）。前一篇的 §1 第四步已经说明次正规区是「相对精度从 `u` 崩到 `1/2` 的那一段」；把它们刷掉，等于**单方面修改了 `p`**，本文的 `|δ| ≤ u` 也就不再成立（§4 第 3 条）。

**数值量级：**

| 量 | 数值 | 来源 |
|---|---|---|
| fp32 的单位舍入误差 `u` | **5.9605e-08**（`= 2^-24`） | §5 表 3 |
| fp32 实测 `max|δ|` | **5.958108e-08**，`/u = 0.999605` | §5 表 3 |
| fp32 最大有限数 | **3.403e+38** | 01 §5 表 1 |
| 每 SM 寄存器文件 | 65536 × 32 bit = **256 KB** | NVIDIA tuning guide，见参考 |
| μ=1e6 时 `E[x²]` 的 fp32 ulp | **6.554e+04** | §5 表 5 后注 |

最后一行值得单独看：`6.554e+04` 不是一个「精度参数」，它是**在 `1e12` 这个量级上，fp32 能分辨的最小差异**。任何小于它的结构，在这条通路里都不存在。

## 3. 实现与演进

求方差（以及一切「大数减小数」型统计量）的算法演进，是本文模型最直接的应用史。

**朴素：单趟公式 `E[x²] - E[x]²`。** 只遍历一次数据、只需要两个累加器，复杂度 `O(1)` 内存。它的失效条件由 §1 第五步给出：`2μ²u/σ²` 接近或超过 1 时结果无意义。μ/σ 大是**常态**而不是特例——LayerNorm 的输入激活就是「均值大、方差小」的典型形态（§0 的场景），所以这不是一个可以「注意到再避开」的坑。

**两趟算法。** 先算均值、再算 `Σ(x-mean)²`。它把放大因子从 `O(μ²/σ²)` 压到 `O(1)`，代价是要**遍历两遍数据**——对显存放不下的张量意味着多一次 HBM 往返，对大模型是实打实的带宽成本。这是「精度换带宽」的第一次交易。

**Welford 在线算法。** 回应上一段的代价。Welford 用一个增量递推同时维护均值与方差，**只遍历一遍**且不产生大数相减：

```text
n ← n + 1
δ ← x - mean
mean ← mean + δ/n
M2 ← M2 + δ·(x - mean)      ← 用的是更新后的 mean，δ 与 (x-mean) 都已是小量
var ← M2 / n
```

关键在于 `δ = x - mean` 与更新后的 `x - mean` 都是 `σ` 量级的量，§1 第四步的放大因子天然 `O(1)`。Welford 的代价是**串行依赖**：每一步都依赖上一步的 `mean`，无法像两趟算法那样在求和阶段并行展开。所以 GPU 上的实现通常仍然用两趟——并行度比遍历次数更值钱。

**Kahan / Neumaier 补偿。** 上面三者都在解决「抵消」，Kahan 解决的是**累加**那一侧的舍入（下一篇 §1）。两者的分工是清晰的：抵消靠换公式消除，累加误差靠补偿项消除。**用 Kahan 去救单趟方差公式是无效的**——B 列已经把这一点证明了：它的两个中间量就是「用 fp64 精确累加」得到的，等效于零累加误差，结果照样是 0。**误差在哪一步产生，就要在哪一步消除。**

## 4. 踩坑与失败模式

### 4.1 用 `finfo.eps` 当单位舍入误差

**现象**：代码里写 `tol = np.finfo(np.float32).eps`，用它做相对误差的容差或误差估计，结果所有误差估计都恰好比真实值大一倍。

**成因**：`finfo.eps` 是 `2^-m`（fp32 下 `1.192e-07`），而误差模型要的是 `u = 2^-p = 2^-(m+1)`（`5.9605e-08`）。两者差 **2 倍**，因为 `eps` 是相对间距的上确界、`u` 是下确界（§1 第二步）。这是本文最容易被忽略的一处：**两个常量都「正确」，只有一个是模型里那个**。而且 `numpy` 只暴露 `eps`——默认路径通向错的那个数。

**规避**：显式写 `u = 2.0 ** -(p)`，或 `u = np.finfo(t).eps / 2`，并在变量名里带上 `unit_roundoff` 而不是 `eps`。审查误差分析代码时，把每一处 `eps` 都找出来问一遍「这里要的是网格上确界还是误差上界」。顺带一条同源错误：把 `eps/u` 当成「舍入误差和机器精度的比值」——它就是 2.0，与格式无关（§5 表 3 三行的 `eps/u` 全是 2.0）。

### 4.2 用单趟公式算方差

**现象**：LayerNorm / RMSNorm / BatchNorm 的实现在 fp16 或 bf16 下输出整体变成 0、`nan`，或者归一化后的张量幅度完全不对；同一个实现在 fp32 下正常，因此被误判为「低精度格式不稳」。

**成因**：`E[x²] - E[x]²` 的放大因子是 `2μ²u/σ²`（§1 第五步）。两件事同时恶化：`μ/σ` 一大，放大因子就按平方增长；`u` 一放大（fp16 的 `u` 比 fp32 大得多），量级再乘上去。实测把这一点拆得很干净——B 列证明即使**累加误差为零**，光靠抵消就足以把结果变成 `0`（μ ≥ 1e4）。**所以这不是「精度不够」，换更高精度的累加器救不了。**

**规避**：改成两趟或 Welford。判断是否必须改的量化标准：算出 `2μ²u/σ²`，量级接近 1 就必须换。注意这个判据依赖 `μ/σ`，而它是**运行期的数据属性**，编译期看不出来——所以不能靠「我的输入一般都很正常」来免检，得在 kernel 里对输入的 `μ`、`σ` 做一次快速估计或者干脆默认用两趟。另外要意识到：**输出层归一化的 `μ/σ` 会随训练推进而漂移**，上线时正常的公式可能在训练几千步后开始失真。

### 4.3 以为 `-ffast-math` / `--use_fast_math` 只影响性能

**现象**：同一段 kernel 在 `-O0` 下与 CPU 结果一致，开了优化或加了 `--use_fast_math` 之后数值对不上；次正规数整片变成 0；某些 `if` 分支突然永远不进入。更隐蔽的是：**误差比预期小**——编译器重结合之后误差反而降了，于是这个改动被当成优化保留了下来，直到某次输入分布变化才暴露。

**成因**：`--use_fast_math` 不是纯性能开关，它同时修改了浮点语义：`-ftz=true` 让次正规数变成 0（等于单方面改小了有效精度 `p`），而允许**重结合**意味着编译器可以把 `a + b + c` 重排成 `(b + c) + a`——本文的复合模型里「每一步只舍入一次、顺序固定」这个前提被打破了，推导出的误差界不再对应实际执行的计算。同时它假定**不存在 NaN / inf**，于是 `if (x != x)` 这类判空被当作恒假式消掉。

**规避**：把精度的编译选项当成**接口契约**的一部分，而不是构建参数——精度敏感的编译单元单独拆文件、单独指定 `-ftz=false -prec-div=true -prec-sqrt=true`，不要跟着全局 `-use_fast_math` 走。判空一律用 `isnan(x)` 而不是 `x != x`（后者依赖一个编译器被允许优化的性质）。如果确实需要重结合带来的并行度，就**显式**写成树形或成对求和（[03-summation-and-accumulation](03-summation-and-accumulation.md) §4），把「谁在哪里重排」的决定权拿回自己手里。

## 6. 小结与延伸

本文的模型只有三行，但能推出上面全部结论：

```text
fl(x) = x(1 + δ),  |δ| ≤ u            映射层面的误差
fl(a ∘ b) = (a ∘ b)(1 + δ),  |δ| ≤ u   单次运算的误差，逐层复合
相对误差 = (绝对误差) / |结果|          抵消的放大机制
```

三个可独立复用的中间结论：

1. **`u` 不是 `eps`。** `u = 2^-p` 是一个 binade 内相对间距的下确界，`eps = 2^-m` 是上确界，两者差 2 倍。误差模型用 `u`（§1 第二步、表 3）。
2. **减法本身精确（Sterbenz），危险的是它后面的分母。** 放大因子 `(|x|+|y|)/|x-y|` 可以提前算出来，`2μ²u/σ²` 就是它在方差公式上的具体形态（§1 第四、五步）。
3. **误差在哪一步产生，就要在哪一步消除。** B 列用 fp64 把累加做到无误差，结果照样是 0——**换精度不能替代换公式**（§1 第五步、§3）。

下一篇 [03-summation-and-accumulation](03-summation-and-accumulation.md) 处理本文留下的另一半：第三步的「逐层复合」在长序列求和上会把误差推到多大，`γ_n` 这个界怎么推出来、为什么它是线性界而实测只按 `√n` 增长，以及 FMA 如何把斜率减半。[04-low-precision-formats](04-low-precision-formats.md) 则把 `u` 从 fp32 换到 fp16 / bf16 / tf32，看同一个模型的斜率如何被放大——那篇的核心结论（误差按 `√K·u` 增长）正是本文模型在累加场景下的直接推论。
