# 求和的误差累积与 FMA

> 求和的误差不取决于加了多少个数，取决于**怎么加**：顺序累加的误差按 `√n` 的统计规律漂移、最坏情形达到 `γ_n = n·u/(1-n·u)` 的线性界；树形归约把它压到按树的层数累积。而 FMA 的存在意义不是更快，是把两次舍入变成一次。

## 0. 背景与动机

一个 reduce kernel，功能是把一段长度为 `n` 的浮点数组求和。为了提升吞吐，把循环从「每轮加 1 个」改成「每轮加 4 个」（4 路展开），指令数一样、访存一样、结果**应该**一样。但两次运行的最后一个数字不同，而且新版本的误差更大。

同一批数据、同一个 fp32 格式，只有相加顺序不同——`n = 2^20` 上实测（§5 表 4）：

```text
顺序求和 -594.30462646   相对误差 2.253e-05
树形归约 -594.31799316   相对误差 4.146e-08
```

同一个和、同一份数据，相对误差差了三个数量级，而这只是「先加哪两个」的区别。**求和的结果不是数据的函数，是「数据 + 加法顺序」的函数。**

这个问题在 LLM 里到处都是：softmax 的分母、attention 输出对所有历史 token 的加权累加、LayerNorm 的均值与方差、loss 的跨 micro-batch 累加。这些求和的长度可以达到 `1e5` 量级（长上下文里 softmax 的分母就是序列长度），而它们又常常被放进 fp16 或 bf16 的 kernel 里。一个 `√n` 的增长在这一量级下足以把结果推到不可用。

本文要回答三个问题：**误差随 `n` 增长多快**（`γ_n` 这个界怎么来的）、**它正比于什么**（`Σ|x|` 而不是 `|Σx|`）、以及**为什么 GPU 上的归约天然比 CPU 上的逐项累加更准**。

## 1. 原理

### 第一步：三种加法，先把现象的差别摆出来

数据服从 `[-1, 1]` 上的均匀分布（正负号随机，误差有机会互相抵消）。单次随机试验的噪声很大——`n` 小时三种方法谁好谁坏甚至可能反过来——所以每个 `n` 跑 7 个种子取**中位数**相对误差：

| `n` | 顺序 | 成对 | Kahan | 顺序/成对 |
|---|---|---|---|---|
| 1000 | 1.813e-07 | 6.609e-08 | 2.006e-08 | 3 倍 |
| 10000 | 8.123e-07 | 3.653e-08 | 3.653e-08 | 22 倍 |
| 100000 | 3.685e-06 | 3.927e-07 | 6.843e-08 | 9 倍 |
| 1000000 | 9.372e-06 | 1.004e-07 | — | 93 倍 |

`n` 从 1e3 涨到 1e6（1000 倍）：**顺序求和的误差涨了约 52 倍，成对涨了约 2 倍**。`√1000 ≈ 32`、`log2(1000) ≈ 10`——顺序法落在随机游走的量级上（`32` 与 `52` 同阶），成对求和增长得更慢。

还有一个信号：成对求和在 `n=1e6` 时误差是 `1.004e-07`，而 fp32 的 `u = 5.96e-08`。**两者已是同一量级**——说明它的误差不再由累加主导，而由「把最终结果表示成 fp32」这一步主导，继续增大 `n` 也不会让它明显变差。这正是树形归约在长序列上不可替代的原因。

### 第二步：`γ_n` 的推导——从递推展开到线性界

为什么顺序求和的误差项数正比于 `n`？下面一步步展开。设每步的相对误差为 `δ_i`（`|δ_i| ≤ u`），第 `n` 步的部分和满足

```text
Ŝ_n = (Ŝ_{n-1} + x_n)(1 + δ_n)
```

**展开前四步，找出规律**（约定 `δ_1 ≡ 0`，因为第一个元素不需要舍入）：

```text
Ŝ_1 = x_1
Ŝ_2 = (x_1 + x_2)(1 + δ_2)            = x_1(1+δ_2) + x_2(1+δ_2)
Ŝ_3 = (Ŝ_2 + x_3)(1 + δ_3)            = x_1(1+δ_2)(1+δ_3) + x_2(1+δ_2)(1+δ_3) + x_3(1+δ_3)
Ŝ_4 = (Ŝ_3 + x_4)(1 + δ_4)            = x_1(1+δ_2)(1+δ_3)(1+δ_4) + … + x_4(1+δ_4)
```

模式很清楚：**每个 `x_k` 都被它之后所有步的舍入因子乘过**，越早加入的元素背负的舍入因子越多：

```text
Ŝ_n = Σ_{k=1}^{n} x_k · Π_{i=k}^{n} (1 + δ_i)
```

真值 `S_n = Σ x_k`，于是误差就是每个元素偏离 1 的那部分：

```text
Ŝ_n - S_n = Σ_{k=1}^{n} x_k · [ Π_{i=k}^{n} (1 + δ_i) - 1 ]
```

第 `k` 项里的连乘有 `n - k + 1` 个因子，最多 `n` 个。用 `|δ_i| ≤ u` 放缩：

```text
| Π_{i=k}^{n} (1 + δ_i) - 1 | ≤ (1 + u)^(n-k+1) - 1 ≤ (1 + u)^n - 1
```

现在需要把 `(1+u)^n` 界住。用二项式展开逐项放缩 `C(n,k) ≤ n^k`：

```text
(1+u)^n = Σ_{k=0}^{n} C(n,k) u^k
        ≤ 1 + Σ_{k=1}^{n} n^k u^k
        = 1 + Σ_{k=1}^{n} (n·u)^k
        = 1 + n·u · (1 - (n·u)^n) / (1 - n·u)          ← 等比数列求和
        ≤ 1 + n·u / (1 - n·u)                          ← 上界放大，要求 n·u < 1
```

代回去：

```text
|Ŝ_n - S_n| ≤ Σ_k |x_k| · [ n·u / (1 - n·u) ]
            = γ_n · Σ|x_k|,        γ_n = n·u / (1 - n·u)
```

这就是 `γ_n` 的完整来历。注意最后一步的一个细节：所有 `n` 项都被赋予了同一个因子 `γ_n`，而实际上第 `k` 项只有 `n-k+1` 个舍入因子——**这个「统一按最坏的那一项算」的动作，正是 `γ_n` 极端保守的来源**（下面要点③）。

### 第三步：这个界的三个要点，每个都常被误读

**① 误差正比于 `Σ|x_k|`，不是 `|Σ x_k|`。** 界里出现的是各项绝对值之和。这意味着「正负相消、结果接近 0」的求和，相对误差可以任意大——**分母塌了，分子没塌**。实测验证（构造一个 `Σx` 精确等于 0 的求和）：

```text
n = 100000，Σ|x| = 50097.9，而 Σx 的真值精确等于 0（前后各半、互为相反数）
顺序求和得到 -2.285e-04——真值是 0，答案是 -2.3e-04
用 γ_n·Σ|x| 给出的绝对误差界 = 3.004e+02，界成立
```

界成立，而且远未顶到（`2.285e-04` 对 `3.004e+02`）。但如果按**相对误差**表述：分母是真值 0，相对误差是无穷大。这不是数值问题，是**指标选错了**——误差正比于 `Σ|x|`、与 `Σx` 无关，所以当 `Σx ≪ Σ|x|` 时相对误差这个指标本身失去意义。

**结论：描述求和精度要看「绝对误差 ÷ `Σ|x|`」，不看「÷ `|Σx|`」。**

**② 界是线性的，`√n` 只是随机数据的统计行为。** `γ_n ∝ n` 是**保证**；`√n` 是「数据符号随机、误差互相抵消」这一前提下的**统计规律**。构造出来的最坏输入（误差符号全部相同）能达到线性界。所以「实测只涨了 52 倍而理论说 1000 倍」不是理论错了——是那一千倍是最坏情形，随机数据从不触发它。

**③ `γ_n` 是上界，通常极其悲观。** 它把每一项都按最坏情况算，还叠加了等比级数的放大：

| `n` | `γ_n` | `n·u` | 说明 |
|---|---|---|---|
| 10 | 5.9605e-07 | 5.9605e-07 | |
| 1000 | 5.9608e-05 | 5.9605e-05 | |
| 100000 | 5.9962e-03 | 5.9605e-03 | |
| 16000000 | 2.0586e+01 | 9.5367e-01 | `n·u` 逼近 1，界失效 |

最后一行值得停一下：fp32 下 `n` 达到 `1.6e7` 时 `n·u` 已经接近 1，`γ_n` 变成 `2.0586e+01`——**不是说误差真的到了这个量级，而是说这个界本身已经不够紧到有用**。用 `γ_n` 做容量规划会得出「fp32 求和到 1600 万项就废了」的结论，而实测（表 1）在 `n = 1e6` 时的误差只有 `9.372e-06`。

**`γ_n` 的正确用法是证明，不是估计。** 要估量级，用 `√n · u`。

### 第四步：误差为什么会按 `√n` 走

要理解表 1 里那 52 倍，得看误差是怎么累积的：

- **顺序求和**：每一步的部分和都可能已经很大，后续加上小项时**小项被舍入掉**。误差**项数**正比于 `n`，但每项的符号随机 ⇒ 随机游走 ⇒ 实际增长约 `√n`。
- **成对求和**：归约树只有 `log2(n)` 层，每层的误差只累积一次 ⇒ 约 `log n`。
- **Kahan**：把每次丢掉的低位存进补偿项 `c`，下次补回去 ⇒ 误差基本不随 `n` 增长。

三者不是「好、更好、最好」的排序，而是**误差累积结构**的三种形态：`n` 项、`log n` 层、常数。这也解释了为什么成对求和会在某个点撞到「地板」——它的误差降到了 `u` 量级，再往下就是表示最终结果这一步本身的下限了。

### 第五步：FMA——把两次舍入变成一次

`a*b + c` 的常规做法是两条指令、**两次舍入**：先算 `fl(a*b)`，再加 `c` 再舍入一次。FMA（fused multiply-add）在硬件里保留 `a*b` 的**完整乘积**，与 `c` 相加后**只舍入一次**。

先看 float64 上的真实差别（用有理数算精确值，`math.fma` 是真实的融合乘加）：

```text
a = 1 + 2^-27,  b = 1 + 2^-27,  c = -1
精确 a*b + c = 1.4901161249358807e-08     (即 2^-26 + 2^-54)
两次舍入     = 1.4901161193847656e-08     相对误差 3.725e-09
fma 一次舍入 = 1.4901161249358807e-08     相对误差 0.000e+00
```

FMA 给出了**精确值**；两次舍入的版本丢掉了 `2^-54` 那一项——它落在第一次乘法的舍入误差里，后面再也补不回来。

把同样的对比放到 fp16 上，后果从「不精确」升级为**「结果消失」**：

```text
a = 1 + 2^-10,  b = 1 - 2^-10,  c = -1
精确 a*b + c = -9.536743164e-07
两次舍入     = 0                    ← 第一次舍入把 1-2^-20 变成 1.0，结果整个丢失
一次舍入     = -9.536743164e-07     ← 完整保留
```

看清楚发生了什么：`a*b = 1 - 2^-20`，它比 `1.0` 小一点点。fp16 在 `[1,2)` 这个 binade 里的格宽是 `2^-10`（`eps`），`2^-20` 比它小 1024 倍——**乘积在第一次舍入时就被压成了 `1.0`**，再加 `-1` 就得 0。FMA 保留完整乘积，`(1-2^-20) - 1 = -2^-20` 一步算出来，而 `-2^-20` 在 fp16 的 `[2^-20, 2^-19)` binade 里是个完全正常的规格化数。

**这就是矩阵乘累加里 FMA 的真正价值：不是为了更快，是为了更准。** 一次 FMA 只有一次舍入，误差界从 `2u` 降到 `u`；对 `K` 很大的累加来说，**误差增长斜率直接减半**。这也是为什么 Tensor Core 的矩阵乘要设计成融合操作——`K` 有多少，两次舍入的代价就乘多少倍。

## 2. 执行映射

**warp 内的归约：`__shfl_down_sync` 的蝶形交换。** warp 是硬件调度的最小单位，由 32 个线程（lane）组成（定义见 [01-ieee754-format](01-ieee754-format.md) §2），每个 lane 持有一个部分和。归约用寄存器间的直接交换完成，不需要走共享内存：

```text
第 1 轮：lane i 与 lane i+16 相加，步长 16
第 2 轮：lane i 与 lane i+8  相加，步长 8
...     共 log2(32) = 5 轮
```

这正是一棵归约树：每一步的加法发生在**等长的部分和**之间，不存在「大数加小数」的长期积累，因此误差界是 `O(log n)` 而不是 `O(n)`。`5` 这个轮数就是 §1 第四步里「按层数累积」中「层数」的具体值。代价是这 5 轮之间有**同步依赖**，指令级并行度被人为压低——**树形归约是用延迟换精度的**。

**跨 warp：共享内存。** 共享内存是 SM 内一块可被同一个 block 的所有线程直接读写的存储。一个 block 有多个 warp，各 warp 归约出 32 个部分和之后，写进共享内存，再由一个 warp（或所有 warp 协作）做第二轮树形归约。这一级的存在让「归约树」的层数从 5 涨到 `5 + log2(warp 数)`——**仍然是 `log`，不退化**。

**跨 block：`atomicAdd` 或两阶段 kernel。** 这里出现一个本文模型之外的量：`atomicAdd` 的执行顺序由硬件调度决定，**不确定**。§1 的表 1 已经证明「顺序改变 → 结果改变」，那么顺序不确定就意味着**同一份代码、同一份输入，两次运行的结果可以不同**。这不是精度问题，是**可复现性**问题——它会让「训练 loss 有微小抖动」这类排查变得极其困难。

**数值量级：**

| 量 | 数值 | 来源 |
|---|---|---|
| `n = 2^20` 顺序求和相对误差 | **2.253e-05** | §5 表 4 |
| `n = 2^20` 树形归约相对误差 | **4.146e-08** | §5 表 4 |
| `n = 1e6` 顺序 / 成对相对误差 | **9.372e-06** / **1.004e-07** | §5 表 1 |
| fp32 单位舍入误差 `u` | **5.96e-08** | 02 §5 表 3 |
| `γ_n` @ `n = 1e5` | **5.9962e-03** | §5 表 2 |
| warp 归约轮数 | **5**（`log2(32)`） | 推导值 |

注意 `4.146e-08` 与 `u = 5.96e-08` 的关系：树形归约在 `n = 2^20` 上的误差已经**低于**单次舍入的量级，说明它已经把累加误差压到了地板——继续改归约树已经没意义了。

## 3. 实现与演进

**顺序累加。** 一个累加器、一个循环，`0` 次同步、`O(1)` 额外空间。误差按 `√n` 统计增长、最坏 `γ_n` 线性。它在 `n` 小的时候没有对手——表 1 里 `n = 1000` 时顺序法的误差是 `1.813e-07`，换算成 `u` 的倍数只有约 3 倍。

**树形 / 成对归约。** 回应上一条的误差增长阶：把加法组织成二叉树，误差只按层数累积。代价是 `log n` 次同步。这个代价在两个场景下不划算：`n` 很小（同步的开销远超精度收益），以及**延迟比精度重要**（在线推理里多一次同步就多一段延迟）。所以它是「需要时再用」的手段，不是默认。

**Kahan / Neumaier 补偿求和。** 回应树形归约剩下的那部分误差。Kahan 的核心是**把每次丢掉的低位存下来、下一步补回去**：

```text
y = x - c            ← 把上次丢掉的 c 先减掉，等于把它加回来
t = s + y            ← 这次加法会丢掉低位
c = (t - s) - y      ← 用又一次减法把刚丢掉的部分捞出来（Sterbenz 保证这两步减法精确）
s = t
```

注意 `(t - s) - y` 这一步能成立，依赖的是 [02-rounding-and-error-model](02-rounding-and-error-model.md) §1 第四步的 Sterbenz 引理——**抵消在这里被反过来用成了工具**。

Kahan 的代价是**串行依赖**：每一步都依赖上一步的 `c`，无法像树形那样展开并行。在 GPU 上这意味着它只能在 lane 内部串行，跨 lane 仍要走树形。而且它给出的是**更准的结果，不是精确结果**——表 1 里 Kahan 在 `n = 1000` 时仍有 `2.006e-08` 的相对误差。

**分块累加（GPU 的三层结构）。** 回应「树形归约的同步代价」与「Kahan 的串行代价」之间的矛盾。主流做法是把两者叠起来：lane 内用顺序累加（少量项，误差可控）→ warp 内用 shuffle 树形 → 跨 warp 用共享内存树形 → 跨 block 用两阶段或原子。**每一层只在它的长度尺度上承担误差**，总误差是各层误差的叠加，而不是任何单一方法的误差。这也是实测数字（`4.146e-08`）能达到 `u` 量级的原因：层数够少，累加不再是主导项。

**补偿型归约算法（前沿）。** 当 `K` 到 `1e5` 以上（长上下文 attention 的 softmax 分母）、且累加器又被逼着用低精度时，单靠树形结构不够了——误差地板被 `u` 抬高。这一代的做法把「补偿」从标量推广到向量：用两个 fp32 表示一个高精度累加器（double-float / 误差补偿向量），或者直接用专为归约设计的补偿算法。它的成本是**两倍的寄存器与两倍的加法**，所以在寄存器预算紧张时（见 [20-gpu-architecture/execution-model/01-sm-internals.md](../../20-gpu-architecture/execution-model/01-sm-internals.md)）它往往挤不进去——**这构成了精度与占用率的直接冲突**。

## 4. 踩坑与失败模式

### 4.1 用「相对误差」衡量 `Σx ≈ 0` 的求和

**现象**：为了验收一个求和 kernel 的精度，写了一个测试用例：取一批正负对称的数据，检查相对误差是否小于 `1e-6`。测试**永远失败**——相对误差经常是 `1e5` 甚至报 `inf`，而同一个 kernel 在随机数据上表现良好。

**成因**：误差正比于 `Σ|x_k|`，与 `|Σ x_k|` 无关（§1 第三步要点①）。构造正负对称的数据时 `Σx` 的真值恒等于 0，**相对误差的分母是真值本身**——分母为 0，这个指标就失去了定义，任何非零结果都对应无穷大的相对误差。实测里顺序求和给出 `-2.285e-04`，而正确的问题是「`-2.285e-04` 相对于 `Σ|x| = 50097.9` 有多大」——把误差放进 `Σ|x|` 这个天然尺度里，它落在末几位，**相当准**。同一份输出，换一个指标，结论从「完全失败」变成「精度良好」。

**规避**：验收求和精度一律用「绝对误差 ÷ `Σ|x|`」。只有在数据保证同号（`Σ|x| = |Σx|`）时才可以用相对误差。如果确实需要监控「结果接近 0」的场景，就同时记录 `Σ|x|`——它是误差的天然尺度，也是判断「这个和是否有意义」的唯一依据。

### 4.2 假设 GPU 归约的顺序是固定的

**现象**：同一份 kernel、同一份输入，连跑两次得到不同的结果；或者单卡结果可复现，多卡 / 换 block 数之后就对不上；训练 loss 曲线出现无法归因的微小抖动。

**成因**：跨 block 的归约通常用 `atomicAdd` 收尾，而**原子的执行顺序由硬件调度决定**。§1 表 1 已经用纯粹的数据证明了「加法顺序改变 → 结果改变」（同一个 `n`、同一批数据，顺序法与成对法的误差差 3 ~ 93 倍）。把顺序交给调度器，等于把结果的最后几位交给不确定性。

**规避**：需要确定性时改用**两阶段归约**——第一阶段各 block 把自己的部分和写进一个固定的输出槽位，第二阶段用固定顺序（或固定树形）合并。这样 `block` 数固定 ⇒ 结果逐位可复现，代价是多一次 kernel 启动或一次全局同步。另一条路是接受不确定性但把它**隔离**：只在最终累加处用量化/取整抹掉低位差异，或对结果做容差比较而不是逐位比较。**注意这不是「精度问题」，提高精度不会让它变确定**——fp64 的 `atomicAdd` 一样不确定。

### 4.3 把 `γ_n` 当成误差估计来用

**现象**：用 `γ_n` 做精度规划——「`n = 1e5` 的归约，界是 `5.9962e-03`，所以 fp32 只能支撑到 `1e5` 量级」——于是把一个本来完全可行的 fp32 求和改成 fp64 或补偿算法，白白付出两倍算力。

**成因**：`γ_n` 是**上界**，而且是最坏情形下的界，它的构造里有两处叠加的悲观（§1 第二步）：每一 `x_k` 都被乘上了最坏那一项的因子，以及 `(1+u)^n` 的等比放大。实测（表 1）在 `n = 1e6` 时的相对误差是 `9.372e-06`，而同期 `γ_n` 已经是 `5.9605e-03` 量级——**界比实测大三个数量级**。更要命的是 `n·u` 接近 1 时界直接失效（`n = 1.6e7` 时 `γ_n = 2.0586e+01`），而表 1 里最大的实测规模 `n = 1e6` 上误差只有 `9.372e-06`——界与实测之间的距离随 `n` 拉大，不是缩小。

**规避**：区分两种用途。**证明**用 `γ_n`（要严格保证时，它是唯一可用的工具，并且要检查 `n·u < 1` 这个前提）。**估计**用 `√n·u`（随机符号数据的量级），或者直接实测。规划精度时先问「这个界是保证还是估计」——把保证当估计用会浪费算力，把估计当保证用则会漏掉构造出来的坏输入。

### 4.4 在小规模归约上盲目套用树形

**现象**：把一个小归约（`n` 在 1000 上下）从顺序累加改成 warp shuffle 树形，精度确实变好了（表 1 里 `n = 1000` 时顺序法 `1.813e-07`、成对法 `6.609e-08`），但**总耗时反而上升**。

**成因**：树形归约的代价是 `log n` 次同步依赖（§2：warp 内 `5` 轮，跨 warp 还要走共享内存），而它的收益是误差从 `O(n)` 降到 `O(log n)`。当 `n` 小的时候，两边都不划算：收益侧，顺序法在 `n = 1000` 时误差才 `1.813e-07`（约 `3u`），本来就在地板上；成本侧，`5` 轮 shuffle 的同步开销与访存延迟完全不可忽略。**精度已经够好时，为精度付出的同步是纯亏损。**

**规避**：按 `n` 选策略，而不是默认选「更准的那个」。一个可用的判据：先算顺序法的预期误差 `√n·u`，如果它已经在 `u` 的量级（即累加不再是主导项），就没有必要上树形。另一条边界同样重要——**如果延迟比精度重要**（在线推理的尾延迟），顺序累加 `0` 次同步的优势会压过误差上的劣势，此时应该在别处补精度（比如用 fp32 而不是 fp16 累加），而不是改归约结构。

## 6. 小结与延伸

本文只有一条主线：**误差取决于结构，不取决于规模**。沿这条线有三个可独立复用的结论：

1. **`γ_n = n·u/(1-n·u)` 的推导**（§1 第二步）：把递推展成 `Ŝ_n = Σ x_k · Π(1+δ_i)`，用 `C(n,k) ≤ n^k` 把连乘界成等比级数。它给出 `|误差| ≤ γ_n · Σ|x_k|`——**误差正比于 `Σ|x|` 而非 `|Σx|`**，这是求和误差分析里最容易被忽略的一句。
2. **线性界 vs `√n` 统计行为**：`γ_n` 是保证、`√n` 是随机数据的规律，两者都真实但用途不同——证明用前者、估计用后者（§1 第三步要点②③）。
3. **FMA 的价值是精度不是速度**：把两次舍入变成一次，误差界从 `2u` 降到 `u`，对 `K` 次累加就是**斜率减半**；fp16 的极端例子里它甚至是「结果存在与否」的区别（§1 第五步、表 4）。

下一篇 [04-low-precision-formats](04-low-precision-formats.md) 把本文的模型接到低精度格式上：同一个 `γ_K` 结构，`u` 从 `5.96e-08` 换成 `4.883e-04`（fp16），误差斜率会放大多少倍，以及为什么实测只按 `√K·u` 而不是 `K·u` 增长——那正是本文 §1 第四步「√n 是随机数据的统计行为」在矩阵乘场景下的完整展开。归约在 GPU 上的工程实现（分块、扫描、跨 block 合并）见 [40-kernels/reduce-scan](../../40-kernels/reduce-scan.md)（正文在该域，回链此处）。
