# 矩阵分解的稳定性：为什么选主元、为什么 Cholesky 要求正定

> 不选主元的 LU 在随机矩阵上**是能用的**（精度只差两三个数量级）；反对它的理由是**没有保证**。同理，Cholesky 要求的不只是「看起来正定」，而在 `λ_min ≈ u·λ_max` 量级上，「是否正定」这个判定本身由舍入方向决定。

## 0. 背景与动机

GPTQ 之类的训练后量化，核心是解一个逐层的加权最小二乘，最终落到正规方程 `(X·Xᵀ)·Δ = …`。其中 `H = X·Xᵀ` 是校准数据在该层输入空间上的协方差，实现在 H 上做 Cholesky 分解（有些版本用 LDLᵀ）。**所以「H 是否正定」直接决定这段代码能不能跑通。**

配套程序用一个纯模拟的模型（`d = 256` 个特征，`n` 个校准样本，`H = X·Xᵀ/n`）量出了这件事的边界：

| 样本数 n | 特征数 d | d/n | rank(H) | κ(H) | cholesky(H) |
|---|---|---|---|---|---|
| 64 | 256 | 4.00 | 64 | 1.226e+18 | LinAlgError（不是正定） |
| 128 | 256 | 2.00 | 128 | 1.539e+20 | LinAlgError（不是正定） |
| 192 | 256 | 1.33 | 192 | 4.326e+17 | LinAlgError（不是正定） |
| 256 | 256 | 1.00 | 256 | 3.125e+06 | 成功 |
| 512 | 256 | 0.50 | 256 | 3.170e+01 | 成功 |
| 1024 | 256 | 0.25 | 256 | 8.504e+00 | 成功 |
| 2048 | 256 | 0.12 | 256 | 4.321e+00 | 成功 |

`n < d` 时 H 的秩只有 n，有一半特征值精确为 0，Cholesky 直接抛异常。而即使 `n ≥ d`，`n = d = 256` 那一行的条件数还有 3.125e+06——**「样本数 ≥ 特征数」远远不够**。

但真正麻烦的不是这个显式的秩亏。麻烦的是**秩满之后、但某个特征值小到和舍入噪声同量级**的情形：此时「H 是否正定」这个问题没有确定答案。程序里有一行数据把这一点摆得很清楚：

```text
λ_min = 1e-16 时 → Cholesky 失败 0/200，而 eigvalsh 报出的最小特征值已是 -1.76e-16（负的）
```

**Cholesky 说「分解成功」和 eigvalsh 说「有负特征值」可以同时成立。** 两个函数看的是不同的量，谁也不是权威。

本文要回答三个问题：不选主元的 LU 到底错在哪（答案不是「精度差」）；Cholesky 要求正定的确切含义，以及为什么这个要求在舍入噪声量级上会失效；三种分解的代价到底差多少（答案不是一个 flops 比值）。

## 1. 原理

### 第一步：不选主元 LU 的失败链条

不选主元的 LU 只有四行：

```text
for k in range(n - 1):
    for i in range(k + 1, n):
        m       = A[i, k] / A[k, k]      # 用对角元当主元
        A[i, k] = m                      # 乘子存进下三角
        A[i, k+1:] -= m * A[k, k+1:]     # 消元
```

致命处在第一行：`A[k, k]` 是**当前位置上碰巧有的那个数**，不是选出来的，它可以是任意小。而乘子 `m = A[i,k] / A[k,k]` 会因此任意大。

程序的 2×2 反例取 `A = [[ε, 1], [1, 1]]`，右端项由 `x = [1, 1]` 生成（所以真解已知）：

| ε | 不选主元 growth | 选主元 growth | 不选主元 相对误差 | 选主元 相对误差 |
|---|---|---|---|---|
| 1e-01 | 9.000e+00 | 1.000e+00 | 6.474e-16 | 2.220e-16 |
| 1e-02 | 9.900e+01 | 1.000e+00 | 6.280e-16 | 0.000e+00 |
| 1e-04 | 9.999e+03 | 1.000e+00 | 7.788e-14 | 0.000e+00 |
| 1e-08 | 1.000e+08 | 1.000e+00 | 3.553e-09 | 0.000e+00 |
| 1e-12 | 1.000e+12 | 1.000e+00 | 9.415e-05 | 2.220e-16 |
| 1e-15 | 1.000e+15 | 1.000e+00 | 7.794e-02 | 2.220e-16 |

看 `ε = 1e-15` 那一行，两个分解的完整因子：

```text
不选主元的 LU 因子         [[  1.0e-15,   1.0e+00], [  1.0e+15,  -1.0e+15]]
选主元的 LU 因子（换行后）  [[  1.0e+00,   1.0e+00], [  1.0e-15,   1.0e+00]]   行置换 = [1, 0]
```

不选主元的 `U₂₂ = -1.0e+15`，量级是 `1/ε`——**原始矩阵里那个 1 被吃掉了**；选主元的 `U₂₂ = 1.000`，量级正常。解出来的结果：

```text
不选主元解 = [1.1102230246251563, 1.0]                相对误差 7.794e-02
选主元解   = [0.9999999999999998, 1.0000000000000002]  相对误差 2.220e-16
```

第一行答成了 1.1102（正确值 1）。原因链条只有三步，每一步都可以单独看懂：

**① 主元小 → 乘子大。** 主元是 `ε ≈ 0`，乘子 `m = 1/ε = 1e+15` 爆炸。

**② 乘子大 → 消元把原始信息冲掉。** L 的第二行全是 `1e+15`，消元后 U 的第二行变成 `[0, 1 - 1/ε] ≈ [0, -1e+15]`。也就是说原始 A 第二行那个 1 的信息被完全冲掉了——这一步是**信息丢失，不是精度损失**。

**③ 回代时两个相近的数相减。** `x₁ = (b₁ - U₁₂·x₂)/U₁₁ = (1+ε - 1)/ε`。分子是 `b₁ = 1+ε` 与 `U₁₂·x₂ = 1` 相减——1 附近的一个 ulp 是 `2.22e-16`，而 `ε = 1e-15` 只有 4.5 个 ulp 宽，所以 `b₁` 里「ε 那部分」的表示本身就只有约 2.2 个二进制位的精度。这个差再除以 ε（放大 1e+15 倍），相对误差就变成 11%。

这就是 [floating-point/02](../../floating-point/02-rounding-and-error-model.md) 讲的**灾难性抵消**在分解里的具体形态：**主元小 → 乘子大 → 相减的两个数接近 → 有效位全丢**。选主元做的事非常朴素：把该列最大的元素换到对角上，于是乘子 `|m| ≤ 1`，第二步的相减永远发生在同量级的数之间。

### 第二步：增长因子——算法引入的那部分误差

衡量分解稳定性的标准量是**增长因子**：

```text
ρ_growth = max|U_ij| / max|A_ij|
```

它衡量消元过程中元素膨胀了多少倍。上面的分析框架是「误差 ~ ρ_growth · κ(A) · u」——`κ(A)` 来自问题本身（[01](01-norms-and-condition-number.md)），`ρ_growth` 来自算法。对 `[[ε,1],[1,1]]`，不选主元的增长因子就是 `1/ε`，选主元恒为 1。

但这是**构造出来的**。随机矩阵上呢？程序跑 200 个矩阵：

| n | 不选主元 growth 中位/最大 | 部分主元 growth 中位/最大 | 中位比 |
|---|---|---|---|
| 10 | 1.80e+01 / 2.22e+03 | 2.13e+00 / 6.88e+00 | 8.4 |
| 30 | 1.06e+02 / 3.88e+03 | 5.00e+00 / 1.04e+01 | 21.2 |
| 60 | 4.52e+02 / 1.16e+05 | 7.72e+00 / 1.40e+01 | 58.5 |

**部分主元的增长因子很小且稳定**：中位 2.1 ~ 7.7，200 个矩阵里最大也只有 14。这不是运气——部分主元保证 `|L_ij| ≤ 1`，而 U 的膨胀在实践中远小于 `2^(n-1)` 的最坏界。

**不选主元的增长因子确实更大**：中位数随 n 从 18 涨到 452，最大到了 1.2e+05。但量级只有 10²~10⁵。

### 第三步：这张表推翻了「不选主元就会算错」

增长因子大不等于结果不能用。看实际求解精度：

| n | 测试矩阵 | 不选主元 相对误差中位 | 不选主元 最大 | 选主元 中位 |
|---|---|---|---|---|
| 30 | 均匀随机 | 1.466e-13 | 7.983e-12 | 2.792e-15 |
| 30 | `A[0,0]` 设为 1e-14 | 4.327e-02 | 4.852e-01 | 3.336e-15 |
| 60 | 均匀随机 | 1.045e-12 | 4.025e-11 | 9.917e-15 |
| 60 | `A[0,0]` 设为 1e-14 | 8.628e-02 | 1.083e+00 | 9.112e-15 |

均匀随机矩阵上，不选主元的 LU 精度是 `1e-13 ~ 1e-12`，与选主元的 1e-15 只差**两三个数量级**——**能用，只是没那么好**。

真正致命的是第二行：**只把 `A[0,0]` 改成 1e-14，其它一切照旧**，中位误差立刻变成 1e-2 量级（4.327e-02），最大到了 O(1)（4.852e-01）——答案整个作废。而这个改动只动了**一个元素**，与均匀随机矩阵的距离就是一个元素。

所以正确的表述是：

- **不选主元没有误差界。** 存在输入让它彻底失败，且这样的输入离随机矩阵只有一个元素的距离（现实中对应「某个特征恰好接近线性相关」）。
- **选主元保证 `|L_ij| ≤ 1`**，于是增长因子至少有界（最坏 `2^(n-1)`，实践中远小于此，实测最大 14），因此**在所有输入上都有保证**。
- **代价只有 O(n²) 次比较**——相对 O(n³) 次浮点运算可以忽略。

结论不是「不选主元精度差几个数量级」，而是「**不选主元没有保证，而保证几乎免费**」。

### 第四步：Cholesky 要求正定——开方那一步的由来

Cholesky 把对称正定矩阵 A 分解成 `A = L·Lᵀ`（L 下三角）。程序先用一个 2×2 验证约定：

```text
A = [[2. 1.]  [1. 2.]]
L = [[1.414214 0.      ]  [0.707107 1.224745]]
‖L·Lᵀ - A‖ = 6.280e-16    ‖Lᵀ·L - A‖ = 7.321e-01
```

`‖L·Lᵀ - A‖ = 6.280e-16` 而 `‖Lᵀ·L - A‖ = 7.321e-01`，确认 `numpy.linalg.cholesky` 返回的是 `A = L·Lᵀ` 里的那个下三角 L（不是 `Lᵀ·L`）——**这个约定必须验证，写反了整段代码都是错的**。

为什么要求正定？按列写开就知道：第 k 列的对角元满足

```text
a_kk = Σ_{j≤k} l_kj²        ⟹        l_kk = sqrt( a_kk - Σ_{j<k} l_kj² )
```

每一步都要开一次方。被开方数必须是正的，否则实数域内没有解。而 `A = LLᵀ` 且 L 可逆时，对任意 `v ≠ 0`：

```text
vᵀAv = vᵀLLᵀv = ‖Lᵀv‖₂² > 0
```

所以**正定性是分解存在的充要条件**（对称矩阵正定 ⟺ 全部特征值 > 0）。程序对比了五种情形：

| 矩阵 | `eigvalsh` | `cholesky(A)` |
|---|---|---|
| `[[1,2],[2,1]]` | `[-1. 3.]` | LinAlgError: Matrix is not positive definite |
| `[[2,1],[1,2]]` | `[1. 3.]` | 成功 `min(diag L) = 1.225e+00` |
| `diag(1, 1e-16)` | `[1.e-16 1.e+00]` | 成功 `min(diag L) = 1.000e-08` |
| `diag(1, -1e-16)` | `[-1.e-16 1.e+00]` | LinAlgError: Matrix is not positive definite |
| `[[1,1],[1,1+1e-16]]` | `[0. 2.]` | LinAlgError: Matrix is not positive definite |

三个失败值得分开看。

**真的不是正定。** `[[1,2],[2,1]]` 的特征值有负的（-1），Cholesky 抛异常是正确行为。

**信息在赋值那一刻就丢了。** `[[1,1],[1,1+1e-16]]` 数学上 `det = 1e-16 > 0`，是正定的。但 `1+1e-16` 在 fp64 里就等于 1（`u = 2.2e-16`），所以存进去的矩阵是 `[[1,1],[1,1]]`——**精确奇异**。`eigvalsh` 给出 `[0, 2]`，Cholesky 失败。这不是 Cholesky 的错。

**可表示的极小正数仍然有效。** `diag(1, 1e-16)` 成功而 `diag(1, -1e-16)` 失败：1e-16 虽然比 `u` 还小，但它是个可表示的正数（fp64 的次正规下界是 5e-324），所以正定性成立。`min(diag L) = 1.000e-08 = √1e-16`，与公式一致。

### 第五步：判定矛盾——`λ_min ≈ u·λ_max` 上的正定性

上面三个失败都还有明确答案。真正的麻烦在中间地带。程序构造 `A = Q·diag(1, λ_min, 1e-3)·Qᵀ`（Q 随机正交，所以精确特征值已知），舍入到 fp64 后看 Cholesky 是否还认为它正定。每个 `λ_min` 跑 200 个 Q：

| λ_min 目标 | Cholesky 失败 | eigvalsh 给出的 λ_min 范围 | λ_min/u |
|---|---|---|---|
| 1e-15 | 0/200 | 7.03e-16 ~ 1.30e-15 | 4.5 |
| 1e-16 | 0/200 | -1.76e-16 ~ 3.07e-16 | 0.5 |
| 1e-17 | 72/200 | -2.59e-16 ~ 3.49e-16 | 0.0 |
| 1e-18 | 99/200 | -2.16e-16 ~ 3.49e-16 | 0.0 |

分界线很清楚，位置正好在 `λ_min ≈ u·λ_max` 上（`u = 2.2e-16`，`λ_max = 1`）：

- `λ_min = 1e-15`（`= 4.50·u`）：失败 0/200，`eigvalsh` 给出最小特征值 `+7.03e-16`。舍入噪声（量级 `u·λ_max ≈ 2.2e-16`）比 `λ_min` 小，正定性是**确定的**。
- `λ_min = 1e-17`（`= 0.05·u`）：失败 72/200（36%）。舍入噪声已经盖过 `λ_min` 本身——此时矩阵「是不是正定」由**舍入方向**决定。
- `λ_min = 1e-18`（`= 0.00·u`）：失败 99/200（50%）。

中间那行值得单独指出：`λ_min = 1e-16`（`= 0.45·u`）时 Cholesky **全部通过**，但 `eigvalsh` 报出的最小值已经是 **-1.76e-16（负的）**。

**两个函数给出相反的结论，因为它们看的是不同的量。** `eigvalsh` 的特征值本身带 `u·λ_max` 量级的误差（它经过了一整条 QR 迭代链），而 Cholesky 只看分解过程中每个主元的符号。在 `λ_min ≈ u·λ_max` 这个量级上，**这两个「正定性」结论都不可靠，不能拿它们互相印证**。

这在参数估计里是个真问题：如果 H 的 `λ_min` 正好落在这个量级，那么「H 是否正定」取决于最后一次加法的舍入方向，而不是数据本身——这正是 §0 那张 GPTQ 表背后的问题。

### 第六步：三种分解的代价——flops 模型与实测的偏离

方阵 `n×n` 的经典 flops 计数（乘加各算一次）：

| 分解 | flops | n=1500 时 | 用途 |
|---|---|---|---|
| LU（带主元） | `2n³/3` | 2.250e+09 | 解一般方阵 |
| Cholesky | `n³/3` | 1.125e+09 | 解对称正定 |
| QR | `2n³/3` | 2.250e+09 | 最小二乘 / 正交化 |

模型预测：**Cholesky 恰好是 LU 的一半**（LU 多做了一倍消元，因为没有利用对称性），而 QR 与 LU 同阶。

实测 `n = 1500`。**这一节的读法与全文其他各节不同，先说清楚为什么。**

其他各节的数字都是逐位可复现的——同一个输入必然给出同一个输出。**计时不是。** CPU 频率漂移、cache 状态、后台进程都会影响它，而且影响的幅度**足以覆盖掉待验证的差异**。所以程序不报单次结果，而是跑 **9 次试验**（每次试验内部再取 5 次的最小值），报出**范围**。

**可复现的是判定，不是数值。** 比值本身在多次运行之间仍会漂移（`cholesky/solve` 的 9 次试验中位数在 `0.392 / 0.415 / 0.416` 之间变化），但**三个判定在反复运行中完全稳定**。下表引用的是程序输出的判定，不是某一个具体数字：

| 比值 | 模型预测 | 程序给出的判定 | 稳定性 |
|---|---|---|---|
| `cholesky / solve` | 0.500 | 范围离 0.5 只剩 10% ~ 19% ⇒ **方向一致，但具体数值对不上模型** | 稳定 |
| `cholesky / qr(mode='r')` | 0.500 | 范围离 0.5 还有 66% ~ 67% ⇒ **模型与实测明显不符，结论成立** | 稳定 |
| `qr(mode='r') / qr(full)` | 0.500 | **范围跨过 0.5 ⇒ 未证实** | 稳定 |

程序里那条判据只有一行，但它是这一节的全部内容：

```text
观察到的范围有没有把模型预测值 0.5 包进去
```

三种结果对应三种写法，不能混：**跨过预测值** ⇒ 只能说「这一次测量与预测一致」，不能说模型被验证（这叫未证实，不叫成立）；**远离预测值** ⇒ 模型与实测明显不符，结论成立；**不远不近** ⇒ 方向一致，但不能说「数值吻合」。

按这条判据逐个读：

**一、`cholesky / solve`：方向一致，但数值对不上模型。** 范围在 `0.376 ~ 0.449` 之间（多次运行），始终低于 0.5 但离得只有 10% ~ 19%。所以准确的表述是「**对称正定省掉一半量级的时间**」，而不是「实测 0.42、模型 0.50、吻合」。差距的来源可以解释：LU 还要额外做主元搜索与行交换，那部分不在 flops 计数里——**模型低估了 LU 的开销，所以真实比值低于 0.5 是符合预期的**，只是这个偏离幅度（约 20%）与测量噪声同量级，无法靠这套测量把它精确测出来。

**二、`cholesky / qr(mode='r')`：模型与实测明显不符，结论成立。** 范围在 `0.12 ~ 0.18` 之间，离 0.5 有 66% ~ 67% 的距离——**噪声盖不住这个距离**，这是全表最结实的一个结论。flops 只差 2 倍（`n³/3` 对 `2n³/3`），实测差了约 6 倍。原因看程序中 `ns/flop` 那一列：numpy 的 QR 每 flop 比 Cholesky 贵约 3 倍。LAPACK 的 Cholesky/LU 有高度优化的分块内核（BLAS-3 占比高），而 QR 的 Householder 反射受限于 BLAS-2 的内存带宽，算力吃不满。

**所以 flops 计数只能比较同一个库里的相似算法，不能跨实现预测时间。** 写 kernel 时听到「QR 和 LU 同阶」而以为两者一样快，是要吃亏的。

**三、`qr(mode='r') / qr(full)`：未证实。** 范围跨过了 0.5（多次运行下分别观测到 `0.422 ~ 0.544`、`0.428 ~ 0.566`、`0.455 ~ 0.509`）——**摆动幅度大于它与模型预测值之间的差距**。两者的差别确实只是「要不要显式组装 Q」（flops 表里 `4n³/3` 与 `2n³/3` 之差），理论上应当成立；但要实测证实它，需要比「多次取最小」更严格的测量方法（固定 CPU 频率、绑定核心、提高重复次数并做统计检验）。**本文如实报未证实——既不说成立，也不说被推翻。**

### 第七步：QR 的稳定性从哪来

`QR` 之所以是最小二乘的默认选择，理由在 [01](01-norms-and-condition-number.md) §1 第八步已经推导过：正交矩阵满足 `‖Q‖₂ = 1`，因此 `κ₂(Q) = 1`，误差不被放大。Householder 反射是初等正交变换的乘积，所以整个 QR 过程由正交变换串起来，**它对误差是中性的**——既不放大也不缩小，而 LU 的增长因子可以放大。

值得注意的是这两件事互不抵消：QR 的**稳定性**（不放大误差）与它的**代价**（每 flop 比 Cholesky 贵 3.4 倍）是两个独立的属性。选 QR 是因为需要它的稳定性，不是因为便宜。

## 2. 执行映射

### 库里的对应关系

三种分解在库层面各有对应例程，GPU 上由 cuSOLVER 提供：

| 分解 | LAPACK | cuSOLVER | 后续三角求解 |
|---|---|---|---|
| LU（部分主元） | `dgetrf` | `cusolverDnXgetrf` | `cusolverDnXgetrs` / cuBLAS `<t>trsm` |
| Cholesky | `dpotrf` | `cusolverDnXpotrf` | `cusolverDnXpotrs` / cuBLAS `<t>trsm` |
| QR | `dgeqrf` | `cusolverDnXgeqrf` | `cusolverDnXgeqrf` + `cusolverDnXorgqr` / cuBLAS `<t>trsm` |

（这一节是**库接口的对应关系**，来自各库文档，不是本文实测。本文实测的是上表的计时数字。）

注意 `getrs` / `potrs` / `<t>trsm` 都是三角求解——分解一次（O(n³)）之后，每次求解只要 O(n²)。这个区别是 [04-iterative-methods](04-iterative-methods.md) 里迭代精化能便宜地反复做的原因。

### 分块分解：为什么 GPU 上的瓶颈在 panel

现代 LAPACK 与 cuSOLVER 都不用教科书的逐列消元，而是**分块分解**：把矩阵切成宽度为 `nb` 的面板（panel）和右侧的尾块（trailing update）。

```text
① panel factorization     对 nb 列做逐列消元（BLAS-2，访存受限）
② trailing update         C -= L_panel · U_panel（一次 GEMM，BLAS-3，算力受限）
```

动机是算术强度：`nb = 32` 时，panel 部分的 flops 占比约 `O(nb/n)`，而 trailing update 是一次大 GEMM，能跑到接近 FP32 的峰值。**这就是 §1 第六步里 QR 输给 Cholesky 的地方**——Householder 反射的 BLAS-3 化不如 Cholesky/LU 彻底，BLAS-2 占比更高，所以每 flop 贵 3.4 倍。

在 GPU 上，这个划分还带来一个并行度问题：trailing update 是 GEMM，能同时占用全部 SM；而 panel factorization 在传统实现里是**串行的**（每一列都依赖前一列的主元选择），只能用一个 block 甚至一个 warp。于是分块分解在 GPU 上的典型形态是「panel 在单个 SM（或回退到 CPU）上做完，尾块更新铺满 GPU」——分解的整体加速比因此被 panel 部分封顶，与矩阵规模不呈线性。这是分块分解在 GPU 上的核心工程约束，也是后面 §3 里「通信避免算法」这一路线的由来。

### 数值量级

| 量 | 数值 | 来源 |
|---|---|---|
| `n = 1500` 的 Cholesky 时间 | 中位约 `9.6 ms`（`1.125e+09` flops） | 配套程序 §4，**单次运行值，不可复现** |
| `n = 1500` 的 LU 求解时间 | 中位约 `23 ms`（`2.254e+09` flops） | 配套程序 §4，**单次运行值，不可复现** |
| `n = 1500` 的 QR（只算 R） | 中位约 `65 ms`（`2.250e+09` flops） | 配套程序 §4，**单次运行值，不可复现** |
| QR / Cholesky 的单 flop 代价比 | 3.4 倍 | 配套程序 §4（由 ns/flop 两列相除） |
| 计时比值（9 次试验，程序自己打印范围） | `cholesky/solve` 离 0.5 约 10%~19%；`cholesky/qr` 离 0.5 约 66%；`qr(r)/qr(full)` **跨过 0.5** | 配套程序 §4 的判定行 |
| 部分主元 growth 实测最大（200 个随机矩阵，n=60） | 1.40e+01 | 配套程序 §2 |

计时只对本机有意义（macOS + numpy 调用 LAPACK，单线程）。三个比值的可迁移性要分开判断：`Cholesky/LU = 0.422` **可以迁移**（来自算法结构，且重复运行稳定）；`Cholesky/QR = 0.147` **不可迁移**（它来自两个具体实现的 BLAS-3 化程度差异，只说明「numpy 的 QR 比 Cholesky 慢 3~4 倍」这件事，不说明任何理论比值）；`qr(mode='r')/qr(full)` 的实测值**不足以支撑任何结论**（重复范围覆盖了它与模型预测值的差距，见 §4.5）。

## 3. 实现与演进

### 朴素做法：无主元 LU

教科书上的直接消元，四行代码（§1 第一步）。它是这条线的起点，也是唯一能被纸笔完整分析的版本——代价 O(n³)，增长因子在最坏情况下是 `2^(n-1)`。

**为什么需要下一步**：§1 第三步的表给出了答案。它在随机矩阵上能用（1e-13 ~ 1e-12），但在单个元素被改成 1e-14 的矩阵上作废（4.327e-02）。一个没有误差界的算法，无法用在任何需要保证的地方。

### 主流：部分主元 LU

每一步在该列剩余元素里挑绝对值最大的换到对角上。两个后果：乘子 `|m| ≤ 1`，于是相减永远发生在同量级的数之间（消除 §1 第一步的第三步）；增长因子从无界变成有界。

程序的实测把「有界」这件事量化了：部分主元的 growth 中位 2.1 ~ 7.7，200 个随机矩阵里最大 14——对比不选主元的 18 ~ 452（中位）与 1.2e+05（最大）。

**为什么需要下一步**：部分主元的界是**存在性的**，不是紧的。它的最坏情形增长因子仍是 `2^(n-1)` 量级（构造见 §4.3），只是实践中极难撞上。对绝大多数工程场景这已经足够；但对「一定要给出保证」的场景（例如需要形式化误差界），部分主元的界太松。

### 完全主元：更稳，也更贵

每一步在**整个剩余子矩阵**里挑绝对值最大的元素，同时做行列交换。增长因子得到更强的界，但主元搜索从 O(n²) 变成 O(n³) 量级的数据比较，且破坏了内存访问的连续性——在分块实现里这一项会直接吃掉 BLAS-3 的收益。所以除了少数数值库和教学演示，实际代码几乎不用完全主元。

### 分块与并行：GPU 上的形态

§2 描述的分块结构是这一代的主流。它的关键工程约束是 panel factorization 的串行性，围绕这个约束有几条路线：

- **右看（right-looking）与左看（left-looking）的取舍**：左看把更新推迟到需要时才做，减少了 panel 期间的同步次数，代价是更多的读带宽。cuSOLVER 与 MAGMA 在不同规模上选择不同。
- **递归分块**：把 panel 自身再递归地分块，让 panel 内部也有 BLAS-3；`dgetrf` 的递归变体走这条路。
- **通信避免算法**：把 `nb` 取得很大（远大于缓存能容纳的宽度），让 panel 的 flops 占比降到 `O(1/nb)`，代价是 trailing update 的一次并行归约需要更多的通信。这是在 GPU 集群与多节点上唯一能继续扩展的方向。

### 与量化方法的接合点

Cholesky 在 LLM 量化里的角色（§0）是这条线的另一条分支：GPTQ 需要在 `H = XXᵀ` 上做 Cholesky，而 H 在数值上常常**恰好落在 §1 第五步的那个临界量级上**。§5 的模拟给出了原因：`d = n` 时 κ(H) 达到 3.125e+06（还有 1e6 是因为特征值分布的特异），往上再加样本数才迅速改善。所以工程实现里几乎必然要加阻尼项 `λI`——它的作用见 §4.4 与 §5。

## 4. 踩坑与失败模式

### 4.1 拿 `eigvalsh` 的结论去印证 Cholesky 的结论

**现象**：代码里写「先 `np.linalg.cholesky(H)`，如果抛异常就 `eigvalsh(H)` 看是不是真的不正定」；或者反过来说「`eigvalsh` 报出最小特征值是正的，所以 Cholesky 一定能跑通」。

**成因**：在 `λ_min ≈ u·λ_max` 量级上两者会给出**直接矛盾**的答案——程序实测 `λ_min = 1e-16` 时 Cholesky 0/200 全部通过，而 `eigvalsh` 报出的最小特征值是 **-1.76e-16**。原因是两者度量的对象不同：`eigvalsh` 的特征值本身带 `u·λ_max` 量级的误差（它经过了整条 QR 迭代），而 Cholesky 只看每个主元的符号。此时两个结论**都不可靠**，用其中一个去验证另一个，等于用一把不准的尺子去校准另一把不准的尺子。

**规避**：用数值上**与分辨率匹配**的判据取代符号判据。可操作的判据是 `λ_min > c · u · λ_max`（`c` 取 10 ~ 100），而不是 `λ_min > 0`。程序的数据给出了这个判据的位置：`λ_min = 4.50·u` 时失败率 0/200（结论确定），`λ_min = 0.05·u` 时失败率 36%（结论由舍入决定）。`κ(H) < 1/u` 这类判据同理——它是必要条件，不是充分条件。

### 4.2 用 QR 去解一般方阵

**现象**：代码里统一用 `lstsq` 或 QR 求解所有线性系统，理由是「QR 更稳定」，结果是耗时变成必要的 3 倍以上。

**成因**：QR 的稳定性优势针对的是**最小二乘**（`m ≥ n`、可能秩亏），因为那里必须用正交变换把残差投影出去。对**一般方阵**、系数矩阵良态的情形，LU 已经有误差界（`ρ_growth · κ(A) · u`，部分主元的 `ρ_growth` 实测最大 14），不需要 QR 提供额外的稳定性。而代价是实测的：`Cholesky / solve = 0.422` 说明对称正定省一半；`Cholesky / qr(mode='r') = 0.147` 说明 QR 是 Cholesky 的 6.8 倍——**而且这 6.8 倍里只有 2 倍来自 flops，其余 3.4 倍来自实现效率**。

**规避**：先看矩阵性质再选算法（§5 的选型表）。一般方阵用部分主元 LU；对称正定用 Cholesky；最小二乘用 QR/SVD。如果只是「不确定要不要用 QR」，先估 `κ(A)`——`κ · u ≪ 1` 时 LU 的误差界已经足够紧。

### 4.3 以为「部分主元」就等于「增长因子不会大」

**现象**：看到部分主元保证 `|L_ij| ≤ 1`，就认为增长因子不可能大，进而在对误差极敏感的路径上不做任何额外检查。

**成因**：`|L_ij| ≤ 1` 只约束了乘子，没有约束 U 的膨胀。部分主元的最坏情形增长因子仍是 `2^(n-1)` 量级（这个构造存在但极难在随机数据上撞到——程序 200 个随机矩阵里最大只有 14）。真正的风险不在随机数据上：**结构化的输入（例如来自外推、插值或者人为构造的测试用例）才容易踩到**，而这类输入在工程里并不罕见（比如用它去验证一个数值库的鲁棒性）。

**规避**：把增长因子当成一个可以主动算出来的量（定义见 §1 第二步，实际就是 `np.abs(np.triu(LU)).max() / np.abs(A).max()`），在精度敏感的路径上算一次并记录。若 `ρ_growth` 明显超出经验区间（部分主元实测中位 2.1 ~ 7.7），改用完全主元或加迭代精化（[04-iterative-methods](04-iterative-methods.md)）——后者的代价可能更低。

### 4.4 加了阻尼让 Cholesky 跑通，就以为解有意义

**现象**：`H` 不正定导致 Cholesky 抛异常，加一个小阻尼 `λI` 后跑通，于是把 `λ` 调到「刚好不抛异常」就收工。

**成因**：数值可行性与统计有效性是两个不同的量级要求，而它们相差约 10 个数量级（`1e-03 / 1.75e-13 ≈ 5.7e9`）。程序在 `d = 256, n = 128`（秩 128，必然奇异）上扫描 λ（`λ_max = 5.7127`）：

| λ | λ/λ_max | κ(H+λI) 实测 | (λ_max+λ)/λ | cholesky |
|---|---|---|---|---|
| 0e+00 | 0.00e+00 | 1.539e+20 | inf | LinAlgError |
| 1e-12 | 1.75e-13 | 5.724e+12 | 5.713e+12 | 成功 |
| 1e-10 | 1.75e-11 | 5.713e+10 | 5.713e+10 | 成功 |
| 1e-08 | 1.75e-09 | 5.713e+08 | 5.713e+08 | 成功 |
| 1e-06 | 1.75e-07 | 5.713e+06 | 5.713e+06 | 成功 |
| 1e-04 | 1.75e-05 | 5.713e+04 | 5.713e+04 | 成功 |
| 1e-02 | 1.75e-03 | 5.723e+02 | 5.723e+02 | 成功 |
| 1e-01 | 1.75e-02 | 5.813e+01 | 5.813e+01 | 成功 |

实测的 κ 与 `(λ_max+λ)/λ` **逐行精确相等**——这不是拟合，是恒等式（因为 `λ_min(H) = 0`，加 `λI` 后最小特征值就是 λ）。而**λ = 1e-12 就已经让 Cholesky 成功了**，尽管此时 κ 高达 5.724e+12。

原因是 Cholesky 只要求「分解过程中没有非正主元」，而 λ = 1e-12 这一个小小的正扰动就足以让最小的那个主元翻正。所以「跑通」这个信号的门槛低得离谱：**表里把 κ 压到 1e3 以下需要 `λ/λ_max ≳ 1e-03`，而让 Cholesky 跑通只需要 1.75e-13——两者相差约 10 个数量级。**

**规避**：把阻尼的主要目的写成**统计正则化**而不是数值可行性，并让 λ 的取值有可辩护的理由（例如按 `λ = c·tr(H)/d` 或按先验方差给出，而不是按「不抛异常」给出）。同时记录加阻尼前后的 `κ` ——如果 `κ` 仍在 1e6 以上，那么该方向上的解基本是噪声，报告结果时必须说明。

### 4.5 拿单次计时下结论

**现象**：跑一次分解计时，看到 `qr(mode='r') / qr(full) = 0.503` 与 flops 模型预测的 0.5 吻合，于是在文档里写「flops 模型在这一条上得到验证」。

**成因**：**计时是本文所有表格里唯一不可复现的一类。** 单次运行给出的 `qr(mode='r') / qr(full) = 0.503` 看着与模型预测 0.5 吻合得很漂亮，但跑 9 次试验会发现范围跨过了 0.5（多次运行下分别观测到 `0.422 ~ 0.544`、`0.428 ~ 0.566`、`0.455 ~ 0.509`）——**摆动幅度大于它与模型预测值之间的差距**。程序里「每次试验取 5 次最小值」的做法消除了部分调度噪声，但消除不了频率漂移、cache 状态与后台进程的影响，而这三个量在这台机器上带来的偏差就足以覆盖一个 0.003 的差值。同一段代码里的 `cholesky / qr(mode='r')` 之所以可信，不是因为它测得准，而是因为它的范围（`0.12 ~ 0.18`）离模型预测 0.5 有 66% 的距离——**噪声盖不住这个差距**。

**这条也是「程序该报什么」的一个判例。** 同一个量，报单次数值会诱导读者得出「吻合」的结论，报范围则直接给出「未证实」。**当测量噪声与待验证差异同量级时，报范围不是保守，是唯一诚实的做法**——它把「我测到了什么」和「这个测量能支撑什么结论」一起交给读者。

**规避**：对计时结论，先问「实测值与预期值的差距，是否大于重复运行的范围」。小于时只能说「本次测量与预期一致，未证实也未证伪」，并把重复范围一并记录下来。要让计时结论真正成立，需要的不是更多次取最小值，而是控制变量：固定频率、绑定核心、关闭后台进程、提高重复次数并给出分布（而不只是最小值）。

**这条既是关于本机的，也是关于文档的**：程序自己的边界说明写着「计时是在本机单线程下测的，绝对值只对本机有意义，但几个比值（Cholesky/LU）来自算法结构，可迁移」——**这句话对 `cholesky / solve` 成立，对 `qr(mode='r') / qr(full)` 不成立**，后者的稳定性没有数据支持。

## 5. 实测数据

环境：macOS（arm64）+ Python 3.13.5 + numpy 2.4.4，CPU 单进程 fp64。无 GPU、无 torch/scipy。

**不选主元 LU 的失败链**：2×2 反例 `[[ε,1],[1,1]]`，ε 从 1e-01 到 1e-15，不选主元 growth 从 9.000e+00 涨到 1.000e+15，相对误差从 6.474e-16 涨到 7.794e-02；选主元 growth 恒为 1.000e+00、相对误差恒为 0.000e+00 或 2.220e-16。

**增长因子（200 个随机矩阵）**：不选主元 n=30 中位 1.06e+02、最大 3.88e+03；n=60 中位 4.52e+02、最大 1.16e+05。部分主元 n=60 中位 7.72e+00、最大 1.40e+01。

**求解精度**：均匀随机矩阵上不选主元中位 1.466e-13（n=30）/ 1.045e-12（n=60），选主元 2.792e-15 / 9.917e-15；把 `A[0,0]` 设为 1e-14 后不选主元中位跳到 4.327e-02（n=30）/ 8.628e-02（n=60）。

**Cholesky 与正定性**：`λ_min = 1e-15`（4.50u）失败 0/200；`1e-16`（0.45u）失败 0/200 但 `eigvalsh` 给出 `-1.76e-16`；`1e-17`（0.05u）失败 72/200；`1e-18`（0.00u）失败 99/200。

**计时（n = 1500，9 次试验、每次内部取 5 次最小值）**：程序打印的是**每项操作的耗时范围**与**三个比值逐次试验的分布**，不是单个数。判定行给出：`cholesky/solve` 的范围离 0.5 只剩 10% ~ 19%（多次运行），`cholesky/qr(mode='r')` 离 0.5 还有 66% ~ 67%，`qr(mode='r')/qr(full)` **跨过 0.5**。

**本节唯一可复现的结论是这三个判定，而不是任何具体数字。** 比值的中位数本身在多次运行间会漂移（`cholesky/solve` 观测到过 `0.392 / 0.415 / 0.416`），绝对耗时更是每次都不同——这也是程序改成打印范围的原因。

**GPTQ 模拟**：`d = 256`；`n = 128` 时 rank 128、κ 1.539e+20、Cholesky 失败；`n = 2048` 时 κ 4.321e+00、成功。Marchenko-Pastur 预测与实测的吻合倍数：d/n = 0.50 时 33.971 vs 3.170e+01（0.93 倍）、0.25 时 9.000 vs 8.504e+00（0.94 倍）、0.12 时 4.384 vs 4.321e+00（0.99 倍）。阻尼扫描见 §4.4。

**程序自报的边界**（原文）：计时在本机单线程下测得，绝对值只对本机有意义；`numpy.linalg` 分别调用 LAPACK 的对应例程，它们的 BLAS-3 优化程度不同，这正是 QR 比值偏离 flops 模型的原因；§2 的 200 个随机矩阵用的是 `[-1,1]` 均匀分布；**§5 的 GPTQ 一节全部是模拟**——X 是标准高斯随机矩阵，不是任何真实模型的激活，真实激活是重尾、强相关的，κ 通常**远大于** Marchenko-Pastur 的预测，本节说明的是「为什么需要阻尼」这个**结构性**原因，不是给出任何具体模型的 κ 数值。

## 6. 小结与延伸

主线一句话：**「能不能用」和「准不准」是两件事，要分开问**。三个可复用的中间结论：

1. **不选主元 LU 的问题是「没有保证」，不是「精度差」**。均匀随机矩阵上它中位误差 1.466e-13，能用；把 `A[0,0]` 改成 1e-14 就作废（4.327e-02）。选主元把这个保证买下来，代价只有 O(n²) 次比较。
2. **Cholesky 的正定性判定在 `λ_min ≈ u·λ_max` 上失效**。`λ_min = 1e-16` 时 Cholesky 0/200 通过而 `eigvalsh` 报出 `-1.76e-16`；改用 `λ_min > c·u·λ_max` 这类与分辨率匹配的判据。
3. **flops 计数不能跨实现预测时间**，而且**计时结论必须按「范围是否包住预测值」来判**：`Cholesky/QR` 的范围离 0.5 有 66% ⇒ 模型与实测明显不符，结论成立（因为 numpy 的 QR 每 flop 贵约 3 倍）；`Cholesky/LU` 的范围离 0.5 只剩 10%~19% ⇒ 方向一致但数值对不上模型；`qr(mode='r') / qr(full)` 的范围**跨过 0.5** ⇒ **未证实**，既不能说成立也不能说被推翻。

两条向外的延伸。**精度侧**：[04-iterative-methods](04-iterative-methods.md) 处理的正是本文留下的问题——当 κ 大到单次分解已经无法给出足够精度时，用高精度残差反复修正。**量化侧**：[130-quantization/ptq](../../130-quantization/ptq/) 与 [130-quantization/theory](../../130-quantization/theory/)（正文在该域，此处回链）把 §4.4 的阻尼取舍直接对应到 GPTQ / LDLᵀ 类方法的超参选择上——本文提供的是「阻尼的数值可行性门槛比统计有效性门槛低约 10 个数量级」这个定量判据。
