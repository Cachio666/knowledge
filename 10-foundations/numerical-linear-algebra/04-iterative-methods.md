# 迭代精化与 Krylov 方法：残差驱动的修正

> 迭代精化把「精度」问题转换成「`κ·u` 够不够小」的问题——κ 小时它白送 4 位以上有效数字，κ 大时它一点忙都帮不上，而且**收缩因子不能写成 `c·κ·u` 这样的等式**（实测该比值跨 97 倍）。

## 0. 背景与动机

混合精度训练里有两个看起来多余的设计：前向和反向都在 bf16 里算，为什么还要额外维护一份 fp32 的主权重（master weights）？为什么优化器状态也必须是 fp32？

配套程序给出了这对问题的原型。它做一件很朴素的事：用**fp32** 的 LU 分解解 `Ax = b`，得到近似解 `x̂`；然后在高精度（fp64）里算残差 `r = b - A·x̂`；再用**同一组 fp32 因子**解出修正量 `d`，在 fp64 里累加 `x̂ ← x̂ + d`；重复。

n = 200，A 对称正定、条件数可控，x_true 随机，b = A·x_true：

| κ(A) | 不精化 | 精化 1 次 | 精化 2 次 | 精化 3 次 | 精化 5 次 | 1 次的增益 |
|---|---|---|---|---|---|---|
| 1e+02 | 1.891e-06 | 4.480e-12 | 2.534e-15 | 2.830e-15 | 3.179e-15 | 422064 倍 |
| 1e+04 | 7.340e-05 | 4.766e-09 | 3.718e-13 | 1.508e-13 | 1.440e-13 | 15402 倍 |
| 1e+06 | 4.683e-03 | 2.075e-05 | 1.141e-07 | 5.650e-10 | 1.263e-11 | 226 倍 |
| 1e+08 | 3.230e-01 | 8.771e-02 | 3.307e-02 | 1.230e-02 | 1.906e-03 | 4 倍 |

κ = 1e2 时一次精化把误差从 1.891e-06 压到 4.480e-12（提升 422064 倍），两次之后就到底了；κ = 1e8 时一次精化只提升 4 倍（从 3.230e-01 到 8.771e-02）。**同一个算法，收益相差 5 个数量级，而差别只在 κ。**

这就是「低精度计算 + 高精度修正」这个模式的全部内容。全文的主线在 §1 的七步里：**第一至三步**讲迭代精化的机制，与它为什么无法写成等式；**第四至六步**讲 Krylov 方法里同一件事的另一种形态——CG 的 `√κ` 收敛率、它的适用边界，以及为什么同一个 κ 可以有 332 倍的迭代次数差异；**第七步**把整条链对应回混合精度训练的工程约定。

## 1. 原理

### 第一步：迭代精化的四步及其代价

```text
① fp32 做一次 LU 分解，解出 x̂                  代价 O(n³)，只做一次
② fp64 算残差      r = b - A·x̂                  代价 O(n²)
③ 用同一组 fp32 因子解 A·d = r，得到修正量 d        代价 O(n²)
④ 在 fp64 里累积   x̂ ← x̂ + d                    代价 O(n)
⑤ 回到 ②，重复
```

关键在于代价的分布：**O(n³) 的分解只做一次**，之后每次迭代都是 O(n²)。这正是 [03-matrix-factorization-stability](03-matrix-factorization-stability.md) §2 里「分解一次、三角求解多次」那个结构的用途——`getrs` / `potrs` / `<t>trsm` 都是 O(n²)，所以精化的每次迭代都便宜。

第三步是整件事的枢纽：**修正量 `d` 自己也在 fp32 里算，所以 `d` 本身带误差**。但第四步把 `d` 加进 `x̂` 时是 fp64——**修正量不准没关系，只要它指向正确的方向**。

### 第二步：为什么有效——把误差分成两项

设 `x̂ = x + e`，其中 `e` 是当前误差。残差

```text
r = b - A·x̂ = A·x - A·(x + e) = -A·e
```

（注意这里用 `A·x = b` 消掉了右端项。残差是误差的**线性像**，不是误差本身。）用近似因子 `Â = LU` 解出修正量：

```text
d = Â⁻¹·r = Â⁻¹·(-A·e) = -(Â⁻¹A)·e
```

现在插一项 `A⁻¹A = I`：

```text
d = -(Â⁻¹ - A⁻¹ + A⁻¹)·A·e = -e - (Â⁻¹ - A⁻¹)·A·e
```

于是新误差

```text
e_new = e + d = e - e - (Â⁻¹ - A⁻¹)·A·e = -(Â⁻¹ - A⁻¹)·A·e
```

**第一项 `-e` 被精确消掉了**——这就是精化的全部威力：不管 `x̂` 有多错，只要残差算得准，`d` 就一定能消掉当前误差的主导部分。剩下的只有第二项，它的相对大小由 `Â⁻¹` 的误差决定，而 `Â⁻¹` 的误差是 `κ·u_low` 量级（[01](01-norms-and-condition-number.md) 的主线）。

**κ 越大，`d` 越不准，`e_new` 缩得越慢。** 这句定性的话就是整节的结论，§1 第三步把它定量化。

### 第三步：收缩因子只能定性描述

定义每一步的**收缩因子** `r_k = err_k / err_{k-1}`。统计时有一个陷阱：κ 小时迭代几步就撞上 **fp64 的地板**，之后的步只是在地板附近随机跳动，会把平均值拉高。所以程序只统计「误差确实下降了 1.5 倍以上」的那些步；若一步都没下降，就报全部步的平均（这时它就是 > 1 的发散率）。

| κ(A) | κ·u32 | 有效收缩因子 | 计入步数 | 首步 err₁/err₀ | 行为 |
|---|---|---|---|---|---|
| 1e+02 | 5.96e-06 | 0.00004 | 2 / 8 | 0.000002 | 收敛（快） |
| 1e+04 | 5.96e-04 | 0.00127 | 3 / 8 | 0.000065 | 收敛（快） |
| 1e+06 | 5.96e-02 | 0.00745 | 4 / 8 | 0.004432 | 收敛（快） |
| 1e+07 | 5.96e-01 | 0.08490 | 8 / 8 | 0.045832 | 收敛（快） |
| 1e+08 | 5.96e+00 | 0.37785 | 8 / 8 | 0.271522 | 收敛（慢） |
| 1e+09 | 5.96e+01 | 4.87336 | 8 / 8 | 3.499476 | **发散** |
| 1e+10 | 5.96e+02 | 2.75362 | 8 / 8 | 2.731030 | **发散** |

顺带看一眼「计入步数」这一列：κ = 1e2 时 8 步里只有 2 步是真的在收敛（其余 6 步已经在地板上），而 κ = 1e8 时 8 步全都在收敛——只是每步赚得少。

把收缩因子和 `κ·u32` 直接相除，看它是不是一个常数：

| κ | κ·u32 | 收缩因子 | 收缩因子 / κ·u32 |
|---|---|---|---|
| 1e+02 | 5.96e-06 | 0.00004 | 6.142 |
| 1e+04 | 5.96e-04 | 0.00127 | 2.133 |
| 1e+06 | 5.96e-02 | 0.00745 | 0.125 |
| 1e+07 | 5.96e-01 | 0.08490 | 0.142 |
| 1e+08 | 5.96e+00 | 0.37785 | 0.063 |
| 1e+09 | 5.96e+01 | 4.87336 | 0.082 |
| 1e+10 | 5.96e+02 | 2.75362 | 0.005 |

**这个比值从 6.142 变到 0.005，跨了约 97 倍——它不是常数。** 所以不要写下「收缩因子 = `c·κ·u32`」这样的公式，实测不支持它。能站得住的只有两条**定性**陈述：

- 收缩因子**随 `κ·u32` 增长而增大**（因为修正量 `d` 自己就是在 fp32 里算的，它的误差量级由 `κ·u32` 决定）；
- 当 `κ·u32` 大到一定程度，收缩因子**越过 1**，迭代从收敛转为发散。

判据因此也是区间，不是等式：

- `κ·u32 ≲ 0.1`：收缩因子 < 0.01，每步赚 2.9 位以上，**安全**；
- `κ·u32 ≈ 1 ~ 10`：收缩因子 0.08 ~ 0.38，每步只赚 0.4 ~ 1.1 位，**勉强**；
- `κ·u32 ≫ 10`：收缩因子 4.87336 / 2.75362 > 1，**发散**。

实测的临界点落在 `κ·u32` 的 5（还收敛）到 59（发散）之间。工程上没人会贴着临界点用，安全区取 `κ·u32 ≲ 0.1`——对应「fp32 分解 + fp64 残差」可靠处理到 `κ ~ 1e6`。

一句话总结这一步：**迭代精化把「精度」问题变成了「`κ·u32` 够不够小」的问题。**

### 第四步：CG 的 √κ 从哪来

CG（共轭梯度）与迭代精化完全不同：它**不分解矩阵**，只用矩阵-向量乘 `A·p`。

```text
r0 = b - A·x0,  p0 = r0
for k = 0, 1, 2, …
    α  = (rᵏᵀrᵏ) / (pᵏᵀA pᵏ)
    x  ← x + α·p
    r  ← r - α·A·p
    β  = (rᵏ⁺¹ᵀrᵏ⁺¹) / (rᵏᵀrᵏ)
    p  ← r + β·p
```

对对称正定 A，收敛率由 `√κ` 控制：

```text
‖x_k - x*‖_A ≤ 2 · ((√κ - 1)/(√κ + 1))^k · ‖x_0 - x*‖_A
```

`κ` 被开了一次平方，这是「CG 用 √κ」的出处。把右边的 `2·ρ^k` 压到 ε 解出迭代数：

```text
2·((√κ-1)/(√κ+1))^k ≤ ε
```

先估底数。`(√κ-1)/(√κ+1) = 1 - 2/(√κ+1)`。用 `1 - t ≤ e^{-t}`（`t > 0`）：

```text
((√κ-1)/(√κ+1))^k ≤ exp( -2k/(√κ+1) )
```

令右边 ≤ `ε/2`：

```text
-2k/(√κ+1) ≤ ln(ε/2)     ⟹     k ≥ (√κ+1)/2 · ln(2/ε) ≈ ½·√κ·ln(2/ε)
```

这就是程序里那个理论式 `½√κ·ln(2/ε)` 的来源。**对数项 `ln(2/ε)` 几乎不变**——`ε = 1e-6` 时它是 `ln(2e6) ≈ 14.5`——所以迭代数与 `√κ` 成正比，与 κ 无关。

实测（n = 800，特征值对数均匀分布在 `[1/κ, 1]`，终止条件相对残差 `< 1e-6`，3 个随机右端项取中位数）：

| κ(A) | √κ | 迭代次数 | 达到 1e-6? | ½√κ·ln(2/ε) | 迭代次数/√κ |
|---|---|---|---|---|---|
| 1e+01 | 3.2 | 22 | 是 | 23 | 6.96 |
| 1e+02 | 10.0 | 71 | 是 | 73 | 7.10 |
| 1e+03 | 31.6 | 222 | 是 | 229 | 7.02 |
| 1e+04 | 100.0 | 666 | 是 | 725 | 6.66 |
| 1e+05 | 316.2 | 800 | 否（撞上限） | 2294 | 2.53 |
| 1e+06 | 1000.0 | 800 | 否（撞上限） | 7254 | 0.80 |

看达标的那四行：κ 从 1e01 涨到 1e04（1000 倍），`√κ` 涨 31.6 倍，迭代次数涨 30.3 倍（22 → 666），最后一列的比值稳定在 `6.66 ~ 7.10`。**迭代次数与 `√κ` 成正比。** 而且实测与理论值 `½√κ·ln(2/ε)` 的比是 `0.92 ~ 0.98`——理论界在这里几乎是紧的，原因是对数均匀的特征值分布恰好让 CG 的表现接近最坏情形。

### 第五步：√κ 的适用边界——`n ≫ √κ`

**κ ≥ 1e+05 的两行没有达标，这不是实现 bug。** CG 有一个精确算术下的定理：**最多 n 步收敛**。所以理论迭代数 `½√κ·ln(2/ε)` 只有在**远小于 n** 时才有意义：

| κ(A) | 理论迭代数 | n = 800 | √κ 规律是否可见 |
|---|---|---|---|
| 1e+01 | 23 | 800 | 是 |
| 1e+02 | 73 | 800 | 是 |
| 1e+03 | 229 | 800 | 是 |
| 1e+04 | 725 | 800 | 是 |
| 1e+05 | 2294 | 800 | **否——被 n 截断** |
| 1e+06 | 7254 | 800 | **否——被 n 截断** |

κ = 1e+05 时理论需要 2294 步而 n 只有 800——CG 来不及走到那里，实测直接撞上限 800 步。

实践含义：**CG 的 `√κ` 只在 `n ≫ √κ` 时兑现。** 表里 κ = 1e4 时理论需要 725 步而 n = 800，已经只剩 9% 的余量；κ 再大一点，所需步数就超过 n，未预条件 CG 直接失去意义。

这正是**预条件**（preconditioning）的意义：它不是「加速收敛」，而是把 κ 本身降下来，让 `√κ` 重新落进 n 允许的范围。换句话说，**预条件解决的是可行性问题，不是速度问题**。

### 第六步：κ 相同，迭代次数可以差 332 倍

上面用的是对数均匀分布的特征值。n = 800、κ 固定为 1e4，只改特征值的分布：

| 谱形状 | κ(A) 实测 | 迭代次数 | 迭代/√κ | 说明 |
|---|---|---|---|---|
| 对数均匀 | 1.000e+04 | 664 | 6.64 | 接近理论最坏情形 |
| 两端聚集（各一半） | 1.000e+04 | 2 | 0.02 | **几乎瞬间收敛** |
| 单点小特征值 | 1.000e+04 | 2 | 0.02 | **几乎瞬间收敛** |

三种谱的条件数**相同**（都是 1.000e+04），迭代次数却是 664 / 2 / 2，相差 **332 倍**。**κ 一样，工作量完全不一样。**

原因在 CG 收敛定理的**推导方式**：它只用到「特征值全部落在 `[λ_min, λ_max]` 里」这一条信息，然后用一个 Chebyshev 多项式去覆盖整个区间。如果特征值只聚集在两个点上，一个二次多项式就能把它压到 0——所以「两端聚集」两次迭代就收敛了，无论 κ 是 1e4 还是 1e12。

（「单点小特征值」也是 2 次：除去那一个离群点，其余特征值全相同，CG 在第 1 步就把那部分解完了，第 2 步处理离群方向。）

所以正确的说法是：

- **κ 决定的是最坏情况**——存在一种谱形状让 CG 需要 `½√κ·ln(2/ε)` 步；
- **实际迭代次数由谱的分布决定**，聚集的谱可以快几个数量级；
- 这与 [01](01-norms-and-condition-number.md) §1 关于 κ 的结论是同一回事：**κ 是界，不是预测值**。

工程含义：报告「CG 跑了多少步」时必须带上谱的信息（或至少是预条件子的效果），只说 κ 是没有信息量的。

### 第七步：与「低精度计算 + 高精度主权重」的逐项对应

把 §1 第一步的四步与混合精度训练逐个对上：

| 迭代精化（本程序） | mixed-precision 训练 | 角色 |
|---|---|---|
| fp32 LU 分解（只做一次） | fp16/bf16 的前向与反向 | 廉价、量大、有误差 |
| fp32 因子解 `A·d = r` | 优化器步产生的更新量 Δw | 同样在低精度里算 |
| fp64 算残差 `r = b - A·x̂` | fp32 主权重上算的 loss / 梯度 | 高精度负责「发现误差」 |
| fp64 累积 `x̂ ← x̂ + d` | fp32 master weights：`w ← w + Δw` | 高精度负责「记住结果」 |
| 收缩因子随 `κ·u32` 上升 | 训练能否收敛取决于 `κ(H)·u_bf16` | 同一个稳定性条件 |

对应关系的要点只有一条：**低精度用来产生修正量，高精度用来累积结果。**

这解释了 fp16/bf16 训练里的两个设计：

**fp32 主权重。** 权重本身用低精度存会因为累积而漂移，但**更新量 Δw 在低精度里算没关系**——正如本程序里 `d` 在 fp32 里算没关系。只要 `w` 这个「累积器」是 fp32，方向正确的 Δw 就能一步步把误差修掉。这正是 §1 第二步那个 `e_new = -(Â⁻¹ - A⁻¹)·A·e` 的结构：误差的主导项被精确消掉，剩下的由 `κ·u` 决定。

**loss scaling。** 这不是精度问题，是 [floating-point/04](../floating-point/04-low-precision-formats.md) 的**动态范围**问题——程序原文指出：fp16 的次正规下界让小于 `6e-8` 的梯度直接归零，乘一个大系数再除回来即可。**它和精化是两件事，不要混为一谈。** 精化对付的是「精度不够」，loss scaling 对付的是「量级不够」。

同样的结构在别处也出现：Kahan 求和（低精度加、高精度存补偿项），以及 GPU 上「bf16 输入 + fp32 累加器」的 Tensor Core。**它们的共同形状都是「窄精度的算子 + 宽精度的状态」。**

## 2. 执行映射

### 训练循环里的对应物

迭代精化在训练栈上不是一个库调用，而是一整套设计约定。对应关系如下：

| 精化里的角色 | 训练栈上的实现 | 约束 |
|---|---|---|
| 低精度分解（`Â`） | bf16/fp16 的 GEMM，`cublasGemmEx` 配 `CUBLAS_COMPUTE_32F` 或 `CUBLAS_COMPUTE_16F` | 累加器宽度决定 `u_low` |
| 高精度残差 | fp32 主权重上算的 loss 与梯度 | 残差必须在比 `Â` 更宽的类型里算 |
| 高精度累积器 | 优化器状态（动量、二阶矩）保持 fp32 | 状态漂移不可恢复 |
| 收缩因子的驱动量 | `κ(H)·u_bf16`，其中 H 是损失对权重的曲率 | 越接近 1 越难收敛 |

三个可操作的量级判断：

**一、安全区。** §1 第三步的判据 `κ·u32 ≲ 0.1` 直接给出「fp32 分解 + 高精度残差」可用到 `κ ~ 1e6`（程序原文的结论）。把同一个判据原样套到更窄的格式上会得到一个很强的约束：`u_bf16 = 2^-8` 时 κ 的上限掉到约 26（推导：`0.1/u`）。**格式越窄，这个模式能覆盖的 κ 范围越小**——这也解释了为什么实际系统宁愿把「宽精度状态」留给 fp32 主权重，而不是把整个流程压到 bf16。

**二、每次精化赚多少位。** 收缩因子 0.00127 对应每步赚约 2.9 位（`log10(1/0.00127) = 2.9`），收缩因子 0.00004 对应每步赚约 4.4 位（`log10(1/0.00004) = 4.4`）。实测表里 κ = 1e2 ~ 1e6 的四行都落在「每步 2 ~ 4.4 位」这个区间，所以**精化的收益最好读作「每步几位」而不是「提升多少倍」**——位数是可以跨问题累加的，倍数不能。

**三、地板在哪里。** κ = 1e2 时精化在 2 次之后停在 `2.534e-15` 附近不再下降（后面是 2.830e-15 / 3.179e-15，在噪声里跳）。这个地板是 fp64 的舍入噪声（`u64 = 1.1e-16`）乘上 κ 的量级，不是算法还能再改进的地方。换句话说是**残差所在的精度决定了精化的天花板**——这也解释了为什么 §4.2 那条失败模式最致命。

### 数值量级

| 量 | 数值 | 来源 |
|---|---|---|
| `κ·u32` 的扫描范围 | 5.96e-06 ~ 5.96e+02 | 配套程序 §1 |

### 一个必须注意的测量口径

CG 的实测是在 **fp64** 下做的，因为程序要考察的是**算法**的收敛性，不是舍入误差。真实低精度 CG 还会额外受到舍入导致的停滞影响，迭代次数会**多于**程序给出的数字。这一点在 §4.3 的判据里会用到：不要拿 fp64 下的迭代次数去预估 fp16 下的迭代次数。

## 3. 实现与演进

### 朴素做法：直接求解

一次 LU / Cholesky 求解，误差量级 `κ·u`。它的优点是确定性、没有收敛性讨论；缺点是这个界无法突破——κ = 1e8、fp32 下一位有效数字都不剩（[01](01-norms-and-condition-number.md) §1 第六步）。

**为什么需要下一步**：因为这个天花板不是算法效率问题，而是算术本身的极限。

### 一次精化：把天花板抬高一个 `u`

第二步加上一次精化。实测的收益：κ = 1e2 时 422064 倍（4.4 位），κ = 1e8 时 4 倍。这一步揭示了收益的**条件性**——`κ·u32` 越小，赚得越多。

**为什么需要下一步**：一次精化的收益由 `κ·u_low` 决定，而 κ 是给定的。要进一步提高，只能降低 `u_low` 的**有效值**——不是换更宽的格式，而是换更聪明的分解。

### 半精度迭代精化：让分解本身也窄下来

GMRES-IR 这一类方案把 §1 第一步的 fp32 LU 换成 fp16 甚至 fp8 的分解（`Â = LU` 用低精度算、低精度存），残差和累积仍在 fp32/fp64 里做。动机是**显存与带宽**：因子的存储量是 O(n²)，在 fp16 下直接减半；而分解本身的计算可以在 Tensor Core 上跑（fp16 GEMM 的峰值远高于 fp32）。

可行性判据仍然是 §1 第三步的那条线：`κ·u_low` 必须落在安全区。**这就是为什么这类方案的适用条件是「中等 κ」**——不是所有问题都能靠换格式解决。

### 自适应精度

再往前一步是让每一步自己选精度：先用低精度试，如果残差的下降速率低于阈值（收缩因子接近 1），就升级到更宽的格式或更精确的分解；反之降级省算力。这个方向在迭代精化与 Krylov 方法上是同一个思路——把「精度」当成一个可以被反馈环调节的资源，而不是一个静态的配置项。

## 4. 踩坑与失败模式

### 4.1 以为迭代精化能无限提升精度

**现象**：把精化写成一个固定次数的循环（比如「跑 10 次」），预期误差会一直往下掉。

**成因**：每一步的收缩因子有一个下限，它由**残差计算所在的精度**决定。实测里 κ = 1e2 那一行，精化 2 次到 `2.534e-15` 之后再迭代就不动了——后面几步是 `2.830e-15` / `3.179e-15`，在地板附近随机跳动。这个地板是 fp64 的舍入噪声（`u64 = 1.1e-16`）乘上 κ 的量级。**继续迭代只会消耗时间，不会改善结果。** 而在 κ = 1e8 那一行，收缩因子是 0.37785，10 次迭代也只能把误差降到 `8.771e-02` 的 0.38 次方——收益递减且永远到不了地板。

**规避**：把精化的停止条件写成**基于残差的判据**（残差的下降速率低于阈值就停），而不是固定次数。同时明确记录「预期的地板在哪里」：地板 ≈ `κ · u_residual`。如果算出来的地板已经高于应用的精度要求，那么精化这条路走不通，应该回头降 κ（预条件）或换算法。

### 4.2 残差也在低精度里算

**现象**：为了统一数据类型，把残差 `r = b - A·x̂` 也放在分解所用的低精度里算。

**成因**：这一步会让整个方法失效。残差的绝对值是 `‖r‖ ≈ ‖A‖·‖e‖`，它本身已经很小；在低精度下计算 `b - A·x̂` 时，两个相近的大数相减（`b` 与 `A·x̂` 几乎相等）会产生灾难性抵消（机制见 [floating-point/02](../floating-point/02-rounding-and-error-model.md)）。更直接的说法是：`r` 在低精度里的表示误差是 `u_low·‖b‖`，而 `r` 本身只有 `‖A‖·‖e‖ = κ·u_low·‖b‖` 量级——**当 κ 接近 1 时，误差信号被自身的表示误差吞掉。**

**这一条是推导，不是本文实测**：配套程序只跑了「残差在 fp64 里算」的情形（§1 第一步的步骤 ②），没有跑低精度残差的对照实验。验证方法是把步骤 ② 改成 `r = b - A @ x` 并用 fp32 计算，观察收缩因子是否变差——理论预期是在 `κ·u_low ≳ 1` 时完全失去收敛性。

**规避**：把「残差计算的精度」当成这个方法的**核心配置项**而不是实现细节。它与分解精度、累积精度是三个独立的旋钮，其中残差精度决定了方法的天花板（§4.1）。在任何文档里都要写明残差用的是什么类型。

### 4.3 把 CG 用到非对称或非正定矩阵上

**现象**：CG 写起来只要十几行、不需要分解、每步只有一次矩阵乘，看起来很划算，于是在任意线性系统上都拿来用。

**成因**：§1 第四步的收敛定理**只在 A 对称正定时成立**。定理的证明依赖 `A` 定义一个内积 `⟨u,v⟩_A = uᵀAv`，而 CG 的共轭性与正交性都是相对于这个内积的；A 不对称时 `⟨·,·⟩_A` 不是内积（不对称、可能不正定），推导从第一步就不成立。实践中的表现是残差不再单调下降，迭代可能在某个点**停滞或振荡**，而终止条件（相对残差 < tol）永远不会被触发。

**这一条同样是推导性的**：配套程序的 CG 全部在 `make_spd` 构造的对称正定矩阵上运行，没有跑非对称的对照实验。可靠的验证方法是检查 `‖A - Aᵀ‖` 是否在舍入量级以内、以及最小特征值是否为正——后者要注意 [03-matrix-factorization-stability](03-matrix-factorization-stability.md) §1 第五步的警告：`eigvalsh` 给出的符号在 `λ_min ≈ u·λ_max` 量级上不可靠。

**规避**：非对称系统用 GMRES / BiCGSTAB；对称但可能不定的用 MINRES；只有确认对称正定才用 CG——判据用 [03-matrix-factorization-stability](03-matrix-factorization-stability.md) §4.1 那条 `λ_min > c·u·λ_max`（`c` 取 10 ~ 100）而不是 `λ_min > 0`。另外注意 CG 的实测是在 fp64 下做的（§2 末），低精度下额外会有舍入导致的停滞，迭代次数会多于程序给出的数字。

### 4.4 以为预条件是「加速收敛」

**现象**：把预条件子当成一个可选的性能优化项——「加了会快，不加也能跑，先不加」。

**成因**：预条件降低的是 κ，而 κ 在未预条件 CG 里同时决定了**精度**（收敛后的残差水平）和**可行性**（能否在 n 步内收敛）。这两个作用里，后者是定性的：§1 第五步的表里，κ = 1e+05 时理论需要 2294 步而 `n = 800`——**不管机器多快、跑多久，未预条件 CG 都不可能达到 1e-6**，因为 CG 在精确算术下最多 n 步收敛，超过 n 步之后的行已经不是「更慢」而是「无意义」。

所以把预条件当成「加速」会让人得出错误的取舍：既然只是加速，那么在算力充裕时就可以省掉。正确的理解是：**预条件把 `√κ` 重新压回 `n` 允许的范围，它解决的是可行性问题。**

**规避**：在决定用不用预条件之前，先算 `½√κ·ln(2/ε)` 和 n 的比值。这个比值接近或超过 1 时，预条件不是优化项而是必需项。实测的参考点：`n = 800`、`ε = 1e-6` 时，κ = 1e4 对应理论 725 步（余量 9%），κ = 1e5 对应 2294 步（已越界）。

## 5. 实测数据

环境：macOS（arm64）+ Python 3.13.5 + numpy 2.4.4，CPU 单进程 fp32/fp64。无 GPU、无 torch/scipy。

**迭代精化**（n = 200，fp32 分解 + fp64 残差）：κ = 1e2 → 1.891e-06 / 4.480e-12 / 2.534e-15（1 次增益 422064 倍）；κ = 1e4 → 7.340e-05 / 4.766e-09 / 3.718e-13（15402 倍）；κ = 1e6 → 4.683e-03 / 2.075e-05 / 1.141e-07（226 倍）；κ = 1e8 → 3.230e-01 / 8.771e-02 / 3.307e-02（4 倍）。

**收缩因子**：κ 从 1e2 到 1e10，`κ·u32` 从 5.96e-06 到 5.96e+02，有效收缩因子从 0.00004 升到 4.87336 再回落到 2.75362；「收缩因子 / `κ·u32`」跨 6.142 → 0.005（约 97 倍）。

**CG**（n = 800，tol 1e-6，3 个随机右端项取中位数）：κ = 1e1 → 22 步（理论 23，实测/理论 0.96）；1e2 → 71 步（73，0.98）；1e3 → 222 步（229，0.97）；1e4 → 666 步（725，0.92）；1e5 → 800 步撞上限（理论 2294）；1e6 → 800 步撞上限（理论 7254）。

**谱形状**（n = 800，κ 固定 1e4）：对数均匀 664 步；两端聚集 2 步；单点小特征值 2 步。三种谱的 κ 实测都是 1.000e+04。

## 6. 小结与延伸

主线一句话：**迭代精化把「精度」问题变成了「`κ·u` 够不够小」的问题。** 四个可复用的中间结论：

1. **误差的两项分解**：`e_new = -(Â⁻¹ - A⁻¹)·A·e`。第一项被精确消掉，剩下的由 `κ·u_low` 决定——这就是「低精度产生修正量、高精度累积结果」的全部依据。
2. **收缩因子只能定性描述**。「收缩因子 / `κ·u32`」跨 6.142 → 0.005（约 97 倍），不是常数。可用的判据是区间：`κ·u32 ≲ 0.1` 安全，`≈ 1 ~ 10` 勉强，`≫ 10` 发散（实测临界点在 5 到 59 之间）。
3. **CG 的 `√κ` 只在 `n ≫ √κ` 时兑现**。n = 800、tol = 1e-6 时，κ = 1e4 已经只剩 9% 余量，κ ≥ 1e5 直接撞上限。这使预条件成为**可行性**要求而非加速选项。
4. **κ 相同不等于工作量相同**。同为 κ = 1e4，对数均匀谱要 664 步，「两端聚集」只要 2 步——相差 332 倍。这与 [01](01-norms-and-condition-number.md) 的结论同源：κ 是界，不是预测值。
