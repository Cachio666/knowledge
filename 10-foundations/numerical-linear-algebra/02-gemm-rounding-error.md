# 矩阵乘的舍入误差：误差正比于绝对值和

> 点积的绝对误差界是 `γ_K · Σ|x_i·y_i|`——分母是**绝对值之和**，不是结果本身。所以相对误差由「结果有多小」决定，与「算得多辛苦」无关。

## 0. 背景与动机

把一个 GEMM 的**累加器**从 fp32 换成 fp16，是低精度推理里最常见的一步优化。（累加器是内积求和的那一个变量：`C_ij = Σ_k A_ik·B_kj`。它的类型由 kernel 决定，与 A、B 自己的存储格式是两件事——本文后面会反复用到这个区别。）预期是「精度掉一点，速度涨一截」。实际跑出来的结果常常是：**大部分输出元素看起来还好，少数元素错得离谱**。

配套程序在同一次 fp32 GEMM 上量出了这个「还好」与「离谱」之间的距离。取 A 为 48×512、B 为 512×48，K = 512，共 2304 个输出元素，逐个元素用顺序 fp32 点积计算，与 fp64 参照值比对：

| | 相对误差 | 该元素的 ρ | 该元素 C_ij |
|---|---|---|---|
| 最小 | 5.456e-11 | 8.930e-02 | -6.901e-01 |
| 中位 | 3.260e-07 | 4.454e-02 | 3.620e-01 |
| 最大 | 1.906e-03 | 1.318e-05 | 1.072e-04 |

**同一份 A、同一份 B、同一个 K，最大与最小的相对误差相差 34932493 倍（7.5 个数量级）。** 中位数是 3.260e-07，看起来完全可以接受；但最大值 1.906e-03 已经把 4 位有效数字吃掉了。所以「这个 GEMM 的精度是多少」这个问题，不加限定就没有答案——必须问「哪些输出元素是小量」。而看这张表的第三列：相对误差最大的那个元素，`C_ij = 1.072e-04`，几乎就是 0。

本文要回答的就是这个机制：**误差的绝对规模由 `Σ|x_i·y_i|` 卡住，而相对误差还要再除以 `|xᵀy|`**。前者约等于常数，后者可以任意小——于是相对误差可以任意大。这条结论同时解释了 [floating-point/04-low-precision-formats](../floating-point/04-low-precision-formats.md) 里那条「累加相对误差 ∝ √K·u」的实测规律（本文 §1 第六步给出完整推导），两篇不矛盾。

本文只讨论**舍入误差**，不讨论 [01-norms-and-condition-number](01-norms-and-condition-number.md) 那种由问题本身的 κ 决定的放大。两者是加法关系：输入数据的扰动被 κ 放大，算术过程的舍入被 `Σ|x·y|` 放大。

## 1. 原理

### 第一步：把递推展开成显式形式

点积 `s = Σ_{k=1}^{K} x_k·y_k` 用浮点算，每一步做两次舍入——一次乘法、一次加法：

```text
ŝ_k = fl( ŝ_{k-1} + fl(x_k·y_k) )
```

把两个舍入都写成相对误差形式。乘法：`fl(x_k·y_k) = x_k·y_k·(1+δ_k)`，`|δ_k| ≤ u`。加法：`fl(a+b) = (a+b)(1+ε_k)`，`|ε_k| ≤ u`（这些是 [floating-point/02](../floating-point/02-rounding-and-error-model.md) 建立的单次运算模型）。代入：

```text
ŝ_k = ( ŝ_{k-1} + x_k·y_k·(1+δ_k) ) · (1 + ε_k)
```

这是一个线性递推。把它从 `k = 1` 一路展开到 `K`：第 `k` 项的乘积 `x_k·y_k` 在第 `k` 步进来，之后要穿过第 `k, k+1, …, K` 每一步的加法舍入因子。注意 `ŝ_{k-1}` 在展开时也要乘上 `(1+ε_k)`，所以每个早期项挂的因子更多：

```text
ŝ_K = Σ_{k=1}^{K} x_k·y_k · (1+δ_k) · Π_{j≥k} (1 + ε_j)
```

（下标约定：`Π_{j≥k}` 覆盖 `j = k, k+1, …, K`。第 `K` 项挂 1 个加法因子，第 1 项挂 `K` 个——每项最多挂 `K+1` 个 `(1+u)` 量级的因子，算作 `K` 个是标准做法。）

### 第二步：界定连乘

现在要估 `Π(1+ε_j) - 1` 的上界。设每个 `|ε_j| ≤ u`，则连乘不超过 `(1+u)^K`。`(1+u)^K` 本身不好用，需要换成 `K` 的一次式。构造一个归纳：断言

```text
(1+u)^K ≤ 1 / (1 - K·u)        （要求 K·u < 1）
```

**基例** `K = 1`：`1 + u ≤ 1/(1-u)`，两边乘以 `(1-u) > 0` 得 `(1+u)(1-u) = 1 - u² ≤ 1`，成立。

**归纳步**：假设 `(1+u)^K ≤ 1/(1-Ku)`。两边乘 `(1+u)`，再验证

```text
(1+u)/(1-Ku) ≤ 1/(1-(K+1)u)
```

两个分母在 `(K+1)u < 1` 时都为正，交叉相乘（不改变方向）：

```text
(1+u)·(1 - (K+1)u) ≤ 1 - K·u
```

左边展开：`1 + u - (K+1)u - (K+1)u² = 1 - K·u - (K+1)u² ≤ 1 - K·u`。成立。

把 `1/(1-Ku)` 拆成 `1 + Ku/(1-Ku)`，就得到那个惯用的记号 `γ_K`：

```text
|fl(xᵀy) - xᵀy| ≤ γ_K · Σ|x_k·y_k|,      γ_K = K·u / (1 - K·u)
```

程序的 `γ_K` 表：

| K | γ_K | K·u | 说明 |
|---|---|---|---|
| 64 | 3.8147e-06 | 3.8147e-06 | |
| 1024 | 6.1039e-05 | 6.1035e-05 | |
| 16384 | 9.7752e-04 | 9.7656e-04 | |
| 1000000 | 6.3383e-02 | 5.9605e-02 | |
| 16000000 | 2.0586e+01 | 9.5367e-01 | n·u 逼近 1，界失效 |

K 小时 `γ_K ≈ K·u`；K 涨到 1.6e+07 时 `K·u = 9.5367e-01` 已经很接近 1，分母 `1-Ku` 把 `γ_K` 推到 2.0586e+01——**此时界已经失效**（`γ_K > 1` 意味着误差可以超过 `Σ|x·y|` 本身，界不再有信息量）。这是 `K·u < 1` 这个前提的直接体现。

### 第三步：三个要点，每个都常被误读

**一、界正比于 `Σ|x_k·y_k|`，不是 `|xᵀy|`。** 这是全文的核心。右边那个量先取绝对值再求和，所以它永远是正的大数；而 `|xᵀy|` 可以因为符号抵消而变得很小。

**二、界随 K 线性增长。** `γ_K ≈ K·u`。但这是**上界**，实际行为远好于此——见 §1 第五步。

**三、界与 x、y 的取值无关**，只由 K 和 u 决定。这意味着界对同一个 GEMM 的 2304 个元素是**统一**的（每个元素有自己的 `(|A||B|)_ij`），而相对误差是逐元素变化的。

### 第四步：只有 u 因格式而变——fp16 累加器意味着什么

把累加器从 fp32 换成 fp16，`K` 和 `Σ|x·y|` 都不变，变的只有 `u`。两个格式的单位舍入误差可以直接从格式定义推出（推导，非本文实测）：fp16 尾数 10 位，`u = 2^-11`；fp32 尾数 23 位，`u = 2^-24`。配套程序里的 `U32 = 2.0 ** -24` 与后者一致。

```text
u(fp16) / u(fp32) = 2^-11 / 2^-24 = 2^13 = 8192
```

所以同一个点积换 fp16 累加后，绝对误差界直接放大 8192 倍。**注意反向也成立**：这不是 fp16 的「缺陷」，而是它的 `u` 大 8192 倍的必然结果——所以工程结论是「累加器保持 fp32」，而不是「fp16 不能用」。

### 第五步：绝对误差 ∝ Σ|x·y|，而 K 不出现在里面

上面的界是上界，实际值是多少？程序对每个 K 跑 21 个种子取中位数，同时报三个量：

```text
A   = 绝对误差 / Σ|x·y|     （界的实际大小）
B   = Σ|x·y| / |xᵀy|        （结果的「抵消程度」）
A·B = 相对误差               （两者相乘，是恒等式）
```

| K | 绝对误差 | Σ\|x·y\| | A | B | A·B | 实测相对误差 |
|---|---|---|---|---|---|---|
| 256 | 3.512e-08 | 3.239e+00 | 1.085e-08 | 1.201e+01 | 1.302e-07 | 1.313e-07 |
| 1024 | 2.368e-07 | 1.324e+01 | 1.789e-08 | 2.797e+01 | 5.004e-07 | 5.527e-07 |
| 4096 | 8.853e-07 | 5.235e+01 | 1.691e-08 | 4.161e+01 | 7.036e-07 | 6.589e-07 |
| 16384 | 2.065e-06 | 2.078e+02 | 9.937e-09 | 1.082e+02 | 1.076e-06 | 1.482e-06 |
| 65536 | 1.284e-05 | 8.349e+02 | 1.539e-08 | 2.189e+02 | 3.368e-06 | 5.423e-06 |

**A 列几乎不随 K 变化。** K 从 256 涨到 65536（涨了 256 倍），绝对误差涨了 366 倍，而 `Σ|x·y|` 也涨了 258 倍——两者同步。于是 `A = 误差/Σ|x·y|` 只在 `9.94e-09 ~ 1.79e-08` 之间浮动（1.8 倍），而 K 本身变了 256 倍。

换算成 `u`：`A/u = 0.18 / 0.30 / 0.28 / 0.17 / 0.26`，即绝对误差约为 `0.2~0.3` 个 `u` 乘上 `Σ|x·y|`，中枢值 `0.26·u`。**绝对误差由 `Σ|x·y|` 和 `u` 决定，K 不出现在里面。**

### 第六步：B 列按 √K 增长——与 `04` 的实测规律对上

`04-low-precision-formats` 测出的规律是「累加相对误差 ∝ √K·u」。它和本文的 `∝ Σ|x·y|` 是同一件事的两面，程序把它拆成了两个因子：

**B 的量级可以解析算出来。** 记 `X_i = x_i·y_i`，取 `x ~ N(0,1)`、`y ~ N(0, 0.02²)`（这正是程序里数据的分布）：

```text
E|X_i| = 0.02 · (2/π) = 0.01273        ⟹   Σ|X_i| ≈ 0.01273 · K      （线性增长）
Var(ΣX_i) = K · 0.02²                   ⟹   E|ΣX_i| ≈ 0.02·√(2/π)·√K   （√K 增长）
```

第二步用的是中心极限定理：独立同分布项的和，其标准差按 `√K` 增长，而零均值高斯和的绝对值的期望正比于其标准差。两者相除：

```text
ρ = |ΣX| / Σ|X| ≈ 1.2533 / √K        ⟹   B = 1/ρ ≈ 0.7979 · √K
```

实测的 `B/√K` 落在 `0.65 ~ 0.87`，与理论值 `0.7979` 同量级：

| K | B 实测 | B/√K | 理论 0.7979 |
|---|---|---|---|
| 256 | 1.201e+01 | 7.506e-01 | 0.7979 |
| 1024 | 2.797e+01 | 8.741e-01 | 0.7979 |
| 4096 | 4.161e+01 | 6.501e-01 | 0.7979 |
| 16384 | 1.082e+02 | 8.456e-01 | 0.7979 |
| 65536 | 2.189e+02 | 8.550e-01 | 0.7979 |

于是两篇的结论互相推出：

```text
相对误差 = A × B = (≈0.26·u) × (≈0.85·√K) ≈ 0.22 · √K · u
```

（程序中打印的系数是 `0.22`；常数差异来自中位数不可交换——表里报的是各自的中位数，而乘积与中位数不是同一个运算。实测的 `A·B` 列与「实测相对误差」列在每一行都只差 1.6 倍以内。）

**这个乘积可以直接和 `04` 的输出对上。** 本文表格的「实测相对误差」一列与 `code/04_low_precision_formats.py` 输出的 **fp32 列逐位相同**（K = 256 时同为 1.313e-07，1024 时 5.527e-07，4096 时 6.589e-07，16384 时 1.482e-06）——两个程序用的是同一套数据与种子，所以这不是「同量级」而是同一个数。`04` 把这条规律写成 `误差 ≲ √K·u`，并给出「实测 / √K·u」落在 `0.10 ~ 0.31`（中位数 0.27）；本文拆出的系数 `0.22 = 0.26 × 0.85` 落在这个区间内，两边一致。

（注：上面那四个相对误差数字取自 `04_low_precision_formats.py` 的实际输出，不在本文配套程序的 stdout 里；两表的其余数字均来自本文的配套程序。）

**关键是因子 B 的来源。** `04` 观察到的 `√K` **不是来自「累加次数变多」**——绝对误差几乎不随 K 变（A 列），`√K` 全部来自**分母**：随机符号的数据里，结果 `|xᵀy|` 自身只有 `Σ|x·y|` 的 `1/(0.85√K)`。这与本文的界完全一致：界说误差被 `Σ|x·y|` 卡住，而相对误差还要再除以结果——结果小多少，相对误差就大多少。

这条拆分的用处是**定位**：要降低点积的相对误差，只有两条路——压 A（换更宽的累加器，或做补偿求和），或压 B（改问题本身，让结果不要那么小）。

### 第七步：受控抵消实验——把 Σ|x·y| 钉死

上一步的 `√K` 是随机数据的统计行为。要证明「误差 ∝ Σ|x·y| 而不 ∝ |xᵀy|」是**结构**而不是统计巧合，需要做一个受控实验：让 `Σ|x·y|` 严格不变，只把结果压小。

程序的构造：取 `b_1 … b_{K/2}` 按 `0.99^j` 递减到很小，令

```text
x = [b, b]                                  （上下两半都是 b）
y = [b, -b 的前 m 项取负再拼回剩余的 b]        （上 U 形抵消）
```

因为 `|x_i·y_i| = b_j²` 与 `y` 的符号**无关**，所以 `Σ|x·y|` 在整个扫描中**严格不变**。每改一次 m，只是把 U 形抵消的深度加深一点。K = 1024，21 个种子取中位数：

| m | Σ\|x·y\| | xᵀy 真值 | ρ | 相对误差 | A=err/Σ\|xy\| | 界 | 界/实测 |
|---|---|---|---|---|---|---|---|
| 0 | 100.7979 | 1.0080e+02 | 1.0000e+00 | 2.4100e-07 | 2.410e-07 | 6.104e-05 | 松 253 倍 |
| 64 | 100.7979 | 2.7888e+01 | 2.7668e-01 | 4.9431e-07 | 1.368e-07 | 2.212e-04 | 松 448 倍 |
| 128 | 100.7979 | 7.6927e+00 | 7.6318e-02 | 1.4025e-06 | 1.070e-07 | 7.982e-04 | 松 569 倍 |
| 256 | 100.7979 | 5.8163e-01 | 5.7702e-03 | 1.8460e-05 | 1.065e-07 | 1.064e-02 | 松 576 倍 |
| 384 | 100.7979 | 4.1420e-02 | 4.1092e-04 | 2.4932e-04 | 1.024e-07 | 1.494e-01 | 松 599 倍 |
| 448 | 100.7979 | 8.9758e-03 | 8.9047e-05 | 1.1407e-03 | 1.016e-07 | 6.853e-01 | 松 601 倍 |
| 496 | 100.7979 | 1.3022e-03 | 1.2919e-05 | 7.8380e-03 | 1.013e-07 | 4.725e+00 | 松 603 倍 |
| 511 | 100.7979 | 6.4638e-05 | 6.4127e-07 | 1.4829e-01 | 9.509e-08 | 9.498e+01 | 松 640 倍 |

四个读数：

**一、`Σ|x·y|` 一列严格不变**：8 行的值都是 100.7979，逐位相同。这是构造保证的。所以后面相对误差的变化，**只能**来自分母 `|xᵀy|` 在变小。

**二、相对误差随 ρ 单调爆炸。** ρ 从 1.00 降到 6.4127e-07（跌了 1559412 倍），相对误差从 2.4100e-07 涨到 1.4829e-01（涨了 615309 倍）。两个倍数相差 2.5 倍，恰好就是下面第三条里 A 列的漂移量——**误差的爆发几乎完全由分母驱动**。

**三、A 列几乎不动**：全文在 `9.51e-08 ~ 2.41e-07` 之间，只有 2.5 倍的浮动，而 ρ 变了 1559412 倍。绝对误差只认 `Σ|x·y|` 和 `u`，不认结果大小。

**四、界从来没有被违反，也从来没有被逼近。** 最后一列 `界/实测` 是 253 ~ 640 倍，均值 588 倍（2.8 个数量级）。这个比值本身也是稳定的——因为 `界/实测 = γ_K/A`，而 A 在整张表里几乎不动、`γ_K` 是个常数。界正确预测了函数形式（`∝ 1/ρ`），但常数高估了 2.8 个数量级。

### 第八步：落到整个 GEMM 上

GEMM 的每个输出元素都是一次长度为 K 的点积，所以界是**逐元素**的：

```text
|ΔC_ij| ≤ γ_K · (|A|·|B|)_ij
```

注意右边是 `|A|·|B|`——**先取绝对值再相乘**，不是 `|A·B|`。这个区别在代码里很容易写错（§4.4）。

程序在 48×512 与 512×48、K = 512 的 GEMM 上验证：

| 量 | 数值 |
|---|---|
| γ_K | 3.052e-05 |
| max \|ΔC\|（绝对误差） | 1.342e-06 |
| max γ_K·(\|A\|\|B\|)（界） | 3.002e-04 |
| 界 / 实际最大误差 | 223.6 |
| 界被违反的元素个数 | 0 / 2304 |

界从未被违反（0/2304），也从未被逼近（松 223.6 倍）。但**相对误差**在同一份数据上跨了 7.5 个数量级（§0 的表）。

### 第九步：为什么 log-log 斜率是 −0.72 而不是 −1

§0 的表看起来像「相对误差 ∝ 1/ρ」，那么对 2304 个元素做 `log(相对误差)` 对 `log ρ` 的回归，斜率应该接近 −1。程序实测：

| 回归 / 相关系数（对 log ρ） | 数值 |
|---|---|
| log(相对误差) 对 log ρ 的斜率 | -0.7244 |
| log(相对误差) 与 log ρ 的相关系数 | -0.5733 |
| log(A) 对 log ρ 的斜率 | +0.2756 |
| log(A) 与 log ρ 的相关系数 | +0.2573 |

**斜率是 -0.72 而不是 -1.0，相关系数是 -0.57 而不是 -1。** 所以不能把这条关系写成「相对误差 ∝ 1/ρ」。

原因在第二行和第四行：`A_ij = |ΔC_ij| / (|A||B|)_ij` 在这个矩阵里**不是常数**——它和 ρ 有 `+0.2573` 的弱正相关。机制是顺序求和的舍入误差正比于每一步的**部分和**，而部分和同样会因为抵消而变小。抵消得越狠，分子也跟着小一点，所以相对误差的爆发比纯 `1/ρ` 略缓。

换句话说，「误差 ∝ `Σ|x·y|`」是**上界**意义上的严格陈述，不是等式。实测里 A 会随抵消程度漂移，抵消越深漂得越小。但漂移是 `0.28` 次方量级的修正，而 ρ 本身跨了 4.2 个数量级——主导项仍然是 `1/ρ`。（相对误差中位数 `3.260e-07` 对应 `A/u` 中位数 `0.22`，与 §1 第五步的 0.2~0.3 一致。）

## 2. 执行映射

### 累加器住在哪里

Tensor Core 的矩阵指令（Volta 起的 `mma`、Hopper 的 `wgmma`、Blackwell 的 `tcgen05`）把 `C += A·B` 这个 tile 级操作交给硬件，输入可以是 fp16/bf16/fp8，**但累加器按设计是 fp32**——正是本文 §1 第四条的那个理由：累加器的 `u` 决定了 `γ_K` 的量级，8192 倍的差距不能靠算法补回来。

配套程序明确报告了一个它做不到的事：它用的是**严格按下标递增**的顺序累加（小规模走 Python 循环，大规模走 `np.cumsum`），而真实 Tensor Core 的归约是**分块**的。分块的机制是：每个 K-tile 内部顺序累加 `K_tile` 项，块与块之间再累加一次，等价于一棵两层的归约树。误差于是按**每一层的项数**累积而不是按总项数累积——这解释了程序原文的判断「误差通常优于本程序，因此这里的绝对误差应读作顺序累加这一实现的上限」。

这也是为什么 γ_K 这个界在实际 kernel 上显得格外松：它假设一条最坏情形的依赖链（每一项都要穿过后面所有步的舍入），而分块归约把这条链打断了。

### 数值量级

| 量 | 数值 | 来源 |
|---|---|---|
| K = 512 时的 γ_K | 3.052e-05 | 配套程序 §4 |
| 界 / 实际最大绝对误差 | 223.6（0/2304 元素被违反） | 配套程序 §4 |
| 界 / 实测相对误差（受控实验） | 253 ~ 640 倍，均值 588 倍 | 配套程序 §3 |
| 实测 A = 绝对误差 / Σ\|x·y\| | 0.17u ~ 0.30u，中枢 0.26u | 配套程序 §2 |
| §2 中 A·B 与实测相对误差的最大差 | 1.6 倍以内 | 配套程序 §2 |

一条可操作的口径转换：**γ_K 与实测差 2.8 个数量级**，所以 `A ≈ 0.26·u` 是一个比 `γ_K` 好得多的经验估计。要判断某个点积的绝对误差，用 `0.26·u·Σ|x·y|`；要判断相对误差，再除以 `|xᵀy|`。`γ_K` 的用途是「保证不被违反」，不是「估计会错多少」。

## 3. 实现与演进

### 朴素做法：顺序累加

最简单的一行 `for` 循环，一项一项往累加器里加。误差按 §1 的推导累积，`γ_K` 是最坏界。它的优点是**确定性**——同一个输入永远给出同一个结果。

### 主流：分块累加

第二步把 K 切块（`K_tile` 常常取 16 或 32），每块内部顺序累加，块间再累加。动机本来是**访存局部性**——把 A、B 的 tile 留在寄存器/共享内存里复用，减少 HBM 流量（正文在 [40-kernels/gemm](../../40-kernels/gemm/README.md)，此处回链）。但它顺带改善了误差：归约从一条长度 K 的链变成一棵两层树，误差按层高而不是按项数累积。

需要这一步的原因是：顺序累加的误差界随 K 线性增长（`γ_K ≈ K·u`），而注意力、大模型的 FFN 里 K 动辄上万——K = 16384 时 `γ_K = 9.7752e-04`，已经吃掉三位有效数字。

### 有代价的一步：split-K

当 M、N 很小而 K 很大时，并行度不足（只有 M/BM × N/BN 个 block），GPU 喂不饱。split-K 把 K 再切成 `S` 份，每一份由一个独立的 block 算，最后把 `S` 个部分和加起来。

**代价在误差上**：原本一条 K 长的累加链，现在变成 `S` 条各长 `K/S` 的链，外加一次长度为 `S` 的归约。各段内部误差变小了，但段与段的结果要被加起来，而每一段都已经带上了自己那段的部分误差。更关键的是**顺序不确定性**：哪个 block 先算完、部分和按什么顺序归约，取决于调度——同一个 kernel 两次运行的浮点结果可以不同。这在需要可复现性的场景（调试、对齐参考实现、单元测试）里是硬伤。

### 更进一步：补偿型 GEMM

要真正突破 `u` 的限制，只能改算术：把输入拆成高低两半（Ozaki 方案），用多次低精度 GEMM 拼出高精度结果；或者用误差补偿累加（每个部分和附带一个补偿项，把舍入丢掉的部分捡回来）。它们都能把有效 `u` 压到比格式本身低若干个数量级，代价是成倍的计算量。这条路线的取舍与 [04-iterative-methods](04-iterative-methods.md) 里「低精度计算 + 高精度修正」的模式完全同构。

## 4. 踩坑与失败模式

### 4.1 指望「换 fp64 累加」来救抵消

**现象**：某段注意力或 softmax 的求和出现明显误差，第一反应是把累加器改成 fp64，误差却没有回到「应有的」水平。

**成因**：fp64 只压 A 因子，压不动 B 因子。`A` 从 `0.26·u32` 降到 `0.26·u64`（推导：`u32/u64 = 2^29 ≈ 5.4e8`，即改善约 5 亿倍），但 `B = Σ|x·y|/|xᵀy|` 完全由数据决定——受控实验里 `B` 到达 `1/6.4127e-07 ≈ 1.56e+06`。相对误差仍然是 `A×B`，仍正比于 `1/ρ`。**抵消造成的相对误差爆炸是问题的性质，不是累加器的性质。**

**规避**：改算法而不是换累加器——softmax 减掉最大值、LayerNorm 用 Welford 递推或两趟算法、求和用补偿（Kahan/Neumaier）。判据是：如果 `ρ = |xᵀy| / Σ|x·y|` 本身很小，任何精度的累加器都救不了；如果 ρ 不小而误差仍然大，那才是累加精度的问题。

### 4.2 为了提速开 split-K，不检查误差

**现象**：M、N 小 K 大的 GEMM（例如 LoRA 的低秩分解、小 batch 的线性层）换成 split-K 后吞吐上去了，但下游精度对不上参考实现，而且**两次跑出的数不一样**。

**成因**：split-K 把一条累加链切成 `S` 条，部分和的归约顺序由 block 调度决定，不可复现；同时部分和的中间结果各自带误差，段数与误差项数同时增加。这与 [01-norms-and-condition-number](01-norms-and-condition-number.md) 的 κ 无关——它是算术过程的问题，不是问题本身的性质。

**规避**：对精度敏感的路径（梯度累加、loss 计算、需要对齐参考实现的测试）禁用 split-K，或改用固定归约顺序的两阶段实现（部分和写回显存，再用一个确定顺序的 kernel 归约）。如果必须用 split-K，把 `S` 记进实验配置——它改变的是数值结果，不是只改变速度。

### 4.3 把 `γ_K` 当作误差估计值

**现象**：用 `γ_K·Σ|x·y|` 设一个「报警阈值」，比如「估计的误差接近界了，说明这里出问题了」。

**成因**：这个界**从不被逼近**。受控实验里 `界/实测` 是 253 ~ 640 倍（均值 588 倍，即 2.8 个数量级），GEMM 那一节是 223.6 倍；而这个比值本身很稳定（因为 `界/实测 = γ_K/A`，`A` 几乎不动）。所以「误差接近界」这件事在实际数据上根本不会发生——把界当阈值用，报警永远不响，等于没设。

**规避**：把两者分工写清楚。`γ_K` 是**保证**：它的用途是「证明误差不会超过某个数」，以及判断补偿方案是否必要。估计实际误差要用 `≈ 0.26·u·Σ|x·y|` 这个经验量级（§2）。**信界的形状，不要信界的数值。**

### 4.4 把 `|A·B|` 当成界的右端

**现象**：手写误差检查代码时写成

```python
bound = gamma_K * np.abs(A @ B)      # 错
```

计算结果远小于界，于是报告「界很松，误差可以忽略」；或者反过来，在某些元素上界被「违反」，误以为推导有错。

**成因**：界里的量是 `(|A|·|B|)_ij`——**先取逐元素绝对值，再做矩阵乘**。`|A·B|` 与 `|A|·|B|` 完全不是一回事：前者已经经历了抵消，可以任意小（GEMM 那节里最大元素的 ρ 低到 1.318e-05，即 `|C|` 只有 `(|A||B|)` 的 1.3e-05 倍）。用 `|A·B|` 做右端，等于用一个被抵消吞掉的小量去乘 `γ_K`，得到的界比正确的界小好几个数量级，自然会出现「界被违反」的假象。

**规避**：正确的写法是 `gamma_K * (np.abs(A) @ np.abs(B))`（程序里的 `AbsAB`）。这个量的计算代价与一次 GEMM 同阶——在离线误差分析里可以接受；在训练循环里不可行，此时改为对关键路径（如 softmax 分母）做小规模抽样检查。

## 6. 小结与延伸

主线一句话：**绝对误差由 `Σ|x·y|` 和 `u` 决定，相对误差还要再除以结果——所以精度问题出在「哪些输出元素接近 0」上**。三个可复用的中间结论：

1. **`A = 绝对误差/Σ|x·y| ≈ 0.26·u`，与 K 无关。** K 从 256 涨到 65536（256 倍），A 只浮动 1.8 倍。
2. **`√K` 来自分母，不来自累加。** `B = Σ|x·y|/|xᵀy| ≈ 0.85√K`，这才是 [floating-point/04](../floating-point/04-low-precision-formats.md) 那条「相对误差 ∝ `√K·u`」里 `√K` 的全部来源（`04` 实测的「误差 / √K·u」落在 0.10 ~ 0.31，中位数 0.27）。
3. **界从不被逼近。** `界/实测` 稳定在 253 ~ 640 倍（受控实验）与 223.6 倍（GEMM），而这个比值本身稳定——信形状，不信数值。

两条延伸。**算法侧**：[40-kernels/gemm](../../40-kernels/gemm/README.md)（正文在该域，此处回链）讲分块与 split-K 的工程实现，本文提供的判据是「分块改善误差、split-K 恶化且破坏可复现性」。**精度侧**：[04-iterative-methods](04-iterative-methods.md) 把本文的分解反过来用——既然低精度算出的近似可以靠高精度残差修正，那么「低精度算子 + 高精度状态」就是通用的模式，而它的可行性判据是一个 `κ·u` 量级的不等式。
