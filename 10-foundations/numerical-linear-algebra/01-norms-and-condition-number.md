# 范数与条件数：误差放大由问题本身决定

> `κ(A) = ‖A‖·‖A⁻¹‖` 是一个**紧的**最坏情形界——存在输入让放大倍数精确等于它；但随机扰动撞不上它，中位放大恒为 1。这两句话缺一句，κ 就会被误用。

## 0. 背景与动机

把一个权重矩阵的元素舍入到 int8，每个元素的相对误差大约是 1e-2（这是量化步长的量级，属于**场景设定值而非实测**：配套程序不涉及量化，它只度量放大倍数）。如果「输入误差 1e-2」直接传到输出，模型输出的相对误差也该在 1e-2 附近——那量化就没什么可怕的。

配套程序测出的却是一个分裂的答案。构造一个 κ = 1e10 的矩阵，对右端项加 1e-9 量级的随机扰动，观测放大倍数 `(‖δx‖/‖x‖) ÷ (‖δb‖/‖b‖)`：

| κ(A) | 随机 δb 中位放大 | 随机 δb 最大放大 | 最坏 δb 放大 | 最坏/κ |
|---|---|---|---|---|
| 1e+02 | 1.02 | 36.03 | 1.00e+02 | 1.000 |
| 1e+06 | 1.01 | 64.96 | 1.00e+06 | 1.000 |
| 1e+10 | 1.00 | 405.59 | 1.00e+10 | 1.000 |

同样一个 κ = 1e10 的矩阵：**随机方向**上的扰动只被放大 1.00 倍（最大也只有 405.59 倍），**最坏方向**上的扰动被精确放大 1.00e+10 倍。所以「这个量化误差会被放大多少倍」这个问题，不问「输入落在哪个方向」就没有答案。

这就是本文要建立的两个概念。第一是**范数**：把「误差有多大」变成一个数，而不同类型的范数给出的数可以差很多（同一个向量 `x = [3.0, -4.0, 12.0]`，`‖x‖₁ = 19.0`、`‖x‖₂ = 13.0`、`‖x‖∞ = 12.0`）。第二是**条件数** κ：它把输入相对误差与输出相对误差联系起来，而这个联系是一条不等式，不是一个等式。

本文只处理「`Ax = b`，b 有扰动」这一种情形。算法本身的舍入误差（分解的舍入、累加的舍入）不在本文范围内，分别在 [03-matrix-factorization-stability](03-matrix-factorization-stability.md) 与 [02-gemm-rounding-error](02-gemm-rounding-error.md)。

## 1. 原理

### 第一步：向量范数——一个公式，三个常用取值

三个常用范数不是三个不同的定义，而是同一个公式

```text
‖x‖_p = ( Σ|x_i|^p )^(1/p)
```

在 `p = 1, 2, ∞` 上的取值。`p = ∞` 是 `p → ∞` 的极限，此时只有最大分量存活下来，所以 `‖x‖∞ = max|x_i|`。

程序算的三个值是 `19.0 / 13.0 / 12.0`。三者之间只存在宽泛的不等式（对 n 维向量 `‖x‖₂ ≤ ‖x‖₁ ≤ √n·‖x‖₂`），具体差多少由数据决定。**因此任何「误差是多少」的陈述，不说清范数就没有意义**——三种范数可以差出 `√n` 倍的因子。

### 第二步：矩阵范数是被诱导出来的，不是元素的最大值

矩阵不能直接用向量范数的公式，因为「矩阵有多大」这个问题没有自然答案：元素取值的最大值？行列式？都不对。正确的做法是让矩阵作用在向量上，看它最多能把向量放大多少倍：

```text
‖A‖_p = max_{x≠0} ‖Ax‖_p / ‖x‖_p
```

程序对三个 3×3 矩阵算了全部三种诱导范数：

| 矩阵 | `max\|a_ij\|` | `‖A‖₁` | `‖A‖₂` | `‖A‖∞` |
|---|---|---|---|---|
| 对角阵 `diag(1,2,3)` | 3.0 | 3.0 | 3.0 | 3.0 |
| 全同阵（只有 `a₁₁=1`） | 1.0 | 1.0 | 1.7 | 3.0 |
| 上三角（对角线全 1、上三角全 1） | 1.0 | 3.0 | 2.2 | 3.0 |

对角阵三列相等只是巧合（它在三组基下都是对角的）。真正的信息在最后一行：**上三角阵的最大元素是 1，但 `‖A‖₂ = 2.247`**。也就是说存在一个向量，A 能使它的长度增加一倍多，而矩阵里最大的那个数只有 1。这是因为 A 的 3 个 1 会**叠加**：取 `x = [1, 1, 1]`，`Ax = [3, 2, 1]`，各分量由不同行、不同列的元素共同贡献。

**只看元素大小会严重低估一个矩阵的放大能力**——而这个低估正是 κ 被误用的第一个入口（§4.1）。

### 第三步：κ 的推导——注意不等号翻转的那一步

设 `Ax = b`。给 b 加一个扰动 `δb`，解变成 `x + δx`：

```text
A(x + δx) = b + δb
```

两边减去 `Ax = b`，得到扰动满足的方程：

```text
A·δx = δb        ⟹        δx = A⁻¹·δb
```

（这一步假设 A 可逆。不可逆时 κ 定义为 `+∞`，本文只讨论可逆情形。）

两边取范数，用诱导范数的定义 `‖Av‖ ≤ ‖A‖·‖v‖`：

```text
‖δx‖ = ‖A⁻¹·δb‖ ≤ ‖A⁻¹‖·‖δb‖
```

这里得到的是**绝对**误差。要变成相对误差，得再除以 `‖x‖`。但 `‖x‖` 不能直接从 `b` 得到，只能从 `b = Ax` 反向界定：

```text
‖b‖ = ‖Ax‖ ≤ ‖A‖·‖x‖        ⟹        ‖x‖ ≥ ‖b‖ / ‖A‖
```

注意这个方向：上界 `‖b‖ ≤ ‖A‖‖x‖` 反过来只能给出 `‖x‖` 的**下界**。这一步是整段推导里唯一容易写错的地方——下一步要用 `‖x‖` 去做除数，而**除以一个下界会让不等号方向翻转**：

```text
‖δx‖ / ‖x‖ ≤ ‖A⁻¹‖·‖δb‖ / ( ‖b‖ / ‖A‖ )
            = ‖A‖·‖A⁻¹‖ · ‖δb‖ / ‖b‖
```

如果把 `‖x‖ ≥ ‖b‖/‖A‖` 误当成**等式**或**上界**代入，有两种常见的走偏方式：当成等式是对的（等号时结果与上式相同），但当成上界 `‖x‖ ≤ ‖b‖/‖A‖` 就会把方向弄反，得到一个「放大倍数是 `1/(‖A‖·‖A⁻¹‖)`」的荒谬结论。**先确认自己手里的 `‖x‖` 是下界，再决定除的时候要不要翻方向**，这一步没有捷径。

中间那个乘积就是条件数：

```text
κ(A) = ‖A‖·‖A⁻¹‖
```

结论：**`b` 的相对误差最多被放大 κ(A) 倍传到 `x` 上。** 注意这个 κ 只依赖 A，与求解算法无关——LU、QR、CG、迭代精化，面对同一个 A 的 κ 完全相同。这是「误差放大由问题本身决定」这句话的确切含义。

### 第四步：κ 是一个紧界

「最多放大 κ 倍」听起来像一句保守的免责声明。程序证明它不是：三行数据的**最坏放大 ÷ κ 全部精确等于 1.000**。

构造方法就在推导里。要让放大达到上界，需要两个条件同时成立：

- 上式第一步的 `‖A⁻¹·δb‖ ≤ ‖A⁻¹‖‖δb‖` 取等——要求 `δb` 是 A⁻¹ 的最大奇异方向，也就是 A 的**最小**奇异向量 `U[:, -1]`；
- 第二步的 `‖x‖ ≥ ‖b‖/‖A‖` 取等——要求 `x` 是 A 的最小奇异方向，即 `b` 取**最大**奇异向量 `U[:, 0]`（此时 `‖x‖` 最小，分母最不利）。

程序正是这样构造的（`b_w = U[:, 0]`，`db_w = 1e-9 * U[:, -1]`）。所以 **κ 不是一个拍脑袋的保守估计，它是可达的**。

### 第五步：但随机扰动撞不上这个界

同一个程序跑了 4000 次随机扰动：中位放大是 `1.02 / 1.01 / 1.00`，最大也只有 `36.03 / 64.96 / 405.59`——哪怕 κ 高达 1e10。

原因是「最坏」要求两个独立的方向对齐：`b` 恰好落在 A 的最不敏感方向，而 `δb` 恰好落在最敏感方向。随机向量落在某个特方向上的概率随维数指数衰减，两条同时命中的概率更低。于是实际观测到的放大，是**平均意义**下的 1 左右——误差进来多少，出去还是多少。

工程结论要写准：**κ 大不等于「实际会错很多」，它等于「存在一种输入会让它错很多」。** 看到 κ = 1e8 就断言会崩，是把界当成了预测值。正确的问题是「我的输入会不会系统性地落在最坏方向上」——在 LLM 里这通常表现为权重矩阵的谱分布是否极端，而不是随机的舍入噪声。

### 第六步：`κ(AᵀA) = κ(A)²`

最小二乘 `min‖Ax - b‖₂` 的经典解法是解**正规方程** `AᵀA x = Aᵀb`，系数矩阵是 `AᵀA`。它的条件数：

设 A 的奇异值为 `σ₁ ≥ … ≥ σₙ > 0`（这里取 A 为方阵、满秩）。`AᵀA` 对称正定，其特征值正是 `σ_i²`（因为 `AᵀA v_i = σ_i² v_i`，`v_i` 是右奇异向量）。于是

```text
κ(AᵀA) = σ₁² / σₙ² = (σ₁/σₙ)² = κ(A)²
```

程序实测的四行里，理论列与实测列逐位相同（`1.00e+04 / 1.00e+08 / 1.00e+12 / 1.00e+16`），确认这一步不是近似。

平方的后果是把精度损失翻倍。程序的第四列用 `log10(1/u) - log10(κ(AᵀA))` 算出 fp32 下还能剩几位十进制有效数字：

| κ(A) | κ(AᵀA) 理论 | κ(AᵀA) 实测 | fp32 下还有效数字吗 |
|---|---|---|---|
| 1e+02 | 1.00e+04 | 1.00e+04 | 1.0 位 |
| 1e+04 | 1.00e+08 | 1.00e+08 | 0.0 位 |
| 1e+06 | 1.00e+12 | 1.00e+12 | 0.0 位 |
| 1e+08 | 1.00e+16 | 1.00e+16 | 0.0 位 |

κ(A) 只要到 1e4，κ(AᵀA) 就到 1e8，已经超过 fp32 能分辨的范围（`u⁻¹ ≈ 1.7e7`，`u = 6e-8`）。**这意味着 fp32 下用正规方程做最小二乘，一位有效数字都不剩**——而 κ(A) = 1e4 在实际问题里根本不算病态。

### 第七步：四种解法在同一个病态问题上的实测

程序构造了 κ(A) = 1.00e+08 的 8×8 矩阵，四种解法：

| 解法 | 相对误差 | 说明（程序原文） |
|---|---|---|
| `inv(A) @ b` | 2.295e-09 | 显式求逆：代价约 3 倍 |
| `solve(A, b)` | 2.480e-09 | LU 分解，标准做法 |
| `solve(AᵀA, Aᵀb)` | 5.039e-03 | 正规方程：κ 被平方 |
| `lstsq（QR/SVD）` | 5.770e-10 | 正交变换，不放大误差 |

三个读数：

**一、`inv` 与 `solve` 精度几乎相同（2.295e-09 vs 2.480e-09）。** 这纠正一个常见说法：显式求逆的主要问题**不是精度**。理由见 §4.3。

**二、正规方程最差（5.039e-03），比 `solve` 差 6 个数量级。** 这正是 `κ(AᵀA) = κ(A)²` 的直接后果：κ 从 1e8 变成 1e16，而 fp64 的 `1/u ≈ 9e15`，精度被吃干净。

**三、`lstsq` 最好（5.770e-10）**，因为它走 QR/SVD，全程用正交变换。正交矩阵满足 `‖Q‖₂ = 1`，不放大误差——κ 只作用一次而不是两次。

### 第八步：为什么正交变换不放大误差

这一条值得单独推导，因为它是「最小二乘用 QR 不用正规方程」的全部理由。设 `Q` 正交，则对任意 `x`：

```text
‖Qx‖₂² = (Qx)ᵀ(Qx) = xᵀQᵀQx = xᵀx = ‖x‖₂²
```

所以 `‖Qx‖₂ = ‖x‖₂`，取上确界得 `‖Q‖₂ = 1`，且 `‖Q⁻¹‖₂ = ‖Qᵀ‖₂ = 1`。代入 κ 的定义：

```text
κ₂(Q) = ‖Q‖₂·‖Q‖₂⁻¹ = 1·1 = 1
```

正交矩阵的 2-范数条件数恒等于 1，与它本身长什么样无关。把 A 分解成 `A = QR` 后，条件数被完全转移到了 R 上：

```text
κ₂(A) = κ₂(QR) ≤ κ₂(Q)·κ₂(R) = κ₂(R)
```

误差的来源被隔离在 R 里，而 Q 那一步是精确的（在 2-范数意义下）。正规方程则相反——`AᵀA = RᵀQᵀQR = RᵀR`，它把 R 又平方了一次，正是第六步的 `κ(AᵀA) = κ(A)²`。

## 2. 执行映射

### 谁在算 κ

组件层面，κ 的计算分两半：`‖A‖` 直接算（一列列求和取最大就是 `‖A‖₁`，代价 O(n²)），难的是 `‖A⁻¹‖`——**显式求逆要 O(n³)，与解一次方程同阶**。

LAPACK 的做法是不求逆，用**条件数估计器**：`dgecon` / `dgeconx`（对应 cuSOLVER 的 `cusolverDnXgecon`）用 Hager/Higham 的 1-范数估计器，只做几次「解 `Aᵀy = e`」的三角回代（每次 O(n²)），靠少量采样把 `‖A⁻¹‖₁` 估到几倍以内。这是 LAPACK Users' Guide 记录的算法，**不是本文的实测**；本文实测的是「显式求逆与求解精度相同但代价约 3 倍」这一条（§1 第七步与 §4.3）。

这个设计反过来印证了本文的主线：`‖A⁻¹‖` 只需要一个量级，不需要精确值——因为 κ 本身就是个界，多估几倍不影响它的用途。

### 数值量级

| 量 | 数值 | 来源 |
|---|---|---|
| κ(AᵀA) = κ(A)² 的实测一致性 | 四行理论列与实测列逐位相同 | 配套程序 §3 |
| 正规方程 vs `solve` 的误差差 | 5.039e-03 vs 2.480e-09，差 6 个数量级 | 配套程序 §3 |
| fp32 的 `u` | 6e-8，`u⁻¹ ≈ 1.7e7` | 配套程序 §3（注释换算） |
| fp64 的 `1/u` | ≈ 9e15 | 配套程序 §3 |
| 最坏放大 ÷ κ | 1.000（三行全部） | 配套程序 §2 |

CPU 上 `numpy.linalg.cond` 默认走 SVD，代价是 `solve` 的好几倍；GPU 上 `cusolverDnXgecon` 走估计器，代价降到几次三角回代。**在训练循环里频繁调 κ 是不可行的**（无论哪种实现），它只适合离线诊断——这与它的用途一致：判断「这个问题的精度上限在哪」，而不是每步都算。

### 一个容易被忽略的口径问题

κ 依赖范数。程序对同一个上三角阵给出 `‖A‖₁ = 3.0` 而 `‖A‖₂ = 2.2`，因此 `κ₁(A) ≠ κ₂(A)`。文献里写「这个矩阵的 κ 是 1e6」而不说范数，是个没有意义（或至少不完整）的陈述。工程上比较 κ 之前必须先对齐范数——本节表格里的 κ 全部是 2-范数条件数。

## 3. 实现与演进

### 朴素做法：直接法 + 事后检查

最原始的做法是解完方程后检查解的合理性。它在 κ 小的时候够用，一旦 κ 大到结果失去有效位，检查也无从下手——**你得先有一个可信的答案才能判断哪个答案可信**。

### 主流：解之前先估 κ

第二步是把 κ 变成求解过程的一部分。LAPACK 的 `dgesvx` / `dgecon` 系列在分解之后顺带给出 κ 的估计，让调用者能判断「这次求解的结果有几位可信」。代价极低（分解已经做完了，估计器只需几次回代），所以成了标准做法。

从这一步可以读出工程上正确的使用姿势：**κ 是用来「事后判读精度」的，不是用来「事前挑选算法」的**。因为 κ 是问题本身的性质，与算法无关（§1 第三步末）——它告诉你答案能有几位有效数字，但不会告诉你该用 LU 还是 QR。

### 需要下一步的动机

但直接法有一个逃不掉的天花板：**算法能做到的最好精度，就是 κ·u 量级**。κ = 1e8 时 fp64 只剩 8 位有效数字，fp32 一位都不剩。

迭代精化是针对这个天花板的：既然分解本身的误差无法消除，那就用它算出的近似解 `x̂`，在**高精度**下算残差 `r = b - A x̂`，再解一次 `A·d = r` 修正。它的收益完全由 κ 决定——κ = 1e2 时一次精化就能提升 422064 倍（从 1.891e-06 到 4.480e-12），κ = 1e8 时一次精化只提升 4 倍（从 3.230e-01 到 8.771e-02）。完整的机制与收敛性分析见 [04-iterative-methods](04-iterative-methods.md)。

### 更进一步：预处理

迭代精化压的是「算法误差」，压不动 κ 本身。要真正降低 κ，只能改问题：解 `M⁻¹Ax = M⁻¹b`，其中 M 是 A 的一个近似但良态的版本。这正是 CG 的预条件子（同样见 [04-iterative-methods](04-iterative-methods.md)）在做的事。这里只需记住一点：**预处理之所以有价值，是因为 κ 决定了精度的天花板，而不只是迭代次数**。

### 前沿：低精度迭代精化

现代 GPU 上的趋势是把第一步的分解也压到低精度（fp32 分解、fp16 甚至 fp8 分解），靠高精度残差把精度买回来。这一路线的可行性判据恰好就是本文的 κ：只要 `κ·u_low` 足够小，修正量就仍然指向正确的方向。这部分的展开属于 [04-iterative-methods](04-iterative-methods.md) 的范围。

## 4. 踩坑与失败模式

### 4.1 拿 `max|a_ij|` 当 `‖A‖` 用

**现象**：评估一个权重矩阵的「放大能力」时看它元素的最大绝对值；或者手写误差界时把 `‖A‖` 写成 `np.abs(A).max()`。程序里上三角阵的 `max|a_ij| = 1.0`，但 `‖A‖₂ = 2.247`。

**成因**：诱导范数的定义是「对向量的最大放大倍数」，它取决于矩阵所有元素的**整体作用**，而不是单个元素的大小。上三角阵的 `‖A‖₁ = 3.0` 是把某一列三个 1 加起来得到的——放大来自列内求和，与单个元素的大小无关。二者可以相差任意倍数（全同阵的 `max|a_ij| = 1.0` 而 `‖A‖∞ = 3.0`，差 3 倍；维数越高差得越多，可达 O(n)）。

**规避**：用 `np.linalg.norm(A, 2)`（真值，代价高）、`np.linalg.norm(A, 1)` 或 `np.linalg.norm(A, np.inf)`（代价 O(n²)，几乎免费），或大矩阵上用 LAPACK 的 1-范数估计器。**绝不要用 `.max()`。**

### 4.2 跨范数比较 κ

**现象**：从一篇论文看到「这个矩阵 κ = 1e6」（其实是 `κ₁`），从自己的程序里算出 `κ₂ = 1e4`，据此判断两者不是同一个矩阵。

**成因**：κ 是**相对于某个范数**定义的，`κ_p(A) = ‖A‖_p·‖A⁻¹‖_p`。换了 p 就是换了另一个数，两者之间只有宽泛的不等式关系（由 `‖A‖₁ ≤ n‖A‖₂` 与 `‖A⁻¹‖₁ ≤ n‖A⁻¹‖₂` 相乘得 `κ₁ ≤ n²·κ₂`，区间宽达 n² 倍），在具体矩阵上可以差很多。程序里同一个上三角阵的 `‖A‖₁ = 3.0` 与 `‖A‖₂ = 2.2` 已经体现了这个差异在范数层面的存在。

**规避**：任何 κ 的数值都必须带范数下标。跨来源比较前先确认两边用的是同一个 p；不确定时统一重算成 2-范数（SVD 给出的 `σ_max/σ_min`）再比。

### 4.3 以「精度更差」为理由反对 `inv(A) @ b`

**现象**：代码评审里写「不要用 `inv(A) @ b`，精度不如 `solve`」。

**成因**：这是一个被广泛转述但**实测不成立**的说法。程序在 κ(A) = 1.00e+08 的病态矩阵上同时跑了两者：`inv(A) @ b` 的相对误差是 2.295e-09，`solve(A, b)` 是 2.480e-09——**几乎相同**，`inv` 甚至略好。原因是两者都做了同一个 LU 分解，之后的差别只在回代路径上，而回代是 O(n²) 的小项。

**规避**：反对 `inv` 的正确理由是**代价**——显式求逆的运算量约为一次 LU 求解的 3 倍，而你要的通常只是解一次方程。省下的是算力，不是精度。把这条区别写清楚很重要：如果理由写成「精度」，一旦有人实测发现两者精度相同，整条建议就会连带失去说服力。

### 4.4 「`AᵀA` 是对称的，那用 Cholesky 解它」

**现象**：解正规方程时看到系数矩阵 `AᵀA` 对称，想起「对称正定用 Cholesky 省一半代价」，于是改用它——结果既没保住精度，还可能直接抛异常。

**成因**：两个陷阱叠加。其一，`AᵀA` 的 κ 已经被平方（§1 第六步），Cholesky 省下的那 2 倍代价在 κ² 带来的精度损失面前毫无意义——程序里的正规方程误差是 5.039e-03，比 `solve` 差 6 个数量级。其二，`AᵀA` 在数值上**未必正定**：当 A 病态或秩亏时它的最小特征值会落在舍入噪声量级，Cholesky 的开方步骤会失败，或者更糟——静默地给出垃圾（判定的机制与失败案例见 [03-matrix-factorization-stability](03-matrix-factorization-stability.md) §1）。

**规避**：最小二乘走 QR/SVD（程序里 `lstsq` 的相对误差 5.770e-10，是四种解法里最好的），**永远不要显式构造 `AᵀA`**。如果确实需要正规方程的紧凑形式（例如迭代法的每一步都要解它），加一个 Tikhonov 阻尼项 `λI` 同时解决正定性与正则化，并明确记录 λ 的取值理由。

## 6. 小结与延伸

本文的主线只有一句：**误差放大由问题本身决定，而这个决定的形态是一个界，不是一个预测**。围绕它有三个可独立复用的中间结论：

1. **κ 是紧的，但只在最坏方向上紧。** 最坏放大 ÷ κ 精确等于 1.000（三行全部），随机扰动中位恒为 1.00~1.02。所以「κ 大」与「会错很多」之间需要额外一个前提：输入方向是否有系统性偏好。
2. **κ 依赖范数。** 同一矩阵的 `‖A‖₁` 与 `‖A‖₂` 不同，κ 也随之不同。报 κ 必须带范数下标。
3. **`κ(AᵀA) = κ(A)²`，多出来的那个平方是可以用公式消掉的（走 QR/SVD），代价只是常数倍。**

接着往下走的两条线。**算法侧**：[03-matrix-factorization-stability](03-matrix-factorization-stability.md) 讲分解本身的稳定性——不选主元 LU 的真实失败模式、Cholesky 与 `eigvalsh` 在 `λ_min ≈ u·λ_max` 上的判定矛盾、以及 flops 计数为什么不能跨实现预测时间。**精度侧**：[04-iterative-methods](04-iterative-methods.md) 讲迭代精化——它把「精度问题」转换成「`κ·u` 够不够小」的问题，也正因为如此，它的收益完全由本文的 κ 决定。

跨域的两处落点。`κ` 在量化里的意义见 [130-quantization/theory](../../130-quantization/theory/)（正文在本域，回链该域）：量化误差是**结构性地**落在最坏方向还是随机方向上，决定了 κ 是否真的会咬人。在混合精度训练里，则是 [04-iterative-methods](04-iterative-methods.md) 把 κ 与「低精度计算 + 高精度主权重」直接对应起来。
