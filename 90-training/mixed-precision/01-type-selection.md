# 类型选择表：主权重、梯度、优化器状态与 loss 各用什么精度

> **混合精度训练不是「把 dtype 改成 fp16」**，而是**逐张量**决定它扮演什么角色：
> 计算副本可以窄、**累积器必须宽**。四行里有两行省了字节、两行没省 —— 净收益是 **0**。
> 而这条链上最容易出错的一步是**更新被静默吞掉**：`Δw < ULP(w)/2` 时 `w + Δw == w` 逐位成立。

### 一个具体的对照场景

（[打开该行](../../10-foundations/numerical-linear-algebra/04-iterative-methods.md)）逐字写着：

> 向外的两处落点。**训练侧**：`90-training/mixed-precision`（正文在该域，此处回链）
> 把本文的对应表落成具体的工程约定——
> **主权重、优化器状态、loss scaling 三者的类型选择**

那篇给的对应表只有一行要点：**低精度用来产生修正量，高精度用来累积结果**。本文把它落成四个**具体的行**：

| 行 | 那个张量是什么 | 选择 |
|---|---|---|
| **主权重** | 优化器**真正更新**的那份参数（`w ← w + Δw` 里的 `w`） | **fp32** |
| **计算副本** | 送进 GEMM 的那份参数（`W16`） | fp16 / bf16 / fp8 |
| **梯度** | 反向后、更新前的那份 `∂L/∂w` | fp16 / bf16 / fp8 |
| **优化器状态** | 一阶矩 `m` 与二阶矩 `v`（Adam 系） | **fp32** |
| **loss** | 反向的**起点** | fp32（它同时是 loss scaling 的作用点，见 `02`） |

**不用它的代价是什么？** 一个可以精确复现的失败：

```
w0 = 1.0     lr = 1e-3     每步梯度 g = 1e-3     ⇒ 更新量 Δw = 1e-6
```

`w = 1.0` 处 fp16 的 `ULP` 是 `9.766e-04`，**`ULP/2 = 4.883e-04`**。而 `Δw = 1e-6` 比它小 **488 倍**（`4.883e-04 / 1e-06 = 488.3`）⇒
`fp16(1.0 + 1e-6) == fp16(1.0)`，**更新被舍入吞掉，一个比特都没进权重**。
本机实测（`code/01_types.py` 的 `C.1`）：**2000 步之后权重精确等于 `1.000000`**，
而且**第 1 步就已经被吞**。同一条轨迹上，主权重保持 fp32 时给出 `0.997973`，
与闭式 `w₀ − n·lr·g = 0.998000` 相差 `2.656e-05` —— **一路跟上**。

## 1. 原理

### 1.1 四行是怎么来的：从「一个张量在循环里扮演什么角色」推

不要从「哪种 dtype 更快」出发，要从**一个张量在一次循环里被读几次、被写几次**出发：

| 角色 | 每次循环的读写 | 它对误差的贡献 |
|---|---|---|
| 计算副本 | **只读**（前向一次、反向一次） | 单次误差，**不累积** ⇒ 可以窄 |
| 梯度 | 写一次、读一次 | 单次误差，但**下层要看它** ⇒ 窄了就丢信号 |
| 主权重 | **读一次、写一次，而且活到下一次循环** | ★ **误差会累积** ⇒ 必须宽 |
| 优化器状态 | 同上（跨步存活） | ★ 同样累积 ⇒ 必须宽 |

⇒ **判据是「跨步存活」**：只有要活到下一步的量才必须宽，因为它们把误差**攒起来**。
这就是上游那句「低精度用来产生修正量、高精度用来累积结果」的可操作形态。

### 1.2 临界条件：更新什么时候被吞掉（判据①的核心）

设 `w` 是 fp16 里可表示的权重。加上一个更新 `Δw` 后要能**改变**这个数，至少要让结果舍到**相邻的**格点。
舍入到最近时，一个数落在两个格点的**中点**才会翻向另一侧 ⇒ 临界值的一半：

```
Δw_crit ≈ ULP(w) / 2
```

`ULP(w)` 是 `w` 处的格距。fp16 的尾数 10 位 ⇒ 在 `w` 所在的那个 binade 里

```
ULP(w) = 2^⌊log2|w|⌋ · 2^-10        ⇒  ULP/2 = 2^⌊log2|w|⌋ · 2^-11
```

本机实测（`A.1`，`|w| ∈ {1, 10, 100, 1000}`，四档都是 fp16 的**格点**）：
「二分实测的临界 / (ULP/2)」= `1.000000 · 1.000000 · 1.000000 · 1.000000`（最大相对差 `2.276e-13`）。

★★ **这个 `1/2` 与论文里那个 `2048` 是同一件事。** Micikevicius 2017 逐字（`[C]` arXiv 1710.03740，
**已确认同行评审** —— 该文 abs 页的 `Comments:` 逐字是 `Published as a conference paper at ICLR 2018`）：

> This can happen when the magnitude of a normalized weight value is at least **2048 times** larger
> that of the weight update. Since FP16 has **10 bits of mantissa**, the implicit bit must be
> **right-shifted by 11** or more positions to potentially create a zero.

`2048 = 2^11` —— **与 `ULP/2 = 2^-11·2^e` 中的那个 11 是同一个数**。
本机实测（`B.1`）：临界比值 `|w| / Δw_crit = 2·|w|/ULP` 落在 `[2048, 4096)`，
且在**2 的幂**处**精确等于 `2048`**（`|w| = 1, 2, 4, 8` 四档都是 `2048.0000`）。
论文的措辞是 **`at least`** —— 那个下界正是 `2^11`。

★ **而 `w` 不在格点上时，量的是另一个东西。** 本机实测（`A.1b`）：

| `|w|` | `fp16(w)` | `fp16(w) − w` | `ULP/2` | 闭式 `ULP/2 + (fp16(w)−w)` | 实测/闭式 |
|---|---|---|---|---|---|
| `0.01` | `0.0100021362` | `+2.136230e-06` | `3.814697e-06` | `5.950928e-06` | `1.000000` |
| `0.1` | `0.0999755859` | `−2.441406e-05` | `3.051758e-05` | `6.103516e-06` | `1.000000` |

⇒ 一般式是

```
Δw_crit = ULP/2 + ( fp16(w) − w )
```

`w` 恰在格点上时第二项为 0，就回到 `ULP/2`。**这就是为什么判据①的扫描表只能用格点值** ——
拿 `0.1` 去测会得到比值 `0.200000`，拿 `0.01` 会得到 `1.560000`，那**不是判据失败，是另一个量**。

### 1.3 四行的动态范围：三个数，三样口径

选型的唯一判据是「数据的量级落在格式的哪一段」。把三个数**同口径**列出来
（`A.3`，容差 ±0.05，本机算出 `9.0307 / 12.0410 / 76.4616`）：

| 量 | 算式 | 值 | 口径 |
|---|---|---|---|
| fp16 **正规区间** | `log10(65504 / 2^-14)` | **9.03** | 只数**正规**数 |
| fp16 **含次正规** | `log10(65504 / 2^-24)` | **12.04** | 连次正规一起数 |
| fp32 **正规区间** | `log10(3.40e38 / 1.18e-38)` | **76.46** | 只数**正规**数 |

★★ **这三个数不能两两相减。** fp16 那一行有**两种口径**，fp32 那一行是**正规**口径 ——
`76.46 − 12.04 = 64.42` 与 `76.46 − 9.03 = 67.43` 是两个不同的量。
库内先例已经逐字警告过：`130-model-optimization/quantization/03-bf16-fp16-tf32.md:154`
说 `2^-126` vs `2^-14`「**两个数不是同一个量，不要混用**」，它给的**同口径**说法是
「bf16 的量程跨度宽 **67.5** 个数量级（`76.5 vs 9.0`）」。
★ 本文因此**只报同口径的那一组**，并把 fp16 的两种口径**并排**写出来（这本身就是那条区分的用处：
`Δw = 1e-6` 落在哪一边，决定了它会不会被吞）。

### 1.4 一个可以手算的闭式：多大比例的梯度会掉到 0

设梯度 `g ~ N(0, σ)`。**归零阈值不是最小次正规数，而是它的一半** —— 舍入到最近，
`|g| < 最小次正规/2` 才会舍到 0。于是

```
P(|g| 归零) = erf( (最小次正规/2) / (σ√2) )        （= 2Φ(x) − 1 的闭式）
```

★ 本机实测（`A.5`，200 万样本的蒙特卡洛，**每个 σ 都先打印「期望命中数」**）：

| `σ` | 闭式 | MC 实测 | 相对差 | 期望命中数 | 判定 |
|---|---|---|---|---|---|
| `1e-6` | `0.023775` | `0.023857` | `0.0034` | 47551 | 进判据 |
| `1e-5` | `0.002378` | `0.002404` | `0.0112` | 4756 | 进判据 |
| `1e-4` | `0.000238` | `0.000248` | `0.0429` | 476 | 进判据 |
| `1e-3` | `0.000024` | `0.000016` | `0.3271` | **48** | ★ **只报不判** |

★ **最后那一行是「判据的小 n 不稳定」的现场**：`σ = 1e-3` 时 200 万样本里**只有 48 个**预期命中，
MC 的噪声（`1/√48 ≈ 14%`）与 5% 的容忍度同量级 ⇒ **它不进判据**，
但**它照样被打印出来**，因为「先确认参照量级够大」这件事本身就是一条纪律（见 §4）。

**反面对照**（`A.5b`）：把阈值取成**最小次正规本身**（`2^-24`，也就是那个常见的错），
闭式给 `0.047529` 而 MC 给 `0.023857` —— **比值 `0.5019`**。
⇒ 「阈值是最小次正规的**一半**」这句话**是被这个反面对照证伪出来的**，不是假设的。

### 1.5 为什么主权重必须 fp32：本文只引，不重推

`10-foundations/numerical-linear-algebra/04-iterative-methods.md:229-266` 已经把
「主权重为什么必须 fp32」的**数值理由**讲完了（迭代精化的 `κ·u` 判据链、`e_new = −(Â⁻¹ − A⁻¹)·A·e` 的结构）。
**正文在彼，此处回链**，本文只补两条**可以自己算**的：

1. **临界条件是 `Δw ≳ ULP(w)/2`**（§1.2）—— 它是一个**逐元素的**、可精确测的阈值，不是「精度不够」这种话；
2. **`lr·g` 越小、`|w|` 越大，越容易被吞** —— 因为 `Δw_crit` 随 `|w|` 的 binade **阶梯式变大**，
   而 `Δw` 不会。本机实测 `|w| = 1000` 处 `ULP/2 = 0.25`：一个 `Δw = 0.1` 的正常更新在那里**完全消失**。

## 2. 执行映射

### 2.1 一次 GEMM 在硬件上分成两段

这是本表在硬件上的落点，**正文在 `10-foundations/floating-point/04-low-precision-formats.md:174`**，

⇒ 这就是表里「计算副本可以窄、累加必须宽」那一行在硅上的样子。

## 3. 实现与演进

| 阶段 | 写法 | 它换来了什么、付了什么账 |
|---|---|---|
| **全 fp32** | 一行不改 | 一切都能表示；代价是显存、带宽与 Tensor Core 吞吐 |
| **fp16 + loss scaling + fp32 主权重** | 计算副本 fp16、梯度 fp16、**主权重 fp32**、loss 乘 `S` | 省一半存储与带宽；代价是**范围**（见 `02`）与一份多出来的 fp32 主权重 |
| **bf16** | 同一张表，把 fp16 换成 bf16 | 省掉整个 loss scaling 机制；代价是尾数 7 位（`eps = 2^-7`，比 fp16 低 **8 倍**） |
| **fp8 + per-tensor scaling** | 计算副本 fp8、靠软件层的 scale 补范围 | 再省一半；代价是 scale 与它的启发式，见 `03` |

★ **四行里唯一从头到尾没变的两行是「主权重」与「优化器状态」** —— 它们都是 fp32。
这不是保守，是 §1.1 那条判据的直接结果：**跨步存活的量不让它窄。**

## 4. 踩坑与失败模式

**① 把两个不同口径的动态范围相减。**

- **现象**：写「fp16 与 fp32 的动态范围差了约 7.5 个数量级」，或者「差了 64.42 个数量级」。
- **成因**：fp16 那一行常常用**含次正规**的下限（`2^-24`）算，fp32 那一行用**正规**下限算 ——
  两个数不是一个量。`76.46 − 12.04 = 64.42`，与同口径的 `67.43` 差了 3 个数量级。
  ★ 本库的规划文档里**真的出现过这个数**，而且它的来源只是探测脚本里一句**紧跟打印、没有推导**的硬编码字符串。
- **规避**：**只报同一口径的一组**，并**把另一种口径并排写出来**（§1.3 的表就是这么做的）；
  要减就把口径对齐了再减。

**② 拿不在格点上的 `|w|` 去测 `ULP/2`。**

- **现象**：同一个判据在 `|w| = 1, 10, 100, 1000` 上给出比值 `1.000000`，在 `0.1` 上给 `0.200000`、
  在 `0.01` 上给 `1.560000`，于是怀疑判据写错了。
- **成因**：`Δw_crit = ULP/2 + (fp16(w) − w)` —— `w` 不在格点上时那第二项不为 0，**量的是另一个东西**。
- **规避**：**扫描表只用格点值**（`code/01_types.py` 的 `D.3d` 把「全在格点」这件事本身钉住），
  并把非格点的那两行**换成另一条判据**（`A.1b` 的闭式）。

**③ 把「bf16 的动态范围与 fp32 精确相同」当成精确的。**

- **现象**：断言 `log10(bf16 量程) / log10(fp32 量程) == 1.0000`。
- **成因**：那个 `1.0000` 是**打印到 4 位小数**的结果。**精确比值是 `0.9999777698`**，
  偏差 `2.223e-05` 来自**尾数位不同**（bf16 的 `(2−2^-7)` vs fp32 的 `(2−2^-23)`），
  **不是**指数位不同 —— 两者的 `emax − emin` 都是 `253`。
- **规避**：**把「到 4 位小数相同」与「精确相同」分开说**；真正成立的那句是
  「**指数位相同 ⇒ `emax − emin` 相同**」。本程序两条都断言（`A.4` 与 `A.4b`）。

**④ 把「更新的临界值」当成 `ULP` 而不是 `ULP/2`。**

- **现象**：断言 `Δw_crit == ULP(w)`，结果实测差一倍。
- **成因**：舍入到最近在中点才翻向另一侧，所以阈值是**半个**格距。同理，
  **归零阈值是最小次正规的一半**（§1.4）。
- **规避**：把 `ULP/2` 写成**两条独立路径**取到的量（二分法 vs `nextafter`，`A.1`），
  并给归零阈值配一条**反面对照**（`A.5b`：用 `2^-24` 时比值掉到 `0.5019`）。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| `w` 是 fp16 的格点、`Δw < ULP(w)/2` | **更新被静默吞掉**（`w + Δw == w` 逐位）；本机 `w₀=1, Δw=1e-6` 时 **2000 步全被吞**、权重恒为 `1.000000` |
| `w` 不是格点（如 `0.1`、`0.01`） | 临界值变成 `ULP/2 + (fp16(w) − w)`，**不再是 `ULP/2`**；拿它当判据会假失败 |
| `|w|/Δw ≥ 2048` | 更新**不可恢复地变成 0**（`[C]` 逐字 `at least 2048 times`，对应右移 11 位）；比值 ∈ `[2^11, 2^12)`，2 的幂处**精确 `2048`** |
| 想知道一个梯度会不会掉到 0 | 阈值是**最小次正规的一半**（`2^-25 = 2.98e-08`），闭式 `erf(thr/(σ√2))`；用 `2^-24` 会把比例算成 **2 倍** |
| 想报「动态范围差多少」 | **必须先对齐口径**：fp16 正规 `9.03` / fp16 含次正规 `12.04` / fp32 正规 `76.46`；**跨口径相减得到的数没有意义** |
| 想断言「bf16 与 fp32 量程相同」 | 只能断言**到 4 位小数相同**（精确比值 `0.9999777698`）；真正精确的是「指数位相同」 |
| 想省字节 | **混合精度不省状态的字节**（本机：两列各 `16` 字节/参数）；省的是计算与带宽 |
| 该让哪个张量窄？ | 判据是「**跨步存活**」：主权重与优化器状态必须宽（误差累积），计算副本可以窄（误差单次） |

> ★ 阈值（`code/01_types.py` 的 `D.3`/`D.4` 逐位钉住）：`TOL_ULP_RATIO = 1e-3`、
> `TOL_RANGE = 0.05`（三个动态范围）、`TOL_UNDERFLOW_REL = 0.05`、
> **`MIN_EXPECTED_HITS = 300`**（判据⑥的小 n 门槛）、`TOL_BF16_RANGE_REL = 1e-4`、
> `TOL_MASTER_VS_CLOSED = 1e-4`、`RATIO_MIN = 2048` / `RATIO_MAX = 4096`。
> ★ 放宽 `MIN_EXPECTED_HITS` ⇒ 判据⑥ 会把 `σ = 1e-3` 那一行（48 个命中）也算进判据，
> 于是它随样本数**随机通过**。

## 6. 小结与延伸

**一句话**：四行的划分依据不是「哪种 dtype 快」，而是「**这个量跨不跨步存活**」；
而这条链上最容易出错的一步是 `Δw < ULP(w)/2` 时更新被**静默**吞掉 ——
那个临界值可精确测，且与论文里 `2048 times`（= 右移 11 位）是同一件事。

  `90-training/autograd-and-backward/03-gradient-lifecycle`（正文在本域，回链该处）。
