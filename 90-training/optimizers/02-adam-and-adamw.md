# Adam 与 AdamW：weight decay 的两种语义

> `torch.optim.Adam` 加上 `weight_decay` **不是** AdamW —— 默认 `decoupled_weight_decay=False`，
> 那个 `λ` 会**进梯度、进而进 `m` 和 `v`**。而一旦它进去了，Adam 的**自适应**会把它
> **归一化成一个恒定的步长**：权重**线性**走向 0，而且**与 `λ` 的大小无关**。
> ★ 这不是「`λ` 越大越明显」——**那是饱和**。

## 0. 背景与动机

### 两个「常见转述」，两个都是错的

**转述 A**：「AdamW 与 Adam+L2 的差别 = 解耦了 weight decay。」

★ 这句话**不算错，但它把两个来源的**不同**归因合并成了一句。一手原文给的不是同一句话：

| 来源 | 逐字 | 它归因到 |
|---|---|---|
| **[C]** AdamW 论文（1711.05101）§2 | `weights x with large typical gradient magnitude s are regularized by a smaller relative` | **L2 的梯度也被自适应归一化了** ⇒ 典型梯度大的权重**被正则得更少** |
| **[B]** PyTorch 2.14 的 `AdamW` 文档 | `weight decay does not accumulate in the momentum nor variance` | **不进动量与方差** |

★★ **两条不矛盾、但不是同一句话** ⇒ 转述时把 PyTorch 的措辞写成论文的理由，
就是「**规范与实现不分**」。本文**两条都引、各标出处**（判据表 B）。

**转述 B**：「`torch.optim.Adam` + `weight_decay` 就是 AdamW。」

★ **这是错的**（[B] PyTorch 2.14 的 `torch.optim.Adam` 签名逐字）：
`decoupled_weight_decay=False` —— **默认是 `False`**。要解耦必须显式传
`decoupled_weight_decay=True`，或者用 `AdamW` 类。
★ 顺带：同一个框架里两个类的**默认 `weight_decay` 都不一样** —— `Adam` 是 `0`、`AdamW` 是 `0.01`
⇒ 「用哪个类」这件事**不只是名字**。

## 1. 原理

### 1.1 两个算法，逐字

**[C] Adam**（1412.6980，**已确认 ICLR 2015**），Algorithm 1 的更新式：

```
g_t ← ∇_θ f_t(θ_{t−1})
m_t ← β₁·m_{t−1} + (1−β₁)·g_t
v_t ← β₂·v_{t−1} + (1−β₂)·g_t²
m̂_t ← m_t/(1−β₁^t)
v̂_t ← v_t/(1−β₂^t)
θ_t ← θ_{t−1} − α · m̂_t/(√v̂_t + ε)          ★ ε 在根号【外】
```

论文自己的措辞是（**PDF 文本层**逐字）：
`Good default settings for the tested machine learning problems are α = 0.001, β₁ = 0.9, β₂ = 0.999 and ε = 10^−8`
—— ★ **它是「作者试过好用」，不是「规范规定」**。

**[C] AdamW**（1711.05101，**已确认 ICLR 2019**），Algorithm 2 的第 12 行：

```
θ_t ← θ_{t−1} − η_t( α·m̂_t/(√v̂_t + ε) + λ·θ_{t−1} )
```

★ **结构上的差别只有一项**，而那一项**不在**自适应缩放内。
★ 同一份 Algorithm 2 的**第 11 行**是 `η_t ← SetScheduleMultiplier(t)`（注释逐字
`can be fixed, decay, or also be used for warm restarts`）—— **论文自己把「学习率调度」
写进了优化器的算法框**，这正是本文与 `03` 的接口。

★★ **`ε` 在根号外是可断言的**（`A.5`）：两种写法 `m̂/(√v̂+ε)` 与 `m̂/√(v̂+ε)`
**只在 `|g|` 与 `ε` 同量级时才分开**（本机：`|g| = 1e-6` 时相对差可观；
`|g| ≥ 1e3` 时相对差 < `1e-8`）。
⚠ **量法口径**：这条引文**不能**在原始字节上核对 —— Adam 论文的 PDF 文本层里 `√`
**单独占一行**（分式排版），而 PyTorch 的 HTML 里它是 MathML 的 `<msqrt>` 元素
（剥标签后整个消失）⇒ **可证伪性由数值断言承担，不由 `raw.count` 承担**。

### 1.2 ★★ 自归一化：「梯度恒为 0」这个最干净的对照

把真梯度设成 **0**，只留 weight decay。这时两条件走的路完全不同：

| | Adam + L2（`λ` 进梯度） | AdamW（`λ` 不进） |
|---|---|---|
| 梯度是什么 | `g_t = λ·w_{t−1}`（**唯一**的梯度） | `g_t = 0` |
| 自适应项 | `m̂/√v̂` | `m̂/√v̂ = 0/0 → 0`（精确 0） |
| 轨迹 | **线性走向 0**，且**与 `λ` 无关** | `w_t = (1 − η·λ)·w_{t−1}` ⇒ **有闭式** |

本机实测（`A.1`/`A.3`，`lr = 0.01`、`λ = 0.1`、`w₀ = 1`、200 步）：

| | 终值 |
|---|---|
| Adam + L2 | **`0.015572505`** |
| AdamW | **`0.818648829`** |
| **闭式 `(1 − lr·λ)^200`** | **`0.818648829`**（与 AdamW 差 `4.441e-16`） |

★ 计划 §0.7-D 的 **D1** 记的是 `0.015573` / `0.818649` —— **本机逐位复现**。

### 1.3 ★★ 机制是「自归一化」，不是「更新被放大」

**为什么 Adam+L2 会塌，而且与 `λ` 无关？**

`g_t = λ·w_{t−1}` 里 `λ` 只是一个**正的乘数**：
`m_t` 随它**线性**、`v_t` 随它**平方** ⇒ `√v̂_t` 也随它**线性** ⇒ **`m̂_t/√v̂_t` 不变**。
⇒ 那个「步长」被**自归一化**成一个与 `λ` 无关的量（在 `|g| ≫ ε` 时就是 `1`），
于是 `w` 每步减掉差不多 `lr`，**一路走向 0**。

本机实测把它量成了三条断言（`A.3`/`A.4a`/`A.4b`）：

| 判据 | 实测 |
|---|---|
| `λ ∈ {0.01, 0.1, 1.0}`（跨 **100 倍**）上**终值**的极差 | **`2.028e-07`** |
| `λ ∈ {0.01, 0.1, 1.0}` 上**整条轨迹**的最大逐元素差 | **`6.430e-07`** |
| **第 1 步的归一化比值** vs 闭式 `g/(\|g\|+ε)` | **逐位一致**（相对差 `0.000e+00`） |

★★ **「与 `λ` 无关」这条的精确形式**：`A.3` 判的是**终值**（计划 §3 表 A ⑥ 的形态），
`A.4a` 判的是**整条轨迹** —— 后者更强，它把「饱和」这件事从「终点碰巧一样」推到「过程处处一样」。

**★★ 而「自归一化」的作用范围有边界 —— 两条**：

**① 它只覆盖真梯度那一项。** 把**整体的梯度**乘上 `c`（`c = 0.01 / 100`）：
纯 Adam（`λ = 0`）的轨迹差 **`1.153e-07`**（缩放不变），
而带 L2 的 Adam 差 **`7.281e-01`**（**不是**缩放不变）—— 因为 `λ·w` 那一项
**不随 `g` 缩放**，它与真梯度的**相对大小**变了（`A.4c`）。

**② 它的下限是 `ε`。** 闭式 `ratio₁ = g/(|g|+ε)` ⇒ 当 `λ·w₀ = ε` 时它**恰好是 `0.5`**。
本机实测（`C.1`，`λ = 1e-8`、`w₀ = 1`、`ε = 1e-8`）：`ratio₁ = 0.500000000000000`（**逐位**），
200 步后 `w = 0.306373`（而正常档是 `0.015573`）⇒ 权重**走不动**。
★ 这条同时给 §1.3 的「与 `λ` 无关」**划了范围**：`A.3` 的三档 `λ ∈ {0.01, 0.1, 1.0}` 都在
`|g| ≫ ε` 的一侧（`λ·w₀ ≥ 0.01 ≫ 1e-8`）。

### 1.4 那个闭式**只在「梯度恒为 0」时成立** —— 而且它**失效得极不稳定**

`w_t = (1 − η·λ)·w_{t−1}` 之所以成立，是因为 `g_t = 0` 时 `m̂ = v̂ = 0`
⇒ **整个自适应项精确为 0**。一旦有真梯度，这一项就回来了。

本机实测（`A.6`，**200 个种子**，随机 `N(0,1)` 梯度、其余口径不变）：

| 量 | 值 |
|---|---|
| `\|AdamW_{200} − 闭式\|` 的**最小值** | **`4.976125e-05`**（seed 198） |
| 最大值 | **`0.525712`**（seed 10） |
| > `0.1` 的种子数 | **94 / 200** |

★★ **这一行里有两个教训**：

1. 「闭式描述 AdamW」这句话**只在梯度恒为 0 时成立** —— 正确的判据是**结构性**的：
   把梯度全部乘 0，闭式**立刻恢复**（`A.6c`：差 `4.441e-16`）。
2. ★★ **绝不能把它写成「差 > 某阈值」** —— 偏差横跨 **4 个数量级**
   （`4.976125e-05` ~ `0.525712`），任何下界都会被某些种子击穿。
   这是「**判据的小 n 不稳定**」的又一次现场，而且这次是**上界方向**的：
   小样本会给出**一条根本站不住的下界**。

### 1.5 `λ` 到底去了哪里：一步就能看见

Adam+L2 与 AdamW 的第 1 步（`A.7`，`g₁` 随机、`λ = 0.1`、`w₀ = 1`）：

| | `m̂₁` | `v̂₁` |
|---|---|---|
| Adam + L2 | `g₁ + λ·w₀`（**多出 `λ·w₀ = 0.1`**，逐位） | 与 AdamW **不同** |
| AdamW | `g₁`（**没有** `λ·w₀` 那一项） | 与 Adam+L2 不同 |

⇒ ★ **`λ` 真的进了 `m` 与 `v`**（`m` 上是线性的、`v` 上是平方的，两者的差都可见）。
这就是「`decoupled_weight_decay=False`」这句话的**机制版本**：

> `[B]` PyTorch 的 `Adam` 伪代码逐字有 `if λ≠0gt←gt+λθt−1`；
> 而 `AdamW` 的伪代码是 `θt←θt−1−γλθt−1` **先于** `mt←…` ⇒ 两条链的**顺序**就不一样。

| **状态合计** | **8 ⇒ 状态 : 参数 = 2 : 1** |

★ 与 `mixed-precision/01` 的四行表**对齐**（那里第三行「优化器状态 8」数的正是这份 `m`+`v`
—— **同一个量**）；而动量（`01`）只有**一份**状态 ⇒ `4` 字节，**不是同一个量**。

★★ **分片策略与通信量**（ZeRO 三阶段 / FSDP / `4x` / `8x` / `16Ψ` 的账）
**正文在** `100-parallelism/README.md:14`（`zero-fsdp`）——**本文只留接口，不写**。

### 2.2 ★★ 更新量的量级：Adam 的 `Δw` **与 `|g|` 无关**

这是本文接住上游让渡的那一格。**常数梯度**下第 1 步有**精确闭式**：
`m̂₁ = g`、`√v̂₁ = |g|` ⇒

```
|Δw₁| = lr · |g|/(|g| + ε)
```

本机实测（`B.2`，`lr = 0.01`，与闭式的最大相对差 `4.885e-15`）：

| `\|g\|` | 实测 `Δw₁` | 闭式 |
|---|---|---|
| `1e-06` | `-9.900990099010e-03` | 同 |
| `0.001` | `-9.999900001000e-03` | 同 |
| `1` | `-9.999999900000e-03` | 同 |
| `1000` | `-9.999999999900e-03` | 同 |
| `1e+06` | `-1.000000000000e-02` | 同 |

⇒ ★★ **`|g|` 跨 12 个数量级，`|Δw|` 只变 `(1 − ε/|g|)` 的量。**
这与 `01` 的 SGD 形成**正面**对照（`|Δw| = lr·|g|`，**随 `|g|` 线性缩小**）。

**★ 而这条对照在 `mixed-precision/01` 的阈值上有一个可断言的后果**（`B.2b`）：
取 `w = 1.0`（fp16 的格点，`ULP/2 = 4.8828125e-04`）、`lr = 1e-3`、`|g| = 1e-3`：

| | `\|Δw\|` | 被 fp16 主权重吞掉？ |
|---|---|---|
| **SGD** | `lr·\|g\| = 1.000e-06` | ★ **是**（`w + Δw == w`） |
| **Adam** | `≈ lr = 1.000e-03` | **否** |

⇒ ★ **同一个 `lr`、同一批梯度，SGD 的更新进不去、Adam 的进得去** ——
这正是「**更新量 Δw 在什么精度下算**」这一侧的可操作形态。
（`ULP/2` 的**判据与阈值定义在** `mixed-precision/01-type-selection.md` §1.2，**此处只消费**。）

### 2.3 「更新量的 RMS」：一个**不能对齐**的外部锚点

`[C]` Muon（arXiv 2502.16982，**不确认同行评审**）逐字：

> `These findings are consistent with our empirical observation that AdamW's update RMS is
> in the range of 0.2∼0.4. We opted to control the update RMS of Muon to 0.2.`

★ 这是本主题「更新量的量级」这一格的**唯一外部锚点**：Muon 是**按更新量的 RMS 调自己**的
（把它对齐到 AdamW 的量级）。同文摘要逐字还给了它的两条技术：
`(1) adding weight decay and (2) carefully adjusting the per-parameter update scale`。

★★ **口径警告（`B.3`）**：论文**没有**说它量的是「含不含 `lr`」的那个量、
也没说是逐张量还是逐元素。而本机（玩具规模、归一化后的更新量、随机梯度上）
量到 `RMS(m̂/(√v̂+ε)) = 0.317252`。**两个数不是同一个量** ⇒
本文**只并列打印、不做比值断言**（`specs.UNSOURCED` 里记了这条）。
★ 这正是「**量法口径是独立的出错环节**」的现场：两个都在 `(0,1)` 里的数，
放在一起看很像，但**它们量的是不同的东西**。

### 2.4 具体组件与数值量级

| 组件 | 它在本文这一格里的角色 | 数值量级（本机实测） |
|---|---|---|
| `ε = 1e-8` | 自归一化的**下限** | `λ·w₀ = ε` 时 `ratio₁ = 0.5`（**逐位**） |
| `β₁ = 0.9` / `β₂ = 0.999` | `m`/`v` 的记忆长度 | `β₂` 的记忆约 1000 步 ⇒ 200 步的轨迹里 `√v̂` 还被**早期**的大梯度主导 |
| `λ` | Adam 侧**进** `m`/`v`；AdamW 侧**不进** | `λ ∈ {0.01, 0.1, 1.0}` ⇒ Adam+L2 的终值极差 `2.028e-07` |
| `(1 − lr·λ)^n` | AdamW 在「梯度恒为 0」下的闭式 | `lr = 0.01, λ = 0.1, n = 200` ⇒ `0.818648829` |
| `m` + `v` | 优化器状态（跨步存活） | `8` 字节/参数（**单卡口径**） |

## 3. 实现与演进

| 阶段 | 写法 | 它换来了什么、付了什么账 |
|---|---|---|
| **SGD + 动量**（`01`） | 一个全局 `lr`，一份 buffer | 简单；代价是**所有参数共用一个步长** |
| **Adam** | 每个参数自己的步长 `lr·m̂/(√v̂+ε)` | 三份超参（`β₁/β₂/ε`）+ **2 份状态**（`m`/`v`） |
| **Adam + L2** | 把 `λ·w` 加进梯度 | ★ 看起来与 AdamW 等价，**实际不是**：那个 `λ` 进了 `m`/`v`，被自适应**归一化掉**了（§1.3） |
| **AdamW** | 解耦：`θ ← θ − η(自适应 + λ·θ)` | 让 weight decay 的**强度**重新可控（与 `λ` 成正比）；代价是**多一个"位置"要记对**（`λ` 不进 `m`/`v`） |
| **Muon**（`[C]` 2502.16982，**不确认同行评审**） | 对**矩阵参数**的动量做**正交化**（Newton-Schulz 迭代），再按**更新量的 RMS** 缩放 | ★ 它的两条关键技术逐字是 `adding weight decay` 与 `carefully adjusting the per-parameter update scale` —— **恰好就是本文与 `01` 的两件事** |

★ **从 Adam 到 AdamW 的那一步不是「加了一个选项」，而是「换了一个语义」** ——
同一个 `λ`、同一个符号，在两边的**作用点**不同；本文的 `A.7` 用一步就能把这件事看见。

## 4. 踩坑与失败模式

**① ★★ 说「`wd` 越大，Adam+L2 塌得越明显」。**

- **现象**：一句话说得通、写出来也像对的，但它**与数据方向相反**。
- **成因**：Adam+L2 在 `λ` 一非零之后是**饱和**的 —— 本机实测 `λ ∈ {0.01, 0.1, 1.0}`
  三值极差只有 **`2.028e-07`**。「越大越明显」描述的是**放大**，而这里发生的是**归一化**。
- **规避**：判据写成「**三值之差 < 1e-5**」（`A.3`），并把**整条轨迹**也钉住（`A.4a`）。

**② ★★ 用「`√v` 变小 ⇒ 更新量被放大」解释那个「塌」。**

- **现象**：一个听起来很顺的机制从句（`w` 变小 ⇒ `g = λ·w` 变小 ⇒ `√v` 变小 ⇒ 步长变大）。
- **成因**：**它与数据矛盾** —— 如果真是「放大」，结果就应当**随 `λ` 变**，
  而实测三个 `λ` 给出同一个值。★ 真正的机制是**自归一化**：`m̂/√v̂` **不变**
  （`λ` 在分子上线性、在分母上也线性）。
- **规避**：把机制写成**可算的量**（`ratio₁ = g/(|g|+ε)`，`A.4b` 逐位对拍），
  而不是写成从句。

**③ 把 `(1 − lr·λ)^n` 当通用闭式。**

- **现象**：拿它去描述随机梯度下的 AdamW。
- **成因**：它成立的前提是「`g ≡ 0`」（那时 `m̂ = v̂ = 0`，自适应项精确为 0）。
- **规避**：正确的判据是**结构性**的（把梯度乘 0 ⇒ 闭式恢复，`A.6c`），
  并**明写它失效**（`A.6`）。

**④ ★★ 把「闭式失效」写成「差 > 0.1」这类下界。**

- **现象**：用一个种子的结果定了一个阈值。
- **成因**：200 个种子上的偏差是 **`4.976125e-05` ~ `0.525712`** —— 横跨 4 个数量级。
- **规避**：**只报区间、不写下界**（`A.6` 与 `A.6b` 是**两条**：
  前者说「可以差很远」、后者说「也可以差极小」）。★ 这是「判据的小 n 不稳定」的
  **上界方向**的现场。

**⑤ 把 PyTorch 的措辞当论文的理由。**

- **现象**：写「论文说 weight decay 不进动量与方差」。
- **成因**：那是 **[B] PyTorch 2.14 的文档**逐字；论文说的是「**L2 的梯度也被自适应归一化了**」
  （所以典型梯度大的权重被正则得更少）。两者**不矛盾但不是同一句话**。
- **规避**：两条**都引、各标出处**（判据表 B 的第一行）。

**⑥ 以为 `torch.optim.Adam` + `weight_decay` 就是 AdamW。**

- **现象**：换了一个 `weight_decay` 的值，以为自己在用 AdamW。
- **成因**：`decoupled_weight_decay` 默认 **`False`**（[B] 逐字），`λ` 会进 `m`/`v`。
- **规避**：用**机制**判（`A.7`：第 1 步的 `m̂` 是否多出 `λ·w₀`），
  而不是用「我传了这个参数」判。

**⑦ 用「更新量」这个词时不说口径。**

- **现象**：把论文的 `update RMS = 0.2~0.4` 与本机量到的 `RMS(m̂/(√v̂+ε)) = 0.317` 放在一起比。
- **成因**：两个数**不是同一个量**（一个含不含 `lr` 未写明，一个只到归一化那一层）。
- **规避**：凡写「更新量」处，**同时写出它是哪一层**（`lr·m̂/(√v̂+ε)`？还是 `m̂/(√v̂+ε)`？）
  —— 与 `130-quantization/numerical-formats/02-e8m0-and-mx.md:276` 那条
  「凡写 scale 必写作用域与 bit 开销」是同一个纪律。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 「梯度恒为 0」、`λ ≠ 0` | Adam+L2 的自适应项变成**唯一**梯度并被归一化 ⇒ 权重**线性走向 0**；本机 200 步后 `0.015573`（区间 `[0.0155, 0.0157]`） |
| 要判断 AdamW 在某一步上「解耦得对不对」 | 在 `g ≡ 0` 时它必须**精确**等于 `(1 − lr·λ)^n`（本机差 `4.441e-16`）；★ 这个闭式**只在 `g ≡ 0` 时成立** |
| `λ = 0` | 两条链**逐位恒等**（本机差 `0.000e+00`）⇒ 「Adam 与 AdamW 有差别」只在 `λ ≠ 0` 时成立 |
| `λ ∈ {0.01, 0.1, 1.0}` 上比较 Adam+L2 | 终值极差 **`2.028e-07`**、整条轨迹差 **`6.430e-07`** ⇒ 它**饱和**；★ 说「`λ` 越大越明显」是**反方向**的 |
| 想解释那个「塌」 | 机制是 **`m̂/√v̂` 与 `λ` 无关**（`λ` 在分子线性、在分母线性）；★ 本机第 1 步的 `ratio₁` **逐位等于**闭式 `g/(\|g\|+ε)` |
| 想断言「Adam 对梯度尺度不变」 | 只有**纯 Adam（`λ = 0`）**成立（本机差 `1.153e-07`）；带 L2 的 Adam **不成立**（差 `7.281e-01`） |
| 想知道自归一化的**下限** | 是 `ε`：`λ·w₀ = ε` 时 `ratio₁` **恰好 `0.5`**（逐位），权重走不动 |
| 想用闭式描述随机梯度下的 AdamW | **不行**：本机 200 个种子上偏差 ∈ `[4.976125e-05, 0.525712]` ⇒ **不可写成下界**；正确的判据是「把梯度乘 0 ⇒ 闭式恢复」 |
| 要判断 `ε` 在根号内还是外 | 两种写法在 `\|g\|` 与 `ε` **同量级**时才分开（`\|g\| = 1e-6` 时可见；`\|g\| ≥ 1e3` 时相对差 < `1e-8`） |
| `torch.optim.Adam(weight_decay=…)` 是 AdamW 吗 | **不是**（默认 `decoupled_weight_decay=False`）；用第 1 步的 `m̂` 是否多出 `λ·w₀` 判 |
| 该把 `λ` 记在哪个语义下 | 论文归因到「**L2 的梯度也被自适应归一化**」，PyTorch 归因到「**不进动量与方差**」 ⇒ **两条都引，不得合并** |
| 优化器状态占几字节 | `m` + `v` = **8 字节/参数**（fp32，**单卡口径**）；★ 分片与通信量在 `100-parallelism`（`zero-fsdp`） |
| 想让 Adam 的更新被 fp16 主权重吞掉 | 做不到：`\|Δw\| ≈ lr`（与 `\|g\|` 无关）⇒ 同一个 `lr` 下 SGD 被吞而 Adam 不被吞（`lr = 1e-3`、`\|g\| = 1e-3`、`w = 1.0`） |

> ★ 阈值与口径（`code/02_adam_adamw.py` 的 `D.3`/`D.4` 逐位钉住）：
> `TOL_CLOSED = 1e-9`（与闭式的差）、`TOL_IDENTICAL = 1e-12`、`TOL_SATURATE = 1e-5`（**M3 的那个数**）、
> `TOL_RATIO = 1e-12`、`TOL_SCALE_INV = 1e-5`、`TOL_MEASURABLE = 1e-2`（**可测性下界**）、
> `TOL_ZERO_RESTORE = 1e-9`。
> ★ **口径常数**：`lr = 0.01`（**本程序的设定，不是论文的默认值** `0.001` —— `D.3b` 把「覆盖过」钉住）、
> `N_STEPS = 200`、`WD_MAIN = 0.1`、`WD_LIST = (0.01, 0.1, 1.0)`、`SEED_SCAN = 200`。
> ★ 放宽 `TOL_MEASURABLE` ⇒ `A.4c`/`A.5`/`A.6` 的反面一起退化成恒真。

## 6. 小结与延伸

**一句话**：`λ` 进不进 `m`/`v` 是**两种语义**；一旦进去，Adam 的**自适应**会把它
归一化成一个与 `λ` 无关的步长 —— 所以正确说法是「**饱和**」，不是「越大越明显」。
