# SGD、动量与 Nesterov：更新式与「状态」

> 优化器是训练里**唯一没有「省」的那一格**：它把梯度变成更新，而这一步只有**选择**。
> 选择的第一层是「要不要记住上一次」。一旦记住，就多出一份**跨步存活的状态** ——
> 而这份状态的**时序**（用更新前还是更新后的 buffer）是一个**数值上完全测不出来**的错误：
> 在「同一个 `g` 序列」上，它恰好把 Nesterov **静默地**退化成重球。

### 一个具体的对照场景

同一个线性回归、同一个学习率、同一批梯度，两种写法：

```
①  w ← w − lr·g                 （SGD）
②  b ← μ·b + g;  w ← w − lr·b   （重球 / momentum）
```

`②` 比 `①` 多一个标量 `μ` 和一个**向量 `b`**。多出来的那个向量**要活到下一步** ——
这就是「状态」。它带来两笔账：

| | 多花什么 | 换来什么 |
|---|---|---|
| **显存** | 每个参数多 **4 字节**（fp32 的 `b`）—— 相对权重是 **+100%** | — |
| **更新量** | — | `Δw = lr·b`，而 `b` 是**过去梯度的指数加权和** ⇒ 噪声被平均掉 |

## 1. 原理

### 1.1 三种更新式，只差一个「用哪个方向」

| 写法 | 递推 | 它用谁当方向 |
|---|---|---|
| **SGD** | `w ← w − lr·g` | 当前梯度 `g` |
| **重球**（heavy ball，即 `momentum`） | `b ← μ·b + g`；`w ← w − lr·b` | 动量的**当前值** `b` |
| **Nesterov** | `b ← μ·b + g`；`w ← w − lr·(g + μ·b)` | `b` 再加一份**前瞻修正** `μ·b` |

★★ **三条的 buffer 递推完全相同**（`b ← μ·b + g`）—— 差别**只在「更新里用哪一支」**。
本文的程序把三支实现成**同一个函数的一个参数**，就是为了让「在**同一个 `g` 序列**上比较」
这件事**严格成立**（否则三支会各自走出不同的梯度序列，比较就不干净了）。

★ **口径：`μ` 不是 Adam 的 `β₁`。** 两者**数值上常都是 `0.9`**，但角色不同：
`μ` 是**动量系数**、`β₁` 是**一阶矩的指数衰减率**；而且动量的 buffer 递推里
**没有** `(1−μ)` 这个因子（见 §4 ①）。

`[B]` **PyTorch 的 `nesterov` 两支**（`torch.optim.SGD` 2.14 的文档，逐字，剥标签后同一段内）：

```
b_t ← μ·b_{t−1} + (1−τ)·g_t          （τ = dampening，默认 0）
if nesterov:  g_t ← g_t + μ·b_t
else:         g_t ← b_t
θ_t ← θ_{t−1} − γ·g_t
```

★ 而 PyTorch 把「Nesterov 动量」的**出处**标成
`Nesterov momentum is based on the formula from On the importance of initialization and momentum in deep learning`
—— 即 **Sutskever et al. 2013**，**不是** Nesterov 1983 那篇。
⇒ 转述「Nesterov 动量」时**不要凭名字往 1983 年那篇上挂**（先看它指向谁）。

### 1.2 动量的闭式：为什么 buffer 的定义里没有 `(1−μ)`

`b_0 = 0`、`b_t = μ·b_{t−1} + g_t` 展开即

```
b_t = Σ_{k=0}^{t} μ^(t−k) · g_k
```

★★ **本文的程序用两条路径取它**：一层循环的**原地递推**，与**双重求和**的显式闭式
（后者是被测路径的**独立参照**，见 `D.12`/`D.13`）。本机实测（`A.1`，`seed = 20260928`、
32 个参数、20 步、`μ = 0.9`）：

| 量 | 值 |
|---|---|
| 递推 vs 闭式的**最大逐元素**差 | **`1.776e-15`** |
| 最坏出现在第几步 | 第 11 步 |
| 参照量级（★ **P22 检查**） | `min\|g\| = 5.390e-03` · `min\|b_t\| = 2.397e-03` · `max\|b\| = 6.675` |

★★ **最后那一行是判据的一部分**：这条判据是「**机器精度档的相等**」（阈值 `1e-12`），
所以**必须先确认参与判据的量没有衰减到次正规** —— 本机的最小参照量级是 `2.397e-03`，
比 fp64 的次正规下界（`2.2e-308`）大 **300 个数量级** ⇒ 那个「相等」测的是**递推的正确性**，
不是次正规噪声。★ 这条检查在程序里是一条**独立的断言**（`A.1c`），不是注释。

**反面对照（`A.1b`）**：把 buffer 写成 `b ← μ·b + (1−μ)·g` —— 那是把 Adam 的
`(1−β₁)` 形式**误搬**到动量上 —— 两条轨迹的最大逐元素差是 **`6.676`**
（相对整个轨迹的量级，这是完全的偏离）⇒ **`A.1` 不是恒真的**。

### 1.3 ★★ 「两种写法」有两种意思 —— 其中一种**不能**拿来做对照

「Nesterov 有两种写法」这句话在文献与代码里被用来说**两件不同的事**：

**(甲) 同一条链的两种记账** —— 「**先走一步**」与「**在偏移点算梯度**」：

```
记账①（先走一步）    ： y ← w − lr·μ·v;  g ← ∇f(y);  w ← y − lr·g;        v ← μ·v + g
记账②（在偏移点算梯度）： y ← w − lr·μ·v;  g ← ∇f(y);  w ← w − lr·(μ·v+g);  v ← μ·v + g
```

★★ **它们是同一个算法**：`y − lr·g = w − lr·μ·v − lr·g = w − lr·(μ·v + g)`。
本机实测（`A.3c`，同一个可微函数 `f(w) = ½λ‖w‖²`）：两条轨迹的最大逐元素差 **`1.110e-16`**
—— **逐位级相同**。⇒ **拿它们做对照是错的**：那里的差不是「两种算法的差」，
而是浮点舍入的差。（这正是「**同名不同指**」在优化器里的一个现场。）

**(乙) 真正不同的两个方向** —— PyTorch 的 `nesterov` 两支：
`g_t + μ·b_t` 与 `b_t`。本机实测（`A.3`，**同一个 `g` 序列**）：
两者的 θ 相差 **`0.558441`**（> `1e-3`），而且这个差**有闭式**
`−lr·Σ_t (g_t − (1−μ)·b_t)`（本机与闭式的相对差 `2.386e-15`）。

**(丙) 一个 buffer 时序错误，它让「Nesterov」静默变成「重球」**：
把「修正项」写成 `g_t + μ·b_{t−1}`（用**更新前**的 buffer）—— 本机实测（`A.3b`）：
它与**重球**轨迹的最大逐元素差是 **`0.000e+00`**（容差 0，**逐位相同**）。
⇒ ★★ 「用更新前的 buffer」**不是第三种写法**，它就是 `nesterov=False`。
这条错误的危险之处在于它**不报错**：程序照跑，只是**那个 `μ·b` 修正从来没有生效**。

★ 三者的关系一句话：**(甲) 是同一个算法；(乙) 是两种算法；(丙) 是一种错误** ——
而 (丙) 恰好等于 (乙) 的分支里那**另一个**。

### 1.4 「更新量在什么精度下算」：`Δw` 的量级与 `ULP/2`

无动量时 `Δw = lr·g` —— 它的量级**随 `|g|` 线性缩小**。而 `mixed-precision/01` 已经量出
（**判据与阈值定义在彼**，此处**只消费、不重定义**）：

> `w` 是 fp16 的格点、`Δw < ULP(w)/2` ⇒ **更新被静默吞掉**（`w + Δw == w` 逐位）。

本机实测（`B.2`，`w = 1.0`、`|g| = 1e-3`）：

| `lr` | `\|Δw\| = lr·\|g\|` | 被吞？ |
|---|---|---|
| `1e-4` | `1.000e-07` | **是** |
| `1e-3` | `1.000e-06` | **是** |

⇒ 临界 `lr* = (ULP(1.0)/2)/|g| = 4.8828125e-04 / 1e-3 = 0.488281`。
★ **`w = 1.0` 处 `ULP/2 = 2^-11`**，而 `w = 1000` 处 `ULP/2 = 0.25` —— 一个 `Δw = 0.1`
的**完全正常**的更新在那个 binade 上**整个消失**。

★★ **而 `ULP/2` 那个点是一个「平局」，含不含等号要看格点**（本机实测，`B.2c`）：

| `w` | 位模式 | 尾数 | `Δw = ULP/2` 时翻不翻 |
|---|---|---|---|
| `1.0` | `15360` | **偶** | **不翻**（舍向偶数 ⇒ 回到 `1.0`） |
| `1 + ULP` | `15361` | **奇** | **翻**（舍向偶数 ⇒ 向上） |

舍入到最近是 **round-half-to-even**，所以**恰好落在中点**时由格点的**奇偶**决定。
⇒ 「临界值 = `ULP/2`」这句话在**平局点**上必须补一句：**它是闭区间还是开区间取决于格点**。
（严格的 `ULP/2·(1∓1e-6)` 两侧分别是「不翻 / 翻」。）

### 1.5 边界：`lr` 多大就开始发散

在一个二次型 `f(w) = ½λ‖w‖²` 上，三种写法的**稳定性边界都有闭式**：

| 写法 | 递推的闭式 | 收敛条件 | `μ = 0.9, λ = 1` 时的边界 |
|---|---|---|---|
| SGD | `w_n = (1 − lr·λ)^n·w_0` | `\|1 − lr·λ\| < 1` ⟺ `0 < lr·λ < 2` | `lr < 2` |
| 重球 | 特征方程 `z² − (1+μ−lr·λ)·z + μ = 0` 的根在单位圆内 | `0 < lr·λ < 2(1+μ)` | `lr < 3.8` |

本机实测（`C.1`/`C.2`）：

- SGD：`lr·λ = 2` **恰好**时 `w = 1.000000000000`（**不衰减也不发散**，因为 `1 − 2 = −1`
  是 `−1` 的不动点）；`2 + 1e-9` 时 `w = 1.0000004`（发散）；`1.999` 时 `w = 6.701859e-01`（收敛）。
- 重球：`μ = 0.5` 时边界 `3.0`、`μ = 0.9` 时边界 `3.8`；恰好落在边界上时 `|w|` **线性增长**
  （`μ=0.9` 时 300 步给 `1.900000e+01`），略大则几何发散（`8.993e+04`）。

⇒ ★ **动量把「可用的最大 `lr`」放大了 `(1+μ)` 倍**（`μ = 0.9` 时是 `1.9` 倍）。
这不是「动量更稳」这种话，而是一个**可算的数**。

## 2. 执行映射

### 2.1 状态在显存里是什么

| 量 | 一个参数占几字节 | 跨步存活？ |
|---|---|---|
| 权重 | 4（fp32） | ★ 是 |
| 梯度 | 4（fp32） | 否（每步重算） |
| **动量 buffer `b`** | **4（fp32）** | ★ **是** |
| （对照：Adam 的 `m` + `v`） | 8 | ★ 是 |

**⇒ 动量让「状态 : 参数」从 `0` 变成 `1`（+100%）。**
★ **单卡口径**：这里只数「一个参数多占几字节」。
**分片策略与通信量**的正文在 `100-parallelism/README.md:14`（`zero-fsdp`）—— 本文只留接口。
★ 与 `mixed-precision/01` 的「优化器状态 8 字节/参数」**不是同一个量**：那里的 8 数是
**Adam 的 `m`+`v` 两份**；动量只有一份 ⇒ **4**。

### 2.2 把 buffer 存窄一点：省一半字节，付什么

`B.1` 实测（20 步、4096 个参数、随机梯度）：把 buffer 从 fp32 换成 **fp16**，
**状态字节减半**（4 → 2），代价是 20 步后的轨迹偏离 **`6.300e-03`**（相对 `6.4301e-04`）。
⇒ ★ **「省精度」这一格的账记在「更新量的精度」上** —— 这正是本域的主线
（**每个「省」都在别处记账**）在优化器状态上的形态。

★ **注意这不是一个「值不值得」的结论**：它只是在说「账存在，且量得出来」。
真实的取舍还取决于 `b` 的动态范围、以及它是否与主权重同精度（见 `mixed-precision/01` 的四行表）。

### 2.3 具体组件与数值量级

| 组件 | 它在本文这一格里的角色 | 数值量级（本机实测） |
|---|---|---|
| 动量系数 `μ` | buffer 的指数衰减率 | 本程序用 `0.9`（**设定值**，不是从论文抄的） |
| buffer `b` | 跨步存活的那份状态 | `\|b\|` 的最大值 `6.675`（20 步、`N(0,1)` 梯度） |
| `ULP(1.0)/2` | 「更新被吞」的阈值（**判据在 `mixed-precision/01`**） | `2^-11 = 4.8828125e-04` |
| `lr·\|g\|` | 无动量时的更新量 | `lr = 1e-3`、`\|g\| = 1e-3` ⇒ `1e-6`（**被吞**） |
| 收敛边界 `2(1+μ)/λ` | 「`lr` 能开多大」 | `μ = 0.9, λ = 1` ⇒ `3.8` |

## 3. 实现与演进

| 阶段 | 写法 | 它换来了什么、付了什么账 |
|---|---|---|
| **SGD** | `w ← w − lr·g` | 无状态；代价是**每个方向都用当前那一个批次的噪声** |
| **重球（momentum）** | 多一份 `b`：`b ← μ·b + g`；`w ← w − lr·b` | 噪声被指数平均掉；代价是 **+100% 的状态字节**，以及**多一个超参 `μ`** |
| **Nesterov** | 更新里再加 `μ·b`（PyTorch 的 `nesterov=True`） | 前瞻修正；代价是它**只在 `momentum ≠ 0` 时才有意义**（PyTorch 文档逐字：`Only applicable when momentum is non-zero.`） |
| **（本主题的下两篇）** | **Adam / AdamW**（`02`）：每个参数自己一个步长 · **调度与裁剪**（`03`） | 见 `02` 与 `03` |

★ **`b` 的递推从头到尾没变**：`b ← μ·b + g`。变的是**它被用在哪里** ——
这一格的分工可以用一句话记住：**「记住什么」与「怎么用记住的东西」是两件事**。

## 4. 踩坑与失败模式

**① 把 Adam 的 `(1−β)` 搬进动量的 buffer。**

- **现象**：实现成 `b ← μ·b + (1−μ)·g`，轨迹与闭式**完全对不上**（本机实测差 `6.676`），
  但梯度下降**看起来还是在收敛**，所以不容易被注意到。
- **成因**：两个递推长得很像：

  ```
  动量（[B] PyTorch 的 SGD 伪代码）：b_t ← μ·b_{t−1} + (1−τ)·g_t     ← 那个 (1−τ) 是 dampening，默认 τ = 0
  Adam（[C] 论文 Algorithm 1）      ：m_t ← β₁·m_{t−1} + (1−β₁)·g_t   ← 这个 (1−β₁) 是**偏置校正的一部分**
  ```
  ★ 前者的 `(1−τ)` 是**阻尼**（默认 0）；后者的 `(1−β₁)` 与 `m̂ = m/(1−β₁^t)` **配对**才成立。
- **规避**：把 buffer 的递推写成**闭式的对照**（`A.1`），并配一条**反面对照**（`A.1b`）。

**② ★★ buffer 的时序错误 —— 一个数值上完全测不出来、但语义全错的错误。**

- **现象**：把 `nesterov` 的修正项写成 `g_t + μ·b_{t−1}`（用**更新前**的 buffer）。
  程序照跑、loss 照降，**没有任何数值异常**。
- **成因**：`g + μ·b_{t−1}` 与「重球」的 `b_t = μ·b_{t−1} + g` **逐位相同**
  （本机实测差 `0.000e+00`，容差 0）⇒ 那个 `μ·b` 修正**从来没有生效过**。
- **规避**：**用「两支之差有没有那个 `μ·b` 修正」来判**（`A.3`：两支相差 `0.558441`，
  且有闭式 `−lr·Σ(g_t − (1−μ)·b_t)`），并**把「用更新前的 buffer == 重球」这件事本身写成断言**（`A.3b`）。

**③ 把「同一条链的两种记账」当成两种算法。**

- **现象**：写「Nesterov 有两种写法，它们给出不同的 θ」，然后拿
  「先走一步」与「在偏移点算梯度」去对拍 —— 得到的差是 `1e-16` 量级，
  于是以为「判据失效了」或「1e-3 的阈值太松」。
- **成因**：那两种记账**代数上相等**（§1.3 的推导）⇒ 它们之间**没有**可测的差。
- **规避**：把「**同一条链的两种记账（应逐位相同）**」与
  「**两条链的两种方向（应相差 > 1e-3 且有闭式）**」**分成两条断言**
  （`A.3c` 与 `A.3`），并**明写「哪一种不能拿来做对照」**。

**④ 把 `ULP/2` 当「含等号的闭区间」。**

- **现象**：断言「`Δw == ULP(w)/2` 时更新**能进**」，结果在 `w = 1.0` 上失败。
- **成因**：`Δw = ULP/2` 恰好落在两个格点的**中点**上 ⇒ 舍入到最近的**平局**由
  **round-half-to-even** 决定 ⇒ 翻不翻取决于那个格点的**尾数奇偶**
  （`w = 1.0` 偶 ⇒ **不翻**；`w = 1 + ULP` 奇 ⇒ **翻**）。
- **规避**：判据只用**严格两侧**（`ULP/2·(1∓1e-6)`），把**平局单列**成一条断言（`B.2c`）。

**⑤ 以为「动量只是多算一点」。**

- **现象**：忘了 `b` 是**跨步存活**的状态。
- **成因**：`w` 与 `b` 都要活到下一步 ⇒ 它们**都**在累积误差（这与
  `mixed-precision/01` 的「跨步存活 ⇒ 必须宽」是同一条判据）；而且 `b` 还要进
  **检查点**（`90-training/checkpointing/01-state-and-bytes` 的正文）。
- **规避**：把 `b` 与 `m`/`v` 一视同仁地记在**状态账**里（§2.1），而不是记在「中间量」里。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 要判断一个「动量」实现对不对 | 拿它的 buffer 与**闭式** `Σ_k μ^(t−k)·g_k` 对拍（本机最大逐元素差 `1.776e-15`）；★ 并**先打印参照量级**（本机 `min\|b_t\| = 2.397e-03`）确认那不是次正规噪声 |
| buffer 的递推里出现了 `(1−μ)` | **错** —— 那是 Adam 的形式被误搬（本机两条轨迹差 `6.676`）；动量的 `(1−τ)` 是 **dampening**（默认 0） |
| 要判断「Nesterov 有没有真的生效」 | 看更新里有没有那一项 `μ·b_t`（**更新后**的 buffer）：用 `g_t + μ·b_{t−1}` 会与**重球逐位相同**（差 `0.000e+00`）⇒ 静默退化 |
| 「先走一步」与「在偏移点算梯度」 | **同一个算法的两种记账**（差 `1.110e-16`）⇒ **不能拿来做对照**；真正的两种算法是「前瞻点求梯度」与「当前点求梯度」（差 `0.255781`） |
| 要判断「两种 Nesterov 写法是否混用」 | 两支之差必须**等于**闭式 `−lr·Σ_t(g_t − (1−μ)·b_t)`（本机相对差 `2.386e-15`），而不只是「不相等」 |
| `\|w\|` 在 fp16 的格点上、`Δw < ULP(w)/2` | 更新被**静默吞掉**；★ 平局点（`Δw == ULP/2`）由 **round-half-to-even** 决定 ⇒ `w = 1.0` 不翻、`w = 1 + ULP` 翻 |
| 想让动量状态省一半字节 | 换 fp16 buffer ⇒ 状态 4 → 2 字节/参数，代价是 20 步后轨迹偏离 `6.300269e-03`（本机） |
| `lr` 开到多大开始发散 | 二次型 `½λ‖w‖²` 上：SGD 的边界是 `lr·λ = 2`（恰好 2 时不衰减也不发散）；**动量把它放大到 `2(1+μ)`**（`μ = 0.9` ⇒ `3.8`） |
| 想让 `b` 与 Adam 的状态对齐口径 | **不能**：动量的状态是 **1 份**（4 字节/参数），Adam 是 **2 份**（8 字节/参数）—— 两个数**不是同一个量** |

> ★ 阈值与口径（`code/01_sgd_momentum.py` 的 `D.3`/`D.4` 逐位钉住）：
> `TOL_CLOSED = 1e-12`（与闭式的逐元素最大差）、`TOL_SAME_ALGO = 1e-12`（两种记账之间）、
> `TOL_DIVERGE = 1e-3`（反面的**可测性下界**）、`TOL_BUFFER_FP16 = 1e-3`（fp16 buffer 的代价）、
> `TOL_BITWISE = 0.0`（「用更新前的 buffer == 重球」是**逐位**的）、
> **`MIN_REGION = 1e-3`**（★ **P22 的门槛**：参与「机器精度档相等」判据的量必须 ≥ 它）。
> ★ 放宽 `MIN_REGION` ⇒ `A.1` 的「相等」有可能测的是次正规噪声；
> 放宽 `TOL_DIVERGE` ⇒ 三条反面对照一起退化成恒真。
