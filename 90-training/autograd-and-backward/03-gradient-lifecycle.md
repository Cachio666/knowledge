# 训练循环里的梯度：累积、清零、裁剪与二阶

> **一个梯度从算出来到被用掉，中间还要过四道手：累积（凑 batch）、清零（不重复计数）、
> 裁剪（限幅）、二阶（再求一次导）。**
> ★ 这四件事里最容易错的两件是**顺序**：裁剪必须作用在**一步的**梯度上，
> 而累积省下的那点写字节要用「**必须**在 step 后清零」来还。

## 0. 背景与动机

### 一个具体的对照场景

显存放不下想要的大 batch，于是把一个大 batch 切成 `k` 个 micro-batch 分 `k` 次算，
梯度按 `1/k` 加权累加 —— 这就是**梯度累积**。它换来的是：

| 做法 | 峰值激活（按样本行数） | 总工作量（行数） | 每步的清零写字节 |
|---|---|---|---|
| 一个大 batch（12 行） | **12** | 12 | `4P` B |
| 累积 4 片（每片 3 行） | **3** | 12（不变） | `4P` B（**但每 4 步才一次**） |

（本机实测 + 推导值，`code/03_grad_lifecycle.py` 的 `B.1` / `B.2`；`P = 15` 是玩具模型的参数量。）

⇒ **累积不省 FLOPs**（总行数一样），它省的是**峰值激活**；
顺带把清零的写字节摊成 `1/4`。这笔「省」的代价是两条纪律：
**必须在 step 之后清零**、**有按片统计的归一化层时不成立**。

⚠ **本文的范围**：`.grad` 的语义（`.grad` 为什么会累积、`set_to_none` 的行为）、
`grad_fn`、`is_leaf`、`retain_graph`、`backward()` vs `autograd.grad()` ——
**正文在 `70-frameworks/pytorch/02-autograd.md`（全篇 256 行），此处回链**。
★ 尤其它 `:139` 那句「用 `autograd.grad` 做梯度裁剪/二阶导时，别指望 `.grad` 里有东西」
是**框架侧**的事实；本文写的是**算法侧**（累积 / 裁剪 / 二阶各自怎么算），两者不重叠。
★ `clip` 这个词在本库另有**量化**含义（`00-meta/glossary.md:99` 的「最优 clipping / ACIQ」、
`:105` 的「PACT 学 clip 上界 α」）—— 本文的 `clip` 一律指**梯度裁剪**。

## 1. 原理

### 1.1 梯度累积为什么必须按 `1/k` 加权

设 loss 是**整批的平均**：`L = (1/N)Σ_{i=1}^{N} ℓ_i`。切成 `k` 片、每片 `B = N/k` 行：

```
L    = (1/N) Σ_i ℓ_i = (1/k) Σ_{片 j} [ (1/B) Σ_{i∈片 j} ℓ_i ] = (1/k) Σ_j L_j
∇L   = (1/k) Σ_j ∇L_j                        ← ★ 每一片的梯度要按 1/k 加权
```

**关键**：每一片算出来的是**它自己那一片的平均** `L_j`，所以加权系数是 `1/k`。
⇒ 累积出来的梯度与「一次性喂 12 行」**在代数上完全相同**。

**本机实测**（`code/03_grad_lifecycle.py` 的 `A.1`）：`dW` 的相对差 `2.079e-16`、
`db` 的 `2.929e-17` —— **机器精度档**（阈值 `1e-12`）。

⚠ **前提是「没有按片统计的归一化层」**。BatchNorm 这类层用的是**当前这一片**的均值/方差，
于是每片算出的 `L_j` 与「大 batch 下的那一片」不是同一个函数 ——
累积出的梯度与大 batch 的梯度**根本不是同一条轨迹**（本程序 `C.1` 实测相对差 `4.173e-01`）。
⇒ 有 BN 时必须改用**同步 BN**（跨片统计）或放弃累积。

### 1.2 梯度裁剪的闭式：`max_norm · T/(T + ε)`

按**全局范数**裁剪（不是逐元素截断）：

```
T = √(Σ_l ‖g_l‖²)                  ← 全部参数梯度**当成一个向量**的范数
coef = max_norm / (T + ε)          ← ★ ε 是保护项（分母为 0 时不出 inf）
若 coef < 1：  g ← g · coef
```

于是裁剪后的范数 = `T · coef = max_norm · T/(T + ε)`，与 `max_norm` 的相对差：

```
相对误差 = |max_norm·T/(T+ε) / max_norm − 1| = ε/(T + ε) ≈ ε/T
```

**本机实测**（`A.2`/`A.2b`，`max_norm ∈ {1.0, 0.5, 0.1}`）：

| `T` | 实测相对误差 | 判据阈值 `1.1e-6/T` | 与闭式 `ε/(T+ε)` 的**最大**相对偏差（三个 `max_norm` 上） |
|---|---|---|---|
| 2 | 5.000e-07 | 5.500e-07 | 1.3e-10 |
| 4 | 2.500e-07 | 2.750e-07 | 3.3e-10 |
| 8 | 1.250e-07 | 1.375e-07 | 9.8e-10 |

⇒ **裁剪后范数「几乎」等于 `max_norm`，而那个「几乎」有闭式**：它**恰好**是 `ε/(T+ε)`。
★ **`T ≥ 1` 是判据的一部分**：`T < 1` 时 `ε/T` 变大，而 `T < max_norm` 时
`coef > 1` ⇒ **压根不会裁剪**（§4 第 3 条）。

★ **`ε = 1e-6` 的来源必须标级**：它是 **PyTorch v2.9.0 的源码**里的
`clip_coef = max_norm / (total_norm + 1e-6)` —— **[B] 级（某实现的规格），不是规范**。
本域的 `specs.py` 把它记成 `TORCH_CLIP_COEF_DENOM_EPS`，并**写明版本**。
（本域的头号错误模式就是把「某实现的文档」当成「规范的文档」，见域 README。）

### 1.3 二阶：Hessian-向量积要**两次**反向

一阶只要一次反向扫；**二阶**（`H·v`）的常规做法是 **Pearlmutter 的两次反向模式**：

```
第 1 次反向：给出 g = ∇L(w)
第 2 次反向：对 ⟨g, v⟩ 再求一次梯度 ⇒ 得到 H·v
```

对本文的模型（`L = mean‖XW + b − Y‖²`，`R` 对参数**线性**），两次反向的局部规则可以直接写出来：

```
第 1 次反向：  dR = 2R/n
第 2 次反向：  把 dR 换成 dR ⊙ (X V + 1uᵀ) 的收缩
⇒ H·(V,u) = ( 2/n·Xᵀ(XV + 1uᵀ),  2/n·(XV + 1uᵀ)ᵀ1 )
```

**本机实测**（`A.3`/`A.4`）：两次反向与**解析 Hessian** 的相对差 `1.363e-16`（机器精度档）、
与**对梯度**做中心差分（`h = 1e-5`）的相对差 `1.110e-11`。

★ **一个必须写出来的作用域**（`C.5`）：在这个「线性 + 平方损失」的设定下，
**Hessian 与参数无关**（本机把参数挪到 `W+3, b−2` 后解析 HVP 的相对变化 `0.000e+00`）。
⇒ 「HVP 与解析一致」这条判据测的是**实现正确性**，**测不到**「Hessian 随参数变化」这件能力。
凡宣称「本程序验证了二阶导的实现」，都要带着这个作用域。

## 2. 执行映射

这四件事在一台真实机器上各落在哪里：

| 事 | 落在哪 | 口径 |
|---|---|---|
| **累积** | 每片的 `∇L_j` 各算一次，按 `1/k` 加权求和 | **不省 FLOPs**（总行数不变），省的是**峰值激活**（`12 → 3` 行，本机 `B.1`） |
| **清零** | 每步结束后把梯度缓冲写 0（或置 `None`） | **字节账**：`4P` B/步；累积 `k` 步后清一次 ⇒ 摊成 `4P/k`（本机 `P=15`：`60 B/步 → 15 B/步`，`B.2`） |
| **裁剪** | 算全局范数（读一遍）→ 缩放（读+写一遍） | **字节账**：`4P + 8P = 12P` B（**每步**，与累积无关；本机 `180 B`，`B.3`） |
| **二阶** | 多一次反向扫 | 本机 `P=15` 的玩具规模，只作**实现正确性**的对照（§1.3 的作用域） |

★★ **一处必须写明的口径差别**：`clip_grad_norm_` 的**返回值是裁剪前**的范数。
逐字（**[B] 级**：PyTorch 文档，`torch.nn.utils.clip_grad_norm_` 的 `Returns` 段，抓取 2026-09-23）：

> Total norm of the parameter gradients (viewed as a single vector).

本机实测（`B.4`）：`T = 2/4/8` 时返回值就是 `2/4/8`（相对差 `< 1e-15`，逐位级），
而裁剪后的范数是 `0.9999995 / 0.99999975 / 0.999999875`。
⇒ **把返回值当裁剪后的范数**，会让「每步记录梯度范数」这件事记成一个**恒定值**（≈ `max_norm`），
曲线看起来永远平 —— 这是监控里最容易被误读的一种。

★ **框架侧的 API 语义**（`zero_grad(set_to_none=True)` 与 `False` 的行为差、
`autograd.grad` 与 `.grad` 的分工）**正文在** `70-frameworks/pytorch/02-autograd.md`，此处回链；
本文只做**算法与字节账**。

## 3. 实现与演进

| 阶段 | 做法 | 它换来了什么、付了什么账 |
|---|---|---|
| 直给 | 一个大 batch 一步算完 | 最简单；峰值激活随 batch 线性涨 |
| **累积** | `k` 片各算一次、按 `1/k` 加权 | 峰值激活降到 `1/k`；代价是**必须**按 `1/k` 加权 + 在 step 后清零（否则梯度恰好变成 `k` 倍，本机 `C.2`） |
| **裁剪** | 按**一步的**全局范数缩放 | 限幅；代价是每步 `12P` B 的额外读写、以及「**顺序**不能反」（§4 第 4 条） |
| **二阶** | 再反向一次 | 拿 `H·v`；代价是又一次反向扫，且**作用域**只到 `H` 与参数无关的那种模型（§1.3） |
| 分布式 | 优化器状态分片、跨卡规约 | ★ **不在本文**：正文在 `100-parallelism`（`README.md:14` 的 `zero-fsdp` 那一栏）；本域只写**单卡算法**，分布式只留接口 |

## 4. 踩坑与失败模式

**① 忘了清零。**

- **现象**：loss 看着在降，但步长/有效 batch 全都不对；换个 `k` 结果又变。
- **成因**：梯度缓冲在**累积**，于是第 `t` 步用的是前 `t` 步梯度的和。本机实测（`C.2`）：
  忘了清零时梯度**恰好**是大 batch 的 `k` 倍（最大偏离 `1.332e-15`）。
- **规避**：`zero_grad` 必须在**每步之后**（或每步之前）做；本程序把「`k` 倍」这条
  **逐位**断言下来（`C.2`），使它成为一个可判定的错，而不是「感觉不对」。

**② 有 BatchNorm 时用累积。**

- **现象**：累积出的梯度与大 batch 的梯度对不上，但每一步看起来都正常。
- **成因**：归一化层用的是**当前这一片**的统计量，每片的函数不一样（§1.1）。
  本机实测相对差 `4.173e-01`（`C.1`）。
- **规避**：要么用**同步 BN**，要么放弃累积。★ 这条**就是**判据 ⑥ 必须写
  「**无归一化层**」这个前提的原因。

**③ `T < max_norm` 时以为「裁剪后范数 == `max_norm`」。**

- **现象**：判据「裁剪后范数 == `max_norm`」在范数**没超限**时失败。
- **成因**：`coef = max_norm/(T+ε) > 1` ⇒ 代码**不缩放** ⇒ 裁剪后范数仍然是 `T`。
  本机实测（`C.3`）：`T = 0.5`、`max_norm = 2.0` ⇒ 裁剪后范数 `0.5`（**没动**），
  与 `max_norm` 的相对偏差 `0.750`。
- **规避**：判据必须写死**取值范围**：`T > max_norm`（本文的 `MAX_NORM_LIST` 全部 `< min(T)`）
  且 **`T ≥ 1`**（否则 `ε/T` 那个「≈ 精确」的说法不成立）。★ 这是计划 §3 表 A ⑦
  专门写死的那份条件，**不在别处重定义**。

**④ 裁剪与累积的**顺序**反了。**

- **现象**：先对每一片的梯度裁剪、再把它们加起来。
- **成因**：每片各按**自己的范数**缩放，与「对一步的梯度裁剪一次」不是同一个算子。
  本机实测（`C.4`）两种顺序的相对差 `3.513e-01`。
- **规避**：裁剪**只在累积完之后做一次**；这条要写进实现规范，不能靠「看起来对」。

**⑤ 判据只写「相对误差 ≤ 某阈值」—— 它是单侧的。**

- **现象**：把保护项 `+ ε` 删掉（实现**更「精确」**了），判据**照样通过**。
- **成因**：`ε/(T+ε) ≤ 1.1e-6/T` 是一个**上界**，而「误差 = 0」也满足上界。
  ★ 本程序实施时实测过这件事：去掉 `+1e-6` 后**原来 25 条断言全绿**。
- **规避**：补一条**两侧**判据 —— 实测的相对误差必须**等于**闭式 `ε/(T+ε)`
  （本程序 `A.2b`；加上它之后，同一个翻转给出 `1.000e+00` 的相对偏差，当场失败）。
  ★ 这是「量级判据的证伪能力弱 ⇒ 能配闭式参照的地方就要配上」的一个现场。

**⑥ 把「数值的 HVP」当独立参照却不写步长。**

- **现象**：`H·v` 与「梯度差分」对不上，遂怀疑解析式。
- **成因**：数值 HVP 是**对梯度**做差分（不是对 `L` 做二阶差分），
  它的步长同样受 §`01-backward-from-scratch` 的双向失效区支配。
- **规避**：写明 `h`（本程序 `HVP_H = 1e-5`），并与**解析**参照（本机 `1.363e-16`）一起报
  —— 两个参照都过才算数。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 梯度累积 `k` 步 vs 一个大 batch（**无归一化层**） | 逐元素相对差在**机器精度档**（本机 `2.079e-16` < `1e-12`）；★ **前提必须写出来** |
| 有 per-micro-batch 归一化层 | 累积 **≠** 大 batch（本机相对差 `4.173e-01`）⇒ **必须**改用同步 BN 或放弃累积 |
| 累积的加权系数 | **`1/k`**（每片算的是它自己的平均）；写成 `1` ⇒ 梯度恰好是 `k` 倍（本机 `4.000000`） |
| 累积换来了什么 | **峰值激活**降到 `1/k`（本机 `12 → 3` 行）；**FLOPs 不变**（总行数 `12 == 12`） |
| 清零的字节账 | `4P` B/步；累积 `k` 步清一次 ⇒ 摊成 `4P/k`（本机 `60 B/步 → 15 B/步`）⇒ 代价是**必须清零** |
| 裁剪后的全局范数 | `= max_norm·T/(T+ε)`，相对误差 **`≈ ε/T`**（本机 `T=2/4/8` → `5.0e-7 / 2.5e-7 / 1.25e-7`）；判据写死 **`T ≥ 1`** 且 `T > max_norm` |
| 要断言「裁剪后 == `max_norm`」 | 只能断言**上界**，且**必须**再配一条**两侧**判据（实测相对误差 == 闭式 `ε/(T+ε)`，否则删掉保护项也能通过） |
| `T < max_norm`（范数没超限） | **不发生裁剪**：裁剪后范数仍 `== T`（本机 `T=0.5, max_norm=2.0` → `0.5`，偏差 `0.750`） |
| 裁剪与累积的顺序 | **不可交换**：对每片分别裁剪 vs 累积后裁剪一次，相对差 `3.513e-01` ⇒ 裁剪只作用于**一步的**梯度 |
| 裁剪的字节账 | 算范数读一遍 + 缩放读+写一遍 = **`12P` B／步**（本机 `P=15` → `180 B`），与累积无关 |
| `clip_grad_norm_` 的返回值 | 是**裁剪前**的范数（逐字 `Total norm of the parameter gradients (viewed as a single vector)`，**[B] 级 PyTorch 文档**）；**不是**裁剪后的（后者 ≈ `max_norm`） |
| 二阶（Hessian-向量积） | 两次反向模式 == 解析 Hessian（本机 `1.363e-16`）== **对梯度**的中心差分（`h=1e-5`，本机 `1.110e-11`）；★ 作用域：在**线性 + 平方损失**下 `H` 与参数**无关**，该判据只测**实现正确性** |
| 引用 `clip_grad_norm_` 的 `1e-6` | 必须标 **B 级**（**PyTorch v2.9.0 的源码**，不是规范），并写出**版本** |
| `.grad` 为什么会累积、`set_to_none` 的行为 | 属**框架 API 语义**，正文在 `70-frameworks/pytorch/02-autograd.md`（此处回链） |

> ★ 阈值（`code/03_grad_lifecycle.py` 的 `D.4` 逐位钉住）：`TOL_ACCUM_REL = 1e-12`
> 与 `TOL_HVP_ANA = 1e-14` 是**机器精度档**（放宽它们，`A.1`/`A.4` 就退化成恒真）、
> `TOL_CLIP_REL = 1.1e-6`（判据 ⑦ 的上界）、`TOL_CLIP_CLOSED_FORM = 1e-6`（`A.2b` 的两侧判据；
> 本底噪声来自 `1 − new/max_norm` 的**灾难性抵消**，约 `1e-16·T/1e-6`）、
> `TOL_BN_DIFF = 1e-3`（负例下界）、`TOL_HVP_NUM = 1e-6`、`TOL_RETURNED = 1e-15`。
> ★ 矩阵的取值范围也钉住：`CLIP_T_LIST = (2,4,8)` 全部 `≥ 1`、
> `MAX_NORM_LIST = (1.0,0.5,0.1)` 全部 `< min(CLIP_T_LIST)`（保证**真的**触发裁剪，不是空跑）。

## 6. 小结与延伸

**一句话**：训练循环里梯度的四件事各有各的账 —— 累积**省激活不省算力**、清零**省写字节但要还一笔纪律**、
裁剪**每步都要付 `12P` B 且顺序不可反**、二阶**要再反向一次且作用域有限**。
