# 重算换显存：O(√n) 的内存、≈2n 的前向、O(log n) 的极端情形

> **反向模式要留着中间激活才能算梯度；把其中大部分扔掉、反向时**重算**出来，
> 就能把 `n` 层的激活账压到 `O(√n)` —— 代价是前向次数从 `n` 涨到约 `2n`。**
> ★ 这两个数是**两个不同的口径**（一个是**内存**、一个是**前向次数**），混用会得出「前向 `2√n` 次」这种错话。

## 0. 背景与动机

### 一个具体的对照场景

一个 `n` 层的网络，反向模式必须保住每一层的中间激活（否则算不出局部导数）。
朴素做法下，**峰值激活数随 `n` 线性增长**、前向只跑一遍：

| 做法 | 峰值激活（`n=1024`） | 前向次数 |
|---|---|---|
| 全存（朴素） | **1024** | **1024**（1.00n） |
| **√n 分段重算** | **63** | **2016**（1.97n） |
| **递归套娃（k=1）** | **10** | **11264**（11.0n） |

（本机实测值，`code/02_checkpointing.py` 的 `B.1`/`B.2`/`C.1`。这是**计数模型**，
不是任何真实网络的显存测量。）

⇒ 论文的原始对照是**绝对内存**：Chen 2016 逐字写着
`Our experiments show that we can reduce the memory cost of a 1,000-layer deep residual network from 48G to 7G on ImageNet problems.`

⚠ **本文的范围**：反向图的**结构**（`grad_fn` / `saved_tensors` 挂在哪）正文在
`70-frameworks/pytorch/02-autograd.md`（全篇 256 行），此处**回链**；
本文只写**「重算」这件事的账**。★★ **本文的术语边界**（域 README 的硬要求）：
文件名里的 `checkpointing` 是 **Chen 2016 论文里的术语**（`gradient checkpointing`），
它指**重算换显存**，**不是权重检查点**。中文一律写「**重算换显存**」；
英文 `checkpoint` 在本库只留给**权重检查点**（正文在 `90-training/checkpointing/01-state-and-bytes`）。
★ 这一点不能省：全库讲「重算」时用的是 **`重算` / `recompute`**
（`40-kernels/attention/03-flash-attention-backward.md` 里 `重算` **36** 次、`recompute` **5** 次、
`checkpoint` **0** 次），而 `checkpoint` 的 10 处用例**全部**是权重检查点。

## 1. 原理

### 1.1 分段方案：`⌈√n⌉` 的存储、`2n − ⌈√n⌉` 的前向

把 `n` 层切成 `k` 段（每段至多 `⌈n/k⌉` 层），**只存每段的输入**，反向时**段内从头重算**
（段的输出 = 下一段的输入，本来就在手 ⇒ 每段只需重算 `段长 − 1` 个内部激活）：

```
存下来的激活数   = k                              ⇒ 取 k = ⌈√n⌉ 时为 O(√n)
前向次数         = n（原来那一遍） + Σ(段长 − 1)  = 2n − k
峰值存活激活数   = k（各段输入） + (段长 − 1)     ≈ 2√n
```

**本机实测**（`code/02_checkpointing.py`，`n ∈ {64, 128, 1024, 4096}`）：

| `n` | `k=⌈√n⌉` | 存下的 | 峰值激活 | 前向次数 | 前向/n |
|---|---|---|---|---|---|
| 64 | 8 | 8 | 15 | 120 | 1.8750 |
| 128 | 12 | 12 | 22 | 244 | 1.9063 |
| **1024** | **32** | **32** | **63** | **2016** | **1.9688** |
| **4096** | **64** | **64** | **127** | **8128** | **1.9844** |

★ 闭式：`前向次数 == 2n − k`（逐位，`B.2`）；`存下的 == ⌈√n⌉`（精确，`B.1`）。
★ 与论文的锚点对齐：峰值激活数 `/√n` 实测 `1.875 ~ 1.985`，与式 (1) 那一段给的
`O(2√n)` **同形状**（`B.4`）。

### 1.2 递归套娃：原文 §4.4 的递推，和它自己的一处不一致

原文 §4.4 给了比「一次分段」更强的东西 —— **把同一个策略递归地用下去**。逐字：

> Let `g(n)` to be the memory cost to do forward and backward pass on a `n` layer neural network.
> Assume that we store `k` intermediate results in the graph and apply the same strategy recursively
> when doing forward and backward pass on the sub-path. We have the following recursion formula.
> `g(n) = k + g(n/(k+1))` … (2)
> Solving this recursion formula gives us `g(n) = k log_{k+1}(n)` … (3)
> As a special case, if we set `k = 1`, we get `g(n) = log_2 n`.

- **内存**的递推是 (2)：切 `k+1` 段、存 `k` 个边界、递归进一个子段 ⇒ `g(n) = k·log_{k+1}(n)`；
  `k=1` ⇒ **`log₂ n`**。
- **前向次数**的递推是它的孪生：`H(n) = n + (k+1)·H(⌈n/(k+1)⌉)` ⇒ `H(n) = n(1 + log₂ n)`（`k=1`）。

**本机实测**（`code/02_checkpointing.py` 的 `C.1`，`k = 1`）：

| `n` | 峰值激活 | `log₂ n` | 前向次数 | `n(1+log₂n)` | 额外前向 `= n·log₂n` |
|---|---|---|---|---|---|
| 64 | 6 | 6 | 448 | 448 | 384 |
| 128 | 7 | 7 | 1024 | 1024 | 896 |
| 1024 | 10 | 10 | 11264 | 11264 | 10240 |
| 4096 | 12 | 12 | 53248 | 53248 | 49152 |

两列**逐位相等** —— **(2)/(3) 与本程序真的递归实现一致**。

★★ **但原文内部对「代价」有两句互相不一致的话**（本文**如实记录，不做判定**）：

| 位置 | 逐字 | 它说的是 |
|---|---|---|
| **摘要** | `In the extreme case, our analysis also shows that the memory consumption can be reduced to O(log n) with as little as O(n log n) extra cost for forward computation.` | 额外前向 = **`O(n log n)`** |
| **§4.4** | `This will require O(log_2 n) cost forward pass cost, so may not be used commonly.` | 前向代价 = **`O(log₂ n)`** |

两者**不是同一个量级**。★ 本程序的递推（`H(n) = n + (k+1)·H(⌈n/(k+1)⌉)`）**真的跑出**
`H(n) = n(1 + log₂ n)` ⇒ **与摘要那一句一致**。⇒ 本文的判据 ⑤ 取**摘要**那一句；
§4.4 那一句只作为**原文的另一种说法**记录在此 ——
**本文不对原文下「谁错」的判断**（那是**转述者**该守的纪律）。

★ 两处引文的**取法**（本库的计数纪律）：`O(log n)` 这个字符串在 HTML 原文里计 **0** 次
（被 `<math>` 切开），可数的连续片段只有 `with as little as` 与 `extra cost for forward computation`
（各 1 次）。⇒ **引跨公式的句子必须先在剥标签 + 折叠空白后计数**，
否则「计数 = 0」会把**存在**的句子读成**不存在**。

### 1.3 ★★ 两个口径必须分开写

这是本文最容易出错的一处，也是计划 §4 的 **T22** 专门点名的一处：

| 量 | 它是什么 | 它的值 | 它的外部依据 |
|---|---|---|---|
| **内存** | 同时存活的**激活张量个数** | `O(√n)`；式 (1) 说 `O(2√n)` | 该节标题即 `An O(√n) Memory Cost Algorithm` |
| **前向次数** | 跑了多少遍 `f(·)` | `≈ 2n`（实测 `1.97n` / `1.98n`） | 摘要的 `an extra forward pass` |

⇒ **`O(2√n)` 那个系数是内存的，不是前向次数的**。把 `O(2√n)` 读成「前向 `2√n` 次」
是**两个口径混用**（本程序的 `B.6` 用形状分类器把两者分开判定：内存 `O(√n)`、前向 `O(n)`）。

### 1.4 顺带一个可手算的换算：`30%` 从哪来

原文说这套策略 `costs 30% additional runtime`，而**前向次数**涨的是**约 100%**。
两个数不矛盾 —— 它们是两个口径，而且可以互相换算：

原文另一句逐字：`the backward operation is nearly twice as time consuming as the forward one`。
记一次前向耗时 `f` ⇒ 反向 `2f` ⇒ 朴素方案总耗时 `f + 2f = 3f`；
重算方案前向工作量翻倍 ⇒ `2f + 2f = 4f`。于是

```
wall-clock 涨幅 = 4f/3f − 1 = 1/3 ≈ 33.3%
```

**本机推导值 0.3333**，与原文的 `30%` 差 `0.0333`（`B.7`）。
★ 这就是「前向次数涨 100%、而墙上时钟只涨 30%」的全部原因 ——
**报这两个数时必须写明口径**。

## 2. 执行映射

「重算」在真实系统里发生在**反向的哪一步**、以及它的账落在哪里：

| 观察 | 后果 |
|---|---|
| 重算发生在**反向扫到那一段时**，而不是前向 | 前向阶段照跑 `n` 层，只是**存**得少了；额外的时间全在反向里 |
| 段内重算要**重新分配**出 `段长 − 1` 个激活 | 峰值激活数 = `k`（各段输入）+ `段长 − 1` ≈ `2√n`（本机 `n=1024` → **63**） |
| 段的**输出**就是下一段的**输入** | 它已经作为边界存着了 ⇒ 段内只需重算 `段长 − 1` 个，**不是** `段长` 个（差一个数，见 §4 第 2 条） |
| 代价与 `n` 的关系不是单调的 | `k` 取太小（没省下多少）、取太大（退回全存）都不行 —— `k = ⌈√n⌉` 是**最优点**（`C.3`：`k = n` 时峰值激活 `4096 ≥ n`，反而比 `√n` 的 `127` 差） |

★ **一处必须与论文区分的归因**：Chen 2016 那篇里还有**另一项**技术 ——
基于计算图的**内存共享 / in-place 优化**（§3）。原文逐字说那项技术
`indeed help to reduce the memory cost by a factor of two to three`。
**它和「重算换显存」是两件事**，两笔账不能合成一个数（见 §4 第 5 条）。

★ **框架侧的 API 语义不在本文**（`torch.utils.checkpoint` 的接口、`use_reentrant` 之类）：
它属「框架 API 行为」，正文在 `70-frameworks/pytorch/02-autograd.md`（此处回链）。

## 3. 实现与演进

| 阶段 | 做法 | 它换来了什么、付了什么账 |
|---|---|---|
| 全存 | 每层激活都留着 | 前向只跑一遍；峰值激活 `= n` |
| **√n 分段** | 存 `⌈√n⌉` 个边界、段内重算 | 内存 `n → 2√n`；前向 `n → 2n − ⌈√n⌉`（本机 `1024 → 2016`） |
| **递归套娃** | 对子段**再**套一次同一策略（§4.4） | 内存 → `log₂ n`（本机 `1024 → 10`）；前向 → `n(1+log₂n)`（本机 `1024 → 11264`，**11.0×**） |
| **自动规划** | 由计算图分析**自动**选段/选 `k` | ★ **这才是那篇论文的贡献**（见下） |

★★ **一句必须纠正的转述**：「**Chen 2016 提出了 gradient checkpointing**」是**错的**。
原文**自承这个词来自别处**，逐字（原始字节计 2 次，其中一次在正文、一次在致谢）：

> Although not widely known, the idea of dropping intermediate results is also known as
> **gradient checkpointing** technique in automatic differentiation literature [9].

致谢里还有一句更直接的：`We would like to thank David Warde-Farley for pointing out the relation to gradient checkpointing.`
⇒ 该论文的贡献是**通用方法 + 自动规划**（原文逐字：`we propose a general methodology that
works for general deep neural networks`、`we propose an automatic planning algorithm`），
**不是**提出这个概念。引用时必须带上这句**归属声明**。

## 4. 踩坑与失败模式

**① 把 `O(2√n)` 当成「前向次数」。**

- **现象**：正文写「前向次数约 `2√n`」，于是 `n=1024` 时预期 64 次，一跑是 2016 次。
- **成因**：`O(2√n)` 是**内存**（该节标题 `An O(√n) Memory Cost Algorithm`、式 (1) 的主语是 `cost-total`
  即内存）；「前向次数 ≈ `2n`」的出处是**摘要**的 `an extra forward pass`。
- **规避**：**两个口径分开写**（本文 §1.3）；本程序的判据 `B.6` 用形状分类器分别判定
  （内存 `O(√n)`、前向 `O(n)`）。

**② 「段内重算 `段长` 个」还是「`段长 − 1` 个」。**

- **现象**：同一个方案，前向次数算出 `2016` 或 `2048`，两个数都「差不多」。
- **成因**：**段的输出就是下一段的输入**（已经作为边界存着了）、最后一段的输出是网络输出
  ⇒ 段内只需重算 `段长 − 1` 个内部激活。按 `段长` 个算会多算 `k` 次。
- **规避**：把**闭式**写进判据（`前向次数 == 2n − k`，本程序 `B.2`）。
  ★ 实测：把 `li−1` 改成 `li`，**区间判据 `[1.8n, 2.1n]` 照样通过**（`2.0000` 也在区间里），
  只有**逐位闭式**抓住了它。

**③ 重算的**起点**取错一格。**

- **现象**：把第 `i` 段的重算起点写成上一段的输入（`bounds[i−1]` 而不是 `bounds[i]`）。
- **成因**：一段的重算**必须从它自己的输入开始**。差一段就是差一整套中间值。
- **规避**：判据要在**数值**上对拍（本程序 `C.4`：起点错一格 ⇒ 与解析参照的相对差 `1.921e+00`）。
  ★ 这个坑是本文实施时**真的踩到**的（第一版就写成 `bounds[i−1]`，`A.1` 当场差 1.4~1.9）。

**④ 报「省了多少倍」不写分母。**

- **现象**：同一个方案，一处写「省 64 倍」、一处写「省 32 倍」。
- **成因**：**两个都合法**，分母不同（本机 `C.5`，取 `n = 4096`）：
  分母取**存下来的个数** → `4096/64 = 64.00×`；分母取**峰值激活数** → `4096/127 = 32.25×`。
  ★ 论文摘要那句是按**存储数**（`存 ⌈√n⌉`）说的。
- **规避**：**报这个数必须写分母**。

**⑤ 把论文的**绝对内存**与本模型的**计数**混起来。**

- **现象**：用本模型算出的「省 `15.6×`」去解释论文的 `48G → 7G`（`6.86×`）。
- **成因**：两个量**不可比**：本模型的单位是「激活张量**个数**」，论文的是 **GB**
  （还含参数、梯度、临时缓冲，以及 §3 那项**另一项**技术）。
  实测两者差 **131%**（`B.5`）。
- **规避**：只断言**形状**（`stored == ⌈√n⌉`、峰值 `/√n → 2`），
  **不断言绝对值**；绝对值只作**量级对照**并写明「不是同一个量」。

**⑥ 把「重算」写成「检查点」而不消歧。**

- **现象**：正文里「检查点」一会儿指重算、一会儿指权重存档。
- **成因**：**全库既有的 10 处 `checkpoint` 全是权重检查点**，而讲重算的地方用的是
  `重算` / `recompute`。本域是**唯一**把「检查点」用在重算上的地方，且只在**文件名**里
  （因为 `gradient checkpointing` 是论文术语，改了就对不上原文）。
- **规避**：正文第一次出现时**写明这一点**（本文 §0 已写）；
  中文一律「**重算换显存**」。

**⑦ 以为「重算只影响内存、不影响数值」。**

- **现象**：不做数值对拍，只看显存降了。
- **成因**：重算**重新跑了一遍前向**，任何「重算与原始前向不等价」的错
  （起点错一格、少重算一层、段边界交错）都会**静默**改变梯度。
- **规避**：判据必须包含「**四条路径给出同一条梯度**」（本程序 `A.1`/`A.2`：
  被测 / 全存 / 解析闭式 / 递归，相对差 `0.000e+00`），
  并且 `C.4` 给出一个**真的会失败**的负例。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 要报「内存省了多少」 | 用**峰值存活激活数**做分母：`k` 段的输入 + 一个段的内部激活 ≈ `2√n`（本机 `n=1024` → `63`，`/√n = 1.97`） |
| 要报「代价涨了多少」 | 用**前向次数**做分母：`2n − ⌈√n⌉`（本机 `n=1024` → `2016` = `1.97n`；`n=4096` → `8128` = `1.98n`） |
| 看到 `O(2√n)` | 那是**内存**的系数（式 (1) 的主语是 `cost-total`）；**不是**前向次数 —— 前向次数的外部依据是摘要的 `an extra forward pass` |
| 要断言「前向次数 ≈ `2n`」 | 只写区间还不够（`li` 与 `li−1` 两种口径都落在 `[1.8n, 2.1n]`）⇒ **必须配逐位闭式** `n + Σ(段长−1) = 2n − stored` |
| 要断言「存下来的 == `⌈√n⌉`」 | **精确相等**（本机 `n=1024` → `32`）；★ 口径要写明「`h_0` 也算一个」 |
| 极端情形（原文 §4.4 的 `k=1`） | **内存 == `log₂ n`**（本机 `1024 → 10`，逐位）；**额外前向 == `n·log₂ n`**（本机 `1024 → 10240`）⇒ 形状名 `O(log n)` 与 `O(n log n)` |
| 极端方案「省得更多」 | 但它**不是免费的**：同一 `n=4096` 上，内存 `127 → 12`，前向 `1.98× → 13.00×`（**6.6 倍**于分段方案） |
| 把 `k` 取成 `n`（每段 1 层） | **不会更省**：峰值激活回到 `n`（本机 `4096 ≥ 4096`），比 `k=⌈√n⌉` 的 `127` 差 ⇒ `⌈√n⌉` 是**最优点** |
| 报「省了多少倍」 | 必须写**分母**（存下来的个数 / 峰值激活数；本机 `64.00×` vs `32.25×`） |
| 引用论文的 `48G → 7G` | 只能作**量级对照**并写明**不是同一个量**（本模型的单位是激活个数，差 131%）；且那 6.86× 里还含 §3 的图分配优化（`a factor of two to three`），**那与重算是两笔账** |

## 6. 小结与延伸

**一句话**：把中间的激活扔掉、反向时重算，能把 `n` 层的激活账压到 `O(√n)` ——
而**代价记在时间上**：前向次数从 `n` 到 `2n − ⌈√n⌉`；
**再递归一层**能压到 `log₂ n`，代价是 `n log₂ n` 的前向。

- **本文的两个口径必须分开**：**内存** = `O(√n)`（式 (1) 的 `O(2√n)` 是它的系数）、
  **前向次数** = `≈2n`。★ 计划 §4 的 **T22** 专门点了这一处。
- **原文内部有一处不一致**（摘要 `O(n log n)` vs §4.4 `O(log₂ n)`）—— 本文**如实记录**，
  用递推说明它与摘要一致，**不替原文判定**。
- **论文的贡献是「通用方法 + 自动规划」**，不是提出这个概念（原文自承该词来自自动微分文献）。
- **反向图的框架侧语义**（`grad_fn` / `saved_tensors` / `no_grad` vs `inference_mode` /
  `retain_graph`）正文在 `70-frameworks/pytorch/02-autograd.md`（此处回链），本文不重写。
- **`recompute` 在别处的正文**：`40-kernels/attention/03-flash-attention-backward.md`
  讲注意力反向的重算（那里 `重算` 36 次）—— 它的账是**算子内部**的，
  本文的账是**层间调度**的，两者是同名不同层的两件事。
- **优化器怎么用梯度** ⇒ `03-gradient-lifecycle`（同一主题的下一个编号）。
- **模型结构的账**（参数怎么分布、残差流怎么涨）⇒ `80-model-architectures`；
  本文的账是**过程**的账。
