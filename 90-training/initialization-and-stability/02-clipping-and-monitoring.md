# 梯度裁剪与范数监控：阈值、监控量、以及「报警什么时候会响」

> **裁剪**的判据与阈值**不在本文**（它们在 `90-training/autograd-and-backward/03-gradient-lifecycle.md`
> 的「表 A ⑦」，**在那里只写一次**）—— 本文**只实现、不重定义**。
> 本文写的是它的**另一半**：**监控**。
> 而监控的每一条判据都挂在**一个口径**上：**你看的是裁剪前还是裁剪后的量**、
> **用 `>` 还是用 `isfinite`**、**阈值定在哪一层**。口径选错，报警就**不会响** ——
> 而且它**不会报错**。

## 0. 背景与动机

### ★★ 先说边界：本文**不写** warmup 的机制

范数监控最常见的搭配是 `LR warmup`（warmup 期梯度尺度会变），
但 —— ★★ **`LR warmup` 的机制解释不在本域**：

> **post-LN 的平均场理由**、以及原文用 `hypothesize` 的措辞纪律，
> **正文在** `80-model-architectures/normalization/02-placement-and-qk-norm.md:83,93-97,100,278`。

本文**一行都不重写它**，只写**工程判据与设定**：阈值定在哪、监控量取谁、报警怎么才响得起来。
★ 顺带一条**同名不同指**：`00-meta/glossary.md:146` 里的 `warmup` 指 **benchmark 预热**
（`45-kernel-lifecycle/convergence-and-tuning/01-benchmark-hygiene.md` 里 `warmup` 出现 23 次）
—— 与本处说的 **`LR warmup`** 不是一件事。那条纪律的正文在
`90-training/optimizers/03-schedules-and-clipping.md`（**此处只回链**）。

### 为什么「监控」值得单独写一节

裁剪本身只有三行伪代码（算范数 → 算系数 → 缩放）。而**围绕它的**那些事全是**口径**：

| 问题 | 错的答案会怎样 |
|---|---|
| 监控量取**裁剪前**还是**裁剪后**的范数？ | 取裁剪后 ⇒ 监控量恒 ≤ `max_norm` ⇒ **阈值永远不触发**（假阴性 100%） |
| 判「非有限值」用 `>` 还是 `isfinite`？ | 用 `>` ⇒ `nan > thr` **恒为假** ⇒ 最该报警的那一类**静默通过** |
| 阈值定在**全局**还是**逐张量**？ | 逐张量 ⇒ 全局范数被放大 **`√L`** 倍 |
| 范数类型用 `2` 还是 `inf`？ | 同一个 `max_norm` 的含义差一个「逐元素 / 全局」的层次 |
| 直接比较**不同层**的范数？ | 会把「**层更宽**」读成「**梯度更大**」 |

★★ 而**每一条都有一个可断言的闭式**（本文的 §1.3–§1.5、§2）。

## 1. 原理

### 1.1 裁剪：判据与阈值在别处（**回链，不重定义**）

```
T     = √(Σ_l ‖g_l‖²)            ← 全部参数的梯度当成一个向量（[B] 文档的「全局」口径）
coef  = max_norm / (T + ε)       ← ε 是保护项（[B] PyTorch v2.9.0 的源码：`+ 1e-6`）
若 coef < 1：  g ← g · coef
```

裁剪后的范数 = `max_norm·T/(T+ε)`，与 `max_norm` 的相对误差 = **`ε/(T+ε) ≈ ε/T`**。

★★ **判据与阈值定义在** `90-training/autograd-and-backward/03-gradient-lifecycle.md`
的「表 A ⑦」（`T ≥ 1`、上侧 `≤ 1.1e-6/max(T,1)`、**下侧 `== ε/(T+ε)`**）——
**本文只实现、不重定义**。本文的贡献是把那条判据**为什么必须两侧**做成一个**可执行的见证**（`A.1c`）：

| 实现 | 相对误差 | 上侧（`≤ 1.1e-6/T`） | 下侧（`== ε/(T+ε)`） |
|---|---|---|---|
| 正确的（带 `+ε`） | `4.999997e-07` | 比值 `0.9091` ⇒ **通过** | 偏差 `9.8e-10` ⇒ **通过** |
| **删掉 `+ε`** 的 | **`2.220e-16`**（**更精确**） | 比值 `0.0000` ⇒ **更满意** | 偏差 **`1.0000`** ⇒ **失败** |

⇒ ★★ **单侧判据会放过一个错实现**（那个实现的结果反而更精确 —— 这是 **T26** 的现场）。

### 1.2 监控量：**裁剪前**的范数

[B]（PyTorch 2.14 的 `clip_grad_norm_` 页）在 `Returns:` 里逐字写着：

```
Total norm of the parameter gradients (viewed as a single vector)
```

★★ **那是裁剪【前】的范数** —— 本机逐位验证（`A.2`：200 步里 `pre − T` 的最大差 **`0.0e+00`**），
而**裁剪后**的范数 == 闭式 `max_norm·T/(T+ε)`（最大相对差 `2.22e-16`）。

★★ **后果**（`A.2b`）：`post ≤ max_norm` **恒成立** ⇒ 用它做监控时，阈值 `max_norm`
**永远不触发**（实测 **`0/200`**），而 `pre` 的触发率在同一批梯度上是 **`98.5%`**（`197/200`）。
⇒ **「监控量取谁」不是措辞偏好，是一条可证伪的口径判据。**

★ 顺带一个**反直觉的**边界（`C.1`）：**`max_norm = 0`** 时训练完全停住
（梯度范数精确 `0`、`‖Δw‖` 精确 `0`），而**看 `pre` 的监控看到的是一个平平无奇的 `1.001692`**
⇒ **报警不响**。⇒ 监控**必须同时**看裁剪后的量（或 `‖Δw‖`），而且那里需要的是**下界**。

### 1.3 非有限值：判据必须用 `isfinite`

| 表达式 | `nan` | `inf` | `1e300` | `3.0` |
|---|---|---|---|---|
| `v > thr` | **False**（静默放行） | True | True | False |
| `isfinite(v) and v > thr` | **False**（抓住） | **False**（抓住） | True | False |

⇒ ★★ **`>` 只抓得住 `inf`，抓不住 `nan`**（`nan` 让**一切比较**为假）。
★ 这不是理论问题：[B] 文档里 `error_if_nonfinite` 的**默认值是 `False`**
（逐字：`if True, an error is thrown if the total norm of the gradients from parameters is
nan , inf , or -inf . Default: False`）⇒ **默认管线下 `nan`/`inf` 不报错**，
监控是**唯一**的报警入口 ⇒ 它的判据必须写对（`A.3` / `C.2`）。

### 1.4 全局 vs 逐张量：差 `√L` 倍

[B] 文档的正文逐字：

```
The norm is computed over the norms of the individual gradients of all parameters,
as if the norms of the individual gradients were concatenated into a single vector.
```

⇒ **全局**口径。★★ 反面（`A.4`）：**逐张量**各自裁到 `max_norm` 之后，
全局范数是 **`max_norm·√L`**（`L = 3` ⇒ 实测 **`1.732050`**，与闭式 `√3 = 1.732051`
的相对差全部来自每层各自的 `+ε`）。
⇒ **「逐张量裁到 `max_norm`」不是同一个 `max_norm`**。

★ 两种范数类型（`B.3`，[B] 的默认是 `norm_type = 2.0`）的含义也不在一个层次上：
`norm_type=inf` 把**每个元素**压到 `max_norm`（实测 `0.999999383`，逐位等于闭式），
而 `norm_type=2`（默认）只保证**全局**范数 —— 单个元素只有 `0.016212`（`max_norm` 的 `1.6%`）
（闭式 `a·‖g‖_inf/(‖g‖_2+ε)` 逐位吻合）。★ 而 `‖g‖_inf/‖g‖_2` 随 `n` 走 `√(2 ln n/n)`
（`n = 73728` 上实测 `0.016212` vs 渐近 `0.017437`，差 7%）⇒ **2 口径的保护强度取决于 `n`**，
不是一个固定的上界（本机 `norm_type=2` 下单元素离 `max_norm` 还差 **62 倍**）。

### 1.5 触发率有一条闭式（`A.5`）

监控最常看的一个量是**裁剪触发率**。若梯度各分量是 `N(0, σ²)`，则

```
‖g‖² / σ² ∼ χ²_n        ⇒    P(‖g‖ > max_norm) = P(χ²_n > (max_norm/σ)²)
```

★ **偶数 `n` 时上尾是有限和**（Erlang）：`e^{−x/2}·Σ_{k=0}^{n/2−1}(x/2)^k/k!`
—— 只用 `math.exp` 就能算，**不需要 `scipy`**。

本机（`n = 8`，`max_norm = 1`，`200000` 次抽样）：

| `σ` | MC 实测 | 闭式 | 相对差 / `4·SE` |
|---|---|---|---|
| `0.2` | `0.00150` | `0.00155` | `0.17` |
| `0.4` | `0.62013` | `0.61925` | `0.20` |
| `0.8` | `0.99130` | `0.99162` | `0.39` |

⇒ 三个 `σ` 上触发率跨 **663 倍**（`0.0015` → `0.9913`）⇒ **「看裁剪触发率」真的能看见梯度尺度的变化**。
★ 闭式本身还有一个可手算的自检（`A.5b`）：`n = 2` 时 `P(χ²_2 > 1) = e^{−1/2}`（**逐位**）。

★★ **但要注意它的分辨率**（`A.2b` 的附带发现）：`‖g‖` 的相对标准误是 `1/√(2n)` ——
本机的玩具模型有 `n = 73728` 个梯度元素 ⇒ 相对标准误只有 **`0.26%`**，
200 步上的相对极差 `1.53%`（≈ 6 个标准误）。⇒ **在这个 `n` 上触发率几乎是一个阶跃**：
`σ√n` 从 `0.92` 到 `1.00` 就让触发率从 0 跳到 99%。⇒ 大模型上「触发率」主要告诉你
**`σ√n` 在哪一侧**，不要指望它平滑。

### 1.6 监控的字节账（`B.1`）

★★ 全局范数可以**只由每层一个标量**重算：`√Σ_l ‖g_l‖²`（实测与「直接当成一个向量」的相对差
`< 1e-15`，且**与顺序无关** —— 逆序给出同一个数）。
⇒ **全局面板的记录量是 `L` 个数**，而梯度本身是 `Σ n_l` 个数（本机 `L = 3` vs `73728`）。

★ **口径**：这是**纯代数**（`√Σ` 与拼接方式无关）。
「怎么把这些标量收集到一起」是**另一件事**（分布式侧的正文在 `100-parallelism`，本文不写）。

★ 还有一个口径坑（`B.2`）：**单层范数被层宽主导** —— `‖g_l‖ ≈ σ√n_l`。
实测每元素 RMS 跨 `n ∈ {64,…,4096}` 的极差只有 **`0.6036%`**，而 `‖g‖` 本身跨 **`8.03` 倍**
（≈ `√(4096/64) = 8`）⇒ **跨层比较必须用每元素 RMS**，否则会把「层更宽」读成「梯度更大」。

## 2. 执行映射

### 2.1 监控面板该记什么

| 记什么 | 口径要求 | 为什么 |
|---|---|---|
| `T_before`（**裁剪前**的全局范数） | [B] 的返回值口径 | 裁剪后的量恒 ≤ `max_norm`，报警不可能响（`A.2b`） |
| `T_after`（裁剪后的范数） | 由 `T_before` 与闭式 `max_norm·T/(T+ε)` 反推也可 | 让「裁剪真的发生了吗」与「`max_norm = 0` 这类静默停训」可见（`C.1`） |
| **裁剪触发率** | 逐窗口统计 | 有闭式（`P(χ²_n > (max_norm/σ)²)`）；★ 大 `n` 下它近乎阶跃 |
| **每元素 RMS**（`‖g_l‖/√n_l`） | 逐层 | `‖g_l‖` 被 `√n_l` 主导（`B.2`） |
| `‖Δw‖` | 每步 | 它是「更新到底有没有发生」的直接证据（`C.1` 的静默停训） |

★ **报警的方向也要两条**：上界（`> thr`）用来抓爆炸，**下界**用来抓「更新为 0」这类静默停训。

### 2.2 三条口径纪律

1. **先 `isfinite`、再比阈值**（`nan > thr` 恒为假）；
2. **范数是全局的**（`√Σ_l ‖g_l‖²`，与拼接/顺序无关）；
3. **触发率要配 `n` 与 `σ` 一起看**（大 `n` 下它是阶跃，不是温度计）。

### 2.3 本机实测的一组典型值

| 量 | 值（`T = 2→8`、`max_norm ∈ {1.0,0.5,0.1}`、`ε = 1e-6`） |
|---|---|
| 上侧：相对误差 / 阈值 | 最大 **`0.9091`**（`≤ 1`） |
| 下侧：与闭式 `ε/(T+ε)` 的最大相对偏差 | **`9.816e-10`** |
| 删掉 `+ε` 的实现 | 相对误差 `2.220e-16`、上侧 `0.0000`、**下侧 `1.0000`** |
| 用 `post` 做监控的触发率 | **`0/200`**（而 `pre` 是 `197/200`，`post` 的最大值 `0.999999013174`） |
| 逐张量 vs 全局（`L = 3`） | **`1.732050`** vs `1.000000`（闭式 `√3 = 1.732051`） |
| `inf` 污染 4 个元素 | 裁剪后 **1 个 `nan` + 3 个精确 `0`** |

## 3. 实现与演进

| 阶段 | 写法 | 它换来了什么、付了什么账 |
|---|---|---|
| **不裁** | 直接 `w ← w − lr·g` | 无超参；代价是**偶发的范数突增**会直接进更新量 |
| **逐元素截断** | `clip(g, −c, c)` | 简单；代价是**改变方向**（全局裁剪只缩放、不改方向） |
| **按全局范数裁剪** | `coef = max_norm/(T+ε)` | 只缩放、**不改方向**；代价是那个 `ε/(T+ε)` 的偏差，★ 以及**它不能替代溢出处置** |
| **`norm_type` 可选** | `2`（默认）或 `inf` | `inf` 给**逐元素**上界；代价是同一个 `max_norm` 的含义变了（`B.3`） |
| **`error_if_nonfinite`** | 默认 `False` | 兼容旧行为；代价是 **`nan`/`inf` 默认静默通过**（`C.2`） |
| **监控** | 记 `T_before`、触发率、每元素 RMS | 报警能响；代价是**口径必须写对**（本文 §2.2） |
| **自适应裁剪 / 跳步** | 检测到溢出就跳步 | 溢出处置在 `mixed-precision/02`（**此处回链**）；裁剪**替代不了它** |

## 4. 踩坑与失败模式

**① ★★ 用裁剪【后】的范数做监控。**

- **现象**：监控面板一片安静，训练其实在被裁剪（或已经停住）。
- **成因**：`post ≤ max_norm` **恒成立**；阈值定在 `max_norm` 上就**永远不触发**（`0/200`）。
- **规避**：监控量取 `T_before`（[B] 的返回值口径），并**同时**记 `T_after`/`‖Δw‖`。

**② ★★ 判非有限值用 `>`。**

- **现象**：`nan` 出现后监控**不响**、训练继续、损失变成 `nan`。
- **成因**：`nan > thr` **恒为假**（IEEE 754 的比较规则）。★ 而 `inf > thr` 是 `True` ——
  所以这个错**只对 `nan` 失效**，恰好是最该抓的那一类。
- **规避**：`isfinite(v) and v > thr`（`A.3`）。

**③ ★ 逐张量裁剪当成了全局裁剪。**

- **现象**：以为阈值是 `max_norm`，实际全局范数被放大 **`√L`** 倍。
- **成因**：[B] 的口径是「当成一个向量」（`A.4` 实测 `√3 = 1.732050`）。
- **规避**：断言全局口径（`√Σ_l ‖g_l‖²` == 拼接向量的范数）。

**④ ★ 直接比较不同层的范数。**

- **现象**：面板上「第 3 层的梯度比第 1 层大 8 倍」，于是去调那一层。
- **成因**：`‖g_l‖ ≈ σ√n_l` —— 那是**层更宽**，不是梯度更大（`B.2`：每元素 RMS 跨层极差 0.60%）。
- **规避**：用每元素 RMS。

**⑤ ★★ 拿 `max_norm = 0` 当「安全设置」。**

- **现象**：训练**静默停住**（`‖Δw‖` 精确 `0`），而监控**不响**（`pre = 1.082910`，平平无奇）。
- **成因**：`coef = 0/(T+ε) = 0` ⇒ 梯度全清零；而 `pre` 是**裁剪前**的量，不受影响。
- **规避**：把 `max_norm > 0` 作为配置校验；面板里加**下界**报警（`‖Δw‖ == 0`）。

**⑥ ★★ 把 `error_if_nonfinite` 的默认值当成「它会报错」。**

- **现象**：以为 `inf`/`nan` 会被框架拦住。
- **成因**：[B] 的**默认值是 `False`**（逐字见 `specs.PYTORCH_CLIP_ERROR_IF_NONFINITE_DEFAULT`
  的注释）⇒ 默认行为是**静默通过**。
- **规避**：显式打开它，或者把 `isfinite` 的监控当成**唯一**的报警入口。

**⑦ ★ 一个 `inf` 就能把整条梯度向量变成 `nan`。**

- **现象**：裁剪之后 `1` 个 `nan` + `3` 个精确 `0`。
- **成因**：`T = inf` ⇒ `coef = 0` ⇒ 有限元素归 `0`、`inf·0 = nan`（IEEE 754）。
- **规避**：**溢出必须在裁剪之前处置**（跳步，正文在 `mixed-precision/02`）—— `A.3b` 是那条接口的负面证明。

## 5. 判据表

| 可机械判定的条件 | 结论 |
|---|---|
| 裁剪后范数与 `max_norm` 的关系 | `= max_norm·T/(T+ε)`，相对误差 **`≈ ε/T`**；★ **判据必须两侧**：上侧 `≤ 1.1e-6/max(T,1)`（`T ≥ 1`）**且**下侧 `== ε/(T+ε)` |
| 想判断「删掉保护项」的实现 | **上侧抓不到**（它更精确：相对误差 `2.2e-16`）；**只有下侧**能抓（偏差 `1.0000`） |
| `T < max_norm` | **不发生裁剪**（裁剪后范数仍 `== T`，逐位） |
| 监控量该取哪个范数 | **裁剪前**的（[B] 的返回值）；取裁剪后的 ⇒ 阈值**永远不触发**（`0/200`） |
| 怎么判 `nan` / `inf` | `isfinite(v) and v > thr`；★ `nan > thr` 恒为假、`inf > thr` 为真 ⇒ `>` 对 `nan` **半失效** |
| 阈值定在全局还是逐张量 | **全局**（`√Σ_l ‖g_l‖²`）；逐张量 ⇒ 全局范数被放大 **`√L`** 倍 |
| `norm_type` 用 `2` 还是 `inf` | 默认 `2.0`（全局）；`inf` 给**逐元素**上界 `max_norm`。2 口径下单元素只到 `max_norm·‖g‖_inf/‖g‖_2 ≈ max_norm·√(2 ln n/n)` |
| 预测裁剪触发率 | `P(χ²_n > (max_norm/σ)²)`（偶数 `n` 时是有限和）；`n = 2` 时 `= e^{−1/2}` 可手算 |
| 触发率能不能当「温度计」 | **大 `n` 下几乎不能**：`‖g‖` 的相对标准误 `1/√(2n)`（`n = 73728` 时 `0.26%`）⇒ 它近乎阶跃 |
| 面板要记多少个数 | **每层一个标量**就够（`√Σ` 与拼接/顺序无关）；全局面板 = `L` 个数 |
| 想比较不同层的梯度大小 | 用**每元素 RMS**（`‖g_l‖/√n_l`）；`‖g_l‖` 本身被 `√n_l` 主导（跨 8 倍） |
| 梯度里有 `inf` 时裁剪会怎样 | 给出 **`nan`**（`coef = 0`）⇒ **裁剪不能替代溢出处置**（跳步在 `mixed-precision/02`） |
| `max_norm = 0` | 梯度全清零、更新恒为 `0` —— **静默停训**，而看 `pre` 的监控**不响** |
| `error_if_nonfinite` 的默认值 | **`False`** ⇒ `nan`/`inf` **默认静默通过**（[B] 逐字） |

> ★ 阈值与口径（`code/02_clip_monitor.py` 的 `D.3`/`D.4` 逐位钉住）：
> `SEED = 20260951`、`CLIP_T_LIST = (2.0, 4.0, 8.0)`（★ `T ≥ 1`）、
> `CLIP_MAX_NORM_LIST = (1.0, 0.5, 0.1)`、`CLIP_TOL_REL = 1.1e-6`（上侧）、
> `CLIP_TOL_CLOSED = 1e-6`（**下侧，回链 Chunk 1 的 `A.2b`**）、`TENSOR_SHAPES`（`L = 3`）、
> `MON_STEPS = 200`、`MON_SIGMA = 0.0037`（★ 让触发率**既不是 0 也不是 1**）、

> `TOL_EXACT = 0.0`、`TOL_IDENT = 1e-15`、`TOL_RMS = 0.02`、`TOL_CHEB = 1e-9`。

## 6. 小结与延伸

**一句话**：裁剪的判据只有一条（两侧的 `ε/(T+ε)`），而**监控**的判据全在**口径**上 ——
