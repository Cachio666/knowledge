# LayerNorm · RMSNorm 与 Welford 单遍

> LayerNorm 要一行数据的**两个统计量**（均值与方差），RMSNorm 只要**一个**（均方值），这是它们全部的结构差异。求这两个量有三种写法：两遍法、`Σx² − nμ²`、Welford 单遍。**`Σx² − nμ²` 在 `μ/σ ≥ 100` 时就开始崩，`μ/σ ≥ 1e4` 时能给出负方差**；Welford 与两遍法都在 `1e-5` 量级以内，但 Welford 的均值是逐项递推的，在大均值下会漂移。

## 0. 背景与动机

先给一个具体场景：**一层 Transformer 的 LayerNorm，hidden = 8192，fp16，batch = 4096**。

一个刚学 CUDA 的人会这样写：一个 block 吃一行，第一遍归约出均值 `μ`，第二遍归约出 `Σ(x−μ)²` 得到方差，然后 `y = (x−μ)·rsqrt(σ²+eps)·γ + β`。两遍都要遍历这一行的 8192 个元素。

有人告诉他：「一遍就够了——同时累加 `Σx` 和 `Σx²`，然后 `σ² = Σx²/n − μ²`。」这确实少一遍遍历，代码也更短。他在标准激活（`μ≈0`、`σ≈1`）上测下来没错，就换过去了。

然后他把这份实现接到了一个**输出量级很大**的子层后面（例如残差做完、`μ/σ ≈ 1e5` 的那种激活），结果开始出问题——不是微小的精度下降，而是**莫名其妙的大误差**。`make verify` 的 §C7 把这条直接跑了出来（推导值）：`n = 8192`、`σ = 1`、只抬 `μ`——

| `μ` | `Σx²` | `n·μ²` | 两者之差 | 方差真值 | 相对误差 |
|---|---|---|---|---|---|
| 0 | 8197 | 0.1398 | 8196 | 1.000537 | 3.429e-08 |
| 100 | 8.192e+07 | 8.191e+07 | 8378 | 1.023558 | 8.823e-04 |
| 1000 | 8.192e+09 | 8.192e+09 | 8303 | 1.002979 | 1.056e-02 |
| 10000 | 8.192e+11 | 8.192e+11 | 1.772e+05 | 0.992053 | **2.080e+01** |
| 100000 | 8.192e+13 | 8.192e+13 | −4.411e+06 | 0.991853 | **5.439e+02** |

最后一行那个负数不是笔误：`Σx² − n·μ²` 给出的方差本身**变成了负数**（`−538.5001`）。方差是平方的平均，不可能是负的——这个负号是纯计算产物，它标志着有效位已经被吃光。

本文要做三件事：

1. 把 LayerNorm 与 RMSNorm 的**结构差异**说清（是否减均值、是否用 `β`）；
2. 把 **Welford 单遍**的两条递推**逐项推出来**，并说明它为什么避开了上面那个灾难；
3. 把「单遍」这件事的**代价与边界**交代清楚——它省的不是自动的，也不是在所有形状上都省。

第 3 点容易被跳过：一个 block 归约一行的场景里，**两遍法的第二遍读的是片上副本，不产生额外显存流量**。单遍省下的东西和直觉不一样（§2、§4.2）。

## 1. 原理

### LayerNorm 与 RMSNorm 的定义

对一行 `x`（长度为 `n`，逐列参数 `γ`、`β`）：

```text
LayerNorm:  μ = (1/n)Σ x_j
            σ² = (1/n)Σ (x_j − μ)²
            y_j = (x_j − μ) · rsqrt(σ² + eps) · γ_j + β_j

RMSNorm:    ms = (1/n)Σ x_j²
            y_j = x_j · rsqrt(ms + eps) · γ_j
```

**两处结构差异：**

- **是否减均值。** RMSNorm 不减。它假设这一行的大均值部分可以整体缩放掉——在 Transformer 的残差流里，这个假设通常成立，而减均值要多一次归约、多一个统计量。
- **是否用 `β`。** RMSNorm 没有 `β`。加了 `β` 之后「减不减均值」就不等价了：`(x−μ)·s + β` 与 `x·s' + β` 是两条不同的曲线。RMSNorm 的论文主张归一化的**缩放不变性**才是真正起作用的部分，平移不变性不是必需的。

`make verify` 的 §B4 用最简的 `x = [1,2,3,4,5]` 把 Welford 的递推逐步打印出来作为手算基线（见本节末）；§B6 给出这两种算子的访存账。

### Welford 的两条递推

记号：`μ_n` 与 `M2_n` 分别是**前 n 个元素**的均值与「离差平方和」：

```text
μ_n  = (1/n) Σ_{i≤n} x_i
M2_n = Σ_{i≤n} (x_i − μ_n)²          ← 注意是**未除以 n** 的平方和
```

最终方差 `σ² = M2_n / n`。要的是**只维护 `(μ_n, M2_n)` 两个数**、每来一个新元素就更新一次，而不回看旧元素。

**第一步：均值的更新。** 记 `S_{n−1} = Σ_{i≤n−1} x_i = (n−1)·μ_{n−1}`：

```text
μ_n = (S_{n−1} + x_n) / n
    = ((n−1)·μ_{n−1} + x_n) / n
    = μ_{n−1} + (x_n − μ_{n−1}) / n
```

最后一步是把 `(n−1)μ_{n−1} = n·μ_{n−1} − μ_{n−1}` 拆开再并回去。记增量 `Δ = (x_n − μ_{n−1})/n`，则 `μ_n = μ_{n−1} + Δ`。

**第二步：`M2` 的更新。** 把 `M2_n` 按「旧元素 + 新元素」拆开：

```text
M2_n = Σ_{i≤n} (x_i − μ_n)²
     = Σ_{i≤n−1} (x_i − μ_n)²  +  (x_n − μ_n)²
```

对旧元素，把「新均值」写成「旧均值 + 增量」：

```text
x_i − μ_n = (x_i − μ_{n−1}) − (μ_n − μ_{n−1}) = (x_i − μ_{n−1}) − Δ
```

平方后求和，交叉项会**自动消失**——这正是 `μ_{n−1}` 的定义给的：

```text
Σ_{i≤n−1} (x_i − μ_n)²
  = Σ (x_i − μ_{n−1})² − 2Δ·Σ (x_i − μ_{n−1}) + (n−1)Δ²
  = M2_{n−1} − 2Δ·0 + (n−1)Δ²
  = M2_{n−1} + (n−1)Δ²
```

（中间那个 `Σ_{i≤n−1}(x_i − μ_{n−1}) = 0` 是均值的定义式本身。）新元素那一项：

```text
x_n − μ_n = (x_n − μ_{n−1}) − Δ = nΔ − Δ = (n−1)Δ
(x_n − μ_n)² = (n−1)²Δ²
```

合起来：

```text
M2_n = M2_{n−1} + (n−1)Δ² + (n−1)²Δ²
     = M2_{n−1} + (n−1)Δ²·[1 + (n−1)]
     = M2_{n−1} + n(n−1)Δ²
```

**第三步：把 `n(n−1)Δ²` 写成两个可复用的量之积。**

```text
n(n−1)Δ² = (nΔ) · ((n−1)Δ)
         = (x_n − μ_{n−1}) · (x_n − μ_n)
```

左因子是「新元素减**旧**均值」，右因子是「新元素减**新**均值」。两者都只用到已经算出来的量：`μ_{n−1}` 是上一步的状态，`μ_n` 是第一步刚算出来的。于是得到最终形式：

```text
μ_n  = μ_{n−1} + (x_n − μ_{n−1}) / n
M2_n = M2_{n−1} + (x_n − μ_{n−1}) · (x_n − μ_n)
```

**每来一个元素：两次减法（`x_n − μ_{n−1}` 与 `x_n − μ_n`）、一次除法（`d/n`）、一次乘法、两次加法。** 没有第二遍，也没有任何「大数相减」。

`make verify` 的 §B4 在 `x = [1,2,3,4,5]` 上把这五个元素逐行打印出来，可以直接对：

```text
n=1: x=1.0  d=+1.0000  mean 0.000000 → 1.000000   M2 0.000000 → 0.000000
n=2: x=2.0  d=+1.0000  mean 1.000000 → 1.500000   M2 0.000000 → 0.500000
n=3: x=3.0  d=+1.5000  mean 1.500000 → 2.000000   M2 0.500000 → 2.000000
n=4: x=4.0  d=+2.0000  mean 2.000000 → 2.500000   M2 2.000000 → 5.000000
n=5: x=5.0  d=+2.5000  mean 2.500000 → 3.000000   M2 5.000000 → 10.000000
终值：mean = 3.0，M2 = 10.0，var = 2.0  ✓
```

### 分块合并：Chan 式

一个 block 有几百个线程，每个线程只能看到自己那一段。所以除了「逐元素推进」，还需要一个**把两个 `(μ, M2, n)` 三元组合并成一个**的算子：

```text
n      = n_a + n_b
μ_ab   = μ_a + (μ_b − μ_a) · n_b / n
M2_ab  = M2_a + M2_b + (μ_b − μ_a)² · n_a·n_b / n
```

它与本文（以及 02 篇）反复出现的结构是同一个：**把「基准的差异」作为一阶与二阶修正项加回去**。`(μ_b − μ_a)` 就是两个部分各自的基准之差；`M2` 那一项把它平方后按 `n_a·n_b/n`（两组之间的「有效样本数」）加权。

这个算子满足结合律，所以 block 内可以用与 01/02 篇完全相同的 warp shuffle + shared memory 树形归约——**只是每次 shuffle 搬的是三个数而不是一个**。`make verify` 的 §A4 断言了这一点：`threads ∈ {32, 64, 256, 1024}` 四种归约宽度下，Welford 给出的方差逐位相同（`1.0117564201`）。

### 为什么它比「大数相减」稳

`Σx² − n·μ²` 的失败机制很简单：`Σx²` 与 `n·μ²` 都是 `n·μ²` 量级的大数，而它们的差是 `n·σ²` 量级的小数。两者的比值是

```text
(n·μ²) / (n·σ²) = μ²/σ²
```

`μ/σ = 100` 时，要从 4 位有效数字的差里掏出真值；`μ/σ = 1e4` 时，需要 8 位——**超过 fp32 的 7 位十进制精度**，剩下的就是噪声。

Welford **全程不构造 `Σx²` 这个中间量**。它维护的 `M2` 本身就是小量（`n·σ²` 量级），更新的增量也是小量（`n(n−1)Δ²`，其中 `Δ = (x_n − μ_{n−1})/n` 是新元素相对旧均值**已经去掉了均值**的偏差）。**相减的两个大数从来就没被造出来过。**

`make verify` 的 §A5 把三种写法并排扫了一遍（`n = 8192`、`σ = 1` 固定、只抬 `μ`，fp32 存储与累加，判据是与 fp64 真值的相对误差）：

| `μ/σ` | 两遍法（分块） | Welford（分块） | `Σx² − nμ²`（分块） |
|---|---|---|---|
| 0 | 2.455e-08 | 2.455e-08 | 3.754e-08 |
| 10 | 3.035e-08 | 3.035e-08 | 1.451e-05 |
| 100 | 1.121e-08 | 4.867e-08 | **1.152e-03** |
| 1000 | 3.010e-09 | 5.365e-06 | **1.690e-02** |
| 10000 | 1.131e-07 | 1.907e-05 | **2.724e+00** |
| 100000 | 9.163e-06 | 3.791e-04 | **5.547e+02** |
| 1000000 | 3.090e-05 | 6.117e-03 | **4.059e+03** |

**这张表有一个反直觉的读数必须点出来：两遍法反而略优于 Welford。** 不是 Welford 不稳，而是两遍法的第一遍求均值走的是一棵树形归约（误差 `~√n·u`），而 Welford 的均值是**逐项**递推的，会撞上「更新量被 `|mean|` 的 `ulp` 吞掉」这个问题——机制与量化见 §4.2。所以准确的结论是：

> **Welford 的价值不是「比两遍法更准」，而是「单遍 + 数值上避开灾难性抵消」。** 它相对 `Σx² − nμ²` 稳 6 个数量级以上（`μ/σ = 1e5` 时比值 `1.463e+06`），代价是分块合并时每次要多算几个乘加。

### 那单遍到底省了什么

`make verify` 的 §B6 给出账（4096 行 × hidden 8192，fp16，即每行 `16.0 KB`）：

| 写法 | 每行字节 | 总量 | HBM 时间 @ 3350 GB/s |
|---|---|---|---|
| 两遍法（`x` 不留在片上） | 读 `x` 两遍 + 写 `y` + 读 `γ/β` | 201.4 MB | 60.1 µs |
| 单遍 Welford（`x` 留在片上） | 读 `x` 一遍 + 写 `y` + 读 `γ/β` | 134.3 MB | 40.1 µs |

比值 `1.499878`（忽略 `γ/β` 时恰为 `3/2`）。**但这个收益有前提**——见 §2 的容量账与 §4.2 结尾的取舍。

## 2. 执行映射

### 归约的层级

LayerNorm 是「一行一个归约」的形态。一个 block 吃一行时，两级归约的形态与 01/02 篇完全一致：

- **warp 内**：`__shfl_down_sync` 五步（`32→16→8→4→2→1`）；
- **warp 间**：lane 0 写 shared memory，第一个 warp 读出后再做五步，两次 `__syncthreads()`。

差别只在**搬几个数**：

| 算子 | 每次 shuffle 搬的字节 | 每步的额外算术 |
|---|---|---|
| 求和（RMSNorm 的均方值） | 4 | 一次加法 |
| 求和 + 平方和（`Σx²−nμ²`） | 8 | 一次 FMA |
| Welford（`μ, M2, n`） | 12 | 一次除法、两次乘法、三次加法 |

Welford 的归约是最重的。但两次 `__syncthreads()` 的成本与搬多少字节无关——**真正把 block 拴住的是同步，不是 shuffle 的数据量**（规格值：shared memory 命中延迟 `20~30` 周期，片外访存往返 `400~800` 周期，每 SM 每周期最多发射 `4` 条指令）。

### 一行的容量账：单遍省的是显存带宽吗？

这是本节要给出的**后果**，不是命名部件。一行 `n` 个 fp16 元素的字节数是 `2n`：

| hidden | 一行 fp16 | 每 SM 的 SMEM 上限 228 KB |
|---|---|---|
| 4096 | 8.00 KB | 放得下 |
| 8192 | 16.00 KB | 放得下 |
| 16384 | 32.00 KB | 放得下 |
| 65536 | 128.00 KB | 放得下 |
| 131072 | 256.00 KB | **放不下** |

但**一行通常由一个 block 处理**，而 shared memory 要在同一 SM 的多个常驻 block 之间分：

```text
常驻 1 个 block → 每 block 228.0 KB → hidden ≤ 116736
常驻 2 个 block → 每 block 114.0 KB → hidden ≤  58368
常驻 4 个 block → 每 block  57.0 KB → hidden ≤  29184
常驻 8 个 block → 每 block  28.5 KB → hidden ≤  14592
```

结论（推导值）：**对 `hidden ≤ 29184` 这种常见形状（常驻 4 个 block），一行放得进 shared memory。此时两遍法的第二遍读的是片上副本，根本不产生额外显存流量——单遍省下的只是片上带宽与指令数。**

只有行长越过这条线时，两遍法的第二遍才真的回显存读，`3/2` 那个比值才落到 **HBM** 上。

**另一个口径是寄存器**：如果 `x` 全程留在寄存器里（每个线程负责 `hidden/threads` 个元素），`hidden = 8192`、`threads = 256` 时每线程是 32 个元素 = 128 个寄存器——已经吃掉寄存器文件的一半以上（每 SM 65536 个 32-bit 寄存器 = 256 KB），会让占用率掉下来。这时候把它放进 shared memory 反而更划算。

### 除法的通路

`rsqrt` 走的是超越函数通路，与 `exp` 同一条。它在每行只算**一次**（不是每个元素一次），所以对 LayerNorm 的代价可以忽略——这与 01 篇 §2 里「softmax 每元素一次 `exp`」是两回事。

## 3. 实现与演进

按「统计量怎么算」分档：

1. **两遍法**。第一遍树形归约 `Σx`，第二遍归约 `Σ(x−μ)²`。数值上好（表 §1 里每一行都在 `3e-5` 以内），代价是遍历两遍——**但只在行装不下时才多付显存流量**（§2）。对应 `code/03_layernorm.cu` 的 `layernorm_two_pass_kernel`。

2. **`Σx² − nμ²`**。一遍同时累加 `Σx` 与 `Σx²`，再相减。**这是本文的反例**：代码最短、指令最少、数值最烂。对应 `layernorm_sumsq_kernel`。

3. **Welford 单遍**。逐元素递推 `(μ, M2)`，分块后用 Chan 式树形合并。一遍、`O(1)` 状态、数值上避开灾难性抵消。对应 `layernorm_welford_kernel`。`verify.py` 的 §A4 断言它与两遍法一致（相对差 `1.178e-07`）。

4. **RMSNorm**。只要一个统计量，归约退化为一棵树形求和（`Σx²`），没有相减，也没有 `μ` 与 `β`。数值上比 LayerNorm 简单一个档次——**`Σx²/n` 本身就是那个小量**，不存在 `Σx² − nμ²` 那个减法。对应 `rmsnorm_kernel`。

再往后是工程结构上的（不在本文展开）：把 LayerNorm 与残差加法融合成一个 kernel（`x + residual` 只读一次）、把 `γ/β` 预取进寄存器、以及「一行一个 warp 还是多个 warp」。这些属于 `40-kernels/elementwise-fusion` 与 attention 主题的形态。

**本文完成的是 1–4 档，落点在「三种统计量写法的取舍」。** 上面第 4 档（RMSNorm）的推导只有一行代数，本文不单独展开。

## 4. 踩坑与失败模式

### 4.1 `Σx² − n·μ²` 的灾难性抵消

**现象**：在标准激活（`μ ≈ 0`、`σ ≈ 1`）上测不出问题，误差只有 `3.754e-08`；接到大均值激活上之后，方差的相对误差涨到 `2.724e+00`（`μ/σ = 1e4`）甚至 `5.547e+02`（`μ/σ = 1e5`），而且**会给出负方差**——`make verify` 的 §C7 在 `μ = 1e5` 时得到 `−538.5001`，在 `μ = 1e6` 时得到 `61440.0000`（真值 ≈ 1）。

**成因**：`Σx²` 与 `n·μ²` 都是 `n·μ²` 量级，它们的差是 `n·σ²` 量级，比值 `μ²/σ²`。要从这两个大数里掏出真值所需的相对精度是 `σ²/μ²`——`μ/σ = 1e4` 时是 `1e-8`，低于 fp32 的 `u = 5.96e-8`。于是差值完全由舍入噪声支配，符号都可以是错的。它**不是**「精度不够」，是**两个本该相消的大数被显式地相减了**。

**规避**：任何用 `E[x²] − E[x]²` 算方差的地方都要检查 `μ/σ`。两条可选路径：

- 用 **Welford**（本文 §1）：全程不构造 `Σx²`，代价是分块合并的算子和状态宽一点；
- 用**两遍法**：先算准 `μ`，第二遍算 `Σ(x−μ)²`。第二遍的每一项都已经去过均值，没有大数。

还有一层容易忽略的掩盖：**LayerNorm 里的 `eps` 会把负方差藏起来**。`rsqrt(负数 + eps)` 在 `|负数| < eps` 时仍然能算出一个数——错了，但看不出来。`μ/σ = 1e4` 那一档 `2.724e+00` 的相对误差还没到负数，但已经足够让下游的数值行为完全变样。

### 4.2 Welford 的均值漂移：单遍的收益会被数值吃掉

**现象**：为了拿到单遍的访存收益，把两遍法换成朴素的顺序 Welford，结果在大均值数据上**方差误差反而比原来大 1~2 个数量级**。§1 的表里 `μ/σ = 1e5` 那一行：两遍法 `9.163e-06`，Welford `3.791e-04`。更极端的形状下差距更大：`n = 8192`、`μ = 1e5` 时把整个数组交给一个线程顺序扫，相对误差到 `6.708e-02`。

**成因**：Welford 的均值更新是 `mean += d/n`，其中 `d/n` 是**新元素相对旧均值的偏差除以 n**。当 `n = 8192` 时 `d/n` 的量级是 `1.221e-04`，而 `|mean| = 1e5` 时 fp32 的 `ulp/2` 是 `3.906e-03`——**更新量比半个 ulp 还小**，`mean` 直接卡住不动。`make verify` 的 §C8 把它量化了出来：

```text
μ        ulp(μ)/2     d/n 量级     δ = Δmean        δ²/σ²（系统项）    总误差
0        0.000e+00    1.221e-04    -0.000000        3.373e-17         8.762e-07
100      3.815e-06    1.221e-04     0.000069        4.737e-09         1.329e-06
10000    4.883e-04    1.221e-04    -0.010791        1.180e-04         1.767e-04
100000   3.906e-03    1.221e-04    -0.002271        5.078e-06         2.339e-04
1000000  3.125e-02    1.221e-04     0.260872        6.707e-02         6.708e-02
```

机制本身是一条**恒等式**（`make verify` §C8 逐行断言过）：设 Welford 给出的均值为 `m̂ = μ + δ`，则

```text
Σ(x − m̂)² / n = Σ(x − μ)² / n + δ²        （因为 Σ(x − μ) = 0）
```

所以 `δ` 造成的偏差**恰好是 `δ²`**，它是一个只加的**系统性**项。表里最后一列的总误差还叠了 `M2` 累加本身的舍入，符号可正可负，两者反号时相消——所以「`Δmean²` 精确等于误差」是错的，但「`Δmean²` 给出这一项的量级」成立（`make verify` §C8 逐行断言的恒等式是上面那一行，不是这个近似）。

**规避**：不要用「单线程顺序扫完整个数组」的 Welford。两条做法，效果在 `make verify` §C8 的末尾直接对照（同一份 `μ = 1e5`、`n = 8192`、`σ = 1` 的数据）：

| 策略 | 方差 | 相对误差 |
|---|---|---|
| 顺序 Welford（整个数组一块） | 1.08267498 | 6.708e-02 |
| 分块 32 | 1.04379845 | 2.876e-02 |
| 分块 256 | 1.02022696 | 5.531e-03 |
| 分块 1024 | 1.01621628 | 1.579e-03 |

**分块本身就是规避手段**：每块内部 `n` 只有几十，`d/n` 不会被 `ulp` 吞掉；块间用 Chan 式合并。更彻底的做法是先把数据减去一个粗中心（比如 `x[0]`）再跑 Welford——`μ` 拉回 0 附近之后这个问题根本不存在。

**最后要说清这个取舍的另一半**：`hidden ≤ 29184` 时一行放得进 shared memory（§2），两遍法**不产生额外显存流量**。所以在那个形状下，「用 Welford 换访存」这笔交易根本不成立——换来的只是「少一遍片上遍历」。**做这个选择之前要先算容量账，而不是先看『单遍』这两个字。**

### 4.3 `eps` 放在分母内还是外

**现象**：同一份权重、同一个 `eps = 1e-5`，换一个实现（或换一个框架）之后，某些层的输出差出几十倍。看代码，两个实现只差一个括号：

```text
内：(x − μ) / sqrt(σ² + eps)         ← PyTorch、RMSNorm 论文的写法
外：(x − μ) / (sqrt(σ²) + eps)
```

`make verify` 的 §B7 把这个差异按 `σ` 扫了一遍：

| `σ` | 内 `sqrt(σ²+eps)` | 外 `sqrt(σ²)+eps` | 比值 |
|---|---|---|---|
| 0 | 3.162278e-03 | 1.000000e-05 | 316.2278 |
| 1e-06 | 3.162278e-03 | 1.100000e-05 | 287.4798 |
| 1e-04 | 3.163858e-03 | 1.100000e-04 | **28.7623** |
| 1e-03 | 3.316625e-03 | 1.010000e-03 | 3.2838 |
| 3.1623e-03 | 4.472152e-03 | 3.172300e-03 | 1.4098 |
| 1e-02 | 1.048809e-02 | 1.001000e-02 | 1.0478 |
| 1.0 | 1.000005e+00 | 1.000010e+00 | 1.0000 |

**成因**：`eps` 是加在**方差**上的还是加在**标准差**上的，决定了它从哪个 `σ` 开始起作用。内式里 `eps` 与 `σ²` 同量纲，所以它从 `σ² = eps` 起生效，也就是 `σ = sqrt(eps) = 3.162278e-03`；外式里 `eps` 与 `σ` 同量纲，从 `σ = eps = 1e-5` 起生效。**两个分界点相差 `1/sqrt(eps) = 316.2278` 倍。**

于是 `σ ∈ [1e-5, 3.1623e-03]` 这一段是「两种实现给出不同答案」的区域：内式已经把分母钉在 `3.16e-3`，外式还以为自己的分母是 `σ`（小到 `1e-5`），最大的时候差 `316.2` 倍。`σ ≥ 0.01` 之后两式趋同到 `4.8%` 以内，`σ = 1` 时差 `0.0005%`——**标准激活上测不出这个差异**，这就是它能藏住的原因。

**规避**：没有「哪一对更对」这种说法，只有**必须固定口径**。切换实现或做数值对齐时，先确认三件事：`eps` 是同量纲还是异量纲、默认值是多少、`eps` 是在 `sqrt` 之内还是之外。另外注意内式在 `σ → 0` 时给出 `(x−μ)/sqrt(eps)`，分母有下界，**不会除零**；外式在 `σ → 0` 且 `eps` 很小时分母趋近 `eps`，也不会除零——两者都安全，但安全值不同。

## 6. 小结与延伸

全文一条主线：**LayerNorm 要一行的两个统计量，RMSNorm 只要一个；「怎么求这两个量」有三种写法，差别全在数值上，而不在数学上。**

1. **`Σx² − nμ²` 不能用。** 它把两个 `n·μ²` 量级的大数相减去掏一个 `n·σ²` 量级的小数，需要的相对精度是 `σ²/μ²`。`μ/σ = 100` 就开始坏（`1.152e-03`），`μ/σ ≥ 1e4` 时方差的量级都不对，还能给出**负方差**（`μ = 1e5` 时 `−538.5001`）。
2. **Welford 的递推**：`μ_n = μ_{n−1} + (x_n − μ_{n−1})/n`，`M2_n = M2_{n−1} + (x_n − μ_{n−1})(x_n − μ_n)`。推导的支点是 `M2_n = M2_{n−1} + n(n−1)Δ²`，再把 `n(n−1)Δ²` 拆成两个可复用的量之积。它全程不构造 `Σx²`，所以灾难性抵消无从发生。
3. **单遍不等于省显存。** 一行放得进每 block 的 shared memory 时（常驻 4 个 block ⇒ `hidden ≤ 29184`），两遍法的第二遍读的是片上副本，`3/2` 那个访存比根本落不到 HBM 上。**先算容量账，再决定用哪种写法。**

三个结论里，第 1、2 条是数值的，第 3 条是工程的——而它们的取舍方向常常相反：Welford 数值上稳但归约更重，两遍法归约轻但（在长行上）多一遍访存。

- [01-softmax-stability](01-softmax-stability.md) 建立了恒等变形、四个阈值、以及「带宽受限」这个判定；
- [02-online-softmax](02-online-softmax.md) 把「两遍」压成「一遍」，并给出 `(m, l)` 重标定递推（attention 主题的正文来源）；
